# 智慧圆屏文档维护

从当前工作树的 `docs/README.md` 和 `docs/documentation-manifest.json` 定位任务。权威来源按事实范围划分：当前优先级归 `ROADMAP.md`，授权归 `AGENTS.md`，日常步骤归对应指南，恢复证据归恢复指南，研究指标归原报告。导航分类不等于内容验收。

## 按需工作

- 使用当前工作树的 `scripts/development/check_docs.py --query <任务词>` 或 `rg`，先读取匹配的权威入口及相关段落，再跟随 `topics[].sources` 核对源码与相关测试。不要因为文档多就默认通读全仓。
- 修改代码时，用 `--changed <仓库相对路径>` 或 `--base <提交>` 得到候选复核范围；未关联路径仍需人工判断。该输出不是语义一致性结论。
- 对照实现、生效时机和最近恢复记录，区分已实现、待验收、历史结果与候选。发现矛盾先记录证据，更新事实所在的权威文档，其余入口引用它。
- 只更新受影响范围，并同步清单的路径、分类依据、关联与 `review`。`verified` 必须有日期、核对范围和证据，不能用一次链接检查证明整篇语义。
- 使用 `--only <文档路径> --strict` 检查变更文件；需要全量时另行执行。新增脚本或机制变更运行 `tests/unit/development/test_doc_maintenance.py`，使用合成目录。

## 保留历史与边界

六种状态为 `current`、`reference`、`historical`、`draft`、`pending`、`superseded`。不按旧日期自动判废。部分替代在 `superseded_by` 明确范围，保留其他有效约束；新决定按项目 ADR 规则记录，不改写已接受决策、研究数字或旧验收。旧路径提示需人工判断历史语境，禁止全仓替换内部 `longmemory` 标识。

读取与写入范围以当前任务和文件归属为准；清单与 skill 不新增执行授权。独立会话须显式指定自己的工作目录，编辑绝对工作树路径，不使用主检出运行会改写产物的命令。只读检查不需要访问 `local/`、个人库、真实音频、日志正文或实验产物。依赖、模型及外部源码获取沿用所有者执行约定；不自动安装 QMD/Context7 或索引私有资料。

详细字段、命令、退出码、解析限制及存量问题处理见当前工作树的 `docs/development/documentation-maintenance.md`，仅在维护清单或检查机制时追加阅读。交付须分别报告文件变更、实际验证、存量待办及未验证范围。
