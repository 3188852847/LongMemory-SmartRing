## 范围与完成标准

所有者授权优化低延迟并检索技术。X 负责 Cosy 服务、PCM/Opus 消费、缓存/暖机和
合成验收；V 负责记忆及输入路径，Z 在交付后独立审查。X 不合入主分支或推送。
工程目标为当前自定义声线真实推理首个可解码 Opus 尽量 ≤1 s，整链路 ≤2 s
仍为更大目标，不作已达标承诺。

完成标准包括原生增量音频即时编码、取消后清理和新轮次隔离、同声线交替 GPU
对照、首包与持续供给两项均可评估、明确回退、独立审查和后续实机体验。
本轮不安装依赖、下载资源、改 torch/锁文件、写个人库、变更声音配置或操作设备。
单次 GPU 窗口最多 20 分钟，异常先释放 X Job，再恢复原日用；不与原日用争用显卡。

## 下一次对照的口径

同一候选可执行代码/同一模型/当前参考声线，对比完整片段模式与增量模式。
完整片段模式复现旧交付屏障，并非另起未修改的旧可执行文件；该限制随结果报告。
普通请求关闭回复缓存，三个重复中交替先后顺序，使用固定种子；流式和非流式声学
输出未声称逐字节相等。固定五类合成句覆盖寒暄、多句、长句、稀疏标点和中英混合。

另测多句/长句的现行自然分段路径，文字已完整可用，不包含 LLM 等待。
单列进程构造/默认暖机、选中声线第一次、实际流式暖机、暖态非缓存、精确缓存命中、
取消后同一编码器的新轮次。已有缓存收益不冒充新推理性能。

记录服务完成 CPU WAV 转换、消费端解包 PCM、首个可解码 Opus、完整请求耗时、
RTF（生成耗时与音频时长之比）、各块/帧到达曲线、供给缺口估算及显存。
供给缺口按首包立即开始、每帧消耗 60 ms 估算，不等于设备播放。
合成原生 WAV 和 Opus 解码 WAV 分别保存在新忽略结果目录，供后续音质检查；
不复制参考录音或真实对话，不以这些文件代替所有者实机听感。
运行时 `last_producer_join_ms` 只计生产线程退出等待；实际取消到服务可再接单的
时间另由客户端轮询独立锁/活动请求记录，不能把线程计时当作全部清理时间。
