## Z 审查 P2 修复：未适配路径的取消清理

Z 正式审查在 `b560e2e` 发现：`stream_runtime.applied=False` 时 v2 buffered
仍传入取消事件，服务在原始模型第一次 yield 后抛取消并 close，跳过原始函数
yield 后的三个请求字典清理。Z 的固定 `074ca6d` 控制流 CPU 证据仅作只读参考，
没有编辑 Z 树或向其发送工具消息。

X 使用同一固定原始函数和 CPU 生产者独立复现：补丁前取消后三个字典计数
`[1,1,1]`，补丁后为 `[0,0,0]`，均不加载模型/网络/GPU。
最小业务修复集中于 `service.py::stream_chunks`：

- 只有 `applied is True` 才启用模型增量和 guard 协作取消；缺失 guard、缺少
  applied 或 applied=False 均完整缓冲，legacy v1 的模型流式配置也不能绕过。
- 未适配路径取消、关闭或 WAV 封装失败时，持锁耗尽原始迭代器后再 close，
  完成原始清理并等待原生产者；不发布排空所得音频，不提前释放锁进入下一轮。
  这会等待原模型完成，不能将其报告为即时 GPU 取消。
- 调用前、缓存块和完整缓冲块交付前检查取消；未安装的 guard 不写入或重置
  external_cancel。默认 buffered、声线、原增量显式门及播放后不重播约束保持原值。

新增 `test_cosyvoice_unadapted_cleanup.py` 的 19 项固定控制流回归：未适配器的
三种形态、调用前/模型调用中/上游 yield 前/WAV 封装时取消、消费端 close、
封装失败、force-buffered、legacy v1/v2 peer 断连、缓存命中与同服务下一话轮。
逐项核对三个请求字典、生产者、模型/合成锁及真实随机端口 HTTP gate/观察线程。
原缓存/模式测试的已适配替身现在显式声明 applied=True，不再让无适配替身冒充支持。

首批 54 项通过（11.55 s）；原 118 项与新增 19 项合并，**137 项通过（19.28 s）**。
本修复未新开 GPU、未合成真实声音、未重启或部署正式服务；46 调用测量身份仍为
e4cebc2，不能改写成这个补丁的 GPU 验收。仅在 X 分支提交补丁交主会话接给 Z；
Z 的最终组合、文档和放行判断由 Z/主会话维护。

## Z 后续 P2：模型自身失败后禁止复用

  适配并能只读确认 guard 活动请求为零、三个已知请求字典全空，就把实例标为不可复用。
