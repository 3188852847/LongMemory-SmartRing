## 诊断事实与尚不能证明的部分

- 对照 main 代码和只读官方 VoiceProfileStore，当前 profile_valid=true、default_voice_active=false、voice_latency_mode=realtime；不输出/复制档案、参考原文或录音。小智现有源码 HEAD 为 `eb4b28c59ed7ed885258498cf757ce14352d620e`。
- 四个默认提示 `.opusframes` 均保留，实时启动仍装 `install_waiting_sender`。基线 `begin_waiting` 对非默认声线传空包；这是当前静默的明确软件条件，属于声线隔离策略，不是 Hy 删掉音频。
- 基线只有 `_ObservedLLM._call` 在 Memory 返回后才开始 0.9 秒计时。上游 chat 先同步等待 `query_memory`，然后调用模型；若慢在 Memory、后续很快，计时可能根本来不及发提示。当前状态不能反推出昨日每轮 cue_state、运行版本或用户当时选中声线。
- 基线网关 `_send_stream` 逐行放队列，`stream` 每行写出并 flush，没有全回答收齐后再伪分块。它持共享调用锁，且每个上游流新建会话/事件循环；排队及连接复用价值需计时，不能仅看这些结构就断言本次变慢。
- 自定义声线还会绕过 `fast_voice_responses` 的整个封闭寒暄快路径，因此普通问候可能进入完整 Memory/模型/TTS。这是另一候选，不等于可以跳过归档或对任意问题返回预置回复。
- CosyVoice 代码默认 `model_streaming=False`，启动构造不传 `--model-streaming`，HTTP 分块不等于模型内部立即出块。ADR-0166 曾为整体实时率、清理与质量权衡选择完整自然片段；未核当前进程健康/参数，不把磁盘默认当现场已加载证明，也不照搬不同条件历史测量。

本轮没有读取现场逐轮阶段数据，无法给出昨日/今日真实 E2E（端到端）中位数或尾延迟差值；所有者“感觉更慢”保留为反馈，不能换算成秒数或认定单一根因。

## 当前关键路径与可观测边界

`最后活动音频 → VAD判停 → ASR正式处理/复用预识别 → ASR交接与线程池排队 → chat → Memory HTTP与Runtime锁 → 平台归档＋Hy observe/add → recall/search＋可选profile/来源复读 → 模型首增量/首文本/首可合成段 → TTS声线注册/生成首块 → Opus/音频队列 → 最终socket发送 → 设备播放`

Runtime 已有 `lock_wait_ms/command_ms/observe_ms/recall_ms/scenario_ms/persona_ms/total_ms`。Hy 不声明 deferred_observation，因此即便圆屏调用请求延后，当前仍先同步 observe 再 recall；旧支持延后的方法可能先归档、完成回执后提取。两者时机不同，是架构取舍，不能为降时延直接改成“跳过 Hy/不提取/只答当前问题”。

可信启动使用常驻 Runtime/SDK；兼容脚本中存在逐轮 subprocess 分支，不代表当前日用逐轮冷启 SDK。此前 V 逐题副本的约 3.4 秒含复制/冷启动，不能拿来当当前常驻检索耗时。当前 observe_ms 尚不能单独拆出来源归档与 SDK 内部多次模型/向量调用。

输入端已有预识别的 reused/fallback、正式等待、模型队列、重叠时长。命中受同一音频前缀、generation、语言和继续说话校验约束；未降低 VAD 阈值或牺牲听全话。主计时起于 ASR 文本后的 chat；直接相加既有输入时长仍缺交接排队，不能假装是完整端到端；预识别的重叠不得再扣一次。

4. 网关：记录共享调用锁等待、上游headers/首文本/完成时长；若测试持久连接，须由X/Z控制loop/session生命周期，保持重定向拒绝、取消、无自动重试、完整usage/DONE与unknown预留，不另开额度。
