## 1. 判断与证据边界

**建议先让现有记忆与陪伴能力更容易被信任和验证，再增加新的生活工具。** 当前项目已超出“聊天加记忆”的基础闭环：纠错、事实变化、来源解释、手动补记、每日回顾、回答反馈、明确事项跟进和受控习惯策略均有实现。再建一套提醒、画像或反馈系统会重复已有能力。

最值得先讨论的四项依次是：**记忆修复后的效果验证、跨重启的记忆许可、换浏览器／电脑的会话恢复、事项完成状态与后续跟进的分离**。这个顺序是产品建议，依据是长程记忆主体定位、已有工程复用程度和当前恢复中实际出现的边界；没有用户统计或收益测量支持，不代表所有者已选择。

采用以下证据口径：

- **源码事实**：在本工作树看到的接口、状态、存储和控制行为。
- **本次合成验证**：只证明临时数据库、替身模型及接口契约，不证明真实提取质量或硬件表现。
- **已有验收记录**：引用仓库中的日期、版本与所有者反馈，未在本会话重做，不能扩大结论。
- **缺口判断**：在所核对的路由与实现中未发现相应纵向闭环；并非对所有外部资源作全量证明。
- **建议／成本推断**：未来可能的切片；成本只用小／中／大，并说明依据。

术语：L0 是原始对话证据，L1 是单条个人事实，L2 是生活场景，L3 是用户画像；召回是从已存记忆中找出当前相关项。ADR 是记录重要架构选择及后果的决策文档。

## 3. 五类发现与排序

① 真正未形成的闭环；② 已有能力的入口／交互问题；③ 已实现但缺真实验收；④ A～G 本轮已在处理；⑤ 更远期或条件未成熟。② 的判断来自当前路线和静态页面，不冒充本会话的浏览器体验结论。

| 建议讨论顺序 | 发现 | 分类与实施条件 |
|---|---|---|
| 先完成已有工作 | 工作区可达性、保存反馈、生效边界、启动状态、脱敏故障摘要 | ②④：C/D/E/F/G 已负责；A/B 负责文档。I 不重复实施；等整合与 H 复测 |
| 先取得实际证据 | 声音克隆听感、新动画、跨日记忆、硬件异常与跟进改时后播报 | ③：见现有验收限制；烧录需新授权。日用恢复成功不等于完整 V1 发布通过 |
| F1 | 记忆问题“处理了”之后能证明什么 | ①：复用问题队列和冻结实验；先做不调用模型的对照证据 |
| F2 | 长期记忆许可跨重启保持，并能只显式记忆 | ①：现有模式是临时且重启恢复开启；需先选许可语义与迁移默认，不当作现有 bug |
| F3 | 会话归属恢复与可验证的恢复清单 | ①：有已记录的换电脑 Cookie 丢失边界；先在独立副本确认归属，不修改活动库 |
| F4 | 把“事项已完成”与“问候已投递”分开 | ①：当前跟进为一次性触发；需所有者确实希望管理持续事项，否则维护成本不值得 |
| 条件候选 | 按来源生成少量日／周回顾，而非仅统计 | ①：每日回顾已有，叙事提炼未有；先问是否真会使用，不默认增加总结模型与播报 |
| 条件候选 | 显式从网页接续到圆屏，或满 40 轮后的可追溯接续 | ①⑤：短期会话独立是当前有意边界；需明确接续任务，不自动拼接全部历史 |
| 暂缓 | 自由指令、自动冲突裁决、全面保留策略、全副本擦除、外部工具生态 | ⑤：语义、数据和服务边界更复杂；不因清单里写着候选就排期 |

## 4. 最值得先讨论的四项

### F1：记忆问题处理后的效果验证

**场景与痛点。** 用户标记“没想起”或“记错了”，管理员补记／纠错／修复召回后把队列设为已处理；下次是否仍出错，当前没有一个与该问题绑定的验证结论。用户需要知道“改了什么”和“这次验证覆盖什么”，研究也需要把真实问题转成可重复检查。

**现有能力为何不足。** `/api/chat-memory-feedback/reviews` 及 `SQLiteMemoryFeedbackReviewStore.record` 只保存目标、修订、处理理由和时间，不要求修复操作或复测档案。已有提取重试、人工来源补记、来源指纹和实验回放各自能用，但尚未发现把它们关联为同一修复任务的接口。将问题设为 resolved 不等于模型回答已经恢复正确。

**最小可验证切片。** 先给一条问题绑定修复证据 ID、待验证问题和“期望召回哪些事实／应当未知”的人工标准。对选定版本的临时副本做只读召回核对，结果分为未验证、召回符合、召回不符、证据不足；仍可仅凭人工理由关闭问题，但明确展示未复测。下一切片才考虑单独授权的真实模型复问，并区分召回通过和最终回答通过。

**重叠、依赖与成本推断。** 复用现有队列、纠错／补录和实验档案，不替换检测器、不再建反馈页面。成本推断中：需追加关联记录、版本指纹与独立验证入口；第一切片无新模型，降低调用与维护成本。若要复制真实样本进入数据集，必须逐项脱敏与批准，不能默默搬运日用库。

**影响与回退。** 验证不写个人事实，不触发自动整理，不自动调阈值或训练。关联记录只追加；撤销该入口即可退回人工处理队列。若验证使用临时副本，应冻结其来源版本并标记后来记忆变化；不能拿今天的库冒充修复当时的结果。

**验收。** 用合成的漏记、错记、无证据、正文后来变化四种样本，验证修复前后证据、重启持久化、重复点击幂等和修订冲突；没运行的项目绝不显示“修复有效”。向既有冻结评估导出一条人工审核的合成／脱敏样本，带代码、配置、数据摘要和运行时间。无需开启当前关闭的影子模型。

### F2：跨重启的记忆许可与“只在我要求时记”

**场景与痛点。** 用户长期希望仅显式记忆，或暂停自动写入后重启电脑仍保持。当前运行期开关重启恢复开启，要求用户每次再检查；“不要记住这句”也不意味着不保留聊天。

**现有能力为何不足。** `MemoryRuntime.__init__` 默认 `_write_enabled=True`／`_use_enabled=True`，`status` 返回 `settings_persistent=False`；`/api/memory-mode` 明确不持久化，页面也标为临时。固定“请记住”虽已存在，但暂停写入时连显式写入也会拒绝；尚无“普通聊天只归档 L0、明确命令可写 L1”的独立许可。这是现有明确契约，新增持久设置需要设计，不应悄悄改变默认。

**最小可验证切片。** 新增独立的持久偏好：自动积累／仅显式／暂停 L1；保留“用于回答”的独立开关与临时覆盖。所有选项都明确 L0 与网页会话是否留存，第一切片继续保留，不冠以“不留记录”的名称。开始会话时能核对当前许可来源，网页与圆屏读同一应用层配置。

**重叠、依赖与成本推断。** 复用自然记忆命令和 Runtime，不新增提取器。成本推断中：需审阅正常观察、后台延迟提取、重试、显式写入和多入口共享，防止稍后任务绕过新许可。该选择影响个人数据写入边界，应先有 ADR；按现状迁移，不能替所有者选择更开放或更严格的策略。

**影响与回退。** 只影响未来写入／使用，历史记忆不删、不批改；模型外发与 L0 留存分别说明。关闭新功能可退回原运行期模式，但不得丢掉已选择的许可或静默恢复自动积累；回退也应明确告知。

**验收。** 临时合成库覆盖普通聊天、明确记住、纠错、无主体、暂停、重启、两入口及已排队提取的许可变化。仅显式模式普通陈述无 L1，合法明确命令可写入并溯源，重复不新增；暂停时无后台补写。不能把这项验收扩大成“敏感内容不会被任何系统保留”。

**扩展边界。** 真正的“不保留本次对话”涉及 L0、旁库、反馈轨迹、日志和外部供应商，不在第一切片；类别禁记也需要另一份规则与负例，不能依赖分类器承诺零漏记。

### F3：会话归属恢复与恢复清单

**场景与痛点。** 换电脑／浏览器后个人库仍在，网页旧会话却看不到；使用者容易以为丢失，甚至误做清库。当前恢复记录已明确浏览器 Cookie 未随备份保留，归属迁移需要另做，不是推测故障。

**现有能力为何不足。** `ChatStore` 保存 `.chats.sqlite3`，`chat.selected/listing` 根据 `OWNER_COOKIE` 的哈希判断所有者；数据库备份工具只验证单个 SQLite，未包含浏览器归属恢复。常驻锁能防止双控制台写旁库，不能替代身份恢复。旧角色、声音与外观各自也有范围和版本，并非一份可恢复整套体验的档案。

**最小可验证切片。** 先做离线、仅本机的恢复检查工具／向导：列出主库、旁库、结构版本、完整性、非敏感条目数量和缺失资产；在独立恢复副本预览指定旧会话的归属迁移，显式批准后才绑定当前浏览器。默认不覆盖活动库、不合并全部会话、不复制旧 Cookie。配置、合法参考音频和外部资源只给分域清单；模型／SDK 重建仍走官方资源流程。

**重叠、依赖与成本推断。** 复用 `verify_restore`、旁库锁及已有配置域，不建新的备份引擎、不改为多用户账户系统。成本推断中：身份接管的授权与副本操作要可靠，并需将“数据库恢复”和“用户能继续任务”分开验收。支持整包导出／导入才会升为大，暂不建议第一切片承担。

**影响与回退。** 迁移前核对停止状态、精确路径与可恢复备份；对个人会话归属的实际批量改写仍须单独批准。记录旧／新归属与所选会话 ID，先在副本验证，失败保留原库。恢复包可能包含私人正文；不默认云备份、不进入 Git、不将密钥加入普通可分享导出。

**验收。** 用两个合成浏览器归属和两份合成数据库，验证失去 Cookie 后不自动显示他属会话、显式选择后仅恢复选中项，取消不写、结构损坏／锁冲突拒绝、旧版配置不覆盖新设置。恢复完成后走“打开旧会话→再发一句→核对来源”任务；再核对长期事实召回，分别报告。

### F4：持续事项的完成状态，而非再造提醒

**场景与痛点。** “之后问我汇报进展”已有一次性跟进；用户提前完成、计划作废或决定延期时，需要让以后少问、问得合适。仅有播报成功并不能证明事情已经办完；说“做完了”也不应被模型自动绑定任意旧计划。

**现有能力为何不足。** `FollowUpCandidateStatus` 仅有 candidate/cancelled，候选指向 L1 与内容摘要；主动账本负责触发、拦截、投递／人工播放观察。未发现独立“事项 open/completed/abandoned”状态及与后续联系的关联闭环。已有互动结果与习惯反馈记录不能充当生活事项的完成证据。

**最小可验证切片。** 所有者显式选择一条已有跟进，把它作为可跟踪事项；只提供未完成／完成／不再跟进及带来源的状态历史。先从后台明确目标，状态变化会停用关联的尚未执行跟进，并显示影响预览；重开事项不自动恢复播报。下一切片才支持最近唯一事项的明确口头关闭；不要立即扩展重复任务、日历或“我都安排好了”。

**重叠、依赖与成本推断。** 复用跟进候选、取消与门控，不建第二套 scheduler。成本推断中：需独立事项数据语义、唯一目标、并发投递处理和迁移；若加入自然时间、多任务规划或外部日历则大。需要 ADR 说明事项状态与 L1 用户事实、主动账本的边界。

**影响与回退。** 完成事项是工具状态，不直接生成长期性格／习惯；需要保留用户来源，不凭沉默或一次回复判定。取消尚未执行触发可回退，已经发送／播放的事实不可改成未发生。停用事项模块后保留旧一次性跟进逻辑，已取消任务不自行重新启用。

**验收。** 合成任务覆盖提前完成、作废、重启、重复提交、目标不唯一、已开始投递、重新打开和 L1 来源变化；“完成”停用可取消的关联联系，但不篡改已执行账本。最终由所有者在真实日用中确认是否降低无用追问；没有实际证据前不称为更懂用户。

**采用条件。** 如果所有者只需要一次性追问，现有功能足够，F4 不应实施。当前不建议把依赖 PC、网络、勿扰和设备状态的主动交流宣传为必须送达的提醒工具。

## 5. 条件候选与不建议立即做的方向

### 可在真实需求出现后讨论的两个小范围方向

| 候选 | 用户任务与现状不足 | 最小切片、影响、成本推断与回退 | 验收 |
|---|---|---|---|
| 有来源的日／周回顾 | 希望重看一周生活、计划和记忆变化；现有每日页偏核查，不是叙事回顾 | 从已选日期与来源生成草稿，逐句引用、区分用户说过与模型概括，保存前可改／拒绝；不写 L3、不自动播报。复用日回顾而非新页面；成本中，模型预算与叙事错误需维护；停用后保留现有计数和来源页 | 合成样本覆盖无对话、助手建议、变化事实、跨日时间、被删来源、未知事项；总结不把建议写成经历，不凭缺少聊天推断情绪 |
| 显式跨入口／长会话接续 | 从网页切圆屏后“刚才那个”缺上下文；网页达到 40 轮后希望继续 | 手工选择最近少量轮次／一段草稿，预览、授权、短期有效并可撤销；不把总结自动写 L1，不合并所有历史，不让新的聊天绕过 32 会话限额。复用会话与上下文，设备适配是前置；成本中，身份、过期、隔离与长度预算需维护 | 两个合成会话验证只接指定内容、拒绝跨属接续、过期与撤销后不可用；同一事实与模型推断分开；真实圆屏“接着聊”由所有者另验 |

两者的需求强度未知。先记录所有者是否真的遇到这些任务；没有使用需求就不提前开发摘要管线。聊天正文搜索也缺入口，但优先级取决于是否经常找旧聊天；它不应复用 Memory Core 的事实召回来冒充完整对话搜索。

### 当前不建议排入近期实现

- **任意自然语言都能改记忆／安排生活。** 固定高精度命令已有，扩大句式有收益，但误改、模糊主体和错时成本上升。先采集明确失败表达并补有限语法；通用模型解析需草稿、目标与时间确认，不直接执行。
- **自动合并冲突、自动学习人格、无人审核整理默认开启。** 来源、失效与候选基础已较完整；缺少长期真实质量证据时，自动化只会扩大错误。F1 的可追溯样本比再加模型更能解释问题。现有关闭状态保持。
- **一键清除所有数据／自动全库保留策略。** 已有单条删除、保留 L0 的重置、含 L0 的主库清除和影响预览。`wipe-preview` 明确保留网页旁库和已有备份，`MemoryBackend.wipe_memories` 还会先创建一致性备份；不能重新包装成完整隐私擦除。跨旁库、备份、资源、外部供应商的删除需要单独范围与确认。先让现有语义看得懂，再讨论保留策略。
- **更多模型、TTS 引擎、角色资源商店或大型 Agent 框架。** 当前主链路已恢复，声音档案与角色已有；新依赖、显存与接口组合增加维护面，缺口并未证明是模型数量不足。命名角色预设可在高频切换需求出现后复用已有版本；不必同时做资源包系统。
- **日历、天气、课程表、笔记／Zotero、音乐与智能家居整套接入。** 属于工具与知识平面，不能因记忆系统能存文本就视为已有接口。公开 `voice_web_search.py` 已有受限搜索适配，不应笼统说项目完全不能联网；当前私有配置和运行能力未核实。可靠外部来源、授权、时间新鲜度与失败行为应各做一个具体任务；此次无需求证据，不排期。
- **OTA、IMU 手势、深睡唤醒与自动硬件恢复。** 固件编译和原实机日用恢复不证明这些能力，动作误触发、功耗与恢复路径还需实机验证。新连续动画也尚未烧录，先处理已授权软件的真实验收。
- **多用户、云端、手机端、公开安装器、开机自启、完整监控平台。** 当前单用户本机定位不需要这些成为前置；会话归属恢复也不等于要做账号系统。自动自恢复须有服务所有权和受控重试，G 的诊断结果先用起来，不能为了“稳定”杀未知进程。
