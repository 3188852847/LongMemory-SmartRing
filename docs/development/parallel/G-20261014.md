## 实现

- 新 Diagnostics 保留 100 个请求／每请求至多 16 个记忆阶段，按每运行唯一文件名独立轮转，写入失败降级为内存摘要；保留全局 logger。
- API 新 `GET /api/observability` 复用原会话保护，默认固定路径只读 `stat`，不提供正文／路径参数；除自身摘要查询外，响应头带服务端请求 ID，忽略客户端同名头。
- 既有记忆审计自动附加 API 上下文 ID；线程调用可关联到请求边界。阶段时间为累计观测点，未伪造独立处理耗时。
- 启动器事件有界轮转／最近 50 条；窄范围修改 `controller.py`，让工作队列、阶段转换与触发 HTTP 请求关联；新增受 Bearer 保护的只读摘要。
- 修复启动失败直接展示 ValueError 正文的实际泄漏入口，改为固定安全提示。超时稳定码、未知结果与设备播放未确认分别保留。
- 新受控 DiagnosticsPanel 及类型、局部 CSS、组件测试，未编辑其他会话的页面、共享客户端或全局样式。UI 采用 `ui-ux-pro-max` 的错误可读与辅助技术反馈指导。

详细契约、日志所有权、默认路径限制、保留边界和整合说明见 [observability-contract](../observability-contract.md)。

## 未验证与整合事项

1. 工作树没有 `web/react-chat/node_modules`；没有安装或共享主仓库可变依赖。TypeScript、Vitest 组件测试、前端构建及真实浏览器尺寸／辅助访问检查尚未运行，由主会话统一安排。
2. 主会话需接入 DiagnosticsPanel；原共享 ChatApi 如要在错误提示中显示 `X-Request-Id`，需统一修改。本会话未改 DeviceApp 或页面入口。
3. API 每运行流受限，不自动删除历次运行文件，未建立全目录自动保留上限。历史清理与厂家日志切换需精确范围和维护窗口。
4. 已验证独立合成 HTTP 调用进程 → API → 记忆线程的请求标识边界；没有完整真实小智／ASR／TTS／WebSocket 链路，不声明设备播放已确认。
5. 本轮不切换日用启动器或 API；仅保存当前分支本地提交。主会话负责审查、整合和远程推送。
