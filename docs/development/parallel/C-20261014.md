## 范围与完成标准

聊天消息独立滚动、输入稳定可见；会话、任意轮次证据和运行说明可以切换或关闭。保留认证、40 轮限制、服务持久化、记忆反馈与证据链接。总览把状态、常用入口和异常优先呈现，完整链路按需展开。不得访问个人库或日用服务。

采用 ui-ux-pro-max（已核对 `focus not obscured` 返回对应 WCAG 规则）、frontend-design 与 web-design-guidelines。布局沿用当前主题的 canvas/surface/text/accent token，不引入字体、素材、依赖或装饰动态；主视觉是日常对话，证据作为可查的研究依据。

## 实现结果

- 聊天外壳采用视口内 grid；消息、辅助面板各自滚动，输入区占正常布局行。没有 fixed 输入栏。发送返回后的自动定位只写消息容器 `scrollTop`，不滚动整页。
- 工具栏直接打开会话、记忆证据、运行状态；辅助面板可切换或收起。每轮回答提供独立证据入口，默认入口查看最新一轮。保留 L0/L1/L2/L3 链接和记忆反馈请求。
- ≤1100px 时消息和辅助面板切换显示，保留消息 DOM 与滚动位置；输入和草稿一直保留。证据详情不再被旧窄屏选择器隐藏。
- 面板打开后标题获得焦点；Escape 或收起按钮返回工具栏入口。导航的当前项仍是可键盘访问的 Link；窄窗口菜单在跳转后关闭，Escape 返回导航按钮。跳到主要内容的目标可获得焦点。
- 总览先呈现状态与常用入口，故障摘要最多列两项并链接对应页面；完整诊断、服务和回答/圆屏链路分别收起。读取失败显示“读取失败”，不一直显示“正在核对”。没有新增模型调用或设备操作。
- 原有 API 客户端、认证、消息 request ID、40 轮限制、会话持久化、置顶、重命名、结果未知只查询和反馈修订保持。PageHeader 属性未改变，折行/间距在 C 样式中调整。
