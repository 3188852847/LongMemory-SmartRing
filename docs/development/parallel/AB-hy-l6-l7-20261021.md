## 已实现边界

L6 显式 ultra 原生 evolve；L7 保留 System1 原生提取。原生 System2 队列仍关闭，平台自己持久管理任务。自动写后任务、重启、幂等认领、暂停、取消、partial/uncertain、代次隔离以及保守管理失效按 ADR 执行。普通召回共享一次查询向量给只读 L7，L6 仅完整同代次且来源可证才注入；原生变更中的 L6 不注入。L7 到期过滤不写库，维护归档不转 L2，不推断已完成，不获得主动联系授权。

旧 proof 仍为图关闭模式。新功能必须证明协议 2；`settings.semantic_layers_enabled=true` 本身不能通过启动守卫。新证明字段为：`protocol:2`、`sdk_version:"2.0.3"`、`rpc_source_sha256`（当前精确摘要）、`real_sdk_rpc_verified:true`、`semantic_background_writes:"managed_v1"`、`derivation_invalidation_verified:true`、`read_only_intention_verified:true`。这些字段是可信装配回执，不能由 HTTP 用户提交，也不能以写出该字典替代实际验收。最终摘要须在主会话整合 AF 等改动后重新核对、重新走组合证据。

`semantic_layers_enabled` 是运行能力而非模型/向量身份，加入后仍能核对旧持久身份和原 scope stamp；没有已有可信 stamp 的旧库拒绝。新 Kuzu 文件与任务账本位于引擎资源目录，备份须覆盖整个引擎目录以及平台来源库、管理账本与既有 stamp，不能只复制 Chroma。

## AH/AI 接力接口（稳定候选）

进程 RPC 和 `HyMemoryMethod.sdk_call` 已实现以下方法；`HyAdministration.extension` 暴露除内部 pause 之外的四项。公共 Runtime/HTTP 白名单尚由 AI/AH 接线，本分支没有越界改公共层。

| 操作 | 参数 | 语义 |
|---|---|---|
| `semantic_status` | 无 | 有界任务/代次/实际图可用性状态；RPC锁非阻塞，5秒回包上限 |
| `semantic_task` | `task_id` | 单任务已有回执；不存在拒绝，不启动模型 |
| `semantic_enqueue` | `task_id,kind="evolve",max_batches=1` | kind 仅 evolve/intention_maintenance；batches 1–4；必须 Runtime 写门与管理权限；重复同载荷返回原状态，异载荷冲突 |
| `semantic_cancel` | `task_id` | pending 才取消；running 返回已认领、无回滚 |
| 内部 `semantic_pause` | `paused:bool` | 仅可信 Runtime 开关同步；不新增用户事实，不作为任意 HTTP 操作 |

`semantic_status` 固定字段：`protocol:2`、`enabled`（实际成功初始化能力）、`desired_enabled`（显式配置）、`mode`（ultra/pro）、`graph_available`、`task_counts`（按实际状态映射，缺键不等于任务故障）、`paused`、`last_task_finished_at`（可为 null）、`management_available`、`schema_state`（ready/isolated/disabled）、`epoch/ready_epoch`（禁用时 null）、`native_evolve_idempotent:false`、`automatic_restart_replay:false`、`intention_read`、`expired_intention_policy`、`execution_authorized:false`、`proactive_contact_enabled:false`。它是真实 owner 状态，机制清单仍只是配置声明，不可混用。

任务 DTO：`task_id,kind,state,created_at,finished_at,elapsed_ms,reason_code`。状态为 pending/running/completed/partial/uncertain/cancelled。cancel 另有 `cancellation_effect`，只能 prevented_start 或 already_claimed_no_rollback。时间为实际账本 UTC；未完成为空，不填造完成时间。reason 只用稳定原因码，不能输出 SDK 原始异常。

逐层接口沿原 `layer_page/layer_detail`。新语义模式的 L6 使用已打开原生图库，`coverage="graph_complete"`、`count_scope="owner_agent_source_layer_state_graph"`；若存在旧 VDB L6，改 `read_status="partial"`、`coverage="graph_only_legacy_vdb_present"`、`reason_code="legacy_vdb_schema_not_in_graph_page"`、`total=null`。L7 继续精确范围 VDB。分页仍有界，不能把末尾空页误判全库为空。

L6/L7 item 额外字段：`semantic_kind`（model_inference/future_intention）、`execution_authorized:false`、`derivation_state`（L6 ready/isolated，L7 stored/expired）、`evidence_memory_ids`（最多16，无法证明为 null）、`updated_at`（原生 gmt_modified 转 UTC 或 null）。原有 `source_event_ids/recorded_at/memory_at/valid_until/status` 保留。L6 的 evidence IDs 会进入回答管理隔离；来源未知保持 null。L7 valid_until 到期只说明计划过期，不说明已执行。

AI 必须在 `MemoryRuntime.configure`（初始化也同步）调用实际 Hy engine 的 `configure_background_writes(write_enabled=…)`；由此暂停未认领任务、禁止新 enqueue/add。已认领任务不假称回滚。Runtime 新增 semantic_enqueue 时使用与现有写操作同一 write_enabled 门；cancel 可在暂停时用于停止尚未执行的任务。只读 status/task 用现有窥视 Runtime 和非阻塞锁；不要为展示懒创建引擎。服务白名单/类型映射、实际部署回执与状态检查由 AI 接力。

AH 需添加新 coverage/计数范围与语义字段，不能把 isolated 显示成“无数据”或“已关闭”；把管理可用性与后台 running 分开。任务状态和图式来源是只读展示，不能由这些字段自动获得执行未来意图或主动联系的权限。

### AE 候选接口（独立于正式 prepare）

可调用 `HyMemoryMethod.candidate_snapshot(query_embedding=list[float],limit=5)` 和 `candidate_validate(snapshot_token=str,memory_digest=None)`；方法在 `method.py`，原生只读实现为 `candidate_snapshot.py`，经 `process_client.py` 同名 RPC。仅使用已经初始化的 owner，方法锁/RPC锁不等待长调用；未初始化不懒创建，传入向量维度必须匹配当前设置且非零有限。调用方负责取得已有查询向量，接口不生成向量、不调用公开 SDK search、不写平台来源、不准备或取消话轮。无 HTTP 扩展，AI 接 Runtime 内部钩子。

响应 `protocol:1`、`read_status`（readable/busy/changed）、`items`、`snapshot_token`、`revision`、`epoch`、`ready_epoch`、`stable`；readable 另有 `expires_at`、`memory_digest`、`policy="latest_only_no_history_expansion_no_models_no_semantic_writes"`、`digest_scope="native_items_before_platform_management_overlay"`。busy/changed 没有可用令牌、items为空，不能复用旧快照作为新结果。

item 为 `memory_id/content/layer/channel/source_event_ids/evidence_memory_ids`；读取当前 ACTIVE/latest 的 L2/L3/L4、可证明基本画像、完整同代次且来源可证的 L6，以及未过期只读去重 L7。当前画像、模型归纳和未来意图使用正式回答相同标签，平台纠正来源叠加、管理 uncertain 证据排除仍有效。`memory_digest` 绑定原生条目，方法随后叠加的管理来源不改签名；AE 应保存返回值，校验时原样传该摘要，不能从加标签后的正文重算它。

令牌以进程随机密钥签名，绑定当前原生 revision/epoch/ready_epoch 和原生条目摘要。最长30秒，若返回的意图更早过期，则截止于该意图到期。每次前台 add/update/delete 尝试及后台任务开始/结束使 revision 前进；有后台写运行时快照/校验拒绝，成功重开也换密钥。校验返回 `protocol/valid/reason_code`，有效时含原生 `memory_digest/revision/epoch`。原因可为 invalid_token/expired/memory_changed_or_busy/memory_digest_mismatch/owner_not_initialized。没有单次消费或取消正式话轮的副作用。

AI/AE 必须在正式采用候选的同一 Runtime 临界区做最终校验，遵守当前 write/use 开关；令牌是时点校验，不是跨进程全程冻结。正式 prepare 只在真实轮次到达时执行一次。候选快照不展开历史、原生 reader 可能使用更多排序/历史支持，因此还必须比较正式准备得到的记忆条目内容与来源（忽略不可比的SDK分数），有差异或无法证明一致就丢弃候选，走正式回答。不能用 epoch 相同承诺查询或历史内容相同。
