# 启动器与声音服务修复（2026-11-21）

基线 `40452b25`，实施分支 `codex/fix-launcher-20261121`。

| 场景 | 修复及验证 |
| --- | --- |
| CosyVoice 已就绪，启动器和试听却报告不可用 | 启动器、语音启动等待、网页状态和试听检查共用有大小上限的就绪探测。在 `GET /health` 请求中指定 `Prefer: return=minimal` 可跳过档案读取、统计和最近请求复制。普通 `/health` 仍提供完整诊断，原有诊断脚本和恢复工具可继续使用。旧服务忽略请求头时，探测器接受 1 MiB 以内的完整响应。随机端口上的合成服务累积 100 次请求后，四处都能确认就绪，也能识别需要重启的服务。 |
| 保存失败后手动刷新，启动仍被禁用 | 后台轮询保留操作错误。手动刷新成功后清除错误并采用服务端的 `can_start`，刷新失败显示读取错误。刷新本身只读。 |
| 网页和命令行同时控制启停 | 工作线程跳过已被停止或退出取代的排队启动。命令行按请求 ID 等待停止完成，直接复用已排队的停止或退出。启动失败、清理或网络同步期间收到的新停止请求保留其状态。停止失败可显式重试，残留进程句柄不会得到启动成功回执。 |
