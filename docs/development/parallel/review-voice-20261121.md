# 圆屏待机、快捷播报与长回答回执修复

2026-11-21，电脑侧分支 `codex/fix-voice-20261121`，基线 `40452b25`。

| 问题 | 修改与验收 |
| --- | --- |
| 待机后重新唤醒，全程静默时无法再次待机 | 在固定小智 SDK `eb4b28c` 的 `ListenTextMessageHandler.handle` 收到 `listen.start` 时，为支持持久连接的设备清除待机标志并重置计时。同一连接连续两次唤醒、只输入静音帧，每轮超时各发送一次待机消息。[监听回归](../../../tests/unit/development/test_voice_persistent_listen.py) |
| 快捷寒暄查询记忆失败时提前发送播报结束动作 | 快捷查询使用协程局部标记，播报由快捷通道发送完整的 `FIRST → MIDDLE → LAST`。用小智 Python 3.10.20 和固定 SDK 的普通回答方法复验，两轮相同寒暄并发、查询都失败时，普通路径只发本轮 `FIRST → LAST`，快捷路径保持完整顺序。[快捷播报回归](../../../tests/unit/development/test_fast_voice_responses.py) |
| 长回答连同召回证据超过完成接口原有的 32 KiB 限制 | 两版协议共用 258,560 字节的请求体拒绝阈值，覆盖最多 16,000 字符的回答、准备阶段返回的证据及固定字段。原版小智提供器以 ASCII 转义提交 15,999 个非 BMP 汉字、1 个常用汉字及 100 条证据，两版均成功写入合成库。相同内容使用 UTF-8 重放时均返回 `created=false`。超出字符或字节限制分别返回 400 和 413。[回执闭环回归](../../../tests/integration/memory_pipeline/test_xiaozhi_bridge.py) |

使用主项目已有的 Python 3.12.13，核对业务模块从本工作树导入。定向回归通过 124 项，另有 2 项原有测试按工作树的默认 SDK 路径跳过，单独指向本机已安装的固定 SDK 后均通过，合计 126 项。小智提供器及安装脚本与基线字节一致。验证使用临时回环端口和合成数据，圆屏实际待机和播报体验仍待实机验证。

## Windows 诊断重定向测试补验

整合树 `55f03d64` 全量测试曾报告 `WinError 10053`。在 Windows 上串行复跑原用例 20 次均通过。受控延后 POST 正文发送时，观察到旧测试服务在客户端发送两个字节的 `{}` 前已开始返回 302。修复后的测试服务按 `Content-Length` 读完正文，再发送长度为零的 302 响应。客户端继续使用日常诊断程序的重定向处理器。用例核对状态码、跳转地址和唯一一次实际请求，包括合成凭据与正文。[诊断回归](../../../tests/unit/development/test_voice_diagnostics.py)

诊断模块 18 项全部通过，修复用例另以 4 个线程共运行 32 次均通过。临时改用标准库默认重定向处理器后，第二个回环路径收到了带合成凭据的 GET，测试按预期失败。所有请求均使用临时回环端口。
