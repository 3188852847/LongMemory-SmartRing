### R1 · P1 · Esc 关闭后弹窗停在退场阶段，遮罩拦截页面（F/C）

**这是本轮合入阻断建议。** 不改动业务数据也能复现，键盘用户无法按常规关闭返回页面。

复现一：1440×900、普通字号、系统不减少动态效果、应用 full；进入设置→助手角色设置，保持内容未编辑→按 Esc→等待 1.3 秒。弹窗仍显示，整页 `.ant-modal-wrap` 拦截页面。复现二：390×844 来源抽屉→删除确认→直接 Esc，等待后同样保留遮罩；并未点击确认删除。证据：`38-modal-interception.png`、`39-escape-modal-repro.png`、`74-role-escape-1440.png`、`79-final-role-escape-block.png` 与 `modal-escape-proof.json`。

最后一次实测：document 可见，`data-input-modality=keyboard`，`data-motion=full`，系统 reduced=false；弹窗 class 为 `ant-zoom-leave ant-zoom-leave-active ant-zoom`，computed animation/transition 均为 none；wrapper 为 display:block、pointer-events:auto，覆盖 1440×900，背景坐标 (1420,450) 命中 `ant-modal-wrap`。将输入方式切回指针并点击背景后，对话框数变为 0（`40-pointer-recovery.png` 另保留手机恢复过程）。这不是仅由定位器超时推断的故障。

源码定位（相对于 J）：`web/react-chat/src/styles/shared-visual.css:143` 的 keyboard 选择器包含 `.ant-modal`，强制 `animation:none!important; transition:none!important`。**推断**：键盘输入切换取消了 Ant Design 退场动效，影响关闭完成后的移除；该 CSS 与实测停留状态相符。未声称所有抽屉都有同样故障，也未修改源码或通过隐藏遮罩绕过。

建议只限制键盘装饰/按钮反馈动效，保留弹窗生命周期所需的关闭完成机制；或通过组件支持的 motion 配置关闭动效。修复后复测鼠标打开→Esc、Tab/Enter 取消、鼠标/键盘交替、full/reduce、390/1440；验收点应包含关闭后弹窗/遮罩消失且背景可操作，不能只检查业务 open 状态。
