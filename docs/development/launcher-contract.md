# 本机启动器契约与观察

2026-10-19 X 候选新增 `hy_memory` 白名单选择，仍只保存下次启动指针。Hy 普通启动要求已初始化来源/状态与固定可信部署配置，不从HTTP接收路径/端点，不自动安装/建库。旧提取/召回选择不作用于Hy，旧定时联系/整理/影子暂停，原偏好保留；面板明示暂停及需重启核对。候选尚未部署，真实状态与切换门槛见 [Hy 日用装配](../guides/Hy-Memory圆屏与日用装配-20261019.md)。

启动器 HTTP 主机独立于聊天 API。Python 标准库提供回环 HTTP，React 双入口构建共用视觉组件；启动和停止复用原 `Manager`、Windows Job 所有权与预检。该边界使聊天服务尚未启动时也能使用界面。

| 接口 | 含义 |
|---|---|
| `GET /api/launcher/status` | 当前阶段、各服务呈现、安全设置、设置摘要与可执行操作 |
| `POST /api/launcher/settings` | 白名单设置及 `expected_revision`，拒绝陈旧保存 |
| `POST /api/launcher/actions` | 固定 `start`、`stop`、`open_console`、`shutdown` 操作 |

浏览器使用 `Authorization: Bearer`；令牌经 URL fragment 引导，读取后立即从地址栏清除，保留在内存。Host、Origin 和跨站请求检查与令牌校验同时生效，无 CORS 放行。只公开 Vite 清单内的资源，拒绝源码、配置、目录越界和联接外跳；HTML 样式使用独立 nonce。

静态请求重新核对构建清单，避免重新构建后的 HTML 引用新文件却仍被旧白名单拒绝。构建尚未完成或清单损坏时明确返回 503；不放开整个资源目录，也不停止聊天/语音。

## 状态含义

- `stopped`：没有受管服务，可开启。
- `starting`：已接收操作，仍需就绪检查；不等于成功。
- `ready`：控制台及既有语音控制桥就绪；本地声音健康单独呈现，不表示设备连接。
- `stopping`：已接收停止操作，尚未证明完成。
- `failed`：启动、健康检查或停止失败。若残留受管进程，先重试停止，不能重复启动。
- `shutdown_complete`：受管服务停止完成。HTTP 主机等待浏览器读取确认或最多五秒，再退出。

状态轮询只读；浏览器关闭、请求中断和轮询失败不会隐式启动/停止服务。未知状态不能绘制成健康。失败消息不包含凭据或原始对话。

2026-10-20 X 候选：`settings` 增加互斥合法的 `voice_ws_port/voice_http_port`、`network_auto` 及只由检测维护的网卡身份；旧默认 8000/8003/false 兼容。`snapshot.network` 单独显示自动检测、等待、更新/失败与候选地址。网页轮询仍只读，后台网络线程按已开启的自动选择和静默租约执行，不能把两者混为轮询隐式重启。实现/设备限制见[独立端口指南](../guides/圆屏独立端口与IP自动跟踪-20261020.md)和[ADR-0187](../adr/0187-roundscreen-network-coexistence-and-auto-lan.md)。

运行后的短暂健康检查失败保留进程、显示“待确认”，不套用首次启动超时停止当前会话；真实子进程退出仍失败。当前 Hy/pipeline 的自动重开另外需要本面板 Job、设备断开及处理结束、网页/Runtime/网关空闲，且先阻止新请求。两个维护接口按当前实例及本机令牌鉴权，租约60秒，忙/未知返回拒绝，不能经浏览器提交任意接口地址。首次未建立归属时不后台写私有配置；停止未确认或更新失败不循环拉起。

绑定预检失败使用固定分类 `lan_address_unavailable`、`port_in_use`、`bind_denied`、`bind_failed`；页面只展示规范 IP/端口及预定义处理文案，不透传系统异常正文。事件日志仅记录分类，不记录该地址。其余 `ValueError` 仍为 `configuration_rejected`，不能据此反推历史失败的系统错误码。绑定提示本身不执行网络修复，自动跟踪是另一项显式设置；没有停止外部服务的能力。

HTTP 响应带服务端生成的 `X-Request-Id`。`data/logs/launcher-events.jsonl` 只记录控制请求结果及观察到的阶段变化，固定投影时间、请求 ID、状态码、操作枚举和阶段；不记录令牌、配置值、本机路径或对话。阶段没有变化时轮询不重复写日志。请求返回 200 可能仅代表操作已排队，仍需核对后续阶段或 `shutdown_complete`，不能把请求日志当成完成证明。日志写入失败不阻断控制，真实状态仍在页面读取。

网络候选增加 `network_changed` 固定事件及状态码，实际自动操作有独立请求 ID 和阶段记录；事件不包含网卡 GUID 或 IP。地址只在本机启动快照显示，后台枚举默认30秒一次，不随聊天调用。

## 验证边界

纯 Python 替身验证授权、非法请求、设置冲突、单实例与进程所有权；真实 HTTP 主机加 React 构建验证浏览器操作、窄屏和减少动画。合成测试不加载模型、不操作真实圆屏、不写个人库。正式启动器切换、声音听感和设备重连须单独验收。

这属于 D 契约与可观测性的启动器切片；不代表全系统指标、追踪或监控平台已完成。

## CosyVoice 交付模式候选（2026-10-21）

设置协议8增加 `cosy_delivery_mode`：`buffered`（默认）、`incremental`、`adaptive`。旧文件缺项或非法值读取为 buffered，不在读取时改写磁盘；保存拒绝非法类型和枚举。只有本地 pipeline＋CosyVoice 3 的语音子进程接收该值。显式维护环境 `LONGMEMORY_COSY_DELIVERY_MODE` 优先，在本次启动前解析一次，不能静默覆盖已保存偏好。其他服务子进程清除该变量。

`GET /api/launcher/status` 的可选 `cosy_delivery` 分别提供下次启动选择与来源、本次启动值与来源、最近连接观测和重启提示。连接摘要只复用原控制面检查，不从页面轮询新增请求；超过2秒或本次语音进程退出即未知。无连接、旧版缺字段或无已观测片段均不宣称实际策略。保存设置不会热切换；运行中沿用既有设置锁定，须停止后重新启动。

原 `/api/device` 可选增加固定13字段交付摘要，上限512字节；既有15519字节合法最大样本加饱和摘要仍小于16384，保留原明细和原客户端限制。它与 AC 的独立 `GET /api/voice-input-signal` 端点互不替代。清理未确认时实际模式为 null、禁止追加并要求重连；回退不写偏好、不重播已开始交付片段。`handoff_started` 只说明回调开始，`reader_cleanup=confirmed` 只说明客户端流退出，都不证明设备播放或服务端空闲；新段仍需串行准入和声音健康检查。

候选行为与验证边界见 [ADR-0203](../adr/0203-cosy-delivery-startup-preference.md)及 [AI接力](parallel/AI-cosy-mode-handoff-20261021.md)。前端组件、类型构建和浏览器等待 ROOT 在冻结精确提交运行既有远程 CI；本机无工作树前端依赖，未安装或借用共享依赖。
