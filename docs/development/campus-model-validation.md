# 校园网模型验证：离线开发与真实调用分开

## 当前状态

回答适配器、模拟 HTTP 测试、最小审计日志、固定合成评估和独立 CLI 进程重启测试已实现。
用户已完成 v1 真实接口调用与手动重启召回，助手已复核报告。
无问号误写和拒答评分漏判现已离线修复，v2 真实调用待用户复验。
实际模型身份未独立核实，效果和延迟不能由单次小样例泛化。助手不探测校园网接口。

## 配置与安全

- 项目根目录 `.env` 是已忽略的本地配置，`uv run --env-file .env` 才会显式读取它。
- 可提交模板为 `.env.example`，不含真实 Key 或私有服务地址。
- `LONGMEMORY_LLM_PROVIDER` 默认 `fake`；真实验证命令用 `--provider openai_compatible` 显式选择。
- Base URL 应包含服务提供的 API 前缀，例如 `/v1`；程序只在后面追加 `/chat/completions`。
- 当前服务为 HTTP。校园网不代表加密，接受凭据与合成文本明文传输的风险后，
  才在本地 `.env` 设置 `LONGMEMORY_LLM_ALLOW_HTTP=true`。优先向服务方申请 HTTPS 或安全隧道。
- Key 已出现在会话中，正式使用前建议更换，并只更新本地 `.env`。
- 仅使用合成数据；远程服务可能记录请求，不能据“私有部署”推断不留日志。

## 1. 仅验证接口，不创建数据库

在项目根目录、连接校园网后执行：

```powershell
uv run --env-file .env python -m longmemory --provider openai_compatible --check-model
```

预期收到“连接验证通过”。这只代表返回了非空的兼容文本，不代表问答质量合格。
失败时程序输出安全错误和退出码，不回显 Key 或远程错误正文，也不自动回退 Fake。
不依赖 `/models` 列举接口。请求不重定向、不自动重试；最大响应 2 MiB。

## 2. 合成记忆评估

```powershell
uv run --env-file .env python -m longmemory.evaluation.runner --provider openai_compatible
```

程序为每个用例和每个组创建独立临时 SQLite 库；不打开个人运行数据库。
默认 v2 的 8 个用例覆盖应记、不应记、精确重复、无相关答案、相关证据不足和无问号提问。
共 16 个用例/组组合；正常完整运行共发起 40 次模型请求（每条历史与查询各调用一次），
不自动重试，请注意服务器负载和调用配额。

两组唯一的干预是是否把检索记忆送入回答器；写入和检索过程保持一致。
两组使用相同题目与评分真值，无上下文组答不出猫名会如实记为失败。
这是回答上下文消融，不是关闭全部存储/检索的系统级无记忆实验。

报告写入 `experiments/runs/smoke-<唯一标识>.json`，拒绝覆盖已有文件。
记录代码提交、工作区状态、源码哈希、数据集版本与哈希、提示哈希、模型配置和运行时间。
报告保留合成回答供人工复核，不包含 API Key。默认不提交实验报告。
每条回答附初筛原因与人工复核标记；报告记录评分器版本/哈希。v1 数据和旧报告保持原样，
旧评分漏判不通过改写历史结果掩盖，也不应把评分器更新造成的分数变化归因于模型提升。

词面答案/拒答检查只是小样例的工程代理指标；误判可人工标注，
不得把检查通过比例当成通用模型准确率。Fake 的结果仅验证链路，不代表真实服务结果。

## 3. 手动体验（可选）

使用一个尚不存在的合成数据库文件，避免首次验证自动迁移真实个人数据：

```powershell
uv run --env-file .env python -m longmemory --provider openai_compatible --database data/databases/campus-demo-new.db
```

依次输入“我养了一只叫豆包的猫。”、`/memories`、`/exit`。
重新启动同一命令，不加问号提问“我的猫叫什么”和“我的猫是什么颜色”。
前者应依据记忆回答，后者应说明缺少颜色信息。
两次提问都不应显示新增长期记忆；再次 `/memories` 应只有最初那条猫名事实。
修复不会自动删除旧库中的错误记忆，复验请用新文件名（例如 `campus-demo-fixed.db`）。

普通聊天会发送本轮输入及检索到的记忆，不会发送完整 L0 历史。
模型失败时，本轮用户消息和已提取记忆可能已经持久化；成功助手消息尚未写入。
这不是整轮事务回滚，CLI 会明确提示，不能以“回答失败”推断“没有写入”。

## 日志与反馈

CLI 日志默认 `data/logs/events.jsonl`，本地 `.env` 可设置合成验证专用路径。
记录 turn_id、记忆 ID、ADD/NOOP、检索/注入 ID、完成/失败事件和耗时，
不复制对话原文、回答正文、完整 URL 或 Key。用记忆 ID 可回到 SQLite 检查来源。
日志最多保留当前文件及两个 1 MiB 轮转文件。ID 仍是可关联元数据，不应公开上传。

切回可与助手聊天的网络后，只提供退出码、安全错误、合成问答结果或脱敏报告；
不要提供 `.env`、Authorization 请求头或原始敏感对话。
