## 共享界面约定

- 保留既有路由、认证、状态语义和内部 longmemory 标识，不以视觉调整改变记忆写入、生效或设备控制行为。
- C 负责页面布局与滚动；F 负责光效与动效。F 不在全局 CSS 改写工作区高度、滚动所有权或页面任务布局；C/D/E 使用自己的新增局部样式。
- 主内容为 `main#main-content`，全局导航继续可访问。聊天历史负责消息滚动，输入区稳定可见；设置分类直接可达；数据页保留筛选与浏览位置。
- D/E 可使用现有 AppShell/PageHeader 接口开展页面任务，不直接修改 C/F 独占组件。新共享接口或路由需求先向主会话报告，再窄范围同步。
- F 在自己负责的 main 入口挂载环境动态组件，不要求其他会话同时改 AppShell。装饰层不截获指针、键盘或阅读焦点；真实状态光效只消费已有可信状态。
- G 先提供稳定的脱敏错误/阶段摘要组件与契约，不直接改 E 所有的 DeviceApp；整合时由主会话接入。保留未确认、结果未知、服务端已发送与设备已播放的区别。

## 各会话执行边界

- 每个会话使用分配的独立 Git worktree 与分支。应用的默认 cwd 仍可能指向主仓库；每次终端读写、构建、测试均显式指定自己的工作树目录，编辑文件使用绝对工作树路径。不得在主目录编辑或运行会改写主目录产物的命令。
- 不复制、读取或编辑主仓库私有配置、日用数据库、真实对话、音频及日志正文。测试使用合成数据和临时服务，独立端口，不连接日用 8767/8000/8003 等服务。
- 已有主项目 Python 和本机浏览器可作为只读运行工具；测试时核对实际导入的源码来自自己的 worktree，输出放入本工作树的临时目录。
- 依赖安装、模型／素材／外部源码下载仍由所有者执行；不自动联网安装，也不通过联接或共享可变 node_modules 混用构建环境。缺少依赖先完成可独立推进的实现与检查，报告所需命令，由主会话统一安排验证。
- A 可创建仓库内专用维护 skill，先本地验证；用户级安装由主会话审查后处理。QMD/Context7 仅评估是否有必要，不自动安装 MCP、下载检索模型或索引私有资料。
- G 本轮不搬迁正在运行的日志、不改私有 YAML、不重启日用服务。实现统一路径与安全元数据机制后，列出兼容与切换步骤供主会话整合。
- 不执行串口、烧录、monitor 或固件更新。0013 已完成的软件与编译工作不重复开工，实际声音克隆听感和新动画实机验收由所有者另行完成。

## 验证与交付

1. 首先读取机器规则入口、项目 AGENTS、ROADMAP 和本任务书，核对基线与自己工作树状态。
2. 每个独立会话将需求、实现、检查与限制记录在自己的 `docs/development/parallel/<编号>-20261014.md`，不向 root README/CHANGELOG 追加。
3. 前端使用现有 UI/UX、设计与动效 skill，明确采用哪些；以真实浏览器的任务完成、首屏可达性和响应为标准，不能只交 CSS 或测试数字。
4. 在 1366×768、1440×900 和窄窗口检查主要路径；扩大字号和减少动画设置也需可用。固定栏不遮挡输入或焦点。
5. 各会话只在自己分支保存已验证提交，不自行合并 main、不推送远程。主会话负责审查、整合、回归、提交与推送，避免多个会话争用主分支。
6. 完成或遇到问题后，在本会话给出提交号、文件清单、实际检查结果和未验证项。主会话读取进度，不要求子会话向其他会话发送消息。
