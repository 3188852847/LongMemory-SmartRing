# 文档维护机制

更新：2026-10-14。本机制只维护公开工程文档及其导航，不连接日用服务、不索引个人资料。总入口是 [docs/README](../README.md)，机器可读清单是 [documentation-manifest.json](../documentation-manifest.json)，只读工具是 [check_docs.py](../../scripts/development/check_docs.py)，专用技能（skill）位于 [.agents/skills/project-doc-maintenance/SKILL.md](../../.agents/skills/project-doc-maintenance/SKILL.md)。

## 范围和完成标准

本轮新增按任务检索、文档状态与依据、事实范围的单一权威来源、源码到文档的复核关联、本地链接与旧路径检查，以及合成目录测试。没有更改现有指南、架构、ADR、研究报告或根规则；没有宣布所有文档语义验收通过。B 负责现行指南与架构，主会话维护根入口及历史索引。

完成标准：公开 Markdown 有清单记录；状态不由文件日期自动决定；权威入口无同一范围的重复；改动能列出候选复核文档与未关联路径；检查不写文件或读取私有目录；合成测试验证错误与成功路径；真实存量问题独立报告，不自动改写历史证据。

## 清单是导航账本

清单使用 JSON，保持可由 Python 标准库读取；唯一编辑来源是该清单，不再维护一份逐文件手写表。`docs/README.md` 只列常用任务入口。

| 字段 | 维护责任 |
|---|---|
| `documents[].path/title/tags` | 文档路径、标题及少量检索标签；新文件、重命名时更新 |
| `status/basis` | 六种状态与实际分类依据；不能按日期、目录名或“当前”一词判定语义有效性 |
| `review.state` | `pending` 待核对、`verified` 已核对；已核对必须同时填写日期、范围与证据 |
| `superseded_by` | 替代目标、精确范围、原文证据；部分替代保持原记录的其他约束 |
| `topics[].id/scope/authority` | 一个明确事实范围与唯一权威入口；范围重叠时先划清责任，不复制同一版本表或命令 |
| `sources/related` | 源码路径或 glob 模式与关联文档；用于提示复核，并非证明源码与文档一致 |
| `known_gaps` | 具体矛盾、待核对范围和负责人；完成复核后记录证据，不凭“脚本通过”关闭 |
| `old_path_rules` | 明确迁移过的路径词及现行入口；只提示，不全仓替换内部 `longmemory` 名称 |

初始清单的多数文档语义标为 `pending`。ADR 和研究资料的目录仅用于检索分组；条目若按资料用途列为参考，不意味着其每条结论均仍适用。已有明确来源的归档、V0.1 阶段资料列为历史；未经正文核对的操作说明列为待核对。恢复记录属于现行恢复证据入口，不能替代其后更新的日用指南。新文档默认登记为待核对，核对后按其真实用途调整。

## 任务驱动维护

1. 读取当前授权与自己的工作树状态；用 `--query` 或 `rg` 找到任务的权威入口和相关条目，不默认通读全部文档。
2. 读取权威文档的相关段落，再核对对应源码、契约、合成测试及最近的恢复记录。运行记录、代码事实、计划和真实设备结果分别判断。
3. 用 `--changed` 或 `--base` 列出改动影响候选。未关联代码仍需人工判断；不能把空输出写成“无需更新文档”。
4. 只更新受影响事实及入口；引用单一来源。若属于历史、研究或已接受 ADR，保留原记录，追加更正/替代关系或按项目规则新建 ADR，不改写过去结果。
5. 同步清单的路径、状态、范围和证据；`verified` 只覆盖填写的范围。检查变更文档的链接与旧路径，并运行合成测试。
6. 汇报实际编辑、实际检查、存量问题和未验证部分。跨会话文件归属由主会话整合，检查脚本不代替整合审查。

## 运行与退出码

在普通检出中可用已安装的项目 Python 或 `uv run --offline --no-sync python`。独立工作树没有自己的环境时，只使用已明确授权的项目解释器作为只读工具；每条终端命令指定自己的工作树，脚本根据自身位置决定默认根目录：

```powershell
& 'D:\03-项目\01-正式项目\智慧圆屏\.venv\Scripts\python.exe' -X utf8 -B scripts/development/check_docs.py --query 声音
& 'D:\03-项目\01-正式项目\智慧圆屏\.venv\Scripts\python.exe' -X utf8 -B scripts/development/check_docs.py --changed src/longmemory/infrastructure/config/cosyvoice_profiles.py
& 'D:\03-项目\01-正式项目\智慧圆屏\.venv\Scripts\python.exe' -X utf8 -B scripts/development/check_docs.py --base HEAD --json
& 'D:\03-项目\01-正式项目\智慧圆屏\.venv\Scripts\python.exe' -X utf8 -B scripts/development/check_docs.py --only docs/README.md --only docs/development/documentation-maintenance.md --strict
& 'D:\03-项目\01-正式项目\智慧圆屏\.venv\Scripts\python.exe' -X utf8 -B -m pytest tests/unit/development/test_doc_maintenance.py
```

`--root` 支持合成目录或显式检出根。`--only` 限定正文读取范围，清单完整性仍检查；`--query` 只检索清单，`--changed`/`--base` 只列候选，不同时运行正文检查。需要二者时分两条命令执行。`--base` 使用 `git diff --no-renames <base> --`，包含相对该提交的已跟踪工作树差异；重命名按旧路径删除与新路径新增同时提示，未跟踪文件要用 `--changed` 显式加入。

输出只到标准输出（stdout），脚本没有修复或写结果选项。退出码 `0` 为所执行检查没有错误，`1` 为发现错误；`--strict` 同时将 warning 或未关联改动作为失败；`2` 为读取、输入或 Git 命令错误。warning 是需人工核对的问题，note 是历史/私有/外部边界提示。检索返回 `0` 不代表匹配到了内容，应查看结果。

本地文件链接支持常见行内、图片、引用式、尖括号及 HTML href/src，百分号编码、括号文件名和可选 title；跳过代码示例及注释。只检查文件存在，不校验标题锚点、跨行 Markdown 标签、模板表达式与外网链接。私有目录、外部绝对路径及目录联接只提示边界，不读取目标。旧路径检测包含代码块，只输出规则 ID、文档行号和替代入口，不打印完整正文。

全量存量检查可能返回失败，应按具体问题分配负责人；不能为了让检查变绿而屏蔽现行失效链接或删除历史资料。历史/已被替代文件的断链为 note，保留提示以供链接重定位时核对。

## 可选检索工具评估

本任务先采用清单、`rg` 与标准库：规模适合文件级主题导航，成本低、无额外依赖，能在离线及独立检出运行。QMD 的本地语义检索仅在关键词持续找不到跨文档概念、且已有可量化检索案例时再评估；增加索引维护、模型下载和私有资料边界的成本，目前不作为前置条件。Context7 类外部库文档检索适合遇到版本接口问题时按任务查询，不能证明本项目代码或本机恢复状态。此处是用途与成本判断，未安装、运行或核实这些工具的当前版本能力，也未下载模型或建立私有索引。

## 已知核对事项

初始清单 `known_gaps` 记录源码与恢复文中已经发现的生命周期矛盾、文字模式旧选择及“以后恢复”的阶段语句。将这些交给现行指南负责人核对，A 不越界修改。所有恢复数字、实机行为和性能结论继续以原记录及后续真实验收为准；本轮只运行文档工具与合成目录测试。
