# V1.0-RC1 日用观察协议

本协议用于把 V1 是否“愿意日常使用”转成可复核证据。观察只针对已冻结的 V1
范围；不借机加入新功能。开始前把本模板复制为
`data/exports/v1-rc1-observation-local.md`，在本地副本填写实际提交号和结果，不直接
填写受 Git 跟踪的模板。期间若修复阻塞缺陷，必须记录新提交并重新执行受影响路径。

## 证据边界

- 观察期至少覆盖 7 个不同的实际使用日，不要求连续，但不能用同一天重复启动代替。
- 日常观察使用真实日用库；隔离验收使用单独的合成库。不要把测试句写入个人库后再
  假装删除干净，因为删除 L1 仍会保留 L0、审计和备份。
- 本地观察副本只记录日期、提交号、结果代码和不含正文的定位 ID。个人对话、记忆
  正文、音频、数据库和包含个人信息的截图保留在 Git 忽略目录，不提交。
- `通过` 表示观察到期望行为；`失败` 表示产品行为错误；`阻塞` 表示环境或设备使该项
  无法判断；`未触发` 表示当天没有自然出现该场景。失败与阻塞不能记作通过。

### 真实日用库路径

只使用自然发生、确实希望保留的个人事实完成下列检查。若当天没有合适事实，该项保持
未完成，不制造内容污染日用库。

| 编号 | 操作与判定 | 结果 | 定位证据 |
| --- | --- | --- | --- |
| L-01 | 网页形成一条 L0/L1，详情能看到原始来源 | 待执行 | L0/L1 ID |
| L-02 | 完全停止并重启后，网页能召回该事实 | 待执行 | 会话/回答 ID |
| L-03 | 圆屏能召回同一当前事实，网页可看到本轮回执和实际证据 | 待执行 | 用户 L0/回执 ID |
| L-04 | 问一个证据中不存在的具体事实，回答明确承认证据不足 | 待执行 | 回答 ID |
| L-05 | 来源询问只返回可追溯来源，不新增错误 L1 | 待执行 | L1/来源 ID |

### 隔离合成库路径

纠正、事实变化、删除、重复合并和误合并恢复会改变记忆状态，统一在临时合成库
完成。先创建合成事实和来源，再通过与日用相同的控制台执行；不得复制个人库来伪装
合成数据。这样可以验证完整能力，又不用等待现实中的个人事实恰好发生变化。

在仓库根目录使用一个从未存在过的文件名。第一条命令若发现同名文件会直接失败，
不会覆盖旧验收结果：

```powershell
pnpm --dir web/react-chat build
uv run --no-sync python -c "from pathlib import Path; from longmemory.methods.longmemory_v1.method import LongMemoryV1; p=Path(r'data/test-tmp/v1-rc1-synthetic.db'); assert not p.exists(), '请换一个新的合成库文件名'; p.parent.mkdir(parents=True, exist_ok=True); LongMemoryV1(p).close()"
uv run --no-sync longmemory-console --port 18777 --database data/test-tmp/v1-rc1-synthetic.db --enable-chat --chat-provider fake --memory-extraction rules --memory-retrieval keyword --allow-memory-delete --allow-memory-correction
```

然后打开 `http://127.0.0.1:18777/chat-react`。该进程不读取 `.env`、不调用真实模型、
不连接圆屏；端口已占用时先确认旧进程归属，不自动停止或换端口规避。每次需要验证
“完全重启”时先用 `Ctrl+C` 停止，再用相同数据库和第二条命令启动。

| 编号 | 操作与判定 | 结果 | 定位证据 |
| --- | --- | --- | --- |
| S-01 | 对一条从开始就错误的事实做纠正，旧项退役、新项生效 | 待执行 | 旧/新 L1 ID |
| S-02 | 对一条合成事实记录变化，旧/新项形成连续有效区间 | 待执行 | 旧/新 L1 ID |
| S-03 | 当前问法只回答现状；唯一明确日期问法只补充相交历史 | 待执行 | 回答/历史证据 ID |
| S-04 | 无效、多日期或证据未覆盖的日期问法保持保守，不拿现状代替 | 待执行 | 回答 ID |
| S-05 | 单条删除经过确认，目标 L1 消失，L0 与删除审计仍在 | 待执行 | L1/审计 ID |
| S-06 | 两条真正重复的 L1 可由所有者选择保留项并合并来源 | 待执行 | 合并账本 ID |
| S-07 | 对 S-06 的可恢复误合并执行恢复，被合并项重新有效 | 待执行 | 恢复事件 ID |
| S-08 | 矛盾候选不能通过重复合并入口处理 | 待执行 | 候选 ID |
| S-09 | 合成库备份恢复后通过完整性、结构版本、表清单和行数核对 | 待执行 | 文件名/SHA-256 |

固定路径全部通过后，才把[RC1 就绪记录](v1-rc1-readiness.md)改为“进入观察期”。

## RC1 通过规则

同时满足以下条件才能宣布 RC1 通过：

1. `L-01` 至 `L-05`、`S-01` 至 `S-09` 全部通过。
2. 表格包含 7 个不同实际日期，且达到重启、跨日召回、连续回答、插话和事项跟进的
   最小次数。
3. 没有未解决的阻塞缺陷；偶发失败必须能定位，修复后重跑受影响路径。
4. 活动库有可恢复备份，恢复副本已独立核对；没有把个人数据加入 Git。
5. 最终完整自动回归在观察期最后一个提交上通过。

通过后更新版本号、CLI 文案、CHANGELOG 和发布记录。Git 标签及正式发布仍按项目约定
单独授权。
