# V1 后产品方向讨论记录

- 记录日期：2026-09-16
- 状态：产品探索输入，尚未排期
- 当前决定：保存讨论结论，V1 收尾完成后再规划；不视为已授权实现

## 1. 原始方向

本轮讨论包含以下候选：

- 根据用户当前状态，让智能圆屏选择不同动作；
- 使用强化学习逐步改善动作选择；
- 在后台展示用户一天的活动状态与日程；
- 探索养老场景，为老人提供生活辅助、理解、共情和日常习惯总结，为家属提供受控的
  活动信息；
- 逐步扩展天气、时间、商品推荐、外部工具和智能家居控制；
- 将智能圆屏发展为边缘计算终端，并在远期形成平台。

## 2. 当前判断

这些想法分属不同层级，不能作为一个功能包同时开发。

| 方向 | 当前判断 | 候选阶段 |
| --- | --- | --- |
| 状态驱动的圆屏动作 | 与陪伴助手方向一致，先采用受控策略 | V1 后 |
| 强化学习 | 缺少真实样本和可靠奖励，不直接接入产品 | 中长期研究 |
| 日常活动时间线与总结 | 与记忆能力结合紧密，要求来源可追溯 | V1 后优先候选 |
| 时间、天气、日程工具 | 适合从只读、低风险工具逐步接入 | V1 后近期候选 |
| 养老应用 | 有独立价值，但会引入多角色、权限和高风险场景 | V2 或独立探索 |
| 商品推荐 | 容易影响陪伴关系和隐私信任，优先级低 | 远期候选 |
| 智能家居控制 | 属于外部写操作，要求确认、回执和失败恢复 | V2 候选 |
| 边缘计算与平台 | 可保留为技术愿景，当前不进行平台化建设 | 远期愿景 |

## 3. 状态驱动动作的安全演进

当前不直接加入强化学习。建议按以下顺序积累证据：

1. 使用确定性规则选择保持安静、简短回应、表达关心、继续询问、执行提醒或改变表情；
2. 只记录脱敏的“可观察状态—候选动作—结果证据”，不把沉默或回复速度解释为满意度；
3. 以默认关闭的影子策略比较不同动作，但不实际控制圆屏；
4. 优先使用用户明确反馈和任务是否完成作为结果信号；
5. 数据充足后先评估上下文多臂老虎机，再决定强化学习是否有额外价值。

用户明确表达、当地时间、近期交互、勿扰设置和待办状态可以成为可审计输入。模型推测
的情绪不能直接写成事实，也不能单独触发高影响动作。勿扰、敏感信息、频率限制和外部
操作确认始终由硬策略约束，不交给学习算法自行改变。

## 4. 日常活动时间线

后台候选应定义为“有来源的日常事件时间线”，而不是模型推测的全天监控。可记录的
事件包括用户主动交谈、明确事项完成、用户主动描述的活动、系统提醒结果和当日摘要。

仅靠聊天不能判断用户是否起床、服药、摔倒或外出。此类信息需要经过授权的传感器、
日历、智能家居或可穿戴数据源，并保存来源、时间、有效性和不确定状态。每日总结是
派生 View，不直接成为新的用户事实；它必须能回到原始事件，并允许用户纠正和删除。

## 5. 养老场景边界

养老场景会把当前单用户本机产品扩展为老人、家属和可能的照护人员多角色系统，至少
需要重新设计：

- 老人与家属分别能看什么，以及老人能否撤回授权；
- 日常动态、私人对话、健康信息和紧急事件的分级；
- 长时间未交互、传感器缺失和真实异常的区别；
- 提醒、健康建议和紧急通知的可靠性、确认与责任边界；
- 多用户身份、审计、数据保留、远程访问与端到端安全。

因此养老保留为独立产品探索，不能把“没有说话”推断为异常，也不能让家属后台默认
读取老人的全部对话或长期记忆。

## 6. 暂定演进顺序

1. 完成当前个人日用 V1 的固定路径、实机证据和发布收口；
2. 评估日常事件时间线、每日总结和低风险只读工具；
3. 以明确状态和硬约束实现受控动作策略，并积累结果证据；
4. 再评估带确认和回执的智能家居等外部写操作；
5. 另行研究养老多角色产品及隐私权限；
6. 真实需求和复用边界稳定后，再讨论边缘平台与学习型策略。

## 7. 当前不承诺

- 不把本记录中的候选加入 V1；
- 不立即实现强化学习、情绪识别、家属后台或智能家居控制；
- 不依据模型推测生成老人活动、健康状态或紧急事件；
- 不以“万能助手”为范围定义同时接入所有工具；
- 不把讨论记录写成已经实现、已经排期或已经通过安全评估的能力。

V1 完成后，应根据真实日用问题、数据来源、隐私边界和最小可验证闭环重新排序，并为
进入实施的重大方向建立独立需求文档和 ADR。
