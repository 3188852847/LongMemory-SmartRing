# L1 提取开发/留出冻结基准 V2（2026-09-13）

## 目的

这套基准把 L0 用户原话变成 L1 原子记忆时的首要问题单独测量，不把检索、回答、L2/L3 或数据库迁移混进结果：

1. 这条消息应该 `ADD`（产生候选）还是 `NOOP`（不记）？
2. 应产生几条互相独立的事实？
3. 事实的主体、否定、时间和不确定性有没有被改坏？
4. 助手猜测、第三方陈述和提示注入有没有被误当成用户事实？

它服务当前“先把日常产品用好”的记忆智能阶段，也是以后比较提取方法时可复用的一项工程协议。它不是公开基准，也不是论文结论。

## 数据边界

- 文件：`datasets/synthetic/l1_extraction_v2.json`
- 16 条 `dev` 开发题：允许据此定位和修改实现。
- 8 条 `holdout` 冻结留出题：默认不运行；开发期间不能反复查看结果后调参。
- 全部内容为项目自编的合成中文消息，不含个人数据库、真实对话或第三方论文数据。
- v2 不覆盖或改写早期 `daily_extraction_v1.json`，避免历史契约悄悄漂移。

每条预期事实不是唯一标准句，而是两组约束：

- `required_terms`：候选中必须全部出现的关键语义锚点；
- `forbidden_terms`：候选中不能出现的方向性错误。

多个事实采用一对一匹配，同一个候选不能同时冒充两条期望事实。这个办法允许有限改写，但仍只是词项代理；同义表达可能被误判，语义正确性仍需逐题人工复核。

## 指标

| 字段 | 含义 |
|---|---|
| `operation_exact` | ADD/NOOP 是否与标签一致 |
| `fact_count_exact` | 候选数量是否一致 |
| `fact_match_exact` | 操作正确，且全部候选能与期望事实一对一满足必需词/禁用词约束 |
| `request_attempts` | 实际越过领域短路门并调用候选模型的次数，不用标点猜测 |
| `failed` | 模型、格式或校验失败；仍留在固定分母中 |

报告还分开列出 ADD 与 NOOP 数量。当前不计算一个综合百分数，避免小数据集给出虚假的精确度。

## 安全与复现约束

- 运行器不打开个人 SQLite，不写入任何记忆。
- 每题最多一次提取请求，失败不重试。
- 报告记录数据 SHA-256、代码 Git 状态、提取提示版本及哈希、模型配置档名称和脱敏后的端点哈希；不写 API Key。
- 逐题报告会包含合成输入和模型候选，因此只能用于这套合成数据，不能直接改成个人对话批量运行。
- `report.json` 通过临时文件原子替换，已完成题目会持续形成可读检查点。

## 运行命令

先在项目根目录进入已经安装好的项目环境。以下命令会真实调用所选模型，所以必须显式加入 `--allow-model-requests`：

```powershell
.\.venv\Scripts\python.exe -m longmemory.evaluation.l1_extraction --model-profile official --allow-model-requests
```

校园模型可用时，把 `official` 改为 `campus`。默认只运行开发题。不要在普通开发中运行留出题；只有正式冻结验收时才同时给出：

```powershell
--split holdout --allow-holdout
```

输出位于 `experiments/runs/l1-extraction-<run-id>/`，其中 `manifest.json` 固定运行条件，`report.json` 保存逐题结果和汇总。

## 运行记录与开发结论

使用读取标签的离线替身验证评估器时，16 条开发题均完成，15 条操作/数量/事实约束一致。唯一未一致的是 `dev-mixed-question`：输入先陈述偏好、末尾再问“你呢？”，现有 `looks_like_question` 在模型调用前把整条消息短路为 NOOP。

首次官方模型运行（数据 SHA-256 `5ba3f104…db1d`、提示 `user-fact-candidates-v2`）完成 15/16：不确定性事实被正确改写成“尚未确诊”，但词面规则未识别它与“没有确诊”等价；注入题返回不可验收结果；混合陈述仍被程序短路。第二次运行在只放开末尾“你呢？”后完成 16/16，混合陈述通过，但模型把明确注入内容生成为“用户是飞行员”。

据此采用 ADR-0139 的 `user-message-safety-gate-v3`：在模型前确定性拒绝明确协议操纵，同时只提取严格互惠追问前的自述子串。第三次官方开发集档案为 `l1-extraction-fb5e74d8755a47c28a3dc99fa715c866`：

- 完成 16/16，实际模型请求 13 次，无重试；
- ADD/NOOP 16/16，候选数量 16/16；
- 自动词项约束 15/16；唯一差异仍为“尚未确诊”与“没有确诊”，当前人工语义核对认为等价；
- 注入题在模型请求前 NOOP，混合“陈述＋你呢？”正确形成一条候选。

这些数字只描述一套很小的合成开发集，而且连续运行也暴露了模型输出波动。它们不能作为通用准确率；留出题仍未运行。下一步不继续为开发集堆规则，而是把日常 L1 提取反馈和该基准并行使用，等候选方法稳定后再一次性执行留出验收。
