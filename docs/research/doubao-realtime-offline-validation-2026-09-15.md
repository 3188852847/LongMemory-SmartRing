# 豆包备用模式离线验证记录

日期：2026-09-15。用户尚未开通豆包服务。本记录仅包含本机合成验证，不代表
真实云端可用、实时对话延迟、声音自然度或圆屏播放已经验收。

## 实现与验证范围

实现随本记录同一提交交付：独立 `voice_mode`、本机 Key 配置、3.0 客户端、
Xiaozhi 实时桥、设备控制兼容及启动状态 V5。原模式仍为默认，不修改 Memory Core，
不读取个人数据库、不调用校园或豆包 API、不保存测试音频、不改变实际启动选择。

官方契约由浏览器核对 [3.0 API](https://www.volcengine.com/docs/6561/2549778)
与[接入必读](https://www.volcengine.com/docs/6561/2549732)。固定模型为 `1.2.6.1`，
只使用新版 JSON 事件和专用语音 Key；没有混用旧二进制接口。

本机客户端依赖沿用 Xiaozhi 已有 Python 3.10、websockets 14.2、opuslib_next 1.1.5
及 native Opus DLL，没有安装或下载。上游接入继续经过现有固定文件哈希检查。

## 实际依赖的本机环回验证

在 Xiaozhi 现有 Python 环境，用临时 `127.0.0.1` 随机端口启动模拟服务，经客户端
注入的测试连接工厂访问。生产地址白名单不变，测试未连接官方地址。

| 检查 | 实际结果 |
|---|---|
| 会话与鉴权帧 | 真实 websockets 14.2 完成握手，模拟服务验证合成 Key 和 PCM 配置 |
| 上传 | 20 个 60ms PCM 输入转成 60 个 20ms / 640 字节包 |
| 上传间隔 | 最终一次 60 包跨度约 1188ms，平均 20.14ms；高精度发送测量约 14.73–31.93ms |
| 下行 | 5961 个 24kHz 样本、跨 998 字节块返回，编码成 5 个 60ms Opus 包 |
| 解码 | 实际 16kHz Opus 解码器逐包得到 960 个样本 |
| 关闭 | 模拟服务收到 `session.close`，客户端收到关闭确认，后台任务退出 |
| 数据 | 仅内存合成波形与测试字幕，未保存原始音频、未读取个人库 |

另用 1 / 1440 / 1441 / 29616 个样本检查尾帧边界，分别输出 1 / 1 / 2 / 21 个
Opus 包；经过现有 v2 封装/解包再真实解码，全部通过。该检查没有测试 Wi-Fi、
真实设备发送队列或扬声器声音。

## 发现并处理的问题

- 上游启动和每连接初始化都会加载模型，实时模式必须同时绕过两处。
- 上游音频发送函数先入另一层队列；桥的事件队列有界并不够，已同时限制下游库存。
- 云端失败后保留设备连接会让后续输入被丢弃，现结束设备连接以便重新唤醒。
- 旧 Windows Python 的 `monotonic` 实测为 `GetTickCount64`、分辨率 15.625ms。
  上传节拍改用现有 `perf_counter` 高精度时钟，等待后复核，按固定时刻补偿轻微
  抖动，限制追赶间隔，严重滞后时重置计划；不修改全局定时器或系统电源设置。
- 新启动快照字段需要版本升级，V5 消费端保留旧版本结构兼容，避免总览误报失联。
