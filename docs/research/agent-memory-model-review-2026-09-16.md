# Agent 记忆模型复盘与 LongMemory 后续输入

- 记录日期：2026-09-16
- 输入来源：所有者整理的本地《复盘》材料
- 当前用途：V1.0 发布后的记忆算法升级输入
- 当前决定：只记录和建立映射，不改变已冻结的 V1 范围、正式召回策略或个人数据库

## 1. 结论

这份复盘对 LongMemory 有参考价值，但它是概念框架和检查表，不是可以直接落地的
算法规格。最有价值的三条边界是：

1. 任务运行状态与长期记忆分离；
2. 原始证据账本、任务派生视图和读写策略分离；
3. 现实有效时间与系统记录时间分离。

这些边界与项目当前方向一致。现有 L0～L3 不应被“四类记忆”替换；后续采用两个
正交维度解释和演进更合适：

| 维度 | 当前含义 |
| --- | --- |
| 证据与抽象层级 | L0 原始证据 → L1 原子事实 → L2 生活场景 → L3 用户画像 |
| 运行用途 | 会话/工作状态、情景事件、语义事实、程序规则 |

同一信息可以同时位于两个维度。例如一段原始经历先以 L0 留下来源，提取为 L1
事件事实，经过复核后形成 L2 场景；它在运行用途上属于情景记忆。程序规则则不应
作为 L0～L3 的普通用户事实自动写入。

## 2. 与当前实现的对应关系

| 复盘概念 | 当前项目对应 | 当前判断 |
| --- | --- | --- |
| 任务状态与记忆分离 | 启动器、会话和任务状态独立于 Memory Core | 基本成立 |
| 工作记忆 | 网页与圆屏各自有界的短期会话 | 有基础，尚无统一工作记忆模型 |
| 情景记忆 | L0、生命周期事件账本和部分 L2 | 有组成部分，尚无通用事件视图 |
| 语义记忆 | L1 原子事实和受控 L3 画像 | 主要闭环已实现 |
| 程序记忆 | ADR、配置、规则和操作流程 | 与用户记忆隔离，尚无产品内技能学习 |
| Ledger 原始账本 | L0 证据及多个追加式生命周期账本 | 已广泛采用，但用户明确删除优先于“永不丢失” |
| Views 派生视图 | 检索候选、当前投影和回答上下文 | 已隐含存在，尚未成为统一契约 |
| Policy 控制策略 | 写入、敏感、冲突、激活、预算和召回门控 | 已有多项策略，仍可统一表达 |
| 双时间 | `valid_from`、`valid_to`、记录时间及历史召回 | 核心能力已实现 |
| 更新与遗忘 | 临时状态过期、派生记忆失效、删除与清空 | 部分实现，完整保留和全副本擦除仍未完成 |
| 质量指标 | 提取账本、召回分数、人工反馈和影子复核 | 采集基础已有，真实标注量不足 |

## 3. 应保留的原则

### 3.1 写入门

长期写入继续检查值得记忆、来源可靠、是否重复、是否冲突、是否敏感及未来是否有用。
模型只能提出候选，不能凭一次推断直接确立高层画像。

### 3.2 检索门

召回继续结合查询用途、关键词与语义、主体、时间和上下文预算。召回内容是回答证据，
不能成为覆盖系统规则的指令。未知问题必须允许空召回和明确承认证据不足。

### 3.3 更新与删除

事实更新需要保留来源和有效区间；不能确认真值时由所有者复核。原始账本的可追溯性
不高于用户删除权：正常演进采用追加历史，用户明确删除时按声明范围删除来源、派生物
和索引。完整备份擦除属于独立的后续隐私工程，不能用“清空当前库”冒充。

### 3.4 程序性记忆

多次成功轨迹可以成为后续候选，但不得根据一次对话失败静默改写正式流程。若以后
引入，只采用“候选 → 审核 → 版本化发布 → 可回滚”，并与 L0～L3 数据分离。

## 4. 当前缺口

1. 尚未把面向本轮任务的记忆 View 定义为统一、可审计的对象；当前能力分散在检索、
   当前投影和上下文构建中。
2. 来源权威等级和置信状态尚未形成跨 L1～L3 的统一冲突决策契约。
3. L0 和多个事件账本尚未形成通用的“交互情景”派生视图。
4. 只有部分临时状态和派生记忆具备明确失效规则，分层保留期与全副本删除仍不完整。
5. 写入准确率、关键召回率、过期命中率和冲突率需要真实标注样本；现有合成集不能
   冒充日用质量。
6. 单用户本机产品已有主体隔离，但没有多用户访问权限体系；V1 不因此扩展权限系统。

## 5. V1 后建议顺序

1. 先以 RC1 日用观察积累漏记、错记、改写召回、过期命中、冲突使用和无依据回答的
   真实样本，不改正式策略。
2. 建立“Ledger / View / Policy 与 L0～L3 的映射”ADR，明确 View 的来源 ID、有效
   时间、预算、版本和解释契约。
3. 实现只读派生 View 与离线评估，先证明它比当前上下文构建更准确或更可解释，再考虑
   接入正式回答。
4. 统一来源权威等级、冲突复核和失效语义，并以真实标签校准，继续保留人工回退。
5. 设计按层保留与删除影响图，单独处理原始对话、L0～L3、事件账本、索引和备份。
6. 程序性记忆、技能沉淀和近期对话摘要放在以上证据形成之后；任何自动学习先经过
   默认关闭的候选与版本化审核。

## 6. 不作为当前承诺的内容

- 不在 RC1 期间重构 L0～L3 或增加新的持久化层。
- 不把四类记忆概念写成四套必须独立部署的数据库。
- 不将近期对话摘要直接视为用户事实；若以后实现，它只能是带来源和版本的派生视图。
- 不将相似度、模型评分或置信度直接解释为事实为真的概率。
- 不自动开启低频整理、语义门控、技能学习或新的个人数据读取范围。

本文保留为算法升级输入。正式改变数据模型、检索行为、遗忘策略或隐私语义前，仍须
用独立 ADR 记录候选方案、实验依据、迁移、回退和验收边界。
