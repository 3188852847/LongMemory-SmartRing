## 目标与首切片建议

用户已决定以 Hy-Memory 为长期记忆目标，可从新库积累、旧库保留；后续重点是主动交流。建议首先完成**有明确用户来源的一次性事项跟进**：用户明确说“明天下午三点，到时候问我报告交了吗”，平台记录事项、时间窗口和许可，届时满足护栏才尝试一次，回应、取消、改时或过期都有可查结果。之后才扩展到日常主动陪伴。该首切片是建议，不把它冒充用户已确定的实施范围。

首切片成功要求三类证据分别成立：记忆提供正确来源和适用信息；调度按许可与时间正确执行且不重复；所有者真实体验能听到、能取消、能打断、没有不合时宜打扰。离线模拟通过不替代后两类实机体验，发送成功也不等于听到。

暂不做模糊时间推断、推断事项自动启用、多设备协调、自动策略学习、旧派生层迁移或 Hy 私有层级扩写。个人库保留；合成验收不读取个人正文。保持现有服务、许可和频率设置，新的日用接入及开关生效须单独定范围。

## 拟议中立事项与最小闭环

以下名称是待接受的契约草图，代码中尚不存在。实施前以新的 ADR（架构决策记录）确定平台持久化位置、身份/版本、迁移和回退；不改写已接受的 [ADR-0181](../adr/0181-neutral-memory-backend-and-platform-sources.md)。建议在独立平台旁库增加所需事项/追加事件，复用原账本用例和受限存储，不创建另一套引擎或分布式服务；具体表名/迁移号留给实施审查。

一个事项最少包含：`item_id`、主体、事项修订、创建种类、原用户 `event_id/session_id/turn_id`、请求原时间、事项短句、明确时区/固定偏移、`not_before/expires_at`、许可依据及许可修订、状态。证据引用包含后端名/版本、资源身份、原来源 ID，以及可得的条目 ID/内容摘要/修订/有效区间；引擎未知字段保持未知。Hy L7/Intention 可提供候选证据，不能代表许可、平台已安排或设备已执行。

`explicit_user_request` 与 `inferred_candidate` 分开：前者仍须时间明确、来源为真实用户、全局许可有效；后者即使来自高置信模型，也只留待确认候选，不自动安排。首切片允许单独保存明确请求，不要求先提取出一条 Hy 事实；这样引擎提取失败不会让平台假称已安排，也不会为了建事项造一条旧 L1。若所需来源/事项有歧义或用户只说“以后”，明确回执未安排并请求必要信息。

1. **登记。** 平台先归档用户请求，再在平台事务内创建/重放事项及安排结果。回执区分“候选”“已安排”和“未安排”，回答模型只消费真实结果。同来源/请求标识重复不创建新事项；语义相似但不同请求不自动合并或重复授权，须结合明确指代。
2. **核对。** 到期时独立主动交流层读取事项/许可/版本与必要 Hy 记忆证据，重新核验来源可得、事项未取消/改时、证据适用。首切片使用明确短句或确定性模板，不让模型自行决定许可、到期时间和执行事实；后续允许模型润色时也保留事实/时序约束及降级文本。
3. **决策。** 使用现有许可、时段、勿扰、频率、在线/空闲、等待回应护栏。时间未到可等待；到期离线、忙碌或护栏拒绝按明确原因结束该尝试，不偷偷改时补发。状态未知按保守拒绝处理，不能把设备离线判成用户不想聊。
4. **占有并投递。** 在平台事务内校验事项修订、许可修订并建立唯一调度结果，再调用设备桥。每个事项/修订/时间窗口最多一次副作用尝试；一旦已占有而回执丢失，重启按不确定结果处理，不盲目再发。服务端 `queued/transport_sent` 不提升为 `played`，设备播放仍为 `unconfirmed`。
5. **反馈。** 保存 `item_id + item_revision + outreach_id/attempt_id + device_id + voice_round_id/turn_id + source_event_id` 的显式关联。用户答复、取消、拒绝、改时、无回应或打断都是平台事件；“后面聊过天”只能证明后来活动，不能直接判定事项完成。需要澄清时保留未决，不猜时间邻近归因。
6. **结束与恢复。** 取消/改时与排队抢占用同一版本检查；投递前取消应阻止发送，投递后回执明确“已尝试，无法保证撤回”，阻止后续触发。改时保留旧修订及已尝试历史，首切片仅允许尚未尝试事项重新安排。过期、失败、无回应、被打断不补发；确需再次联系必须有新的明确用户指令和新安排依据。

事项业务状态、投递状态与播放证据分开：例如事项可为候选/已安排/取消/过期/已回应/已完成，投递沿用候选/受理/发送/失败/不确定等真实证据投影。它们不是 Hy 记忆层级，也不自动生成“用户不喜欢我”“已完成任务”等用户事实。确需进入记忆的用户答复仍走原有归档→提取→检索链路，并保留来源。

## 首切片验收矩阵（尚未执行）

| 场景 | 必须观察的结果 |
|---|---|
| 正常明确请求 | 来源/时间/许可版本可追溯，回答只确认实际已保存的安排；窗口内满足条件只尝试一次；用户回应能关联事项，普通闲聊不冒充完成。 |
| 权限拒绝/来源不足/模糊时间 | 不产生可投递安排，返回稳定未安排原因；推断候选不自动启用，助手建议不变成用户请求。 |
| 取消/改时 | 旧修订请求被拒绝；取消先于占有则零投递；并发取消与发送有唯一可查次序。改时保留旧事件，不产生两个活动安排。已尝试事项不以“改时”偷偷重试。 |
| 离线/忙碌/勿扰/频率/等待回应 | 每种护栏分别命中且可审计；不调用设备或模型的分支保持零副作用，失败/过期后不补发。 |
| 重复/并发 | 同请求重放返回同事项/同结果；多个 tick 或重复回执不会重复安排、发送或记为多次听到。不同事项共享全局频率预算。 |
| 重启/崩溃 | 保存后重启恢复安排；占有前中断可重新评估，发送前后未知窗口不重发；过期事项仅终结。来源/引擎失败与平台状态分别核对。 |
| 来源/许可变更 | 原来源不可得、证据版本变化或授权撤回，不能沿旧快照继续发送；明确请求的事项依据与辅助记忆分开，辅助记忆变化不伪造取消指令。 |
| 无回应/打断/失败 | 保留真实状态、继续抑制重复联系；不把未听到归为用户拒绝，不把桥受理归为听到；新的用户交流可解除相应等待门控，事项完成仍需关联证据。 |

上述断言须用合成库、受控假时钟、随机回环端口和假设备桥验证；分别统计记忆写入/召回/最终答复、调度决策/重复副作用数、体验观察，保留所有拒绝、失败和未知分母。

| 阶段 | 范围 | 放行证据 |

| B：真实模型与记忆效果 | 明确 Hy 提取、Embedding（向量表示）与回答端点、维度、出口；完成真实开发集及保留集比较 | 整轮共享请求/token/金额硬预算、超时/停止执行器先具备；相同历史/回答条件/提示/上下文及来源评分，错误不减分母；逐题副本语义状态审查，不能假称冻结。质量标准与样本先定，不把当前固定模拟响应评分当结论。 |
