# LongMemory 陪伴助手产品能力地图

更新：2026-09-09。

## 1. 文档目的

本文集中记录 LongMemory-SmartRing 未来可能具备的产品能力，并区分当前事实、近期工作和远期候选。它回答“产品最终可以做什么”，不代替 [ROADMAP](../../ROADMAP.md) 的执行顺序，也不把候选功能视为开发承诺。

产品目标是：以 SmartRing-Plus 智能圆屏为主要交互入口，以长期关系和用户可控记忆为核心，提供可定制、可解释、可关闭、可纠正和可遗忘的个人陪伴助手。

## 2. 状态定义

| 状态 | 含义 |
|---|---|
| 已有基础 | 已存在可运行链路；不代表长期质量、全部场景或实机体验均已验收 |
| 正在完善 | 已进入当前产品路线，仍有明确体验或可靠性缺口 |
| 候选新增 | 方向合理，但尚未授权为近期开发任务 |
| 需验证 | 依赖硬件、固件、模型或外部服务能力，验证前不能承诺 |
| 研究保留 | 为未来论文、对照或分析保留，不进入近期日常产品主线 |

## 3. 两个产品平面

| 平面 | 面向对象 | 核心职责 |
|---|---|---|
| 日常陪伴 | 圆屏终端的最终使用者 | 自然聊天、被记住、接受陪伴、自然纠正和控制主动程度；不要求理解 L0–L3 或打开网页审批 |
| 内部控制与研究 | 当前所有者、开发者和研究人员 | 配置、诊断、来源查看、纠正、回滚、方法切换、实验和安全审计 |

两个平面可以共用记忆、模型和设备适配层，但界面语言与权限不同。内部控制台不能成为普通用户聊天和记忆积累的必经入口。

## 4. 能力总览

### 4.1 日常对话

| 能力 | 目标体验 | 当前判断 |
|---|---|---|
| 圆屏语音聊天 | 开机后自然说话，不需要终端命令 | 已有基础，启动和故障体验正在完善 |
| 网页文字聊天 | 用于日常输入和开发测试，可恢复历史会话 | 已有基础 |
| 网页语音与朗读 | 网页试听回答、停止播放和本地说话打断 | 已有基础；朗读失败可区分类别并进入声音设置 |
| 多轮短期上下文 | 一次会话内自然承接前文 | 已有基础；网页与圆屏短期会话仍彼此独立 |
| 跨入口长期认识 | 网页和圆屏读取同一长期记忆空间 | 已有基础；召回失败仍可能表现为“不记得” |
| 自然语音打断 | 助手说话时用户可直接插话 | 正在完善；圆屏双工链路尚未成立 |
| 清楚的故障回答 | 模型、TTS、网络或设备失败时说明真实原因 | 正在完善；模型预检与网页 TTS 已有受控分类提示 |
| 有限离线对话 | 无公网时保留本地可用能力 | 候选新增，取决于本地模型组合 |

### 4.2 长期记忆

| 层级/能力 | 目标 | 当前判断 |
|---|---|---|
| L0 原始证据 | 保存必要原话、角色和时间，作为审计来源 | 已有基础 |
| L1 原子记忆 | 形成可以单独召回的事实、偏好和计划 | 已有基础，真实提取质量仍需完善 |
| L2 生活场景 | 将多条相关 L1 整理成有上下文的经历或阶段 | 已有候选、复核和生命周期；自动整理默认关闭 |
| L3 用户画像 | 对偏好、习惯、价值观、目标和行为模式形成一份持续演化的统一投影 | 已有可追溯统一画像基础；自动质量和日常使用仍待完善 |
| 显式记忆 | 支持“请记住……” | 已有高精度第一版 |
| 暂不记忆 | 支持跳过本轮 L1、未来扩展禁记类别 | 跳过本轮已有；类别规则为候选 |
| 来源解释 | 回答和记忆可回到 L1/L2/L3 及 L0 原话 | 已有基础；聊天已分层显示本轮 L1/L2/L3，三层均可深链接核对各自保存的依据；证据充分性判断继续完善 |
| 错误纠正 | 新事实取代旧事实，不原地覆盖历史 | 已有基础 |
| 事实变化 | 区分“原来错误”和“后来发生变化” | 已有基础 |
| 删除与停用 | 明确区分删除 L1、保留 L0、暂停写入和暂停使用 | 已有单条控制与不含正文的未来删除审计；完整数据清理仍是候选 |
| 重复与冲突 | 自动识别语义重复、过期事实和冲突 | 部分基础；通用自动处理尚未完成 |
| 混合召回 | 关键词和本地向量共同找相关记忆 | 已有可选链路；真实长期效果待观察 |
| 方法切换 | 在 LongMemory、小智摘要、无记忆及未来论文方法之间切换 | 圆屏三种后端已有；外部论文方法属研究保留 |

记忆系统成熟的标准不是“表中存在 L1/L2/L3”，而是长期提取、更新、召回和使用在真实生活中可靠，并且错误能够被发现和修复。

### 4.3 个性化陪伴

| 能力 | 目标体验 | 当前判断 |
|---|---|---|
| 称呼与表达偏好 | 记住称呼、回答长度、表情频率和互动方式 | 已有基础 |
| 倾听或建议 | 根据明确设置和当前请求决定先倾听还是解决问题 | 已有结构化设置基础 |
| 长期事项跟进 | 之后自然询问毕业设计、计划或生活事项的进展 | 候选新增，依赖可靠时间与事项记忆 |
| 临时状态 | 区分“今天心情不好”和长期性格画像 | 候选新增 |
| 稳定习惯 | 用跨日证据形成可否认、可停用的习惯认识 | 已有第一种时间候选基础 |
| 陪伴策略演化 | 根据明确反馈和多次结果提出可回退策略 | 已有保守策略版本基础；通用质量学习尚未实现 |
| 每日回顾 | 汇总当天对话、事项、记忆变化和证据不足的推断 | 日回顾第一版已实现：L0 角色计数、历史日期、L1 新增/纠正/变化/未来删除审计与直达来源；对话总结、事项提炼和不确定推断仍未实现 |
| 回答级记忆反馈 | 标记正常、没想起、错误记忆或记忆无关，并回看原回答轨迹 | 内部网页入口、每日动作/当前判断汇总和跨日问题工作台已实现；不自动学习，圆屏自然反馈待后续 |

### 4.4 主动交流

| 能力 | 目标体验 | 当前判断 |
|---|---|---|
| 固定时间问候 | 在明确日期和时段问候一次 | 已有基础并通过实机播报 |
| 勿扰与频率 | 限制时段、次数、间隔和连续催促 | 已有基础 |
| 记忆话题 | 从所有者允许的生活场景中选择安全话题 | 已有受限第一版 |
| 习惯时段 | 从跨日互动形成候选，经回放后可激活和回滚 | 已有第一种保守策略 |
| 自然反馈 | “少主动一点”“这个时间不合适”“别再聊这个” | 固定拒绝表达已有；自由反馈待扩展 |
| 触发解释 | 告诉所有者为什么此时联系、使用哪个策略和来源 | 已有审计基础，页面继续完善 |
| 事项式主动跟进 | 对明确计划进行一次恰当追问 | 候选新增 |

主动交流必须默认可关闭，不把沉默解释为情绪或拒绝，不在设备离线后补发过期内容。

### 4.5 助手角色

| 能力 | 当前判断 |
|---|---|
| 助手名称、用户称呼、回答长度、互动方式、表情频率 | 已有基础 |
| 完整角色提示词与内置预设 | 已有基础 |
| 网页角色显式同步到圆屏 | 已有基础 |
| 多套用户命名预设、导入导出和版本对比 | 候选新增 |
| 临时模式，例如“今天只听我说” | 候选新增 |
| 角色头像、背景和统一角色资源包 | 候选新增 |

助手角色描述“助手是谁”，L3 描述“用户是什么样的人”；二者永不合并为同一 Persona 数据。

### 4.6 声音与语音

| 能力 | 当前判断 |
|---|---|
| Edge 标准音色、VoxCPM2 本地声音方案与网页试听 | 已有基础 |
| 圆屏 TTS 后端切换 | 已有基础 |
| 参考音频、表达指令、CFG 与质量档 | 已有受控基础 |
| 语速、音高、情绪强度的统一设置 | 需验证不同 TTS 的真实参数能力 |
| 快速模式与高质量模式 | 候选新增；需要测量首句延迟和实时率 |
| 声音来源和实际生效状态 | 正在完善，避免多后端导致男女声漂移 |
| 定制角色声线 | 候选专项；必须使用有权使用的素材 |
| 圆屏说话打断与回声消除 | 正在验证设备端和服务端能力 |

### 4.7 视觉与外观

| 载体 | 目标 | 当前判断 |
|---|---|---|
| React 控制台 | 未来控制台、平静浅色、经典深色和响应式布局 | 未来主题及聊天真实状态轨、分层证据栏已实现；其他页面继续渐进深化 |
| Windows 启动面板 | 与控制台共享颜色和状态语义，突出启动与故障处理 | 未来主题、四项受管状态和一次启动自动安全同步已实现；真实可见体验待观察 |
| 圆屏终端 | 待机、聆听、思考、说话、打断和错误一眼可辨 | 状态脸和轻量动画已烧录，逐态自然观察仍未完成 |
| 角色皮肤 | 可替换颜色、几何、表情和未来合法角色资源 | 受限颜色/尺寸皮肤已有；资源包为候选 |
| 可访问性 | 字号、减少动画、键盘导航和窄窗口 | 已有基础，未来主题仍须持续回归 |

### 4.8 圆屏设备管理

| 能力 | 当前判断 |
|---|---|
| 音量、亮度和明暗主题 | 已有实时能力入口 |
| 电量、充电、Wi-Fi 信号和芯片温度 | 已有快照基础；真实性取决于固件上报 |
| 屏幕休眠、自动熄屏和唤醒方式 | 需验证 |
| IMU 动作输入 | 已确认 QMI8658A 与 INT1→GPIO42 硬件基础；小智 B V2 尚未接入。动作唤醒、拿起问候和翻转勿扰作为后续候选，不进入当前主线 |
| 播放停止、按键/触摸打断 | 需验证并设计确定性通道 |
| 固件版本、构建身份和能力清单 | 部分可审计，产品页仍待集中呈现 |
| 配网入口、重启和恢复 | 需验证后再开放，不能提供无底层能力的假按钮 |
| OTA 更新与回退 | 候选新增；需签名、版本、分区和恢复方案 |
| 麦克风、扬声器、按键和显示自检 | 候选新增 |

### 4.9 启动、模型与运行

| 能力 | 当前判断 |
|---|---|
| 一个入口启动网页和可选圆屏语音 | 已有基础 |
| 端口、IP、配置和进程归属检查 | 已有基础 |
| 服务状态、停止和重新打开网页 | 已有基础 |
| 学校与官方模型配置分流 | 已有基础 |
| 网页模型与圆屏模型独立选择 | 已有基础 |
| Key 只写不读、合成连接检查和明确故障 | 已有基础，提示继续产品化 |
| 回答、提取、整理和评分使用不同模型档案 | 候选新增 |
| 调用延迟、次数和成本观察 | 候选新增 |
| Windows 登录后自动启动 | 候选新增，必须显式开启 |
| 故障自恢复 | 候选新增；不得通过杀死未知进程冒充修复 |

### 4.10 生活工具与外部知识

| 能力 | 定位 | 当前判断 |
|---|---|---|
| 日历、待办和提醒 | 结构化生活工具，不等同于个人记忆 | 候选新增 |
| 天气、课程表和学习计划 | 经显式授权读取的外部上下文 | 候选新增 |
| 本地文件、笔记和 Zotero | 独立知识平面，通过引用参与回答 | 候选新增 |
| 音乐与简单智能家居 | 外部工具调用，不直接写成用户事实 | 候选新增 |
| 知识库与个人记忆联合编排 | 分别检索，再由上下文编排层合并证据 | 架构保留，近期不插队 |

外部文档中的陈述不能自动变成用户事实；日历事项、知识资料和用户画像必须保持不同数据语义。

### 4.11 数据、隐私与恢复

| 能力 | 当前判断 |
|---|---|
| 当前数据库、模型通道和数据归属可见 | 已有基础 |
| 个人库一致性备份和结构迁移 | 已有工程流程 |
| 配置版本与回退 | 多个子系统已有基础，尚未统一体验 |
| 聊天、L0、L1、派生记忆分别设置保留策略 | 候选新增 |
| 数据导出与导入 | 候选新增；必须明确隐私范围 |
| 完整删除影响预览 | 候选新增 |
| 本地优先和外发范围说明 | 持续边界；当前学校 HTTP 接口仍存在明文风险 |

“停止记忆”“不在回答中使用”“删除 L1”“删除原始对话”和“删除全部副本”是五种不同操作，不能由一个含糊开关代替。

### 4.12 内部研究能力

| 能力 | 当前判断 |
|---|---|
| 提取、检索、注入和回答轨迹 | 已有基础 |
| 冻结数据集和无记忆对照 | 已有基础 |
| 关键词与向量召回比较 | 已有基础 |
| 可替换 MemoryMethod | 已有基础 |
| 实验档案与逐题复核 | 已有控制台入口 |
| 外部论文方法复现与适配 | 研究保留，产品主线暂缓 |
| 正式语义评分、人工一致性与多次运行 | 研究保留 |

研究模式应隐藏在“实验室”分组，不让普通产品设置充满算法参数。真实个人数据默认不进入实验。

## 5. 控制台信息结构

未来控制台按使用目的分组：

1. **日常**：对话、每日回顾。
2. **记忆**：L0/L1、生活场景 L2、统一用户画像 L3。
3. **个性化**：助手角色、声音、外观、主动交流。
4. **设备与系统**：圆屏设备、服务、模型、数据与诊断。
5. **实验室**：方法切换、实验运行、结果复核和来源轨迹。

当前导航不为尚未实现的功能提前放空页面；只有形成可用纵向切片后才增加入口。

## 6. 执行优先级

### G1：每天愿意打开

- 完成未来科技视觉在控制台和启动面板中的真实组件化呈现。
- 集中展示真实服务、模型、记忆和圆屏状态，不用静态“正常”文字冒充检查。
- 完成圆屏五态自然观察，并处理明显视觉问题。
- 改善模型失效、TTS 切换和设备离线提示。
- 保留语音首句延迟日志；算法优化和自然说话打断分别作为后续专项。

完成标准：无需终端即可启动和定位故障；主要页面可读、可操作；控制台状态与真实后端一致。

### G2：它确实越来越了解用户

- 用真实日常对话检查 L1 提取、重复、冲突和改写召回。
- 在受控开关下试用 L1→L2→L3 低频整理。
- 在记忆页集中观察两阶段的来源门槛、调用预算和最近结果，再进入 L2/L3 页面核对候选；状态查看本身不得触发模型。
- 让回答稳定使用相关 L1/L2/L3，并明确没有证据与检索失败的区别。
- 增加每日回顾和低成本纠正入口。
- 从每日回顾核对当天未形成 L1 的用户原话，积累可能漏记的真实样本；未关联状态不自动等同于提取错误。
- 对人工确认的漏记，允许从原用户 L0 显式补成 L1；不自动规范化、不调用模型，且必须保留原话来源与重复去重语义。

完成标准：跨会话常见偏好和持续事项可可靠召回；错误能修正；自动整理不会把助手推测伪装成用户事实。

### G3：从问答工具变成陪伴者

- 支持事项后续追问、自然主动话题和用户反馈调节。
- 区分临时状态、生活场景、长期画像和陪伴策略。
- 以真实使用结果评估主动交流频率和接受度。

完成标准：主动行为有来源、有原因、可停止且不过度推断；没有回应时不施压。

### G4：扩展生态与研究

- 评估日历、待办、本地知识库和工具调用。
- 复现外部论文记忆方法并在同一协议下比较。
- 基于真实使用数据重新选择论文主张。

完成标准：外部工具、知识、个人记忆和研究实验保持数据及接口隔离。

## 7. 当前明确不做的捷径

- 不因为功能很多就引入大型智能体框架统一所有流程。
- 不把控制台审批当作圆屏用户必须完成的产品步骤。
- 不把模型生成内容直接写成可靠用户事实。
- 不把浏览器圆屏预览、编译或烧录成功冒充真机体验完成。
- 不提供底层固件不支持的设备按钮。
- 不为增加黏性设计负罪感、连续催促或排斥现实关系的陪伴策略。
