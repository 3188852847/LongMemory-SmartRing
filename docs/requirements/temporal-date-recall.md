# 明确日期历史召回

## In Scope

- 只在同一分句同时满足问句特征和唯一明确日期表达时建立目标区间。
- 支持 `YYYY年`、`YYYY年M月`、`YYYY年M月D日/号`、`YYYY-MM-DD`，以及以
  UTC+8 当前日期解释的“今年/去年＋可选月日”。年月日可使用阿拉伯数字，月日还可
  使用常见中文数字。
- 年份限定为 1900–2100；自然年、月、日统一转换为 UTC+8 左闭右开区间。
- 仍以当前召回且读取时有效的 L1 为锚点，只沿主体一致、前后有效时刻精确衔接的
  事实变化链查找。
- 日期目标只补充与目标区间相交的退役事实；当前事实本身由正式召回保留。一个日期
  若跨越变化时刻，可以同时存在变化前后的证据，回答必须说明区间。
- `valid_from` 缺失时只从 `recorded_at` 起认为事实可证，不把首次记录之前的未知时段
  猜成事实成立。
- 目标区间没有任何可证事实时，向回答上下文加入明确的“证据不足”边界，不允许用
  当前事实替代历史答案。

## Out of Scope

- 缺少年份的“五月”、节日、季度、星期、年龄阶段和“小时候”等模糊时间。
- “2025 到 2026”“五月之前/之后”等日期范围和比较运算。
- 同一句包含两个日期时猜测起止关系。
- 从没有进入当前召回的主题扫描退役 L1，或读取退役 L2/L3。
- 模型时间分类、时区自动推断、事实插值和自动真值裁决。

## Definition of Done

- 纯函数测试覆盖绝对年/月/日、ISO 日期、今年/去年、中文月日、无效日期、多日期、
  缺少年份和跨分句借词。
- SQLite 合成链覆盖历史月份、当前月份、证据空档和本地自然日跨越 UTC 变化时刻。
- 普通历史问句继续使用 `explicit_temporal_history_v2`；日期问句使用独立策略
  `explicit_temporal_date_v1`。
- Runtime 保留当前 L1 影子候选边界；日期补充和无证据约束都不伪造召回条目。
- 不迁移数据库、不调用模型、不读取个人库；定向和完整 Python 回归通过。

## 已知限制

SQLite 适配器为保证变化链与来源处于同一快照，目前会物化单用户库的完整 L1 集合，
再只沿当前锚点的精确链选择；这不会把无关退役事实暴露给回答，但不是大规模数据库的
最终查询方案。V1 先以实际准备耗时判断是否需要新增 `superseded_by_id` 索引和递归
定向查询，不为尚未出现的性能问题增加结构迁移。
