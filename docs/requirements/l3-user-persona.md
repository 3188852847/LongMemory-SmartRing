# L3 用户画像：第一版基础需求

日期：2026-09-06。当前仅实现技术中立领域模型和 SQLite V7 空结构；个人库已在一致性备份后迁移且 L3 表为空，画像生成、存储服务、API、React 页面和回答注入均未实现。

## 用户可见目标

L3 用于保存经过来源核对的稳定认识，例如：

- 用户明确偏好：用户明确表示希望助手先倾听，再询问是否需要建议。
- 系统推断习惯：多个不同日期的互动共同显示，用户通常在午后与助手聊天。

第二种不能由一次聊天、一个 L2 场景或模型印象直接得出。L3 用户画像也不等于“爱莉希雅”等助手角色设定。

## 第一版数据边界

- 每条记录只保存一个画像断言，并带类型、依据性质、状态、现实有效期、生成器和修订号。
- `user_declared` 至少追溯到一条用户 L0；页面必须明确显示这是用户自述。
- `system_inferred` 至少覆盖两个来源、三条用户 L0 和两个观察日；页面必须明确显示这是系统推断。
- 来源可以是 L1 或已接受 L2，但必须能够继续向下检查 L0。
- 所有自动结果先进入候选；用户拒绝后不参与回答，来源失效后不得继续使用。
- 外部文档、助手回答和角色提示词不能成为用户画像事实来源。

## 本切片明确不包含

- 扫描或回填现有个人记忆。
- 自动创建画像候选、定时任务或后台模型调用。
- L3 管理页面、接受/拒绝、来源失效传播和回答注入。
- 自动主动问候、行为原因推断、情绪诊断或画像置信分数。

## 后续实现门槛

1. 来源选择服务能够验证主体、状态、底层 L0 数量与观察日数。
2. 候选、来源快照、生成审计在同一个事务中保存。
3. L1/L2 退役、删除或失效会使相关画像变为 stale，并留下原因。
4. 控制台先提供来源核对和人工复核，再考虑受控回答注入。
5. 真实模型体验前使用合成数据覆盖一次事件误判、跨日证据、无关场景污染和来源变化。
