# L3 用户画像：第一版验收需求

日期：2026-09-06。代码已实现人工候选、显式模型草稿预览、证据门槛、来源追溯、接受/拒绝、来源失效传播、统一画像聚合投影、候选式取代、自动策略独立审计身份及默认关闭的低频整理周期；个人数据库后续已在逐版一致性备份后迁移至 V14，现有画像仍来自人工复核。

显式模型预览现在使用整理操作契约：模型只能建议 ADD、UPDATE 或 NOOP。UPDATE 必须指向一条当前有效的同类型画像，返回后只填充可编辑候选表单；不会自动落库或接受。

## 用户可见目标

L3 用于保存经过来源核对的稳定认识，例如：

- 用户明确偏好：用户明确表示希望助手先倾听，再询问是否需要建议。
- 系统推断习惯：多个不同日期的互动共同显示，用户通常在午后与助手聊天。

第二种不能由一次聊天、一个 L2 场景或模型印象直接得出。L3 用户画像也不等于“爱莉希雅”等助手角色设定。

## 已实现边界

- 一条记录只保存一个画像断言，类型为偏好、习惯、互动方式或行为模式。
- 用户主视图只展示一份统一画像，并按上述类型汇总当前 `active` 断言；候选、拒绝和失效记录留在次级工作区。聚合发生在读取时，不生成不可追溯的大文本，也不修改数据库。
- `user_declared` 至少追溯到一条用户 L0；页面明确标为“用户自述”。
- `system_inferred` 至少包含两个 L1/L2 来源、三条不同用户 L0，并覆盖两个 UTC 观察日；页面明确标为“系统推断”。
- 来源只能选择当前有效的 L1 或已接受的 L2，并继续展示 L0 原话与来源快照。
- 创建只得到 `candidate`；用户通过 revision 保护的二次确认接受或拒绝。
- 人工复核明确记录为 `user`；V10 支持将未来的自动接受记录为 `policy`，并强制保存策略版本和决定原因。自动策略不能记录拒绝或冒充用户。
- L1 退役/删除或 L2 失效时，关联候选或生效画像自动转为 `stale`，并记录生命周期事件。
- 网页写入需要独立画像管理能力、本机会话、同源/CSRF 校验和明确确认。
- 用户可手工填写，或在选择来源并二次确认后让当前模型生成一个不落库草稿；服务在调用前后都验证证据门槛，模型不能引用未选择的来源。
- 模型草稿允许拒绝生成；成功草稿仍可编辑，并需另行创建候选、核对来源和人工复核。
- 当前有效画像可发起人工更新。新内容先成为候选；接受时才在同一事务激活新画像并将 revision 未变化的旧画像标为 stale，拒绝不改变旧画像。
- 打开页面不会调用模型，也不会扫描历史、自动创建或自动接受画像。

## 当前明确不包含

- 定时扫描、批量回填、自动选择来源或自动创建候选。
- 更强的语义 L3 召回；当前已提供默认关闭的关键词安全基线。
- 自动合并重复/冲突断言，以及长期规划、价值观、兴趣和关系等新增画像类型。
- 自动发现应更新的画像、模型自动改写或自动接受；第一版更新由用户从一条旧画像显式发起。
- 自动重建失效画像、撤销复核或画像版本链。
- 自动主动问候、行为原因推断、情绪诊断或画像置信分数。

## 下一阶段产品边界

- 当前人工复核页保留为内部观察、纠正与回滚工具，不作为圆屏最终用户的日常步骤。
- 确定性的证据/风险决策契约、独立策略审计、个人库迁移和应用层自动生效执行器已经完成；执行器从数据库复算证据，只让 `AUTO_ACTIVATE` 接入既有原子复核路径。
- 敏感、来源归因不清、冲突或高影响候选保持 HOLD/BLOCK；适合澄清的内容通过圆屏自然对话询问，而不是弹出网页确认。
- 自动 UPDATE 必须继续复用候选式取代、目标 revision 与原子提交；自动路径不包含 DELETE。
- 助手怎样回应、何时主动交流属于独立陪伴策略，不写入 L3 用户画像。见 [ADR-0047](../adr/0047-round-screen-autonomous-evolution-boundary.md)。

## Definition of Done

1. 声明型画像没有用户 L0 时拒绝创建。
2. 推断型画像未满足“2 来源、3 用户 L0、2 观察日”时拒绝创建。
3. 候选、来源快照和生成审计在同一个事务中保存。
4. 详情能从 L3 沿 L1/L2 追溯到 L0 原话。
5. 接受/拒绝使用 revision 防止旧页面覆盖新状态。
6. 来源退役、删除或失效会使画像 stale，并留下原因；画像和证据不被静默删除。
7. 页面、HTTP API、数据库迁移及全量回归通过；真实个人库已迁移，页面体验另行验收。
8. 模型预览前后均检查来源白名单和对应证据门槛；预览不落库、失败不重试。
9. 统一画像只聚合当前主体的 `active` 断言，每项仍能按原 ID 打开证据详情；读取页面不产生数据库写入。
10. 创建更新候选不改变旧画像；接受时新旧状态和取代时间原子提交，目标状态或 revision 冲突时全部回滚。
11. 用户和策略复核身份不可混用；策略接受必须可在 API 与控制台查看版本和原因，V9 人工复核迁移后仍保持用户身份。
12. 自动执行器不采用模型自报的证据数量；HOLD、ASK、BLOCK 和 NOOP 均不产生 active 画像，UPDATE 继续使用目标 revision 与原子取代。
13. L3 回答使用默认关闭；开启后只注入相关、active 且当前有效的画像并遵守数量/字符预算，每轮保留 L3→来源→L0 轨迹。
