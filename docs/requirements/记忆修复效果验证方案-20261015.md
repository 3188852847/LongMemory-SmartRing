# 记忆修复效果验证方案

日期：2026-10-15。状态：设计提案，供下一轮定范围；没有实现新 API、数据表、迁移、模型调用或开关。源码核对基线为 `449516ea2d457e2a9e515e17613368346541a9ca`，产品基线为 `e15a867`。范围来自[本轮任务书](../development/并行优化-20261015.md)；起因见 [I 的 F1](../development/parallel/I-20261014.md) 与 [H 复测 H08](../development/parallel/H-retest-20261014.md)。不选择或实施 F2／F3／F4。

## 目标与首个切片

把一条问题串成：问题 → 修复证据 → 待验证问题／人工预期 → 冻结召回核对 → 结果／复核；模型复问属于未来独立阶段。人工标已处理、验证已执行、召回符合、回答正确分别记录，任何一步不替下一步背书。

第一切片建议只做合成数据、无模型的 L1（单条事实）关键词召回验证：修复前后各保留独立冻结库，在相同代码、查询、时点和检索配置下核对来源与被取代事实。构建合成修复夹具时可复用管理服务，验证进程只读；不运行提取重试、不加载 BGE 或其他模型、不调用回答器（包括 Fake 回答器）、不写事实或自动修复。向量编码替身仅可用于工程测试，不产出语义效果结论。

切片完成意味着能追溯和复核这一组合成问题的召回变化，不代表日用关键词＋BGE 混合召回已修复，更不代表答案、长期记忆准确率或完整 V1 验收通过。影子复核、低频整理、主动调度保持关闭；不导出个人样本。

## 拟议最小流程与接口

以下适配器、命令和接口均未实现，不是可直接执行的操作说明。

1. **定位问题。** 由已有质量页选中当前问题修订，带来源定位和当时 review_revision；保存验证关联时重新确认目标仍可访问。网页定位补充 chat_id 与所有者范围以消除 request_id 歧义，圆屏使用 feedback_event_id；仍保留现有复核存储键，不在本轮改其契约。目标多义、过期或已不可访问时拒绝新关联，不靠时间相近猜测。
2. **登记修复证据。** 人工选择已有纠错／变化／补记结果，关联实际返回的记忆、来源和终态标识；允许一种问题多条证据。没有统一操作 ID 时用类型＋旧／新记忆 ID＋来源 ID＋操作前后详情摘要＋时间定位，在冻结库复核取代链或证据边。仅“记忆已纠正”原因码不充分。算法／配置修复须另带代码和配置摘要，无事实变更则不伪造记忆操作。
3. **先定预期。** 冻结查询文本、查询时点、主体、至少一组充分来源集合、应出现／应排除的记忆与版本，以及未知信息或冲突的人工处理标准。标签只给评分器，不能传入 recall（召回）或未来回答模型。修改查询／预期／修复证据即新建 case_revision，不覆盖旧标签。
4. **构建并冻结。** 独立合成夹具依序生成 before／after 两份库与证据清单，关闭连接后做一致性和摘要校验，再只读重开。不回滚 after 库来伪造 before，也不把 WAL 中未纳入的一部分状态当完整快照。无 before 只能做修复后核对，界面须标“缺少修复前对照”，不得声称改善。
5. **只读运行。** 拟议 `run_repair_recall` 适配器复用 `open_method(..., frozen=True)` 的 L1 关键词路径、来源评分与摘要思想；先验证方法身份/schema 与修复证据，再分别召回、保存 ID／来源／顺序和实际上下文、检查前后全部状态摘要。修复夹具须经适配与兼容性检查，不能直接调用现有 `run_retrieval` 冒充已兼容。只从注册的合成档案选择输入，不接收任意文件路径。
6. **展示并复核。** 默认同屏显示人工处置、是否执行、召回结论、适用版本、复核状态和“回答未验证”。展示修复证据与 before／after 差异；人工可判断符合／不符／不可评分，并写受控原因。人工判断与机器来源检查并列保留，不能覆盖原报告或自动把问题改为已处理。

建议首切片先交付离线用例服务和合成验收；不以新网页/API 为前置条件。若下一轮同时需要页面关联，可讨论新增 `POST /api/memory-repair-validations`（创建版本）、`GET /api/memory-repair-validations/{case_id}`（读取）、`POST /api/memory-repair-validations/{case_id}/runs`（只读召回任务）、`POST /api/memory-repair-validations/{case_id}/reviews`（追加复核／撤销）。这些路径是提议，尚不存在；沿用现有认证、同源与 CSRF（跨站请求伪造防护）检查，不更改已有 reviews 的严格字段集合，不增加隐式修复或重答。

## 状态与成功标准

| 独立维度 | 拟议状态／判定 | 不能推出的结论 |
|---|---|---|
| 人工队列 | 沿用 open／resolved／dismissed；无验证也可按既有规则处置 | resolved 不自动成为验证通过；reopen 不删除旧证据 |
| 执行 | not_run → running → completed／failed／interrupted；取消记 interrupted＋原因 | 接收请求、写 started 或进程退出不等于已完成；completed 只指证据收集完成 |
| 召回 | not_checked／meets_expectation／mismatch／insufficient_evidence | 来源齐全不证明语义与回答正确；failed／interrupted 不给符合／不符 |
| 回答 | not_run；未来才有 pending_review／correct／incorrect／unscorable | 首切片恒为 not_run；Fake 不给真实回答质量结论，词面初筛不自动填 correct |
| 适用性 | current／superseded／unknown，与历史结果并存 | 库或配置改变后，旧通过仍是旧版本结果；不是现库有效证明 |
| 人工复核 | pending／confirmed／disputed／unscorable／withdrawn，记录 human／assistant | 助手复核不是所有者反馈或独立盲评；撤销不删除执行历史 |

召回符合仅限：档案和修复证据完整、执行完成且冻结未破坏；对可回答题，召回来源覆盖至少一组充分集合，人工列定的必需记忆版本存在且被召回，应排除的错误／过期版本不进入本次上下文；上下文裁剪若无法证明保留必要事实，则为证据不足。缺少必需来源或出现禁止项为不符。存在未裁定的冲突、来源丢失或过程缺失时标证据不足，不能用条目数或相似度代替判断。

未知信息题不要求零召回；机器只记录“未发现目标属性的已核对证据”，总体召回结论默认不足，待人工对照合成来源确认该未知预期是否成立。即使确认，也仅是证据层符合，回答是否拒答留待后续。无结果对于有充分来源标签的题可判不符；对于无标签的题不能自行造标签。before 不符且 after 符合才可说“本题召回由不符变符合”；两边均符合只说明未见本题回归，不证明修复带来提升。

## 版本、来源与最小数据关联提案

复用问题、记忆、来源、提取尝试与实验实体的 ID；建议新增独立验证实体，而不扩充 `memory_feedback_review_events` 的原因码或写入正文。理由是同一问题可多次修复、多版本复测、多个执行与复核；队列状态继续只有管理语义，已有 [ADR-0100](../adr/0100-append-only-memory-quality-review-state.md) 的无正文和追加约束得以保留。

拟议最小持久化为两张附加表，均只是提案：

- `memory_repair_validation_cases`：以 case_id＋case_revision 追加版本；保存问题键、完整来源定位、创建时 review_revision、修复证据引用、查询／预期档案引用与摘要、协议版本、创建时间和撤销前驱。问题、答案及事实正文留在受控合成档案中，不复制到问题队列。网页所有者范围复用已有可信归属解析，不保存 Cookie 或令牌。
- `memory_repair_validation_events`：追加 run_started／run_finished／review／withdraw 受控事件；含 event_id、case_revision、attempt_id、expected_event_revision、请求幂等键与请求摘要、结果档案引用／摘要、终态／原因、复核者类型和 UTC 时间。结果含 before／after 侧别，事件唯一序号与每次 attempt 唯一终态；不把任意 JSON 或自由正文塞入日志。

每份 manifest（版本清单）至少绑定：源码提交和脏状态／相关源码摘要、依赖锁摘要、方法名称／版本／实际策略及参数、协议与评分规则版本、数据集／查询／预期摘要、查询时点与主体、schema 版本、before／after 一致性库的字节摘要、来源／记忆详情摘要、运行起止时间和全部选定题目。摘要用于版本比对，不是匿名化或鉴权凭证；不把私人正文摘要公开当作脱敏样本。

当前 [memory_presenters.revision](../../src/longmemory/entrypoints/api/memory_presenters.py) 是单项详情摘要，不是全库版本；`effective_state` 依赖当前时间。新档案应规范化排序、编码、时间格式，固定查询时点与原始有效期字段，不用随墙钟变化的展示状态生成稳定版本。冻结目录摘要与规范化来源摘要同时保留；运行日志、时间和结果写在状态目录之外，避免自身写报告破坏冻结校验。

修复后日用库再变化：历史结果保留，当前适用性不再沿用。首切片只比较注册合成库的摘要；未来若接个人库，应单独决定可靠的变更检测范围，在每次显示“适用于当前库”前重新核验库／策略／预期版本；无法核验即 unknown，不后台读取或复制个人库。before／after 不同代码的比较必须显式标为跨版本对照，不能归因于事实修复。

并发／幂等／重启拟议约定：

- 创建版本和追加复核使用预期 revision 在同一短事务中比较并写入；陈旧反馈、旧 case 或同键不同请求摘要拒绝（拟议 409），不覆盖赢家。
- 同一 case_revision＋输入指纹同时最多一个运行；请求幂等键相同且摘要相同返回原 attempt_id 和状态，不重跑。显式再测需新键／attempt，保留前次失败；不对修复操作本身新增自动重试。
- 运行开始前落 started，冻结校验后写终态；结果档案排他创建、临时写入后原子定名，只有文件摘要校验通过且完成事件持久化才可投影 completed。跨文件与 SQLite 不假称原子；孤立档案待核对，不当成功。
- 重启发现无终态的 started，追加 interrupted／process_restart，不自动重放；保留部分检查点但不评分为通过。旧幂等键仍定位该 interrupted，所有者显式重测才新建 attempt。复核提交也有独立幂等键和并发检查。

## 合成验收矩阵（下一轮实施标准，尚未执行）

所有行在独立临时目录、无个人库、无网络／设备的环境验证；重开库验持久化。不得用未来测试项冒充当前通过。

| 场景／刺激 | 必须观察的结果 |
|---|---|
| 漏记→人工补记 | before 不符、after 符合；来源身份一致，保留补记 created／evidence_added 差异；问题仍按人工状态展示 |
| 错记→纠错 | 旧来源不删，新事实／来源和取代链可核对；after 不注入旧错误，召回符合但回答仍未验证 |
| 事实变化→按时点查询 | 当前与历史预期分开；同一固定时点前后可比，不把合法历史事实当错记 |
| 空查询／空预期／空证据引用 | 创建拒绝，返回受控原因；未知题仍须有明确人工标准，不把空字段当未知 |
| 空库／无召回／过程为 None | 空库运行可完成；有答案标签而零召回为不符，无过程或无充分标签为不足；结果不混淆 |
| 未知信息但召回相关事实 | 不以零召回判通过；保留上下文与“回答未验证”，人工确认的证据结论不扩大为正确拒答 |
| 同内容多来源／重复登记 | 允许替代充分来源集合；按项／来源身份去重，不凭条数提升判定；同幂等键同输入不新增执行 |
| 新旧事实冲突／错误项仍召回 | 明确禁止项命中则不符；未裁定冲突为不足，不能仅凭一组来源命中填通过 |
| 无 before／修复仅获 202／NOOP | 分别标缺少对照／未完成修复证据／需核对实际事实；不声称改善或修复有效 |
| 反馈改标／旧页面／双人并发 | 旧修订关联拒绝；同 expected revision 只一个赢家，历史结果留在原修订，不继承到新问题 |
| 重复点击／同键异载荷／显式重测 | 同键同摘要返回同 attempt，同键异载荷冲突；新键生成新 attempt，旧结果不覆盖 |
| 重启／取消／结果文件损坏 | 无终态变 interrupted；取消不自动重跑；损坏／缺失摘要不得 completed 或通过，保留受控故障码 |
| 冻结库或来源运行中变化 | 当前 attempt failed；余题 interrupted，拒绝继续使用污染快照；前次结果仍绑定原版本 |
| 修复后库／配置／标签再次变化 | 旧通过保留但适用性 superseded 或 unknown；新版本重新验证，不静默把新库冒充旧库 |
| 撤销复核／重新打开问题 | 追加撤销／reopen，状态独立；不恢复旧事实、不删除报告、不撤销真实纠错 |
| 无权／目标丢失／路径越界／诊断异常 | 不泄露正文，不跟随目录联接或任意路径；新任务拒绝或降级为不足，已有聊天与人工队列可继续用 |

## 未来模型复问、迁移与回退

模型复问须另定实施范围及数据外发预算。只接已冻结且可追溯的修复档案，每题独立无历史上下文，不 observe／写入库；记录实际注入、截断、模型配置／提示摘要和未知的服务端采样条件。复用 [retrieval_answers.run_answers](../../src/longmemory/evaluation/comparison/retrieval_answers.py) 与既有复核设计前须适配验证档案，不能直接当现有 jobs 已支持。保留未运行／失败分母；召回与注入、答案分别判，词面指标仅初筛，人工阅读整段答案后才给 correct／incorrect／unscorable。一次题目通过不作通用准确率结论。

现有 [dataset.load_dataset](../../src/longmemory/evaluation/comparison/dataset.py) 只接受 `synthetic=true`；真实问题即使脱敏也不能冒标合成。真实样本进入回归集须另获逐项脱敏、存放范围和用途授权，再设计独立数据类型与导出路径；本方案不读取、不复制、不导出个人库。

两表若获准落地主库，需下一轮登记 schema 版本并做向前附加迁移：执行前核对精确库、服务所有权、一致性备份与恢复校验；已有复核不回填为已验证。合成档案／结果路径只存受控相对引用，不改变旧 API、事实表或研究分数。本次没有选择迁移号或执行迁移。

回退优先禁用新入口／停止新验证任务，保留附加表和档案、恢复纯人工队列；不自动降 schema、删表、覆盖个人库或反向纠错。旧程序若拒绝新 schema，须使用经过兼容审查的版本；不能承诺旧二进制直接可用。必要恢复备份另核对备份后的新数据影响，不自动覆盖。验证子系统不可用时显示“验证不可用／未验证”，不阻断聊天、正常召回与既有人工处置，也不降级显示成功。

## ADR 草案要点与下一轮定范围

ADR（架构决策记录）候选：**问题处置与修复效果验证分离，采用版本化关联及追加执行证据**。尚未接受，不新增 accepted ADR、不修改旧决定。

- 决策理由：保留 ADR-0100 的管理语义和无正文事件，复用原记忆／来源／实验实体，避免 resolved、提取成功或关键词命中被当答案正确。
- 备选：扩充复核表会耦合处置与多次运行；只写实验 JSON 缺少问题修订关联和并发控制；新建完整实验平台超出首切片。建议两表＋受控档案，代价是附加迁移、档案生命周期和引用一致性维护。
- 方法边界：第一阶段只验证冻结 L1 关键词证据，显式披露与日用混合策略的差别；不向 Memory Core 注入问题标签或供应商依赖。
- 接受条件：主会话确定离线服务与页面范围、合成档案契约和迁移策略后，按上表验收并独立审查。实现、API 与新表仍是待决定内容；日用模型／混合召回、L2／L3、真实样本与模型复问另分阶段，不自动扩展授权。

下一轮建议只批准上述无模型合成切片，以“可追溯运行与失败边界完整”为完成标准；不把本提案交付当实施已授权或验证已运行。
