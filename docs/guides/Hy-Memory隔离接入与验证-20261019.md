## 决策记录 HY-001：隔离与数据边界（已按 U 契约实现）

原因：core 包依赖 `pydantic`、`numpy`、`openai>=1.40,<3`、`python-dotenv`、`pyyaml`、`chromadb>=1.5.9`、`kuzu`、`langdetect`、`scikit-learn`、`tiktoken`、`json-repair`、`rank-bm25`、`jieba`；多数未固定完整版本。向主环境安装会引入向量库/原生组件以及模型适配器版本变化，扩大日用环境风险。

决策：Hy 独立环境，最终优先独立进程边界；不用大规模服务框架，不变更根 `pyproject.toml`/`uv.lock`。最小条件为 pro/chat、graph 关闭、无主动意图召回、无 evolve，不安装 extras。关闭图功能不等于 core 的 Kuzu 依赖消失。替代是直接进主环境，当前不选；lite 可作为单独组件对照，不能冒称 pro 效果。回退为停止使用新实验目录并保留旧系统；不删除旧库、不自动回迁。

低层 `HySdkBridge` 接受调用方注入 client；`HyMemoryMethod` 适配 U 方法契约，`build_hy_memory_runtime()` 经 `assemble_backend()` 复用平台来源账本。SDK 在独立解释器的 JSONL（逐行 JSON）worker 中运行，显式配置/凭据只经 stdin，不进入 argv/报告。日用入口和旧方法工厂没有切换。管理仅列表/详情可用；纠正/删除缺少原子修订比较，明确拒绝。中立边界依据 [ADR-0181](../adr/0181-neutral-memory-backend-and-platform-sources.md)，没有扩张通用协议。

## API 映射与不伪造的能力

低层映射依据[固定 client.py](https://github.com/Tencent-Hunyuan/Hy-Memory/blob/2a4c5e38e78a42ae0acae1fe6f12cfcd8ecb64ed/hy_memory/client.py)：

| 输入/输出 | 本轮映射与限制 |
|---|---|
| 原始事件 | `add([{role,content}], user_id, agent_id, session_id, scene="chat", memory_at, request_id)`；保持历史时区和助手角色 |
| 来源 | 使用 `meta={namespace,source_event_ids,occurred_at,role}`；SDK 将多次写入的 meta 保存为列表。`metadata` 是内部 extra 控制通道，不能替代业务来源 |
| 写入结果 | `success`、原始 `memory_id`、可选派生 `memory_ids`；没有操作明细时不编造 ADD/UPDATE 轨迹 |
| 检索 | 显式 chat/default，固定 user/agent/source，跨会话；`intention_limit=0`、`schema_limit=0` |
| 通道 | 实际 2.0.3 为 `schema/normal/proactive`，不是 README 的 `profile/normal/proactive`；严格拒绝未知结构 |
| 画像 | `get_user_profile(user_id=...)` 独立 opt-in，不参与自动检索；没有 agent/source 过滤，须使用独占合成 user |
| 分数 | 保留为 `sdk_score`，不映射成旧 keyword/dense/fused 同量纲分数 |
| 来源缺失 | 返回未知，不从正文、metadata 或相似内容推断来源；真实 SDK＋模拟模型已验证单条派生事实的列表/详情/召回 meta，不推及全部层级 |
| 失败/重复 | U 来源账本持久回放已完成事件，冲突载荷拒绝；失败/回执中断保留 failed/uncertain。Hy 不声明原生幂等，不允许 failed/uncertain 盲目重试 |
| 层级 | 保留 Hy 原生层名，不把 Hy L0–L7 改称本项目旧 L0–L3 |

离线 Fake client 测试只检查参数/结构/异常，不模拟提取质量、存储、重启或幂等保证。

## 检索的冻结检查

固定源码 `_spawn_search_dedup` 默认开启，可能将相似 L2/L4 节点置为 SHADOW（逻辑删除、可恢复），这是**语义记忆变化**。`search` 还有可选 access_count/last_accessed_at 回写，history 搜索记录、profile/intention/cache 及日志也需分类。不能把这些一概称为“完全无写”或“非语义遥测”。

[配置模板](../../config/examples/hy-memory/synthetic-settings.json)列出关闭搜索去重、strength、access tracking 和搜索历史的环境开关，但该模板未被运行入口消费，开关自身也不足以证明冻结。参考[固定 config.py](https://github.com/Tencent-Hunyuan/Hy-Memory/blob/2a4c5e38e78a42ae0acae1fe6f12cfcd8ecb64ed/hy_memory/config.py)。

真实验证按以下顺序进行：

1. 从新合成历史建库，等待完成，关闭所有 SDK 句柄和后台任务；独立进程重开，核对记录和来源。未完成写入不能当空结果。
2. 封存构建状态；每题从关闭后的状态复制到独立新目录，不在封存源上搜索。复制保持相同历史，问答标签只给评分器。
3. 搜索前后、关闭进程后分别核对文件摘要及逻辑记录。逐项区分语义记录/SHADOW/版本/来源、会影响后续排名的访问计数、缓存/历史/日志。未知变化仍记 unknown。
4. 现有 `comparison.runner` 要求逐题**磁盘摘要完全不变**，因此目前不能直接注册 Hy 或宣称它通过冻结。新条件如容许遥测写入，必须另命名协议并记录差异；不能豁免 cache/history 文件名来让检查通过。

逐题副本由独立 `hy_memory_runner` 实现，协议 `hy-closed-source-per-question-clone-qa-v1`。关闭 SDK 后封存构建目录，每题复制 engine、另建空来源账本；封存源前后摘要必须不变，副本变化单独记录。构建账本保留原历史，覆盖率依据 SDK 原事件 ID。真实 SDK＋模拟模型已验证该路径；副本 `semantic_state_unchanged` 仍为未知，不将它注册成原 strict frozen 方法。真实 smoke 观察到副本 Chroma SQLite 和 SDK 默认日志变化，未自动归类为纯遥测。

## 合成比较与预算

开发集为 [hy_memory_dev_v1.json](../../datasets/synthetic/hy_memory_dev_v1.json)：12 条历史、3 会话、10 题。保留集为 [hy_memory_holdout_v1.json](../../datasets/synthetic/hy_memory_holdout_v1.json)：9 条独立历史、3 会话、7 题；人物、事实、事件 ID 独立。适配调试只使用开发集，本轮未运行保留集检索/问答；保留集为本地作者合成，不能称外部盲测。

覆盖稳定偏好、事实变化、否定纠正、临时状态到期、跨会话、未知拒答、助手建议归因、来源追溯；失败/重复/重启由[实验计划](../../experiments/configs/hy_memory_comparison_v1.json)定义生命周期用例，不在合法历史中放重复 event_id。到期题使用明确题目日期，Hy 内部时钟/衰减差异必须记录，不能伪造 now 支持。

复用 `comparison.dataset`、来源覆盖、答案词面初筛、既有回答提示和 4000 Unicode 字符预算，不复制新评分平台。写入、召回、注入后来源充分性、最终答案和重启分别报告；修正/否定/时间词面的初筛必须人工复核。所有错误/不支持/中断保留分母；未观测 token/成本填未知，不写零。提取模型和检索器不同属于完整系统比较条件，不能声称论文复现或统一框架分数。

pro 会将合成历史/提取上下文发送给明确的 LLM（大语言模型）端点，Embedding（向量表示）端点收到待写内容及检索问题。最终回答模型还收到问题和截断后记忆；独立 profile 调用按固定源码不调 LLM/Embedding，但仍有本地读取/日志。兼容 OpenAI API 不意味着必须部署 Hy 30B，也不证明现有本地 BGE 可直接复用。

当前外部调用预算为 **0**，没有真实密钥、外部端点或真实模型调用。真实实验前由主会话明确端点/模型/维度/数据出口、超时、请求数/token/金额上限和执行方式。pro 一次 add 可能多次调用提取/冲突处理/向量服务。worker 已实现单进程生命周期内跨 LLM/Embedding 的请求次数硬上限、端点范围及重定向拒绝；多个题目副本/回答器的整轮共享预算、token/金额上限尚未实现，不能声称已统一强制执行。CLI 仅加载无密钥离线配置，不读取环境密钥或开启网络；后续真实配置由另获授权的装配者显式提供。

过渡边界：Hy 提供相关记忆/事项证据；独立主动交流层决定是否/何时/说什么并执行许可和打扰控制；设备桥执行，回应/取消等结果进入可追溯反馈。当前缺口是新后端的旧圆屏完成关联/反馈适配、方法中立的待办/证据读取、取消/过期状态关联以及调度结果到原事项/来源的回写契约。U 非 legacy 后端仍拒绝旧陪伴/跟进命令，server 不装主动调度；这些限制保持。后续按具体目标另定接口/验收，不把平台许可/调度塞进 Hy 私有层级。

具体首切片、现有能力复用和阶段门槛见 [主动交流阶段草案](../requirements/主动交流阶段方案-20261019.md)。该文为 draft/pending，由主会话审阅后定案，没有实现、迁移或开启调度。
