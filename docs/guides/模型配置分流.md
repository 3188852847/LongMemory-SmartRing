# 学校模型与官方 DeepSeek 配置分流

## 目的

本项目在同一台电脑上保留两个互不覆盖的模型配置档：

| 配置文件 | 使用者与用途 | 网络 | 是否提交 Git |
| --- | --- | --- | --- |
| `local/config/.env` | 学校模型配置档；校园网内手工验证 | 学校服务当前要求校园网，且可能使用 HTTP | 否 |
| `local/config/.env.deepseek.local` | 官方 DeepSeek 配置档；日常备用与受控验证 | 官方 DeepSeek HTTPS API | 否 |

这是一种**配置隔离约定**，不是操作系统权限隔离。任何能够读取相应文件的本机进程，理论上都能读取其中的密钥。两个文件都被 `.gitignore` 排除，不应复制到日志、截图、Issue 或聊天中。

## 第一次填写官方密钥

打开项目目录的 `local/config/.env.deepseek.local`，只填写这一项：

```dotenv
LONGMEMORY_LLM_API_KEY=你的官方_DeepSeek_API_Key
```

其余官方配置已经预填：

- API 根地址：`https://api.deepseek.com`
- 模型：`deepseek-v4-flash`
- 明文 HTTP：关闭

不要改动 `local/config/.env`；它继续保存学校模型配置。不要把真实密钥写入 `config/examples/.env.example` 或任何受 Git 跟踪的文件。

## 在控制台选择日常模型

1. 双击根目录 `启动智慧圆屏.cmd` 启动当前配置。
2. 打开“设置中心 → 模型与服务”。
3. 在“网页服务：下次启动配置”选择“学校模型”或“官方 DeepSeek”。核对地址、模型名；只有需要覆盖 Key 时才填写 Key，留空会保留旧值。
4. 在“圆屏语音：下次启动配置”独立选择圆屏模型并保存。按需点击一次“检测圆屏模型连接”；它只发送固定合成短句。
5. 停止启动面板中的服务，再点击启动。仅刷新网页不会切换模型；启动器会在语音端口均空闲后备份小智 YAML，并只同步地址、模型名和 Key。
6. 回到模型页核对网页“当前进程”和圆屏“小智磁盘配置”，按需点击一次网页连接检测。

官方档案可以保留 `https://api.deepseek.com`。由于当前 Xiaozhi 的模型配置
契约要求 `/v1` 根路径，圆屏同步适配器会写入等价的
`https://api.deepseek.com/v1`，不会反向修改网页所用 env 文件。

配置页不会读取或显示旧 Key，也不会把 Key 保存到浏览器。当前进程不热切换，是为了避免同一轮聊天或记忆整理同时使用两套模型配置。

### 学校模型终端检查

需要在终端单独检查学校模型时，在项目根目录执行：

```powershell
uv run --locked --env-file local/config/.env python -m longmemory --provider openai_compatible --check-model
```

学校地址当前使用 HTTP，因此终端出现明文传输警告是预期行为；只在你已经接受风险的校园网环境使用。

日常控制台的聊天页会显示本次进程最近观察到的模型状态。设置中心的“模型与服务”页还会集中显示实际模型名、无凭据服务地址及 HTTP/HTTPS 状态；网页永远不显示 API Key。刚启动时是“尚未验证”，不会为了启动而自动发送请求；点击“检测模型连接”才会发送固定合成短句，且不读取、不写入个人记忆。失败会区分鉴权、部署地址不存在、网络、超时、限流、服务端故障和响应格式变化。状态只保存在当前进程，重启后重新变为“尚未验证”。

学校重新部署后，新地址、模型名或 Key 可能同时变化。拿到新配置后：

1. 更新项目目录 `local/config/.env`，停止并重新启动控制台；仅刷新网页不会重载环境变量。
2. 如果还使用圆屏语音，在设置中心给圆屏选择学校档案并重新统一启动。启动器会自动完成有备份的窄范围同步。以下命令只作为控制台不可用时的故障恢复入口：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing"
uv run --offline --no-sync python scripts/development/xiaozhi/sync_model_config.py --project "D:\02-项目\LongMemory-SmartRing" --server "D:\LongMemory-local\runtime\xiaozhi-esp32-server\main\xiaozhi-server"
```

该命令读取本机 `local/config/.env`，修改前会给 Xiaozhi 私有配置创建备份，不输出 Key。同步完成后需要从启动面板重启圆屏语音服务。

## 官方 DeepSeek 终端检查

助手代执行真实模型测试时，必须显式指定官方配置档：

```powershell
uv run --locked --env-file local/config/.env.deepseek.local python -m longmemory --provider openai_compatible --check-model
```

后续评估命令也遵循同一规则：把 `--env-file local/config/.env` 换成 `--env-file local/config/.env.deepseek.local`。命令必须显式选择配置档，不根据网络状态、密钥是否存在或当前时间自动猜测。

为避免误调用和意外费用，执行规则如下：

1. 第一次只做一次连接检查，失败后先读错误，不自动反复重试。
2. 真实评估先核对数据集、请求数量和模型，再开始调用。
3. 依赖安装、模型权重下载和仓库拉取仍由用户执行；这里的委托只扩展到官方 DeepSeek API 测试。
4. 测试报告可以记录供应商、模型和配置摘要，但不得记录 API Key。
5. 日常启动会读取控制台最后选择的配置档；小智服务和圆屏仍不直接读取这些 env 文件。

## 为什么网页和圆屏可以选不同模型

网页 LongMemory 进程从网页所选 env 档案启动；圆屏对话由 Xiaozhi 私有 YAML 中的模型配置负责。因此控制台保留两个独立选择，不能把网页检测成功当成圆屏已经可用。保存圆屏选择不会热改正在运行的小智；下次统一启动时，启动器才在端口空闲的前提下执行有备份的窄范围同步。页面中的“已匹配”只证明磁盘字段一致，真正连通性仍以圆屏专用检测或实际对话为准。

## 快速判断当前命令会用哪一个配置

- 命令含 `--env-file local/config/.env`：学校模型。
- 命令含 `--env-file local/config/.env.deepseek.local`：官方 DeepSeek。
- 命令没有 `--env-file`：不作为真实模型测试的规范命令，先停止并补全参数。

填写官方密钥后，只需告诉助手“官方配置已填写”；不要发送密钥本身。助手随后可以先运行一次连接检查，再按已说明的调用预算执行测试。
