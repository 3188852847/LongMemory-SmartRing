# 数据库一致性备份与恢复演练

本流程用于 V1 发布前证明现有 SQLite 可以从一致性备份恢复到独立副本。它不会把
恢复副本覆盖回活动库，也不会读取或输出对话、记忆和主动交流正文。

## 执行前检查

1. 在启动面板停止受管服务，并确认控制台、Xiaozhi 和本地 TTS 已退出。
2. 核对活动库的精确路径；日常默认是 `data/databases/xiaozhi-demo-v1.db`。
3. 不要把 `data/backups` 中的文件提交、上传或分享；备份包含与活动库相同的个人数据。

## 只读状态

```powershell
uv run --no-sync python scripts/development/memory_database.py status `
  --database data/databases/xiaozhi-demo-v1.db
```

状态会显示绝对路径、当前结构版本、程序目标版本和是否需要迁移。不存在、目录、损坏
或高于程序支持版本的数据库会被拒绝，不会自动创建空库。

## 创建备份并验证恢复

```powershell
uv run --no-sync python scripts/development/memory_database.py verify-restore `
  --database data/databases/xiaozhi-demo-v1.db `
  --backup-directory data/backups `
  --confirm-backup
```

工具依次执行：

1. 以只读模式检查活动库 `quick_check` 和外键；
2. 使用 SQLite Backup API 创建带微秒时间戳的一致性备份；
3. 从该备份创建另一个独立恢复验证副本；
4. 再次检查恢复副本的 `quick_check` 和外键；
5. 比较备份与恢复副本的结构版本、业务表清单和逐表行数；
6. 输出两个文件的 SHA-256、表数量和总行数，不输出任何字段正文。

目标文件意外存在时工具拒绝覆盖。任一步失败都会保留已经创建的诊断副本，不会回写
活动库；先停止使用相关副本并定位原因，不要用文件复制覆盖活动数据库。

## 与结构迁移的区别

`verify-restore` 只验证备份和恢复，不修改结构版本。确有新迁移时仍使用同一工具的
`migrate --confirm-upgrade`，并遵循迁移前停止服务、核对路径、形成备份和迁移后验证
的流程。恢复演练通过不代表允许删除旧备份或批量改写个人数据。
