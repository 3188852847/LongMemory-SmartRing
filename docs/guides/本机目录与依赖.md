## 为什么还有旧目录名

目录联接（Windows Junction）让旧路径指向集中目录中的同一份内容，不是复制品，也不额外占用模型空间。
本轮共保留 7 个联接，只有 `D:\sr-bv2-lvgl-assets` 位于 D 盘根目录。

- CosyVoice 和小智的已安装命令入口分别有 47 个、56 个内嵌旧解释器路径；VoxCPM2 的旧入口也需保留。
- 当前固件的 CMake 缓存固定使用 `D:\sr-bv2-lvgl-assets`；原路径继续有效。
- 启动器首选项、BGE 固定快照路径、设备恢复镜像的历史文档引用继续有效。

不要把联接入口与目标目录当作两份重复文件清理，也不要直接递归清理这些入口。
备份或统计时应只选择真实目标，避免重复遍历。后续若要完全去掉旧路径，须单独处理命令入口、
配置迁移和全新固件构建，并在回归后撤销联接；本轮没有做这一步。

## 验证与恢复依据

- 每项迁移都是同盘目录移动；前后比较相对文件名、目录名、文件长度和修改时间的排序清单摘要。
  这不是逐文件内容哈希证明。14 项均无清单差异，7 个联接目标逐项核对。
- CosyVoice 模型文件检查、Python / torch / torchaudio 导入及旧 CLI 入口通过。
- 小智 Python / torch / aiohttp 导入、旧 CLI 入口和本地私有配置检查通过；不输出密钥，不调用模型。
- VoxCPM2 的 Python / torch / voxcpm 导入和旧 CLI 入口通过。
- 启动器三项启动命令的解释器与工作目录存在；TTS 与记忆后端只读配置检查通过。
- BGE 固定快照逐文件 SHA-256 校验通过，离线合成输入编码输出 512 维向量。
- 当前固件应用和原厂恢复镜像经新旧入口读取的 SHA-256 一致；0012 的回退镜像仍可访问。
- 启动器、首选项、小智安装检查和 CosyVoice 检查相关 138 项测试通过。
- 未启动日用服务、调用联网模型、访问个人记忆内容或重新烧录。完整圆屏重连、实际出声和重新构建未验证。

本机详细清单与逐项执行记录保存在 Git 忽略的
`data/exports/disk-organization-20261006/`。`migration-*.jsonl` 中的 `verified` 为完成项；
`skipped_incomplete_inventory` 是未迁移记录，不能算完成。一次性迁移脚本不应重新批量执行。

需要恢复时先停止相关服务，按本机记录确认精确源、目标及联接身份，再制定单项反向移动。
对于联接入口，不能把普通目录当作联接删除；历史环境和固件缓存可能仍要求原始路径。
这一阶段未删除内容，也未创建不可逆的数据格式变更。

## 后续文件放置规则

新增项目专属源码、独立环境和模型先在上述集中目录确定归属，不再散放 D 盘根目录。
长期保留的原始测量应放在项目已有实验产物目录，并保留脱敏报告引用；测试临时目录只放可再生夹具。
环境继续按项目依赖隔离，不把不同 Python / CUDA 版本合并进一个环境，也不移动其他项目共用工具。

临时缓存删除、AuK 权重删除、权限修复和撤销兼容联接均不属于本轮“只归档”的执行结果。
