# 聊天会话：关闭后继续聊

## 操作

1. 停止旧控制台并重开 `启动智慧圆屏.cmd`，按原方式启动。无需安装依赖或迁移记忆数据库。
2. 打开文字聊天。“已保存的聊天”下拉框列出本浏览器创建的会话。
3. 点击“新聊天”创建独立短期上下文，旧会话和长期记忆都保留。
4. “重命名”修改标题（1–60 字）；下拉框可切换。未发送草稿切换时会询问是否丢弃。
5. 刷新网页，或停止服务后重新启动，保留浏览器 Cookie 时可以恢复档案。默认恢复上次选择；浏览器偏好不可用时打开最近创建的会话。
6. 继续发送时只带最近六轮成功对话，最多 24000 字符的完整轮次；不是把全部历史送给模型。

## 必须知道的边界

- 更新前聊天没有会话编号，不会自动分组到列表里；原记忆库不因此丢失。
- 网页短期历史仍不与圆屏会话同步，二者共用的是指定库里的长期记忆。
- 清除 Cookie 或换浏览器，暂不能从页面找回原会话入口；档案文件仍在电脑。Cookie 是浏览器关联方式，不是正式账号系统。
- 当前最多 32 个会话，每个 40 轮；重启不清空这个限额。归档/删除界面尚未提供，不要通过删除数据库来绕过限制。
- 回答过程中断会显示“写入状态未知”，不要假定没有存入记忆，更不要自动重发。
- 重启后模型与角色采用本次启动设置，旧记录仍保留原轮次的角色/模型信息。

## 文件与隐私

例如记忆库为 `data/databases/xiaozhi-demo-v1.db`，网页档案为同目录 `xiaozhi-demo-v1.db.chats.sqlite3`，锁文件后缀为 `.lock`。首次新建会话才创建档案；不会迁移原库。

旁库也包含真实对话和证据，不能上传 GitHub。备份时先停止服务，再一并备份原库和旁库。删除长期记忆不等于删除历史聊天中的原话。本次没有新增彻底擦除能力。
