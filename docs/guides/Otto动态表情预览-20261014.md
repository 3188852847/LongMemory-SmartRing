## 预览操作与验收

1. 先比较“240 原尺寸居中”和“360 等比放大”：设备画布为 360×360，前者四边各留 60 像素，后者将原图放大 1.5 倍并受圆形边缘裁切。窄窗口会按比例缩小整个预览；不是实际设备像素测试。两个浏览器 GIF 不保证逐帧同相同步。
2. 网格包含全部 21 个表情。默认展示原 GIF 的静帧；勾选“播放网格动画”并保持全局播放时，进入可见区域的网格才播放。点击任一表情进入“单表情循环”。主预览可暂停/播放；暂停抓取当前帧，继续时原 GIF 从头加载，不声称支持原生 GIF 精确续帧。
3. “按状态仲裁”下依次点“聆听 → 思考 → 选择 happy → 模拟 llm.emotion → 说话”，应显示 happy。点“被打断”，短暂 surprised 后回聆听 neutral；此时再发 happy 不得覆盖聆听。
4. 点“错误/断线”后，普通聆听/说话按钮不得覆盖故障；用“清除故障 / 回到待机”恢复。它只是本地演练，不是实际网络修复。
5. 点“连接中”或“聆听 → 思考”，再点“推进到当前超时点”验证提议超时。说话由 tts.stop 结束，不按 GIF 时长结束；聆听不强制超时。
6. 检查全部 21 个单表情、暂停/播放、两种尺寸、网格播放、键盘操作、窄屏和减少动态效果偏好。页面隐藏后暂停，重新显示需手动播放。系统偏好减少动态效果时初始暂停，仍允许用户主动播放素材。“本地回退与减少动态演练”可模拟缺失/解码失败/全部不可用，或走与减少动态偏好相同的暂停路径；不改素材/系统设置，不冒充真实坏文件或系统偏好切换验收。

播放失败的回退顺序为当前素材 → 固定 neutral 素材 → 静态“素材不可用”文字。逻辑交互状态保持不变；回退图不能伪装连接或解码已经恢复。此轮缺素材回退与合成状态已验收；完整真实素材与设备验收状态以阶段记录为准。

## 状态切换方案与实际来源

以下映射属于预览方案，尚未接入固件。中性 GIF 不能独自区分待机、连接和聆听，未来设备还需保留现有状态文字/指示；不伪造麦克风或连接专用 Otto 素材。

| 展示状态 | 已核对的实际代码来源 | 预览映射、持续与返回 |
|---|---|---|
| 待机 | `Application::HandleStateChangedEvent` 的 Idle；`session.idle` 仅在 Listening 时使设备回 Idle | neutral；持续到下一真实状态 |
| 连接中 | 本地 Connecting，先于 OpenAudioChannel | neutral＋状态文字；15 秒看门狗为提议，超时转错误 |
| 聆听 | 本地 Listening，`SendStartListening`；显示 `microphone` | neutral＋聆听文字；用户情绪不覆盖，不新增强制超时 |
| 思考 | `stt.text` 设置“思考中...”和 `thinking`；不是独立设备枚举，也没有 `thinking.start` 网络事件 | thinking；到 tts.start/错误/新聆听；20 秒看门狗为提议 |
| 说话 | `type=tts,state=start` → Speaking；stop 后自动模式 Listening，手动模式 Idle | 当前轮 `llm.emotion`，未知为 neutral；不把 GIF 当作音频口型或播放完成信号；本预览 stop 演练自动模式 |
| 被打断 | Speaking 中唤醒路径标记 `show_interrupted_on_listening_`，AbortSpeaking 后回 Listening 并显示“已打断，请继续...” | surprised 提示 650 ms 后 neutral 聆听是提议；不延迟采集；非 Speaking 点击不会伪造 abort |
| 错误 | `OnNetworkError`/`MAIN_EVENT_ERROR`/Alert；板级识别 triangle_exclamation、cloud_slash、wifi_off | confused＋文字；故障锁定到明确恢复是提议，不能由晚到 emotion 解除 |
| 断线 | WebSocket 的底层 OnDisconnected 通知 `OnAudioChannelClosed`，应用回 Idle；Protocol/MQTT 有 OnDisconnected 回调但当前应用未挂接专用显示 | sad＋断线文字为明确异常断线证据下的提议；音频通道正常关闭仍回 neutral Idle，不能一律当故障；不存在 `disconnected` 设备枚举或该名 JSON 网络事件 |

优先级为故障锁定 > 打断提示 > 真实交互状态 > 说话情绪 > 待机；交互状态互斥，不靠优先级把正在说话误判为聆听。`llm.emotion` 在思考时只缓存，在同轮说话时显示，在聆听/打断/故障时忽略；新聆听轮清空缓存。预览的 `turn` 是本地合成轮次，真实协议的这些 JSON 没有对应的回合 ID；乱序情绪若晚到下一轮思考，仅靠现协议不能可靠辨别，未来适配需保留这一限制或另提带来源/轮次的契约，不暗改协议。

当前板级 `SetEmotion("thinking"/"speaking"/"microphone")` 也会改展示交互状态。后续 Otto 适配应区分来自 STT/真实状态的展示命令与 `llm.emotion` 情绪，不能把普通情绪字符串当成实际设备状态迁移。

快速操作即时替换目标 GIF，不等待旧循环结束，不叠加多个解码器淡入淡出。动效用途为状态指示；高频控制无需额外 UI 位移动画。保留原素材节奏，任何自然程度、剪裁和视觉过渡结论须在真实素材/真机观察后再判。

当前 `SmartRingFaceDisplay` 优先恢复壁纸：A/B 的 `RoundWallpaperStore` 或 assets 的 `round_wallpaper.gif`；`IsGif360`、实际解码尺寸检查都要求 360×360。原 Otto 240 图不能冒充壁纸上传通过。wallpaper_ready 后原几何脸定时器暂停。因此仅改 `SetEmotion` 名称不会使现有壁纸自动变为 Otto。

推荐下一阶段方案（需另行确定执行范围）：

- 在板级显示适配内新增独立 Otto 表情目录/资源映射及一个活动解码器，保留既有 `SetStatus`/`SetEmotion` 入口和音频状态机。直接读取固定 GIF 字节，用现有 `LvglRawImage`＋自定义 `LvglGif`；上游 C API 只提供版本/枚举名，不嵌入资源，也不是播放器。不要直接套用上游 README 的 `lv_gif_set_src` 替换当前厂商包装器。
- 优先保留 240 原图并在显示端居中/验证 1.5 倍缩放；不先转码放大全部 GIF。先做单解码器预分配/切换与回退，故障立即让真实交互状态文字可见。无口型同步承诺，不同时后台运行 21 个解码器。
- 保留原壁纸文件与 `round_wallpaper` NVS（非易失配置存储）选择。Otto 若遮挡壁纸，必须作为未来明确选择的显示模式，不能自动停用/覆盖/改名壁纸，也不默认修改已有配置。新增持久模式或资源布局时另写 ADR（架构决策记录）及迁移/回退说明。
- 不嵌入全部 GIF 到当前应用。assets 的理论预算只是候选，需要另获资源写入授权、核对实际装机完整资源包与备份、离线重包并验证索引/模型/字体均保留；不能按 CSV 的 spiffs 子类型把当前自定义映射包当普通 SPIFFS 格式化。当前不实施资源包、分区或固件更改。
- 如需更多空间，先审查构建体积与可选显示集合；改分区/OTA 边界属新决策，不能占用 wallpaper_a/b 或套用 K 的旧烧录授权。未来须验证 GIF 解码、峰值堆/PSRAM、帧时间、语音并发、打断延迟和长时间循环，全部在适配完成后的独立验收中完成。

此轮没有读取设备备份正文或实际芯片状态。K 对 0013 的应用烧录/读回保护核验属于已有记录，不能替代所有者尚未确认的真机动态表情/语音验收，也不授权本轮写设备。
