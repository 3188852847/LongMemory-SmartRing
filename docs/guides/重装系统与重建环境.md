## 第三步：分别恢复小智和 CosyVoice

三个日用 Python 环境必须分开：LongMemory 用 3.12.13，小智与 CosyVoice 用 3.10.20。

```powershell

$voice = "D:\LongMemory-local\runtime\xiaozhi-esp32-server\main\xiaozhi-server"
uv venv "$voice\.venv" --python 3.10.20

uv pip check --python "$voice\.venv\Scripts\python.exe"

uv venv "$cosy\.venv" --python 3.10.20
uv pip install --python "$cosy\.venv\Scripts\python.exe" --index-url https://download.pytorch.org/whl/cu121 "torch==2.3.1+cu121" "torchaudio==2.3.1+cu121"
uv pip install --python "$cosy\.venv\Scripts\python.exe" -r "$meta\cosyvoice-pypi.txt"
```

CosyVoice 实际环境为 PyTorch 2.3.1+cu121、Transformers 4.51.3、ModelScope 1.20.0；

更不能合并两者的 torch。`cosyvoice-pypi.txt` 从完整版本表排除了单独安装的两个 CUDA 包。
历史 AuK 和备用 VoxCPM2 的环境快照也保存，但不在首轮恢复主链路的范围。

现有 Opus 原生 DLL 在小智 `native` 中随源码快照保留。FFmpeg 旧版为 9.0.1 essentials，
需用户从项目记录的发布来源重新安装到 `D:\LongMemory-local\tools\ffmpeg`，核对 ffmpeg/ffprobe。

## 第五步：数据与实机验收

1. 对恢复后的每个 SQLite 执行只读 `quick_check` 和外键检查；主库与聊天旁库一起恢复。
2. 先启动文字入口，查看已有记忆和角色设置；不要把合成验收数据写进个人库。
3. 网页旧聊天以 HttpOnly Cookie `longmemory_chat_owner` 关联归属。本包没有导出浏览器 Cookie，
   因此旧聊天正文保住了，但新浏览器未必显示旧会话；需要之后在所有者授权下做明确的归属迁移，不能删库“修复”。
4. 分别做 CosyVoice 固定合成句、本地 ASR、Opus 和模型调用检查，然后统一启动圆屏链路。
5. 核对新局域网 IP、校园网可达性、必要防火墙规则。旧 IP 不能直接沿用；启动器有显式同步入口。
6. 圆屏检查出声、自然插话、连续多轮和重启后的记忆召回。电脑重装不要求重刷已经可用的设备。
7. 当前固件 `build-relocated` 的五个烧录文件与地址说明另存，但其中的新路径构建尚未烧录。
   不要把保留镜像理解为自动刷机授权。需要开发固件时再安装 ESP-IDF v5.5.4 和工具链。
