## 启动设置与自动行为

| 项目 | 本次选择 | 生效范围 |
|---|---|---|
| 圆屏语音端口 | 18000 | 本项目 WebSocket；Docker 的 8000 保留 |
| 圆屏 OTA 端口 | 18003 | 本项目 HTTP/开机配置入口；Docker 的 8003 保留 |
| 自动跟踪电脑 IP | 已开启 | 已记录物理以太网身份，之后只跟踪同一网卡 |
| 网页/控制桥/壁纸/声音 | 原值 | 8767/8766/8768 及当前声音服务端口不迁移 |

旧偏好缺少新字段时仍默认 8000/8003、自动跟踪关闭；不会静默抢占旧端口。修改端口后须停止再启动；只改网页控制台端口不能改变圆屏端口。独立端口支持当前 pipeline 本地语音，豆包备用仍需原默认，兼容 Tk 不执行自动网络模式。

自动检测每 30 秒运行一次，不随聊天或记忆查询执行。首次没有已确认服务归属时只显示候选；点击“开启陪伴”后会重新核对网卡和端口，再备份同步本项目配置。唯一物理候选可自动纠正失效 IP；多网卡有歧义时，在停止状态输入圆屏可访问的物理网卡 IP，再开启。已选网卡断开时不会自动切到另一张卡。

运行中地址变化会先显示提示，等待稳定、设备断开和实际处理完成。网页关闭后尚未完成的任务、语音线程池/TTS 工作者、Runtime/网关活动均不能被当作空闲；无法确认就保留原服务，提示稍后手动停止并开启。能取得两个本机静默租约时，才停止本面板拥有的服务、重验地址、备份同步并重开。新面板无归属时不会在后台修改私有配置；已确认停止过自己服务后，可在停止状态自动同步。停止不确认或更新失败时停止自动重试，不自动改端口、回填旧 IP 或恢复数据库。

状态区显示的是电脑配置与受管服务事实，不能替代所有者设备反馈；本轮已通过范围见开头，不由电脑状态推断其他体验。网页会话若在受控重开后失效，请刷新陪伴空间。跨新会话长期记忆、来源和纠正待验收项继续保留，插话仅按本次可暂停反馈登记通过。

## 最小正式部署清单

仅由主会话审查、合入并交接精确 SHA 后执行，无需再向所有者重复询问普通部署许可：

1. 核对正式源码/候选构建、未知改动、当前本机物理网卡及 18000/18003、8766/8767/8768/声音端口。保存 Docker 原容器身份、端口映射和运行状态，只读核对，不停止或改动。
2. 核对正式启动器归属与当前活动，通知停止窗口；只停止并退出自己拥有的正式服务。取得当前人工 YAML、消费副本/摘要、启动偏好和正式前端产物的新检查点并核对备份摘要。数据与 Hy 原路径保持，不 create 新空间、不重放来源、不更改官方费用账本。
3. 设置本项目 `voice_ws_port=18000`、`voice_http_port=18003`、`network_auto=true`。重验唯一物理网卡，沿受控同步更新网络五字段和消费副本；保留校园/Hy/声音/角色/壁纸等选择。前端只复制本次已核对的候选构建，不安装或升级依赖。
4. 正式入口开启一次，核对实际新监听与自有进程、API/控制桥/声音身份、消费地址和 Hy 配置；不代发聊天或合成事实。Docker 原映射和服务继续保留。若监听或防火墙不通过，报告精确阻塞，不停 Docker、不自动写规则。
5. 将部署时真实电脑 IP 和完整 OTA URL 交给所有者，按下一节改目标圆屏，再由所有者自然唤醒确认连接、字幕和声音。本轮该范围已获反馈通过；另一设备按所有者最新决定取消额外实机验收要求，保留软件保护核验事实即可。

失败时保留当前配置、检查点和数据，暂停候选；回退只能在停止、归属和实际网络条件核对后进行。不能把含旧 IP/冲突端口的整份备份盲目覆盖，更不能覆盖新的记忆/来源或转回官方直连来“恢复”。

## 所有者在圆屏上改连接地址

只操作这台智慧圆屏，保留 Docker 的另一台设备。以下根据当前本地固件和配网页源码核对，实际入口以设备屏幕为准；助手没有读取或写入设备 NVS。

1. 电脑端本次正式部署已就绪，核验 LAN（局域网）IP 为 `192.168.120.4`。操作设备前再看面板当前检测值；若已变化，以下 URL 中替换为当时实际地址。
2. 让目标圆屏进入现有 Wi-Fi 配网模式。当前板型在上电后“启动中、尚未连上 Wi-Fi”时，轻触屏幕或短按 BOOT 可进入；已联网时普通点击只是聊天开关。以屏幕出现配网热点和网页地址为准，不长按恢复出厂、不清 Wi-Fi 或壁纸。若无法进入，停在这里反馈实际界面，不用烧录或串口改址代替。
3. 手机连接圆屏屏幕显示的配网热点，打开屏幕显示的网页地址。进入“高级选项 / Advanced”，找到“自定义 OTA URL / Custom OTA URL”。OTA 在这里是设备开机取得服务器配置的入口，本轮不更新固件。
4. 完整填写 `http://192.168.120.4:18003/xiaozhi/ota/`（按第 1 步替换实际 IP），保留结尾 `/`。不要填 Docker 的 8003、网页的 8767 或只填 WebSocket URL；其他选项保持原值。
5. 点击高级页保存，确认保存成功提示。此页源码只保存配置，不自动重启；然后正常重启这台圆屏，让它连接原 Wi-Fi，并从新 OTA 入口取得 `ws://192.168.120.4:18000/xiaozhi/v1/`。不用重填原 Wi-Fi 密码，除非设备所在网络本身已变；不操作另一台设备。
6. 在电脑设备页查看目标圆屏活动连接，再自然唤醒说一句普通短问，确认字幕和声音。仅有电脑 ready 或端口监听不能代替这一步。

当前没有可交付的稳定主机名：固件具备 `.local` 查询基础，但没有验证电脑发布、网段广播和设备解析的完整链路。不要把电脑名称或任意 `.local` 名称填进去。电脑 IP 将来再变时，电脑配置会按上述规则自动跟踪；圆屏的数字 OTA 地址仍可能需要重复本节改址。这是明确限制，不承诺一次配网永久免改。
