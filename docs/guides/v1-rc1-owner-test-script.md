# V1.0-RC1 所有者真机验收脚本

日期：2026-09-16。

## 当前进度

当前候选已经完成自动回归、隔离记忆 S-01～S-09、真实日用记忆 L-01～L-05，以及
圆屏播放中自然插话和中止后的下一轮回答。不要重新制造个人事实重复这些检查。

现在唯一缺少的固定实机路径是：创建一次性事项跟进、改到新时间、旧时间不播报、
新时间在圆屏实际播报。0012 圆屏持续连接问题按所有者决定在正常使用中观察，不单独
压测。固定路径通过后继续记录不同自然日的日用体验，最后再跑发布门禁。

## A. 现在执行：事项跟进创建、改时和播报

整个测试约 12 分钟。使用虚拟事项即可；它会进入 L0/L1 和主动交流审计，不要把它
误认为测试结束后可无痕删除。测试完成后可以正常删除 L1，但审计和原始证据按产品
规则保留。

### A-1 启动与设置

1. 从 `Start.cmd` 启动“文字＋圆屏”，选择 LongMemory、当前可用模型和 CosyVoice3。
2. 等启动面板显示控制台、圆屏语音和 CosyVoice3 均就绪，并确认圆屏已经连接。
3. 打开“设置中心 → 主动交流”。
4. 打开“允许主动联系”。“后台定时问候”可以保持关闭，它与本次一次性跟进无关。
5. 确认今天属于允许星期，当前时刻到 20 分钟后都位于允许时段内，临时勿扰已解除。
6. 为避免旧测试占用频率额度，把“每天最多次数”临时设为 20，把“最短间隔”设为
   0 小时，然后点击“保存主动交流设置”。测试结束后可以恢复自己的日用值。

通过标准：页面显示“主动联系许可：已开启”，没有“设置尚未保存”提示。

### A-2 生成两句可直接念的台词

在项目根目录运行：

```powershell
uv run --no-sync python scripts/development/v1_follow_up_test_script.py
```

工具只读取本机时间，不访问服务、模型或数据库。它会输出旧时刻、新时刻和两句完整
台词。不要自己把句子简化成“等会提醒我”；该模糊表达按设计不会建立跟进。
如果距离午夜不足约 12 分钟，工具会要求零点后重新运行，避免生成解析器不接受的
“凌晨零点几分”。

### A-3 创建跟进

对圆屏完整念出工具显示的“第一句”，例如：

> 我今天晚上八点零七分要检查虚拟项目发布记录，到时候问我检查结果。

通过标准：

- 圆屏明确回答已经安排到具体时间，不能再说“我不能主动开口”。
- 刷新“设置中心 → 主动交流 → 长期事项跟进候选”，能看到这条虚拟事项。
- 卡片显示“已启用”，计划时间等于工具输出的旧时刻，并存在一次性账本。

如果只显示“候选/未启用”，先不要手动补点“启用一次跟进”，把结果报告为失败；这能
保留自然对话自动安排链路的真实问题。

### A-4 修改时间

在创建成功后的 30 分钟内，对圆屏完整念出工具显示的“第二句”，例如：

> 请把时间改成晚上八点十二分。

通过标准：

- 圆屏明确回答已经改到新时间，不能只口头声称成功。
- 刷新跟进候选后，旧安排显示已取消，新安排显示已启用。
- 新安排保留相同事项和“检查结果？”追问，计划时间等于工具输出的新时刻。

### A-5 等待两个时刻

1. 在旧时刻前让圆屏保持联网、空闲，不要让它正在播放其他回答。
2. 到达旧时刻后等待约一分钟：圆屏**不应播报**旧安排。
3. 继续保持联网直到新时刻：圆屏应主动询问“检查结果？”或语义相同的话。
4. 亲耳听到后，在“最近运行记录”找到该次记录，确认来源计划时间是新时刻，再点击
   “确认已听到”。没有听到时不要点击。

最终通过必须同时满足：旧时刻未播报、新时刻只播报一次、页面记录对应新安排，并且
你亲耳听到圆屏声音。页面只有 `queued` 而没有声音不算通过。

### A-6 只需反馈这些结果

复制下面模板回复即可，不需要发送个人对话或数据库：

```text
A-1 设置：通过 / 失败
A-3 创建：通过 / 失败；页面状态：____
A-4 改时：通过 / 失败；旧安排：____；新安排：____
A-5 旧时刻：未播报 / 错误播报
A-5 新时刻：播报一次 / 未播报 / 重复播报
圆屏是否中途断连：是 / 否
其他现象：____
```

任一项失败时先停止测试，不要连续重建多个候选。我会依据失败阶段检查对应回执、账本
和脱敏运行状态，再决定是否需要你复测。

## B. 固定路径通过后的正常使用观察

正式 V1 定义仍要求 7 个不同实际使用日。这不是每天执行一套测试：正常使用即可，
只在自然发生时记录结果。当前已经完成的 L-01～L-05、S-01～S-09 和打断路径不需要
为了凑次数重做。

剩余观察总量为：至少 3 次完整停止后重启、3 次跨日召回、3 段圆屏连续回答，以及
持续连接是否再次卡在“连接中”。插话与一次性事项跟进已有固定路径证据后，只需留意
异常，不要求每日重复。

每天只回复一行即可：

```text
日期：____；完整重启：是/否；跨日记忆：通过/未触发/失败；连续回答：通过/未触发/失败；断连：无/有；其他问题：____
```

七个日期和最小次数满足、没有未解决阻塞缺陷后，由助手执行最终完整回归、版本号
`1.0.0`、README/Roadmap/CHANGELOG 收口和普通 Git 提交推送。Git 标签和正式发布仍
按项目约定另行授权。
