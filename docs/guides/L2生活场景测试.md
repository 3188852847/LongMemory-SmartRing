# L2 生活场景合成测试指南

本文用于体验 `/scenarios` 的 L2 人工候选、模型辅助草稿、来源追溯与复核流程。测试内容完全虚构，不需要填写真实个人信息。

## 测试目标

确认以下链路可用：

1. 多轮用户原话保存为 L0，并派生出可选择的 L1。
2. 多条相关 L1 可以组成一条待复核的 L2 生活场景。
3. L2 可以追溯到 L1 内容快照和对应的 L0 原话。
4. 无关事实不会因为时间接近就被人工加入同一场景。
5. 接受或拒绝只改变复核状态，不会立刻改变网页或圆屏回答。

## 开始前

1. 双击项目根目录的 `启动智慧圆屏.cmd`。
2. 使用带文字聊天的日常启动方式，并选择一个测试数据库或你明确允许写入的数据库。
3. 打开 React 控制台的“文字聊天”。
4. 确认“记忆管理”中的“生成新 L1”处于开启状态。

如果使用个人数据库，下面的虚构内容会作为 L0/L1 留在库中。若不希望混入个人数据，应先使用单独测试库。

## 第一部分：输入合成对话

下面四句话必须分成四轮依次发送，不要合并成一条消息。

第一轮：

```text
我这周五下午要进行毕业设计汇报。
```

第二轮：

```text
我这几天晚上都在修改毕业设计汇报的PPT。
```

第三轮：

```text
我准备在周四晚上完整演练一次汇报。
```

第四轮是故意加入的无关干扰项：

```text
我平时喜欢喝乌龙茶。
```

发送完成后进入“记忆管理”，检查是否形成了与上述陈述对应的活跃 L1。具体措辞可能因提取方式不同而变化；只要事实主体和含义正确即可。

如果相关 L1 少于两条，不要勉强创建 L2。先检查运行时是否暂停了 L1 写入，以及本轮是否显示提取失败或仅保存 L0。

## 第二部分：创建 L2 候选

1. 打开左侧“生活场景”，或访问 `/scenarios`。
2. 点击“新建 L2 候选”。
3. “待整理 L1”只表示该来源尚未进入待复核或已接受场景。可勾选“只显示待整理 L1”缩小列表，但不要把这个标记当作主题推荐。
4. 填写以下内容。

场景标题：

```text
准备毕业设计汇报
```

场景总结：

```text
用户本周正在准备周五下午的毕业设计汇报，这几天晚上主要在修改PPT，并计划周四晚上进行完整演练。
```

5. L1 来源只选择前三轮形成的相关记忆。
6. 不要选择“用户喜欢喝乌龙茶”一类记忆；它与汇报准备场景无关。
7. 点击“创建候选”。

若待整理来源较多，也可以直接点击左侧“从待整理 L1 推荐一个草稿”：

1. 页面会选取最新最多 20 条待整理 L1，并显示模型发送确认窗。
2. 点击“生成不落库草稿”后只调用一次学校模型；模型可以选择其中真正相关的子集，不要求使用全部来源。
3. 如果没有至少两条记忆能共同支持同一场景，模型应拒绝生成。页面出现失败提示时可以返回人工选择，不应反复点击碰运气。
4. 成功结果只填入新建候选表单。检查标题、摘要和来源，尤其确认无关偏好没有被合并；只有再点击“创建待复核候选”才会写库。

也可以在选择前三条 L1 后点击“用学校模型生成草稿”：

1. 先核对确认窗列出的发送数量和模型名称。
2. 点击“生成不落库草稿”。这一步会把所选 L1 内容发送到当前学校模型，最多调用一次且不自动重试。
3. 返回的标题、总结和来源只是表单草稿；数据库中此时仍没有新增 L2。
4. 检查模型是否排除了“喜欢喝乌龙茶”，必要时直接修改标题、总结或来源。
5. 最后点击“创建待复核候选”才会写入 `candidate`；仍需进入详情执行接受或拒绝。

若场景只在一段现实时间内成立，可在创建时填写“现实开始时间”和“现实结束时间”。例如“本周准备答辩”应尽量给出结束时间；留空表示这一侧没有已知边界，不代表系统会自动判断它何时结束。结束时间不能早于开始时间。

若按钮为灰色，通常表示当前不是使用兼容模型的日常启动方式，或选择的 L1 少于两条。此时仍可人工填写。

服务端还会检查：至少两条不同 L1、同一主体、覆盖至少两个不同的用户 L0。页面允许点击提交不代表一定满足服务端证据门槛。

## 第三部分：核对来源并复核

候选创建后，预期状态为“待复核”。打开详情并检查：

- 标题和总结与填写内容一致。
- 生成方式显示为人工控制台。
- 每条 L1 都显示创建候选时的内容快照。
- 展开“查看 L0 原话”后，能够看到对应的原始用户陈述。
- 来源中不包含“喜欢喝乌龙茶”。

确认无误后点击“接受”。状态应变为“已接受”，修订号增加。

“已接受”只表示通过人工复核，不会自动改变回答。若要体验使用效果，请到“记忆管理”→“本次运行的记忆模式”，另行开启“回答时使用已接受 L2”并应用到网页与圆屏。随后用与标题或摘要有明确关键词重叠的问题提问；聊天过程应显示“本轮使用 L2”。该开关默认关闭且重启后复位，候选、拒绝和 stale 场景永不进入回答。

如果现实中的场景已经结束，可在详情中点击“结束场景”，核对说明后再次确认。成功后状态显示为“已失效”，现实结束时间取本次操作时间，生命周期记录显示“用户手动结束”；原摘要、L1 快照和 L0 原话仍可查看。重复结束不会新增第二条事件。

## 第四部分：可选的来源失效测试

这一步会继续改变测试数据，首次体验可以先跳过。

1. 在“记忆管理”中找到“周五下午进行毕业设计汇报”的 L1。
2. 使用“纠正错误”或“记录变化”生成新事实，使旧 L1 退役。
3. 返回“生活场景”并刷新。

引用旧 L1 的候选或已接受场景应转为“已失效（stale）”。详情中的生命周期记录应说明是 L1 退役还是删除；历史摘要和来源快照继续保留，但不再具备以后参与召回的资格。

## 数据清理提醒

这些合成内容不是你的真实个人记忆。测试后若需要清理，先核对 L2 与 L1 的引用关系，不要直接删除整个数据库。当前控制台的拒绝操作只保留审计历史，不等同于物理删除；完整的跨层测试数据清理工具尚未实现。
