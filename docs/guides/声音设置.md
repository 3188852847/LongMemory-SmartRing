# 声音设置

当前有两层入口：统一启动面板负责真正启动和停止 EdgeTTS、VoxCPM2、sanoTTS 与 CosyVoice3；React 设置中心既能保存“下次启动使用哪个后端”，也负责当前后端的试听与已接通参数。不要把保存成功理解为运行中的语音已经热切换。

## 选择下次圆屏声音

1. 打开“设置中心 → 声音 → 圆屏声音后端”。
2. 在 EdgeTTS、VoxCPM2、sanoTTS、CosyVoice3 中选择一个，点击“保存下次启动选择”。这一步只写入非敏感后端指针，不启动模型、不占用显存，也不打断当前回答。
3. 如果页面提示“等待重启生效”，回到统一启动面板停止服务，再重新启动。面板会在启动瞬间读取网页选择，无需关闭并重开面板。
4. 启动器会按既有规则检查本地服务、同步小智私有配置并等待就绪。网页显示“已保存”不代表外部目录、模型或网络一定可用。
5. 若你在启动面板中又亲自修改了声音下拉框，本次以面板的明确选择为准，并同步回网页指针。

此入口不修改 Edge 音色、VoxCPM2 参考声音、sanoTTS 语速、扬声器音量或拾音灵敏度；这些设置仍在各自区域单独管理。设计边界见 [ADR-0121](../adr/0121-react-next-start-tts-backend.md)。

聊天回答旁点击“网页朗读”并成功取得音频后，页面会显示“最近一次网页合成等待”。它从浏览器发出请求开始，到完整音频返回为止，包含本机接口与 TTS 合成，适合同一电脑和网络下用相同文本比较方案；它不是纯模型推理时间，也不是圆屏从说完话到播出首句的时间。

圆屏语音另有一条更贴近真实链路的分阶段计时。重启统一服务后，让圆屏完成一轮真实对话，再打开“设备与状态”；页面会显示最近一次真正发出音频的回答所经历的记忆准备、模型首个有效输出、首句组织、TTS 生成与编码、首包发送及总等待。紧随其后的空识别或心跳不会覆盖该样本。它只保留当前连接内存中的相对毫秒数，不保存问题、回答、记忆、音频或设备标识。计时起点已经晚于录音和 ASR，终点是服务端发送首包返回，也不能冒充圆屏扬声器实际出声时间。

比较 EdgeTTS、VoxCPM2 与 sanoTTS 时，应尽量使用相同问题、相同模型与相近网络条件，各自完成一轮后查看设备页。先观察“模型首个有效输出”和“TTS 生成与编码”哪个占主要等待，再决定优化模型链路还是语音链路；不要把网页朗读等待和圆屏首句时序直接横向比较。

## EdgeTTS 标准音色

1. 用启动面板停止旧服务并重新启动控制台。
2. 打开“设置中心 → 声音”（例如 http://127.0.0.1:8767/settings），点击“声音设置”。原生 `/chat` 回退页没有此功能。
3. 选择音色：Xiaoxiao（晓晓）、Xiaoyi（晓伊）、Yunxi（云希）、Yunjian（云健）。
4. 点击“联网生成试听”，完成后点击播放器播放。只发送界面显示的固定文本，不发送聊天、角色或记忆；不自动播放，不保存音频文件。
5. 点击“保存音色”并确认，只修改小智音色，不改角色、记忆或扬声器音量。
6. 停止并重新启动小智，让圆屏重新连接后体验。配置保存成功不代表运行中的服务已经加载。

## 限制与排障

- 复用小智现有 Edge TTS，无新增依赖。它是联网服务而非本地模型，见 [edge-tts 说明](https://github.com/rany2/edge-tts)。四个音色于 2026-09-04 通过公共列表核实，未来可用性可能变化。
- 试听使用默认语速、音调与音量，圆屏已有参数和扬声器不同，听感可能不同。
- React 页面可识别四个已接入后端；只有 EdgeTTS 开放标准音色修改，VoxCPM2 开放受控声音方案，sanoTTS 开放语速。CosyVoice3 第一版只开放状态、网页朗读和固定测试台。它不会用一个后端的参数修改另一个后端。
- 其他页面修改配置后，旧版本保存会失败；“重新读取配置”再选择，不自动重试。重新读取会丢弃未保存选择。
- 受管实例配置在 `local/config/xiaozhi.yaml`，备份在 `local/archive/config-backups/` 中，使用 `xiaozhi.yaml.role-*.bak` 命名，共享角色同步锁；显式其他小智实例仍在其 `data` 中备份。备份包含私有配置，不上传、不提交 Git。
- 试听单次最长约 30 秒、最多 2 MiB、间隔至少 3 秒；网络失败不影响文字聊天。
- 不需刷固件，不含声线训练、网页聊天自动朗读或语速调整。VoxCPM2 受控参考音频属于下方独立本机方案，不由 EdgeTTS 页面处理。

合成配置、权限、备份、冲突及音频边界已测试；真实试听与圆屏生效待用户验收。

## VoxCPM2 本地声音

从 `启动智慧圆屏.cmd` 的“圆屏声音”选择 `VoxCPM2（本地 plain）`，先点“检查并同步”，再按普通语音模式启动。模型服务与小智均由同一面板托管；停止后释放显存。完整步骤、资源成本和 Edge 回退见 [VoxCPM2 指南](VoxCPM2独立试听.md)。

模型就绪后打开“设置中心 → 声音 → 声音设置”：

1. “参考音色”选择模型默认声线，或 `data/audio/` 下已经存在的受控 WAV。参考 WAV 才是改变说话人音色的主要参数。
2. “表达指令”填写语气、情绪和速度倾向，例如“年轻女性，声音温柔明亮，语速自然，带着微笑”。这不是事实记忆或助手角色提示词。
3. “指令强度”范围 1–3；越高不保证越自然，建议从 2.0 开始。
4. “生成质量”可选快速 6 步、均衡 10 步、细致 20 步；步数越高通常越慢，不等于音色变化。
5. 保存后网页和圆屏的下一次 VoxCPM2 合成读取同一方案，不需要重启。声音配置和参考音频被 Git 忽略。

VoxCPM2 当前是整句非流式适配：必须先生成完整 WAV，再由 Xiaozhi 重采样、编码并发给圆屏。因此“快速/均衡/细致”主要改变整句生成等待，不能把它变成边生成边播放。2026-09-10 的真实链路记录中，均衡档一段 18 字首句约占 11 秒 TTS 等待；切到快速档后，本机独立测得 13 字和 18 字正常波形分别约 3.57 秒、4.74 秒。数据只代表当时模型、参考音色和本机负载，不是固定性能承诺。

适配服务会在写入 WAV 前抽样检查时长、RMS 与峰值，拒绝 VoxCPM2 偶发产生的“有时长但近乎全静音”结果，并换种子重试一次。单段生成上限同步收紧，避免异常静音长期占住圆屏播放队列。该检查是故障门，不是听感评分；真正降低首声延迟仍需要后续专用流式 TTS 提供器。

网页聊天中，每条助手回答都有“网页朗读”和“停止”。同一时间只播放一条：从另一条回答或声音设置开始新朗读时，会先停止旧朗读并释放旧麦克风、AudioContext 和临时音频 URL。开启“说话打断”会请求麦克风权限，只在浏览器本地检测连续讲话能量，录音不会上传或保存。扬声器回声仍可能误触发，因此这是测试入口，不是最终全双工算法。

当前使用受控参考 WAV，不提供任意路径或浏览器直接上传声线；本机 HTTP 合成和圆屏完整播放已验证。自然说话打断已可触发，但整句非流式首声延迟仍是已知限制。该增量决定见 [ADR-0025](../adr/0025-local-voxcpm2-tts-adapter.md)，它扩展了 ADR-0024 当时“先复用 Edge”的阶段边界。

## sanoTTS 本地中文小雅

1. 从 `启动智慧圆屏.cmd` 的“高级设置 → 圆屏声音”选择 `sanoTTS（本地中文小雅）`。
2. 核对“sanoTTS 外部目录”为 `D:\LongMemory-local\runtime\sanoTTS`，其中应保留上游 `web/` 目录结构。
3. 正常启动。面板会先校验固定文件组合指纹，再在 `127.0.0.1:18769` 启动 Node/WASM 服务，随后启动小智；无需另开终端。
4. 进入“设置中心 → 声音”，应看到 sanoTTS 配置匹配和服务已就绪。可直接用网页朗读或下方 TTS 测试台运行固定文本。
5. 当前只有 `xiaoya` 音色。控制台“声音设置”可在 0.75–1.5 倍之间调整语速并安全保存；网页朗读立即读取新值，已经运行的小智仍使用启动时配置，因此圆屏需要停止并重新启动语音服务后生效。
6. 保存只改写小智私有 YAML 中 `CustomTTS.params.speed` 一个标量，写入前校验摘要并保留 `.tts-*.bak`。它不修改模型、角色、记忆、扬声器音量或其他 TTS 后端。

当前仍需整段 WAV 完成后才能播放。提高语速会缩短朗读时长，但不是模型流式化，也不保证同比缩短合成等待。

项目不会复制或上传外部运行时与模型。更换上游文件后若指纹不一致，服务会明确拒绝启动；需要先重新审查许可、功能和回归，不能通过关闭校验静默升级。见 [ADR-0118](../adr/0118-external-sanotts-node-wasm-adapter.md)。

## CosyVoice3 本地高质量声音

1. 从“设置中心 → 声音”把下次后端保存为 `CosyVoice3`，或在 `启动智慧圆屏.cmd` 高级设置中直接选择它。
2. 停止当前服务并重新统一启动。面板会使用 `D:\LongMemory-local\runtime\CosyVoice\.venv`，在 `127.0.0.1:18770` 加载并预热模型，并启动 Xiaozhi；当前进程启动顺序没有等待 TTS ready 的屏障，应等面板检查整套服务就绪后再对话。
3. 打开声音页核对“CosyVoice3 已就绪”，可先运行固定测试台或网页朗读；随后再用圆屏完成真实对话验收。
4. 若外部源码、环境或 `pretrained_models\Fun-CosyVoice3-0.5B` 缺失，启动会明确失败，不会悄悄换成 Edge 掩盖问题。
5. 要回退时把下次后端改为 EdgeTTS，停止并重新启动。切换不修改记忆、角色或模型配置。

当前固定使用官方零样本参考声音，暂不开放上传参考音频、风格、语速或任意路径。网页试听和兼容回退仍使用完整 WAV；圆屏在固定 CosyVoice3 地址下使用本机专用长度前缀 WAV 通道，收齐自然标点片段后连续编码为 Opus；当前服务默认直接完整生成这个片段，避免内部重复分块计算。用户已确认声音质量、连续性和播放期间自然插话，但 2026-09-14 的日用反馈确认首声仍偏慢，因此此前“速度达到日用门槛”的结论已撤回。修改前热态 8～12 字相近短句约 1.83～2.30 秒才取得第一个模型音频块，且只有一个块；新实现把固定参考提示改为启动期预计算，并在每次请求前恢复模型原始 25-token 流式步长。修改后的隔离服务中，6～10 字短句首块约 1.24～1.29 秒；先生成 34 字长句后，紧接的 8 字短句仍约 1.14 秒。该结果不含回答模型和圆屏链路，须在统一启动后重新做实机验收。取消只在模型下一次产出时观察到连接关闭，因此仍是协作式取消，不宣称即时 GPU 抢占。历史脱敏样本中的入口到首包约 3.81 秒只用于定位等待分布，不是当前性能承诺。见 [ADR-0123](../adr/0123-isolated-cosyvoice3-buffered-adapter.md)、[ADR-0126](../adr/0126-cosyvoice3-loopback-streaming-bridge.md)与 [ADR-0157](../adr/0157-cosyvoice3-reference-cache-and-stream-reset.md)。

## 拾音环境与旁人误触发

有两个等价入口：启动面板“高级设置 → 圆屏声音 → 拾音环境”，以及 React “设置中心 → 声音 → 拾音灵敏度”。两处共用三档 SileroVAD（语音活动检测）配置：

- 普通环境：`threshold=0.50`、`threshold_low=0.30`，保持原有灵敏度。
- 嘈杂环境：`0.70/0.45`，优先过滤较远、较小的旁人声音，是当前本机日常选择。
- 近讲严格：`0.82/0.55`，需要靠近圆屏说话，轻声或较远说话可能漏检。

启动面板会在下次统一启动前核对它的选择；React 页面在你点击“保存拾音档位”时直接保存。两者都只替换小智私有配置中的起声阈值、回落阈值和停句静默时间；写入前校验配置摘要并保留 `.vad-*.bak`，不修改 ASR、麦克风增益、AEC、模型或记忆。运行中的 SileroVAD 不热加载配置，因此切换后必须停止并重新启动圆屏语音。

VAD 只判断音频“像不像人声”，不能判断说话者身份。提高门槛能够减少远处人声和部分环境声误触发，但无法可靠屏蔽近距离或很响的其他人；真正的“只听主人”需要后续增加声纹确认、唤醒词/按键门控或硬件方向性拾音，不能把调阈值冒充为说话人识别。


### 2026-09-14 运行优化如何生效

保留 CosyVoice3，在启动面板停止当前服务后重新启动，即可加载完整片段生成和未使用文本输出层优化。没有更换模型、参考声线、精度或安装新依赖。新进程固定测试合成耗时约降低 17%，短句首个 Opus 约 1.35～1.44 秒；这不包含听写与回答模型等待，也不是圆屏扬声器实测。

用户已确认体验改善，但第一小句后仍有停顿。后续修复已让回答结束时的余文继续遵循自然标点分段；这还不能保证消除停顿。2026-09-15 同进程可逆实验进一步确认 Windows 调度偏好可修复额外慢态，详见下方说明。重启后用普通问题连续对话，并试一次打断后继续说话；观察设备页 V6 数据和实际声音。阻塞中的 HTTP 读取和 GPU 仍不能即时中止，过期音频会被丢弃。

隔离服务的 `--model-streaming --no-hidden-only` 两个参数可恢复原模型运行方式；健康检查中的 `runtime.model_streaming`、`runtime.hidden_only` 和源码指纹可确认实际加载版本。详见[运行优化实测与复现](../research/cosyvoice-runtime-optimization-2026-09-14.md)。

排障时可读取本机 `http://127.0.0.1:18770/health` 的 `diagnostics`，比较一次固定合成前后
`llm_job`、`flow`、`hift`、`text_normalize` 各项的 `calls` 和 `wall_ms` 差值。
这些分别表示语音 token 生成、声学特征生成、波形生成和文本整理方法的墙钟耗时；
计数包含暖机，且阶段可能重叠，不能直接相加或当作纯 GPU 用时。
数据只存在当前声音进程内存中，不含对话内容；多个请求混入时不能当作单次结果。
健康检查本身不发起合成。新的离线保护只使用本机已有 WeText 文件，不会补下载缺失资源。
详见[首段衔接问题记录](../adr/0167-cosyvoice-first-segment-handoff.md)。

### 2026-09-15 第一小句后的衔接

下次从原启动面板启动即可加载本次修复。系统会把很短的“好的，”等开头与后文合并，
避免抢先说几个字又等待较长第二段；已有完整短句的首声尽量保持。已经到齐的后续文字
会及时合成，固定寒暄也恢复整句预置命中。模型、声线和设置保持不变。

固定测试的句间供给空档已消除，但短开头首声通常会晚约 1 秒；真实圆屏仍需听感确认。
如果再次出现长停顿，保留设备页该轮 V6 和本机 TTS health 的阶段数据即可，不必提供
个人记忆或整份私密日志。详见[衔接修复与实测](../research/cosyvoice-short-opening-2026-09-15.md)。

### 2026-09-15 日用后台速度修复

继续保留 CosyVoice3。服务下次启动时自动为自己的进程申请 Windows HighQoS，
让系统明确按需要及时完成的声音任务调度；不修改整台电脑的电源计划。固定数字句
的同进程反复切换中，生成从约 5.8 秒降到 2.2～2.4 秒。模型、声线和分句不变，
合成期间功耗可能增加；这不代表停嘴到出声已经只有 2 秒。

`/health` 中 `runtime.windows_qos.applied=true` 表示服务启动时已回读确认。
该字段是启动快照；旧进程不会因文件更新自动获得新字段。若 API 不支持或设置失败，
服务仍可运行，`reason` 会给出固定原因码。隔离命令增加 `--system-qos` 可跳过
显式设置、恢复系统默认调度作对照；只改一次进程，不写入模型或个人设置。
真实圆屏继续检验首声、句间长停顿、自然度及打断。见[调度实测](../research/cosyvoice-windows-qos-2026-09-15.md)。
