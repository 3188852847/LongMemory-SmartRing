# 统一启动：不用自己开两个终端

更新：2026-09-04。P1 的最小启动入口，不是整个 P1 已完成。

## 第一次使用

1. 如果之前手动启动过控制台或小智，先在对应终端按 `Ctrl+C` 停止。启动器不会接管或关闭这些外部进程。
2. 在资源管理器中打开项目根目录，双击 **`Start.cmd`**。出现“LongMemory · 日常启动”面板；不要求管理员权限。
3. 默认只启动文字聊天。要同时使用圆屏，勾选“同时启动圆屏语音”。
4. 核对日常数据库。默认沿用 `data/databases/xiaozhi-demo-v1.db`；必须是已有文件，不要填一个新名字期待自动建库。
5. 语音模式额外核对小智目录与电脑局域网 IP。面板自动发现本机 RFC1918 地址；唯一地址自动选中，多网卡需要选择。地址变化时点击“同步小智地址”，确认后仅更新小智三个网络字段并在原私有目录保存 `.bak` 备份。防火墙和圆屏仍按下面说明处理，不会自动修改。
6. 网页角色选择 `elysia_v1` 或 `plain_v1`。这个设置不改变小智自己的角色。
7. 圆屏模式可选择 `EdgeTTS（联网标准音色）` 或 `VoxCPM2（本地 plain）`。选择与小智磁盘配置不一致时，点击“检查并同步”并确认；普通启动不会暗中切换。VoxCPM2 由本面板一起启动和停止，关闭后释放显存。
8. 选择长期记忆提取策略。`规则提取（稳定基线）` 是默认旧行为；`模型辅助（P3.2 试用）` 会对非问句用户陈述增加一次校园模型候选请求。它先保存 L0，提取失败时仍可回答并在 React 页面提示 L1 失败，不会暗中切回规则。
9. 选择长期记忆召回策略。`关键词召回（稳定基线）` 是默认旧行为；`关键词＋BGE（P3.2 试用）` 使用面板所示的本地固定模型快照，在 CPU 内存中融合关键词与语义排名。它不联网下载模型、不改数据库；BGE 失败会在 React 页面提示本轮已回退关键词。语义相似不等于事实可信，也不保证未知问题零召回。
10. 需要删除某一条 L1 时，可在启动前勾选“允许 L1 单条删除”。默认关闭；开启后仍需在记忆详情二次确认。它保留 L0 原话、备份和日志，不等于彻底遗忘。不需要时不要勾选。
11. P3.1 起，面板会给控制台和小智注入同一个临时 Runtime 身份。无需填写令牌：它只存在于本次受管进程环境中。网页和圆屏共用同一个记忆引擎、提取/召回策略与数据库，但短期聊天记录仍各自独立。
12. 阅读并勾选聊天写入/明文 HTTP 风险提示，然后点“启动”。当前学校接口只建议用于已确认风险的非敏感合成体验。
13. 控制台实例就绪后自动打开 React 版 `http://127.0.0.1:8767/chat-react`；“打开控制台”按钮也进入该地址。原版 `/chat` 保留回退，并提供进入 React 新版的链接。VoxCPM2 模式还需等待状态文字显示模型与语音进程运行中。

校园模型由你连接校园网后实际聊天验证。启动不测试模型，不把“控制台已就绪”当作“模型可用”。语音进程运行不等于圆屏在线，可在网页设备页核对；待机可能无活动连接。

启动完成后，在 React 聊天页点击“声音设置”可以只读核对当前后端。VoxCPM2 模式应显示 `VoxCPM2 · plain`、配置匹配且本机模型服务已就绪；这仍不代替圆屏实际播放与听感验收。切换后端继续使用启动面板，不在网页里暗中改配置。

## 怎样停止、重新启动

- 保留启动面板，关闭浏览器不会停止服务。
- 结束聊天后点击“停止服务”，确认后结束本面板创建的整棵进程树，包括 uv 和小智后代进程。
- **这是进程终止，不是等待所有聊天请求优雅完成。** 正在生成的回答/音频会中断，当前轮可能已写入用户消息或记忆，不能直接认定没有发生写入。
- 关闭启动面板会询问并停止受管服务。异常退出时 Windows Job 也会清理其子进程；不删除数据库。
- 停止后可修改模式再启动。Windows 可能短暂尚未释放端口，提示占用时稍候再试，不要批量杀 Python。
- 同步成功的 IP 保存在忽略提交的 `data/control/launcher.json`，其他选项仅本次有效；没有开机自启、托盘常驻或跨面板接管。

## 默认没有开启的功能

- 管理页 L1 单条删除默认关闭；需要时在启动面板显式勾选，聊天本身仍会按所选策略写入。
- 新实验作业（仍可看报告，运行实验请用原终端指南）。
- 自动切换语义检索或历史 L0 自动重处理、声音克隆/训练、主动交流。混合召回只能由面板显式选择。
- 静默配置同步、数据库迁移。网页会话列表恢复已支持，见[聊天会话](聊天会话.md)。

当前核对语音模式下 LongMemory 的数据库、项目、解释器路径与本面板一致，并核对所选 TTS 后端；不自动同步两端的学校模型或角色。

## 电脑 IP 变化后的操作

### 推荐：面板操作，不需要终端

点击主面板“网络与防火墙”。圆屏已能正常聊天时无需添加规则。

1. “检查监听与规则”只检查电脑侧；规则不存在不等于连接被拦截，可能已有其他规则放行。权限不足显示未知。
2. 确需放行时，先启动小智，再填写圆屏单个 IP（优先）或已确认来源网段，例如此前的 `192.168.120.0/21`，点击“添加圆屏放行规则”。来源不默认填写，避免猜测范围。
3. 确认范围后，在 Windows 管理员授权窗口同意。只有规则助手提权，整个启动面板不提权。取消会明确提示未确认修改。
4. 操作结束重新检查。已有规则不覆盖；地址不匹配时，核对后点击“撤销本项目规则”，再按新地址添加。撤销可能影响圆屏连接，但不影响其他应用规则。
5. 监听正常/规则存在不代表圆屏已连上，仍到控制台设备页确认。

下方终端命令仅作为排障备用，并非日常必做步骤。

1. 停止旧服务，关闭旧启动面板，重新双击 `Start.cmd` 加载新版。
2. 点击“刷新地址”，选择圆屏能访问的有线网卡地址，点击“同步小智地址”。确认前确保外部终端小智也已停止；同步不会强制停止它。
3. 勾选圆屏语音与风险确认，点击启动。
4. 若项目防火墙规则不存在，在**管理员 PowerShell**执行（下例为 2026-09-04 已核实地址；之后变化请替换）：

```powershell
& "D:\02-项目\LongMemory-SmartRing\scripts\development\xiaozhi\firewall.ps1" -Action Allow -ListenAddress 192.168.124.93 -RemoteSubnet "192.168.120.0/21"
```

规则只开放小智实际监听程序的 8000/8003，限定当前地址和原校园来源网段。提示规则已存在时，不要重复新增；先检查旧规则，再按原指南显式撤销并重建。不要关闭系统防火墙。

5. 在圆屏配网页把 OTA 地址改为 `http://192.168.124.93:8003/xiaozhi/ota/`，保留原 Wi-Fi 信息并保存；不重新烧录、不清空记忆库。进入配网页方式沿用当前厂商 B_V2 固件说明，不假定所有固件按键相同。
6. 唤醒圆屏，在控制台设备页确认在线，再进行一句合成对话。电脑侧配置同步成功不等于圆屏已重连。

已定位故障：旧地址 `.45` 已不在本机网卡上，绑定失败；当前为 `.93`。新版区分 IP 不存在、端口占用及系统拒绝绑定，不再统一归因为“旧服务”。备份含原配置凭据，不要上传或分享。

## 常见问题

### 更新代码后语音仍走旧的逐轮子进程

项目模板不会静默覆盖小智目录中的代码副本。停止服务后，在项目根目录执行一次：

```powershell
& "D:\ESP32-Workspace\xiaozhi-esp32-server\main\xiaozhi-server\.venv\Scripts\python.exe" `
  "D:\02-项目\LongMemory-SmartRing\scripts\development\xiaozhi\setup.py" update-memory
```

该操作只会把已知的旧版 LongMemory 提供器升级为仓库版本；不会修改 `.config.yaml`、数据库、角色、声音或固件。检测到陌生/手改内容时会拒绝覆盖。升级后重新打开启动面板并启动服务。

若手动绕过面板运行 `setup.py start`，适配器会继续使用旧 `subprocess` 回退。这种模式没有共享常驻 Runtime，只用于排障和兼容。

2026-09-04 已修复：`console（退出码 2）` 的一次实际原因是 uv 对反斜杠/空格绝对 `.env` 参数的解析，导致环境文件找不到。新版在明确项目工作目录中使用相对 `.env`；更新代码后必须关闭旧面板并重新打开。退出码 2 也可能来自其他参数/配置错误，不能一概归因。小智未启动时运行防火墙 Allow 会提示无监听，应先解决启动错误。

| 提示或现象 | 处理方式 |
|---|---|
| 面板已打开 / 18767 被占用 | 找原启动面板；18767 仅作本机单实例锁，不提供管理 API，不修改防火墙 |
| 8767 无法绑定 | 停止之前手动启动的控制台；不自动改端口或接管未知服务 |
| 8000 / 8003 / 8766 不可绑定 | 检查 IP 或是否有旧小智；不是重新烧录的理由 |
| 缺少 `.env`、数据库、uv 或 Python | 按原使用说明准备已有环境；本工具不安装、不自动建库 |
| `console` 退出 | 常见为已有库版本、依赖、模型配置或角色资源无效；按原指南在终端启动查看脱敏提示 |
| 选择 BGE 后 `console` 退出 | 检查 `semantic` 可选依赖是否已安装、快照目录是否仍完整；启动器离线运行，不会替你下载或修复模型 |
| `voice` 退出码 3 | 私有配置无效、未启用 LongMemory，或数据库/项目/解释器路径不一致；不覆盖配置，核对后再试 |
| `voice` 退出码 4 | VoxCPM2 在 90 秒内未就绪；检查独立环境、模型权重、CUDA 与 18768 端口，不要反复启动多份模型 |
| `voxcpm2` 退出 | 固定权重校验、CUDA、模型加载或本机端口失败；不会自动退回 Edge，需明确切回后重启 |
| 18768 提示占用 | 新版只在存在真实监听者时拦截；旧版可能把刚停止后的 `TIME_WAIT` 误判为占用，请关闭旧面板并重新打开最新版 |
| `voice` 其他退出码 | 检查原小智启动命令和 `check-config` 的本地检查；可能缺模型文件、FFmpeg、提供器或端口冲突 |
| 控制台 90 秒未就绪 | 面板停止受管服务；按原指南核对，不继续反复拉起进程 |
| 网页开了但回答失败 | 模型/网络尚未通过验证，控制台启动成功不代表校园模型可达 |
| 双击没有窗口 | 先确认 `.venv/Scripts/pythonw.exe` 存在；必要时用下面命令查看面板自身错误 |

仅在排障时，在项目根目录 PowerShell 执行：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing"
.\.venv\Scripts\python.exe scripts/development/launcher/app.py
```

面板不额外保存原始服务 stdout/stderr，避免复制识别文本或配置；上游已有日志行为不因此改变。原终端操作完整保留在[使用说明](使用说明.md)。
