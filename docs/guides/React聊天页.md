# React 控制台体验与构建

## 现在怎么打开

这次已在本机完成构建。统一启动面板现在默认打开 `/chat-react`，“打开控制台”按钮也进入 React 版，无需再手动修改网址。例如控制台在 8767 时地址为 `http://127.0.0.1:8767/chat-react`。

不用另开终端或启动 Vite。左侧导航已经按“日常使用 / 长期记忆 / 控制与观察”分组；底部“兼容入口”可展开原版页面，供迁移故障时回退。新旧页面使用同一聊天和记忆数据库，发送真实消息也会真实保存；它不是隔离实验沙盒。不要同时在两个页面发送同一会话。

可以依次体验：新建聊天 → 输入合成内容 → 展开本轮证据 → 刷新恢复 → 搜索/置顶/重命名/切换 → 主题、字号与动画。会话搜索只匹配名称，不读取正文；置顶只在当前浏览器保存会话 ID，不改变服务端或长期记忆。输入框默认 Enter 发送、Shift+Enter 换行；下方可切换为 Ctrl+Enter 发送、Enter 换行。该偏好只保存在当前浏览器，中文输入法仍在组词时不会误发送。请求结果未知时只点击“查询结果”，不重复提交。当前仍是原来的规则记忆方法，迁移不提升记忆智能程度。

记忆管理已迁移到 React，入口仍是 `/memories`。页面分为 **L1 原子记忆**和 **L0 原始记录**：L1 可以向下查看原始来源，L0 可以向上查看由它派生的 L1；“未形成 L1”不是丢失，表示原话存在但没有成为可召回事实。旧原生页面临时保留在 `/memories-legacy`。

L2 生活场景位于 `/scenarios`。这里可以浏览、核对来源并显式创建、接受或拒绝候选；已接受场景还可显式结束并查看生命周期事件。接受后仍不会自动影响回答；需在“记忆管理”的运行期模式中另行开启 L2 使用。开启后网页与圆屏只召回当前有效、与问题有关键词重叠的已接受场景，最多 3 条，聊天过程单独显示 L2 标题。首次体验可直接照着 [L2 生活场景合成测试指南](L2生活场景测试.md) 操作。

设备与状态已迁移到 `/device`：自动轮询的是连接状态；设备快照、音量、亮度和明暗主题都只在点击后读取或写入，失败不会自动重试。快照可显示固件实际返回的电量/充电、信号和温度，并删除 SSID。按钮是否可用取决于当前圆屏实时上报的工具，不根据旧源码猜测。页面同时显示握手是否上报 AEC；这是自由说话打断的必要基础之一，不等于打断链路已经通过实机验收。

圆屏状态预览位于 `/display-preview`，也可从左侧“圆屏预览”进入。这里可以切换交互阶段、情绪表达和系统覆盖状态，并显示中央安全区；所有变化只发生在浏览器，不会控制或写入真实圆屏。其用途是先核对状态是否一眼可辨，再决定固件实现，详见[圆屏状态协议](../architecture/round-display-state-protocol.md)。

设置中心位于 `/settings`：模型与服务、助手角色、声音、外观与阅读、主动交流分别放在独立标签页中，并不是一个统一配置事务。模型页显示当前进程实际使用的模型与无凭据地址，可手动发送固定合成短句检测；修改 `.env` 后仍须重启服务。切换标签不会保存或修改设置；角色保存后用于网页下一轮，圆屏需在角色弹窗中单独预检/同步；声音按页面提示决定是否需要重启小智；主题、字号和动画偏好只影响当前浏览器。L3 用户画像不在此页编辑。

实验中心位于 `/experiments-react`，可选择冻结检索档案、预检预算、明确确认后运行回答对照、查看/停止任务、搜索档案、核对逐题证据并另存人工复核。预检不调用模型；真实模型确认会显示请求上限和网络风险；活动任务只用 GET 刷新进度。复核不会改原报告或自动初筛，响应未知时只刷新核对。原版 `/experiments` 暂留回退。

隔离 Fake 环境的真实 Chromium 验收已经覆盖发送/刷新恢复和统一导航；它不替代个人数据库、真实模型、声音、圆屏或视觉体验验收。遇到空白页、弹窗或下拉异常，先返回原版并提供现象；不要关闭安全策略解决。

## 换电脑或源码更新后怎么构建

开发环境需要 Node（本次 24.19.0）和 pnpm（本次 11.19.0）。安装阶段会下载前端依赖，不调用模型；日常运行不下载。项目不会自动修改全局 PATH 或安装 Node。

已经配置 Node/pnpm 的 PowerShell：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing\web\react-chat"
pnpm install --frozen-lockfile
pnpm test
if ($LASTEXITCODE -ne 0) { throw "前端测试失败，请勿继续构建" }
pnpm build
if ($LASTEXITCODE -ne 0) { throw "类型检查或构建失败" }
```

需要运行真实浏览器关键路径时，在同一目录执行：

```powershell
pnpm test:e2e
if ($LASTEXITCODE -ne 0) { throw "Playwright 浏览器验收失败，请查看 test-results" }
```

该命令会先构建生产资源，再自动启动 `127.0.0.1:18777` 的临时 Fake 控制台。它创建临时 SQLite，不读 `.env`、个人数据库、校园模型或圆屏。通过时终端显示 `3 passed`；其中包含桌面关键路径、只读实验流程和窄屏无页面横向溢出检查。失败截图和 trace 位于 `web/react-chat/test-results/`，HTML 报告位于 `web/react-chat/playwright-report/`，二者都被 Git 忽略。若提示浏览器不存在，只安装与锁定版本配套的 Chromium：`pnpm exec playwright install chromium`；这一步需要联网。

助手当前使用的随附 pnpm 不代表用户终端已有 `pnpm` 命令。若提示找不到命令，先核对开发工具路径，不重新安装 Python 或删除项目。

构建输出在 `web/react-chat/dist/`，不提交 Git；依赖锁文件提交，个人数据库不提交。出现 503 表示缺少或无效构建；出现 404 通常先检查是否仍运行旧控制台进程。旧版入口不依赖这些产物。

## 目录用途

- `web/react-chat/src/`：React 页面、接口封装、局部样式和接口测试。
- `web/react-chat/e2e/`：Playwright 真实浏览器关键路径，只连接隔离 Fake 控制台。
- `web/react-chat/playwright.config.ts`：浏览器、临时服务、trace 和报告设置。
- `web/react-chat/dist/`：生成的生产页面与资源，不手写。
- `web/react-chat/node_modules/`：包管理器安装的开发依赖，不手写。

当前共享 antd/AppShell 块约 473 kB、聊天入口约 187 kB、设备页约 78 kB、记忆页约 84 kB（均为未压缩构建输出）；设备与记忆代码按路由动态加载。构建器仍对共享块给出体积提醒但无构建错误，之后根据真实加载体验决定是否做更细的依赖分块。最新验证数量见 CHANGELOG；自动测试不代表浏览器视觉、弹窗及个人库内容验收已完成。
