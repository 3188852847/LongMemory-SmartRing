# 圆屏实时优先

这一版继续使用当前 CosyVoice 声线。优化开口前的等待，保留原策略作为对照。

## 使用与回退

1. 退出旧启动面板后重新打开 `Start.cmd`，在“圆屏与声音 → 圆屏声音”找到“响应策略”。
2. 选择“实时优先”，停止并重新启动服务。保存选择不会改变已经运行的进程。
3. 正常和圆屏说话；不需要改 API Key、模型、声线或个人记忆。
4. 若发现漏掉后半句、抢话或体验变差，选择“原策略（对照）”，停止后重新启动。

实时优先会在等待确认停嘴时提前听写一次，并让普通回答先给简短完整的有用句子。
连续聊天还会尽量复用与官方回答服务的连接，减少重复连接等待；刚启动后的第一轮
仍需建连，云端响应时间也会波动。
你明确要求详细说明时仍应保留必要内容。豆包备用模式独立，不使用这里的本地优化。

## 怎么判断是否改善

两种策略各说十轮类似问题。不要只用“你好”等已命中预置声音的短语；加入普通问题，
例如询问一个原理、请给一个建议，并测试说到一半停顿后继续说、播放中插话。

在设备页查看“输入侧耗时”和“首句时序”。看到“停嘴确认后的听写等待”为 0 秒时，
看旁边“已提前计算”的说明：模型在停嘴确认前已经完成，计算并没有消失。复用次数
只统计当前连接；手动模式、太长的输入或不支持的设置会正常走完整识别。

分别关注三个感受：你说完多久开始回答、第一句之后会不会停住、插话时能否停止并
听完新问题。首包是服务端发送时刻，扬声器实际出声还包含传输与设备缓冲。

合成基准中，提前听写把输入到文字的中位时间从 980ms 降到 732ms；这不包含回答
模型和声音合成，不能承诺整轮只需 0.73 秒。云端首字仍会波动，具体数据与限制见
[本轮验证记录](../research/voice-realtime-first-2026-09-15.md)。

命令行的原策略开关为 `--voice-latency-mode original`，通过项目启动脚本使用；
无需修改上游 Xiaozhi 或配置个人数据库。
