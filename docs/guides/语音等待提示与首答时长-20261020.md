# 同声线等待提示与首答时长

2026-10-20 隔离候选。实现完成不代表正式服务已加载，也不代表新提示已由所有者听验。原校园问答/字幕/声音通过记录保留；新的等待听感、长记忆、首答与打断另验收。[实现与证据](../development/parallel/V-voice-latency-20261020.md)、[ADR-0188](../adr/0188-profile-matched-waiting-cache-and-answer-priority.md)。

## 为什么当前可能没有等待提示

基线只在默认声线使用公共预生成提示；自定义参考或 style 会主动静默，避免混入原声线。等待又在记忆查询后才启动，因此“记忆准备很久、模型/TTS随后很快”的一轮可能全程没有提示。当前配置只读结果符合前一条件，但没有逐轮现场时长可以据此认定实际慢了多少。

新候选支持按当前声线身份查私有缓存，记忆→模型→首个真实答案音频就绪前共用一个等待窗口。快答不播，每轮至多一次；真答案就绪后优先，未发提示尾包作废。已送往设备的包不能撤回，不把发送完成等同于扬声器播放确认。

## X 正式交接时准备

首次正式准备中，X 报告“我想一下。”完整音频 1.68 秒、“我查一下。”3.4 秒；后者超过 35×60ms 上限，因此整套未发布。原 WAV 未留存，无法判断首尾静音比例，不为诊断重生成。修复将两个场景统一为完整短句“稍等。”，一次合成复用；不裁剪、不改语速、不放宽上限。X 的一次独立短句探针为 24kHz、1.32 秒，两种编码各 22 帧；这不是正式缓存发布或永久时长保证。正式准备仍须按下面步骤完整验证。

1. 合入并审查语音候选，核对正式代码根、已保存的当前声线和声音服务版本；不在 V 工作树缺少私有档案时猜默认声线。缺选中档案会拒绝准备。
2. 在 X 所有权控制的维护窗口中隔离全部语音/网页合成生产者，仅让本地 CosyVoice 就绪。不能在正常问话时或当前 TTS 正合成答案时运行准备；`--maintenance-window` 不会自动停止设备/服务或赋予抢占优先级。
3. 使用已有小智 3.10 环境及原 Opus 资源运行正式代码的脚本（以下为待执行交接命令，不是本轮执行记录）：


4. 脚本只向回环 18770 请求一次固定短句“稍等。”，显式携带开始时选中的声线快照、禁用回复缓存，分别编码 16/24 kHz 单声道 60ms Opus，供 model/web 两场景复用。先记录完整波形的采样数/时长并检查不超过 2.1 秒（包含首尾低电平），编码后仍限制最多 35 帧；不裁音频。过程中声线变化、格式/长度异常或失败即不发布整套新清单，不自动换声线或重试。
5. 结果仅在 `local/runtime/voice-waiting/cosyvoice3/<身份短前缀>/`：摘要命名的 `.opf` 和 `manifest.json`。完整声线/内容/文案摘要、编码版本和长度均要匹配。先发布不可变包，再原子切换清单；命中同一完整缓存不再次合成。缓存为私有派生音频，不提交 Git、不从中导出参考原文。
6. recipe（准备规则版本）更新为 `opus60-neutral-wait-v2`，改变缓存身份；旧私有缓存和默认素材文件保留。旧默认素材没有当前文案清单，不再自动回退；默认和自定义声线都需要当前文案的有效缓存。准备成功后由 X 核对四包、恢复正式语音链路并检查加载版本，最后由所有者听验。保存新声线会换身份；没有新缓存时静默降级，不在第一问临时合成提示。

## 看哪些时长

既有 `input_timings_ms` 分开记录 VAD（语音活动检测）判停和 ASR（语音识别）处理；`voice_latency` 的主时钟从拿到识别文本后的 chat 入口开始，不含全部输入阶段。`llm_first_output_ms` 也可能是工具增量，不能当作可朗读首字。

候选新增进程内 `stage_snapshot()` 和固定无正文日志：`memory_requested_ms`、`memory_returned_ms`、`model_first_text_ms`、`first_segment_ready_ms`、`audio_dispatch_ms`。首分段表示可交给 TTS 的片段，不保证已经形成语义完整的第一句。原 `tts_started/audio_ready/first_audio_sent` 与等待反馈的 `first_feedback/first_answer` 保留，各有不同边界。

严格设备协议仍为 v6，新增细分字段没有直接塞入面板接口；X/Z 如接线，应共同更新允许字段和兼容读取，不能单改一端。现场导出只保留同轮匿名关联、有限状态与阶段时长，不复制真实聊天或音频。

“用户说完→首句有用回答”还需补 ASR 交接→chat 排队，以及设备接收/真实可听时间。没有播放确认时只报告最后发送，不填写扬声器耗时；输入预识别重叠不要再重复扣减一次。按同一模型、声线、样本、库快照、负载和缓存条件分组，分别报告冷/热、普通/含记忆、短/长、取消/插话；少量样本先报中位数和范围/最大值，不宣称稳定 p95 或提升百分比。
