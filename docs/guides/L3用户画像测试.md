# L3 用户画像测试指南

用户画像页默认打开“统一画像”：这里只汇总已接受且仍有效的 L3 认识。需要创建、复核或查看拒绝/失效历史时，切换到“画像依据与候选”；统一画像中的每项也可直接点击“查看依据”回到 L1/L2 与 L0 原话。

本指南用于体验“选择来源 → 手工填写或模型生成草稿 → 查看证据 → 接受/拒绝”。只有点击模型按钮并再次确认才会调用学校模型；画像不会立刻参与回答。

## 1. 启动

当前代码结构与个人数据库均为 V9；个人数据库已完成一致性备份与完整性复核。使用日常启动面板启动控制台，面板会为本机日常模式显式开放画像管理能力。手动启动 API 时需额外传入：

```powershell
--allow-persona-management
```

打开控制台后选择顶部导航中的“用户画像”。

## 2. 先准备来源

页面只能选择当前有效的 L1 和已接受的 L2。建议先用合成内容聊天并确认它们出现在“记忆管理”：

```text
我平时喜欢喝乌龙茶。
如果我心情不好，希望你先听我说，不要马上给建议。
```

若要体验“系统推断”，需至少准备两个 L1/L2 来源；它们向下合计至少三条不同用户原话，并覆盖两个 UTC 日期。一次对话不能伪装成稳定习惯。

## 3. 创建用户自述候选

1. 进入“用户画像”，点击“新建画像候选”。
2. 类型选择“偏好”，依据选择“用户自述”。
3. 标签填写“饮品偏好”，断言填写“用户平时喜欢喝乌龙茶。”。
4. 选择能够支持该断言的 L1 来源；不要把仅仅相关但不支持结论的来源选入。
5. 点击创建并确认。此时状态应为“待复核”，不会参与回答。

## 4. 核对并复核

1. 打开候选详情，核对依据性质、来源数、用户原话数和观察日数。
2. 展开每个 L1/L2 来源，确认内容快照和 L0 原话真正支持断言。
3. 正确时点击“接受”；过度概括、主体错误或证据不足时点击“拒绝”。
4. 接受后状态应为“已接受”，但当前版本仍不会将它注入网页或圆屏回答。

## 5. 模型辅助草稿（可选）

1. 使用配置了校园模型的日常启动方式；页面应显示当前草稿模型名称。
2. 选择“用户自述”或“系统推断”，再选择必要的 L1/L2 来源。
3. 点击“让模型生成不落库草稿”。此时还不会调用模型。
4. 阅读弹窗中的发送范围：派生内容、底层用户 L0 原话和 UTC 观察日；确认后才发出一次请求，失败不重试。
5. 返回后检查类型、标签、断言和模型最终保留的来源。可以人工修改，但不要把证据没有支持的内容补进去。
6. 点击“创建待复核候选”才会写入数据库；创建后仍按上一节接受或拒绝。

模型可以因证据不足拒绝生成。`system_inferred` 即使输入池满足门槛，模型最终选择的子集仍必须满足两个来源、三条用户 L0 和两个 UTC 观察日。

## 6. 来源失效测试（可选）

对画像引用的一条 L1 执行“纠正错误”“记录变化”或单条删除，或者结束被引用的 L2。回到画像详情后，原候选/已接受画像应转为“已失效”，生命周期记录应显示对应来源和原因。系统不会静默删除原画像和来源快照。

## 7. 更新一项画像

1. 在“统一画像”点击某项的“查看依据”，确认它当前为“已接受”。
2. 点击“更新这项画像”。类型固定为原类型；修改标签和完整断言，并重新选择真正支持新内容的 L1/L2。现实开始时间不会从旧画像自动复制，需要时请重新填写。
3. 创建后，新内容只是待复核候选，旧画像仍留在统一画像。
4. 打开新候选，核对“准备取代的旧画像”和 L0 原话。拒绝时旧画像不变；接受时，新画像进入统一画像，旧画像转为 stale，并在双方详情中保留取代关系。
5. 也可以选择来源后点击“让模型提出整理建议”。二次确认会说明将发送所选 L1/L2→L0 与当前有效 L3 的最小字段。ADD 会填入普通新候选，UPDATE 会同时填入取代目标，NOOP 不填表也不写库；返回内容仍需人工编辑、创建候选并复核。

## 8. 验收记录

- [ ] 用户自述候选能创建，且能看到 L0 原话。
- [ ] 未满足门槛的系统推断被拒绝。
- [ ] 接受/拒绝后状态正确。
- [ ] 来源变化后画像转为 stale，并保留生命周期记录。
- [ ] 页面不会自动调用模型；只有二次确认才生成不落库草稿。
- [ ] 模型不能引用未选择来源，证据不足时不会生成可保存草稿。
- [ ] 画像尚未影响网页或圆屏回答，界面对此有明确提示。
- [ ] 更新候选在接受前不改变旧画像；拒绝保持旧画像，接受后统一画像只显示新内容且能双向查看取代关系。
- [ ] 整理预览的 ADD/UPDATE 只填表不落库，NOOP 不创建候选；未经二次确认不调用模型。
