# React 启动面板

根目录仍只有一个日常入口：`启动智慧圆屏.cmd`。它使用现有 Python 环境打开 React 启动页面；不需要安装 Electron、WebView 或新的前端依赖。

已安装 Edge 时，启动面板以独立应用窗口显示，没有浏览器地址栏和标签栏；内部仍由浏览器渲染 React。找不到该浏览器或窗口启动失败时，回退到默认浏览器窗口。聊天控制台继续使用正常网页，不改变系统默认浏览器。

## 使用

1. 双击中文入口。启动器仅建立本机控制界面，不自动启动聊天或语音。
2. 选择文字聊天或圆屏陪伴；模式变更只有明确点击后才保存。
3. 点击“开启陪伴”，等待各项服务状态，再进入陪伴空间。
4. 需要修改启动选项时，先停止服务，再打开“启动设置”。模型、记忆提取/召回、语音模式、拾音环境及起始页保留原含义。
5. “停止服务”停止本启动器拥有的进程树；“停止服务并退出面板”还退出本机控制主机。两项操作都会先确认。

关闭浏览器页面不会停止服务。再次双击中文入口可重新打开同一个 React 面板；不同启动器不会接管或终止外部程序。旧 Tk 面板仍打开时，需要先在旧面板停止服务并退出，再打开新入口。

“服务已就绪”表示本机服务检查，不代表圆屏已连接、模型账号可用或真实声音验收完成。声音预热与其他服务分别显示；实际设备情况在设备页核对。

## 地址变化与端口冲突

启动器沿用已保存的电脑局域网 IP，不自动替多网卡选择地址。换网或电脑地址变化后，在服务停止时核对当前网卡，再在“启动设置”更新“电脑局域网 IP”。圆屏模式启动会在端口预检通过后同步小智人工配置中的网络字段；它不会替设备修改保存的 OTA/服务器地址。

地址失效、端口被占用和系统拒绝绑定会分别提示具体地址与处理方向；其他配置异常继续隐藏原始错误正文。遇到端口占用，先核对进程归属；启动器不关闭外部程序，也不会自动换端口。当前语音链路使用固定 8000/8003，启动设置里的控制台端口不能解决语音端口冲突。

若设备仍保存旧电脑 IP，需要由所有者在设备现有配网页核对 OTA 地址 `http://<当前电脑局域网IP>:8003/xiaozhi/ota/`，或其所用的直接 WebSocket 地址 `ws://<当前电脑局域网IP>:8000/xiaozhi/v1/`。先确认电脑服务及对应 LAN 监听，再重连设备、查看活动连接并自然唤醒验收；不能把本机 ready 当成设备、字幕或声音已经通过。现场故障与恢复边界见[排障记录](../development/troubleshooting.md)。

## 构建与回退

沿用 `web/react-chat/` 的 Node、pnpm 版本和锁文件。现有依赖已安装时，在该目录执行 `pnpm.cmd build`。构建同时生成聊天与启动页面；主机只提供构建资源，不公开源码或配置。

构建缺失会显示明确提示，不静默启动其他界面。需要临时回退时，先停止并退出 React 面板，然后在项目根运行：

```powershell
& '.\.venv\Scripts\pythonw.exe' '.\scripts\development\launcher\app.py'
```

旧 Tk 的网络/防火墙等排障入口仍在兼容面板中；React 日常面板不提供清理外部服务、写入密钥或数据库迁移操作。新界面隐藏旧 TTS 和网页角色选择，不删除其底层配置；助手表达仍在网页设置页管理。

## 数据与控制边界

- 继续使用 `local/config/` 的人工配置和共享偏好指针，不搬迁个人数据或模型。
- 浏览器得到一次性启动器会话令牌，读写只允许固定的本机接口；令牌不存浏览器持久存储。
- 启动页与网页共用 React 组件和视觉规范。两者端口不同，浏览器外观偏好不会因此自动跨端口同步。
- 新界面不会下载依赖、更新固件或烧录圆屏。

接口与故障含义见 [启动器契约](../development/launcher-contract.md)。
