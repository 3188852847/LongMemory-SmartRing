# 圆屏联网与等待反馈

在 `启动智慧圆屏.cmd` 选择 CosyVoice3 和“实时优先”。“配置联网搜索”可选择 Tavily、
秘塔或关闭，密钥只保存在本机 `.env.web-search.local`，不会提交 Git；留空保存
可保留同一供应商已有密钥。旧面板需重新打开才能看到新按钮。保存后下一轮生效。

普通聊天直接回答；需要公开网页资料时，由回答模型决定调用一次搜索。不是新闻
专用模式，也不是能登录网站、操作网页的浏览器代理。当前只使用最多三条摘要。
查询只发送本轮用户原问句，不附加私人记忆和历史；含代词或缺少地点时应补充。

回答处理开始约 900ms 后，如果还没有答案音频，会播放一次同声线“我想一下”；
如果届时正在查询，则说“我查一下”。不会为了提示再调用模型或合成服务。
已开始的提示会自然说完，赶巧到达的答案可能等待剩余约一秒；快速答案跳过提示。
搜索失败会如实说明，不用猜测冒充查到的结果。

设备页“等待反馈与真正答案”分别显示提示首包、答案首包、查询耗时。它们从回答
处理入口计时，是服务端发送观测，不是停嘴到扬声器出声。V6 首包仍指真正答案；
LLM 首输出在联网轮次可能是工具决定，不等于答案首字。

## 实机验收

1. 问普通常识：应直接回答，没有查询耗时。
2. 说“帮我联网查一下 Python 官方文档中 asyncio 是做什么的”：应查询并说明来源。
3. 换成产品资料、近期公开消息等问题，检查是否仍能触发搜索，而非仅识别新闻。
4. 等待提示或答案播放时打断并问新问题：旧答案不应继续串入新轮。
5. 暂时关闭搜索，要求查询：应说明无法联网核实，不能声称查过。

每类至少三轮，记录停嘴到真正首包、提示是否多余、打断和听感。网络耗时随服务
波动；软件验证不能替代圆屏实测。已发送到设备缓冲的包无法追回，阻塞中的模型/
网络读取也不保证立即停止计费或计算。

回退：关闭搜索只停用联网；切回“原策略（对照）”并重启，同时停用本轮搜索适配
和等待提示。豆包完整实时模式独立，不受这些设置控制。
