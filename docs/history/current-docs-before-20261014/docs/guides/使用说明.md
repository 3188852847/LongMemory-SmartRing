# LongMemory 使用说明：启动命令与网页操作

更新时间：2026-09-07（增加手动主动问候验证，启动命令未改）。适用于当前这台 Windows 电脑及已经安装好的项目环境。

**日常可先用[统一启动面板](统一启动.md)，双击根目录 `启动智慧圆屏.cmd`；不要同时用面板和下面命令启动相同服务。** 本文保留终端方式：文字聊天从第 3 节开始，圆屏再加第 4 节，实验用第 1、2 节。

返回[项目首页](../../../../../README.md)；查看[自定义候选](../../../../requirements/自定义功能清单.md)、[系统架构](../architecture/overview.md)与[运行流程](../architecture/workflows.md)。

## 0. 先记住这几件事

- 使用普通 **PowerShell**，或 PyCharm 内的 PowerShell 终端。不需要 ESP-IDF 终端，也不要求手动激活 `.venv`。
- 复制代码框内部的命令，不要复制三反引号、`PS D:\...>`、`>>>` 等提示符。
- 一个终端运行一个长期服务。出现启动日志后没有返回 `PS ...>` 是正常现象，说明服务正在运行，不是卡住。
- **运行期间保持终端开启。** 关闭网页不会关闭服务；关闭终端、电脑重启或程序异常退出可能让服务停止。网页还开着不代表后端还活着。
- 停止服务：切到运行它的终端，按 `Ctrl+C`，等命令提示符回来。重启：再执行同一段启动命令。
- 本文所有网页控制台统一使用 **8767**，方便沿用你当前打开的页面。这只是本文选用的端口；程序默认是 8765。**同一时间只用一个控制台启动方案，不要重复启动同一端口。**
- 本文的 `uv run --no-sync` 使用已经安装好的环境，不重新同步或移除依赖。环境缺依赖时看第 7 节，不要反复重装。

| --- | --- | --- |

## 1. 实验用途：启动实验中心

如果已经有控制台占用 8767，先在它的终端按 `Ctrl+C`。不需要停止小智。

在 PowerShell 中复制执行：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing"
uv run --no-sync --env-file local/config/.env python -m longmemory.entrypoints.api --port 8767 --enable-experiment-runs
```

**当前电脑上这段命令不用修改参数。** 它会：

- 启动本机网页控制台，允许你在网页确认后运行实验。
- 从项目目录的 `local/config/.env` 读取已有模型配置；不会把密钥放到网页里。
- 不打开日常记忆数据库，不启用文字聊天，不启动小智。
- **仅启动服务，不会自动调用学校模型。** 查看报告、预检预算也不调用模型。

正常应出现类似提示：

```text
实验作业已启用；仅用户在网页预检并确认后执行。兼容模型配置可用（未联网验证）。
控制台：http://127.0.0.1:8767；仅本机访问，Ctrl+C 停止。
```

如果提示“未配置兼容模型，目前仅能运行 Fake”，可以先用 Fake；真实模型配置见第 6 节。

保持终端运行，浏览器打开：

**[http://127.0.0.1:8767/experiments](http://127.0.0.1:8767/experiments)**

原页面已经打开时，刷新一下。请使用完整的 `127.0.0.1` 地址，不要改成 `localhost` 或电脑的校园网 IP。

## 2. 在网页运行实验

### 2.1 第一次建议选 Fake

Fake 是固定规则写成的“模拟回答器”，不是大模型。它不联网，用于熟悉操作和检查程序流程；**Fake 分数不能评价记忆方法的质量。**

在上方“运行回答对照”区域填写：

| 页面项目 | 这次填什么 | 含义 |
| --- | --- | --- |
| 冻结检索档案 | 选择 `retrieval-92deeedf9d8d4d419abdec3f2e45f4c4` 对应项，列表编号尾部为 `2e45f4c4` | 复用之前保存的检索结果；不是让你手工输入路径 |
| 回答模型 | `Fake（只验证流程）` | 本地规则回答，不调用学校模型 |
| 记忆上限（字符） | `4000` | 每题最多注入的记忆字符数，不是记忆库容量；字符不等于 token |

依次操作：

1. 点击 **“预检与核对预算”**。这一步检查本地输入，还没有启动回答请求。
2. 弹窗中核对输入档案、模型、四个实验组和预算。当前是 **4 组 × 8 题，最多 32 次回答请求**。
3. 阅读提示，勾选确认框，点击 **“确认启动”**。预检超过 10 分钟需要重新做。
4. 在进度区查看“已尝试、成功、失败、未结束”。Fake 通常很快结束，不一定能看到每个中间数字。
5. 点击 **“打开结果”**，进入四组对照与逐题查看。

本流程只重做“回答”，**不会重新提取记忆、运行 BGE 编码或修改日常记忆**。每次新实验产生独立报告，不覆盖旧报告。

### 2.2 用学校模型运行真实回答

不必重启控制台，只需：

1. 确保电脑连接能访问学校模型的校园网。
2. 冻结档案保持相同，把“回答模型”改成 **DeepSeek-V4-Flash（真实模型）**。
3. 记忆上限保持 `4000`，便于与上一轮保持相同预算条件。
4. 点击预检，核对目标服务、模型、请求次数和单次回答上限。
5. 阅读网络风险提示。当前学校接口使用 HTTP，会明文发送密钥、合成问题和记忆；只在已确认风险的环境使用，不拿它发送敏感个人信息。
6. 勾选并确认启动，等待完成，打开结果。

“模型可选”只代表启动时配置有效，**不代表此时网络一定可达**。调用失败不会自动重试，也不会偷偷改用 Fake。

### 2.3 结果怎么看

1. **完成 / 总题**：先确认有没有请求失败。完成不代表答对。
2. **词面初筛**：按答案中的文字规则自动筛查，可能误判，不能直接当最终准确率。
3. **逐题对照**：选“我是谁？”等问题，比较四组回答。
4. 展开 **实际注入、完整检索、召回条目、原始来源**，检查回答有没有证据。
5. 想保存自己的判断：填写稳定的复核署名，在对应卡片选通过/失败/待判断/不可评分，写理由，点击“保存此题复核”。复核另存，不改原始分数。

需要停止实验时，点击 **“停止后续请求”**。已发出的那一次请求可能继续完成或计费，不能撤销；未运行的题保留为未完成。

刷新或关闭网页不会取消作业。服务中断后不会自动续跑；先查看已有结果，不要反复重新启动同一实验。

## 3. 可选：同时启用网页文字聊天和记忆管理

React 记忆页顶部的“每日记忆回顾”按当前浏览器的本地日期显示当天形成的 L1，可切换到此前日期，最多展开最近 5 条，并可直接打开 L0 来源。页面同时显示当天归档的用户/助手 L0 条数，用于区分“没有聊天”和“聊过但没有形成 L1”；它不是会话轮数或内容总结。回顾会依据现有证据类型与双时间字段，把记录标为“新增”“纠正”或“事实变化”，同时显示当天各类计数。当前有效项可从回顾卡直接进入既有纠正确认窗；纠正仍新建 L1 并取代旧版本，不会原地覆盖。当天已经被纠正或取代的 L1 仍会出现并标为“已退役”，因为该区域回答的是“当天系统写入了什么”，不是“现在有哪些事实仍有效”。V28 起发生的 L1 删除会显示计数，并可展开查看被删 L1 ID 与时间；审计不保留被删正文，也不回填旧版本中无法证明的历史删除。读取不会调用模型、生成 L2/L3 或修改数据库。

回顾还会单列当天“没有形成 L1 的用户原话”数量。点击“核对当天未形成 L1 的原话”，页面会切换到 L0，并同时应用用户角色、未关联状态和所选本地日期三个筛选；L0 工具栏中的日期输入也可以改选或清空。未关联不等于漏记：普通问句、寒暄和不值得长期保存的内容本来就不应生成 L1。只有人工确认该原话确实漏记时，才打开详情、点击“补成 L1”，并填写一条以“用户”为主体、可独立理解的完整事实。确认后会复用这条 L0 作为证据，不复制原话、不调用模型；如果已有内容完全相同的当前 L1，只为它增加这条来源。成功时每日回顾的“所有者确认漏记”会增加；该事件不复制正文，旧补录不回填，也不等于提取器的自动错误率。助手 L0、已关联 L0 或未启用纠正权限时，按钮保持禁用。

每个已完成的网页回答下方还有四个内部复核按钮：**记忆使用正常、没想起已有记忆、使用了错误记忆、回答与记忆无关**。点击只保存人工判断，不会重新回答、修改记忆或训练模型；误选时可以直接改选，页面会增加修订号并保留旧判断。标记后出现的文字只是依据本轮是否实际召回 L1/L2/L3 给出的下一项排查方向，不代表系统已经判断出根因。记忆页的每日回顾会分别显示当天的“当前有效判断”和包含改标历史的“复核动作”，展开后点击“查看回答与证据”可返回对应聊天轮次，核对当时实际使用的 L1/L2/L3 和完整运行过程。这些数字仍不是准确率。

左侧“长期记忆 → 记忆质量”是跨日期工作台。默认“需要核对的问题”显示网页中仍被标记为“没想起/错误记忆”的回答，以及圆屏上明确指向上一轮的同类反馈；来源标签会区分“网页聊天”和“圆屏语音”。网页样本可返回原聊天轨迹，圆屏样本可打开目标用户 L0，并在“在此核对”中查看当轮回答及召回证据。列表只返回时间、修订号、L1/L2/L3 召回数量和定位 ID，不复制正文。

核对后可选择“标为已处理”并注明是纠正记忆、处理召回或处理回答行为，也可选择“不是记忆问题”。默认问题页随后不再显示该样本，但历史没有删除，可用“已处理问题”或“不是记忆问题”筛选查看并重新打开。这里的“已处理”只管理内部待办，不会自动修改或删除 L0/L1/L2/L3，也不代表算法已经普遍修复。若网页回答的反馈类别后来被重新标记，新修订会重新成为独立待处理样本。

圆屏第一版只识别“你刚才没想起来……”或“你上一轮记错了”这类明确表达；“我刚才说错了”“你错了”等歧义句不会触发，记录也不会自动纠正或删除长期记忆。

每日回顾下方的“低频记忆整理”会一次显示两个阶段：L1→L2 场景整理和 L2→L3 画像整理。每个阶段列出尚未处理的新来源数、触发门槛、当天剩余模型调用预算和最近结果。`已达到触发门槛` 只表示有资格接受下一次调度评估；只有状态标签明确显示“后台已启用”时，常驻进程才可能按冷却与预算运行。打开或刷新这张卡不会调用模型，也没有绕过门控的立即执行按钮。需要查看候选、来源和复核状态时，使用卡片下方的 L2/L3 入口。

**这一段替代第 1 节，不是另开第二个控制台。** 先在旧控制台终端按 `Ctrl+C`，再执行：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing"
uv run --no-sync --env-file local/config/.env python -m longmemory.entrypoints.api --port 8767 --enable-experiment-runs --database "D:\02-项目\LongMemory-SmartRing\data\databases\xiaozhi-demo-v1.db" --enable-chat --chat-provider openai_compatible --assistant-role elysia_v1 --allow-memory-correction
```

上述数据库路径已在编写本文时核对：文件存在，且小智私有配置的 `Memory.LongMemory.database_path` 使用这个路径。**如果以后修改了小智的数据库，也要同步修改这条命令。** 本次只核对路径，没有读取你的对话内容。

打开对应页面：

| 页面 | 地址 | 作用 |
| --- | --- | --- |
| 文字聊天 | [http://127.0.0.1:8767/chat](http://127.0.0.1:8767/chat) | 打字聊天；发送会写入原始对话及符合当前规则的记忆，并调用学校模型 |
| 记忆管理 | [http://127.0.0.1:8767/memories](http://127.0.0.1:8767/memories) | React 版 L1/L0 分层、双向来源与模式控制；此命令没有启用管理删除 |
| 实验中心 | [http://127.0.0.1:8767/experiments](http://127.0.0.1:8767/experiments) | 运行隔离实验、查看和复核结果 |
| 设备与状态（React） | [http://127.0.0.1:8767/device](http://127.0.0.1:8767/device) | 需另开第 4 节的小智服务，才可能控制圆屏音量；原生回退页仍在 `/` |

注意：

- `elysia_v1` 是爱莉希雅风格的助手角色；换成 `plain_v1` 就是普通助手。它改变网页聊天文字风格，不改变音色，也不改变实验的中立回答提示。
- `--chat-provider openai_compatible` 只选择**聊天**回答器；实验用哪个模型仍在实验页面另选。
- 文字聊天和圆屏共用同一数据库，才可能共享长期记忆；双方短期聊天上下文仍独立。存入了记忆也不保证当前关键词检索每次都能找到。
- 网页聊天实际使用启动面板本次选择的提取与检索策略；可在聊天页运行配置和设置中心核对，不要根据旧终端命令猜测。
- 网页回答不会自动从圆屏播放。只用文字聊天不需要启动小智或接上圆屏。
- “新聊天”不删除长期记忆；网页会话列表、名称和轮次会持久恢复，置顶偏好只在当前浏览器保存会话 ID。
- 如果系统漏掉一条明确事实，可在“记忆管理”右上角点“明确添加”，输入以“我/我的”开头的完整陈述。它会保留一条 L0 管理操作来源并生成或去重 L1，不调用回答模型；若本轮已暂停 L1 写入，则只保存 L0，不绕过开关。
- 如确实想启用管理页单条删除，可在启动命令末尾加 `--allow-memory-delete`。不要默认加：删除仍需逐条确认，且不等于彻底擦除原始对话。

### 圆屏自然纠正与来源操作

统一启动并让圆屏连上本机小智服务后，可以直接说以下固定格式。第一版强调不误改，因此不是任意近义说法都能识别：

| 目的 | 推荐说法 | 实际数据语义 |
| --- | --- | --- |
| 明确记住一条事实 | `请记住：我叫小林` | 原话保存为 L0，自指陈述规范化为单条 L1；重复事实只增加来源 |
| 纠正原本错误 | `不是豆包，是年糕` | 唯一命中旧 L1 后，新建 `user_corrected` L1 并取代旧条目 |
| 记录后来变化 | `我以前喜欢喝咖啡，现在不喝咖啡了` | 旧 L1 写结束时间，新 L1 写开始时间 |
| 询问来源 | `你怎么知道豆包？` | 读取 L1 对应的用户 L0 原话，不新增 L1 |
| 本轮不生成长期事实 | `不要记住：我今天想喝茉莉花茶` | 原话仍保存为 L0，但本轮跳过 L1；不是彻底擦除 |
| 请求删除 | `请忘掉豆包` | 只回读待删目标，不立刻删除 |
| 确认删除 | 紧接着说 `确认删除这条记忆` | 两分钟内且目标未变化才删除单条 L1；L0 原话仍保留 |
| 取消删除 | 紧接着说 `取消删除` | 清除待确认目标，不改数据库中的 L1 |

“请记住”后必须是一条以“我/我的”开头的完整陈述；`请记住：豆包` 或问题句不会强制落库。如果只说“这句不要记”，系统不会猜测并回删上一轮；请改用“不要记住：具体内容”。如果系统说没有找到唯一记忆，请同时说出旧事实和新事实，不要只说“不是这样”。删除确认之间插入其他对话会自动取消，这是防止误删的设计。网页聊天命中这些命令后会单独显示“实际记忆操作结果”，判断执行结果时以该回执和记忆管理页为准，不以模型回答中的口头承诺为准。圆屏操作结果可在控制台记忆详情中事后核对；当前不等于彻底清除聊天记录、备份或日志。

### 首次使用人工纠正前：显式升级 V3 日常库

P3.3 把证据类型扩展到 `user_corrected`，因此旧 V3 库需要一次非破坏性升级到 V4。先停止启动面板和小智服务，避免迁移时仍有写入者。以下命令只读检查版本：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing"
.\.venv\Scripts\python.exe scripts\development\memory_database.py status --database "data\databases\xiaozhi-demo-v1.db"
```

只有路径正确并输出 `version: 3` 时，才执行迁移：

```powershell
.\.venv\Scripts\python.exe scripts\development\memory_database.py migrate --database "data\databases\xiaozhi-demo-v1.db" --backup-directory "data\backups" --confirm-upgrade
```

正常结果包含 `from_version: 3`、`version: 4`、备份路径和 `backup_sha256`。工具使用 SQLite backup API 先生成一致性备份，不覆盖已有文件；备份目录被 Git 忽略。迁移完成后再打开日常启动面板。

进入“记忆管理”，选择仍有效的旧事实：

- 如果旧内容从一开始就记错了，点“纠正错误”，输入可独立理解的完整事实（例如“用户的猫叫年糕。”），并确认旧记录本来就错误。
- 如果旧内容过去正确、后来才变化，点“记录变化”，输入变化后的完整事实和实际生效时间。当前只接受已经发生的变化，不接受未来预约。

成功后默认列表显示新事实；切换“全部 L1”可看到旧事实已退役并指向新 ID。详情中的“系统记录时间”表示何时写入数据库，“事实开始/结束生效”表示现实世界中的有效区间。两类操作都会保留旧 L1 和 L0 来源，不是原地改字；事实变化不需要再次迁移 V4 数据库。

### 本次运行的记忆模式

使用第 3 节命令或统一启动面板启用聊天后，打开“记忆管理”，页面顶部有两个互相独立的开关：

- **从新对话生成 L1 长期记忆**：关闭后，网页和圆屏的新用户话语仍保存为 L0 原始记录，但不再提取新的 L1 事实。
- **回答时使用已有长期记忆**：关闭后，网页和圆屏本轮不检索、不注入已有记忆；它不会删除数据库内容，也不阻止另一个写入开关继续工作。

选择后点击“应用到网页与圆屏”。设置从下一轮开始作用于共享 Runtime，只在本次服务运行期间有效；关闭或重启启动面板后，两项恢复为开启。它不是隐私擦除，也尚未提供“只在我说记住时才记”的自动模式。

## 4. 可选：启动圆屏语音和音量控制

**只有要使用圆屏时才需要本节。跑记忆实验不需要启动小智。**

小智与 LongMemory 是两个程序，各自使用自己的虚拟环境。保持第 1 节或第 3 节的控制台终端不动，另外新开一个 PowerShell。

前提：沿用已配好的圆屏、小智配置和防火墙；电脑能访问学校模型。下面的 `192.168.124.45` 是之前使用的电脑有线 IPv4，**不是永远固定的地址**。

如果网络或 IP 没变，执行：

```powershell
Set-Location "D:\LongMemory-local\runtime\xiaozhi-esp32-server\main\xiaozhi-server"
.\.venv\Scripts\python.exe "D:\02-项目\LongMemory-SmartRing\scripts\development\xiaozhi\setup.py" start --lan-ip 192.168.124.45 --allow-insecure-http --device-control
```

这条命令直接使用完整脚本路径，**不依赖旧终端的 `$xiaozhiSetup` 变量**。若已有小智服务，不要重复启动，需先在旧小智终端按 `Ctrl+C`。

参数含义：

| 参数 | 作用 |
| --- | --- |
| `start` | 启动现有小智语音服务，不是烧录固件 |
| `--lan-ip 192.168.124.45` | 使用电脑的这一个局域网地址，让圆屏连接；必须匹配已有私有配置 |
| `--allow-insecure-http` | 明确接受本次学校模型 HTTP 明文传输风险；不会把连接变成加密 |
| `--device-control` | 开启本机音量控制桥，让网页可以读写已连接圆屏的音量 |

正常应看到设备控制桥 `http://127.0.0.1:8766` 已开启，以及记忆模块 `LongMemory` 初始化成功。等待圆屏连入，再打开控制台“设备与状态”。待机无活动连接时，轻触圆屏进入聆听，再刷新状态。

**不要用浏览器打开 8766、8000 或 8003 来代替控制台。** 它们是控制桥/设备通信接口，不是当前管理网页。

如不确定 IP 是否变化，可以先运行下面的只读命令，找到有线网卡的 IPv4：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, IPAddress
```

若不再是 `192.168.124.45`，不要只改启动命令就继续：小智私有配置、圆屏连接地址和窄范围防火墙也可能需要同步。先保留当前配置，提供新 IP 和固定错误提示再处理，不要重新烧录或删除数据库。

### 4.1 P4.1：手动验证圆屏主动播报

这不是定时主动聊天，只验证“电脑上的小智能否在圆屏在线且空闲时主动播一句话”。保持上面的 `--device-control` 小智服务运行，等待圆屏已经连入，然后在另一个 PowerShell 执行：

```powershell
Set-Location "D:\02-项目\LongMemory-SmartRing"
& "D:\LongMemory-local\runtime\xiaozhi-esp32-server\main\xiaozhi-server\.venv\Scripts\python.exe" "D:\02-项目\LongMemory-SmartRing\scripts\development\xiaozhi\control.py" status
& "D:\LongMemory-local\runtime\xiaozhi-esp32-server\main\xiaozhi-server\.venv\Scripts\python.exe" "D:\02-项目\LongMemory-SmartRing\scripts\development\xiaozhi\control.py" announce "这是一条主动播报通道测试。" --ttl-seconds 30
```

第一条期待 `connection_count=1`、`announcement_supported=true`、`announcement_ready=true`。若圆屏只有进入聆听状态才保持连接，先轻触或唤醒它，再重新运行 `status`；不要重刷固件或重新配网。

第二条成功只会返回：

```json
{
  "state": "queued",
  "playback_acknowledgement": "unavailable"
}
```

`queued` 只表示小智已把文本交给现有 TTS 队列，不代表圆屏已经播放。请以屏幕是否出现字幕、扬声器是否实际发声作为本次实机结论。设备忙碌、离线或请求过期时不会排队等待，也不会自动重试；不要使用包含个人隐私的测试文本。

## 6. 参数和配置：哪些要填，哪些不用动

### 6.1 控制台启动参数

| 参数 | 本文使用值 | 什么时候修改 |
| --- | --- | --- |
| `--no-sync` | 保留 | 使用现有环境，不因一次启动重新安装/移除依赖；不是离线模型开关 |
| `--env-file local/config/.env` | 有真实模型时保留 | 从项目根目录读取现有配置；这不是把密钥写在命令里 |
| `--port 8767` | 保留 | 只有明确要换网页端口时修改，浏览器地址也要一起换 |
| `--enable-experiment-runs` | 要跑实验就保留 | 去掉后只能看已有实验、写复核，不能新启动实验 |
| `--database "…xiaozhi-demo-v1.db"` | 第 3 节完整路径 | 选择日常记忆库；与实验报告无关。网页不会自动创建或迁移此库 |
| `--enable-chat` | 要打字聊天就保留 | 启用聊天写入，不只是展示一个输入框 |
| `--chat-provider openai_compatible` | 真实聊天时保留 | 改为 `fake` 只替换聊天回答器；不替你选择实验模型 |
| `--assistant-role elysia_v1` | 按喜好 | 可选 `plain_v1`；只影响网页聊天角色，不自动同步小智 |
| `--allow-memory-delete` | 默认不加 | 只有想启用管理页单条删除时才加 |
| `--allow-memory-correction` | 日常启动面板自动添加 | 允许逐条确认后用追加＋取代纠正错误事实 |
| `--enable-memory-consolidation` | 默认不加 | 由共享 Runtime 单一启用低频 L1→L2→L3；有预算、失败留痕和独立风险复核 |

### 6.2 学校模型配置在哪里

LongMemory 网页/实验：`local/config/.env`。

小智语音：`local/config/xiaozhi.yaml`。

**这是两份不同配置，不会自动互相同步。当前已经配好时不需要重填，也不要拿示例文件覆盖已有配置。**

仅在模型配置缺失或学校地址变动时，检查 `local/config/.env` 中这些变量：

| 变量 | 应填内容 |
| --- | --- |
| `LONGMEMORY_LLM_BASE_URL` | 学校提供的兼容 API 根地址，通常以 `/v1` 结尾；不是完整 `/chat/completions` 地址 |
| `LONGMEMORY_LLM_API_KEY` | 你自己的有效密钥，只填在本机 `local/config/.env`，不发聊天、不写进此说明书 |
| `LONGMEMORY_LLM_MODEL` | 当前模型名 `DeepSeek-V4-Flash`，以后以学校实际提供的名称为准 |
| `LONGMEMORY_LLM_TIMEOUT_SECONDS` | 默认 `30`，单次请求等待配置；不是整个实验的总时长 |
| `LONGMEMORY_LLM_MAX_TOKENS` | 默认 `512`，单次回答输出上限；不是长期记忆字符预算 |
| `LONGMEMORY_LLM_ALLOW_HTTP` | 只有明确接受 HTTP 风险时填 `true`；HTTPS 可用时优先使用 HTTPS |

改完 `local/config/.env` 后，需要 `Ctrl+C` 停止并重新启动控制台才会读取新值。**只刷新网页不够。**

不用为了使用本页修改 `LONGMEMORY_LLM_PROVIDER`：网页聊天由 `--chat-provider` 指定，实验由页面选项指定。日常库由本说明的 `--database` 显式指定，不依赖 `local/config/.env` 中的默认数据库变量。

| 设备页提示圆屏离线 | 轻触进入聆听后刷新；配网成功不等于始终保持活动连接 |

这不是每次启动都要执行的命令。它按锁文件同步依赖，可能下载文件并占用磁盘；不要在小智目录执行，也不要为了排障删除 `uv.lock`、`.venv` 或数据库。向量权重不会因这条同步命令重新生成。

## 主动交流设置

统一启动控制台后打开 `/settings`，进入“主动交流”。首屏只保留状态概览、总开关、周期问候开关、频率、问候内容和保存按钮；允许时间、勿扰、测试诊断、记忆话题、一次性跟进、习惯学习和运行记录按任务折叠，需要时再展开。

后台周期问候使用独立开关，默认关闭。频率可设为 1～1440 分钟；24 小时模式可选择每日问候时刻，短周期保存并开启后从下一个允许分钟自动开始，不需要设置锚点。1～5 分钟会显示高频提醒。频率是“最多多久尝试一次”，不是保证发声：上一条主动问候仍待回应、设备离线或忙碌、处于勿扰状态或不在允许时段时都会停止本次尝试，过期后不补发。24 小时模式保留原每天一次规则，当天已经出现真实用户消息时跳过；短周期不会因为当天聊过一次就跳过余下整天。

也可以在网页或圆屏直接说 `把主动交流频率改成每十分钟一次`、`主动联系频率设为每1分钟一次` 或 `请把定时问候调整为每二十四小时一次`。系统会先确定性解析并真实写入当前数据库，再返回结果；模糊的“主动一点”“每半小时找我”和超出 24 小时的数值不会猜测。语音修改只调整周期，不会暗中打开主动交流总开关或周期问候开关。

开发阶段若需要在已经聊天的当天验证 24 小时模式的真实后台计时器：展开“允许时间与勿扰”，先把每日问候时刻改成今天稍后的时间并保存，再到“测试与诊断”点击“允许下一次定时验证”。授权目标会显示在页面上；它只绕过“今天聊过”和“上一条待回应”，仍受星期/时段、勿扰、频率和设备忙碌限制。短周期使用自己的时间槽，不显示这项每日验证授权。

若要验证工程链，请先启动小智并让圆屏保持已连接，在页面打开总开关、把当前时间纳入允许时段并保存；然后在“手动验证圆屏问候”输入 1–80 个字符，点击“发送一次测试问候”。这次点击由所有者明确触发，因此不受“上一条仍待回应”限制；它仍遵守勿扰、每日次数、最短间隔和设备会话限制，失败不会自动重试。同一次浏览器请求即使重复到达也不会重播。

页面显示“小智服务已接收并排队”只证明服务端接受了请求，不证明圆屏已经播放。请以实机声音为准；若被策略拦截，页面会显示状态与原因。该测试不调用模型、不读取 L0–L3，也不会替你开启后台主动交流。

同一张卡片底部的“最近运行记录”会显示最近 10 次账本结果。`blocked` 表示策略拦截，`queued` 表示小智服务端已接收，`failed` 表示投递失败；当前不要把 `queued` 当作圆屏已播放。由日常习惯策略产生的记录还会显示策略版本、激活修订、来源候选、评估日期和检查时刻；这些字段解释“为什么在这天检查”，最终是否发送仍以状态和原因事件为准。普通显式定时没有这段习惯策略来源是正常的。发送后页面只刷新这份记录，不会自动再次发送。

长期事项可从控制台手动建立，也可以在网页或圆屏自然对话中说出严格形式，例如：`我明天下午三点要提交毕业设计汇报，到时候问我汇报进展`。系统会先保存正常的 L0/L1；主动交流总开关已开启时，这句明确请求会直接原子安排一次跟进，总开关关闭时只保存候选，并提示到“设置中心 → 主动交流”核对后启用。当前只识别今天/明天/后天或完整年月日、明确时段和时刻、以及“问我……”；`明天三点`、`以后`、`过几天`等表达不会猜测。即使说得符合格式，也必须先成功形成唯一一条新增 L1，问题句和重复事实不会偷偷建立候选。圆屏的普通 L1 提取可以延后，但这类严格跟进请求会在回答前完成写入和安排，因此本轮可能比普通闲聊稍慢；回答必须明确区分已安排、仅保存候选或失败，不应再声称系统没有主动跟进能力。

安排后的 30 分钟内，如果只有一条仍未执行的自然跟进，可以说 `请把时间改成20点49分` 或 `请把时间改成晚上九点`。系统沿用原日期、事项和追问短句，追加取消旧安排并原子创建新安排；旧时间不会再触发。新时间已过、最近有多条候选或跟进已经开始处理时不会猜测，也不会让模型口头假装修改成功。修改日期、事项内容或追问内容仍使用“取消刚才的跟进”后重新创建。

如果你亲耳听到圆屏播报，可在对应 `queued` 记录点击“确认已听到”。系统会以人工观察证据将其记为 `played`；这不会再次播报，也不会写入个人记忆。没有听到时不要点击，继续保留 `queued` 才能如实反映当前证据。

P5 开发区还会展示“用户主动出现时间”和“可能的日常交流时段”。至少三个不同日期落在同一半小时区间才形成时段候选；这不表示某天没有出现就是异常。对当前候选点击“生成离线验证草案”会执行固定合成回放并保存参数、协议和数据集 SHA-256。把门控通过的版本设为当前后，它会在常见时刻加 60 分钟宽限的唯一分钟进入后台检查；显式定时同分钟优先，错过不补发，并继续遵守主动交流总开关、勿扰、频率、待回应、会话与设备状态。停用会立即让后续检查跳过，版本和切换历史仍保留。

结束使用时：

1. 实验仍在运行而你不想继续：先点“停止后续请求”，等待任务结束。
2. 在 LongMemory 控制台终端按 `Ctrl+C`，等待返回提示符。
3. 如果还启动了小智、也不再用圆屏，再去小智终端按 `Ctrl+C`。
4. 不需要删除文件，不需要重新烧录；下次用对应章节命令重新启动。
