# ADR-0103：只从时间明确的对话请求形成跟进候选

> 状态：部分被 [ADR-0104](0104-conversation-authorized-one-shot-follow-up.md) 取代。解析、来源与保守拒绝规则仍有效；“自然形成一律需要网页二次启用”不再适用于总开关已经开启的明确请求。

## 背景

V34/V35 已支持从 L1 手工建立候选、显式启用并经 P4 护栏投递，但每次都要抄写来源、时间和追问短句。直接让模型从任意“计划”“以后”中猜测时间，会把普通陈述扩大成潜在打扰；而用户明确说“到时候问我……”时，日期、时刻和意图已经足够具体。

## 决定

1. SQLite V36 为候选增加 `creation_kind` 和可空的 `source_message_id`。旧记录默认是 `owner_created`；自然形成的记录是 `explicit_conversation_request`，并直接关联触发它的用户 L0。
2. 第一版采用本地确定性解析，不调用模型。只接受今天/明天/后天或完整年月日、明确时段与时刻，并且同一句包含“问我……”的表达。
3. 未带时段的 1–12 点、过去时间、超过 90 天、模糊未来表达、问题句以及本轮没有唯一新增 L1 时，不创建候选。
4. 候选绑定本轮唯一新增 L1 的 ID 与内容指纹。旁路保存失败不撤销已经提交的 L0/L1，而是向入口返回固定警告类别。
5. 自然形成仍不等于投递许可。候选不会自动启用；网页显示计划时间和未启用提示，圆屏得到固定的“已形成、尚未启用”回执，所有者仍需在“设置中心 → 主动交流”核对。

## 后果

- 明确事项不再需要手工复制 L1、追问和时间，并且可沿候选 → L1 → L0 核对原话。
- 该版本有意牺牲覆盖率：诸如“下周找我聊聊”“过几天提醒我”等不会触发。
- 未来若引入模型建议，应使用新的形成方式、独立质量样本和相同的未启用边界，不能把本 ADR 当成自动投递授权。
