# ADR-0043：L3 模型能力先作为显式、不落库草稿预览

- 日期：2026-09-06
- 状态：已接受并实现；真实校园模型体验待用户执行

## 背景

人工创建 L3 候选能够验证证据链和复核流程，但日常手工归纳标签、类型与断言成本较高。直接让模型扫描历史或自动写入会放大过度概括、来源角色混淆和隐私风险，也无法证明模型选中的证据真正满足声明型或推断型门槛。

## 决定

1. 模型只在用户选择 L1/L2 来源并二次确认后调用；页面打开、来源刷新和普通候选创建均不调用模型。
2. 请求包含选中来源的派生内容、底层用户 L0 原话和 UTC 观察日期。来源文本按不可信数据处理，不能作为系统指令。
3. 用户在调用前选择 `user_declared` 或 `system_inferred`；模型不能改变依据性质。服务在调用前检查整个输入池，在返回后再次检查模型最终选中的来源子集。
4. 模型只能从白名单选择来源，只能输出一个类型、标签和原子断言；允许返回 `candidate: null` 表示证据不足。严格拒绝额外字段、重复字段、越权来源和不合法枚举。
5. 每次点击最多一次请求，不自动重试。数据库连接在模型请求前关闭；返回草稿可编辑但不落库。
6. 用户另行创建后只得到 `candidate`，生成审计记录 `model_assisted_console` 与提示词版本；仍需核对 L0 并接受或拒绝。
7. 本切片不扫描历史、不批量生成、不自动接受，也不让 L3 进入网页或圆屏回答。

## 后果

该方案减少人工填写成本，同时保留模型调用、写入和复核三道明确边界。代价是用户仍需主动选择来源，且模型草稿质量要通过真实校园网体验核对。未来自动整理不能绕过当前契约，应另行定义调度、隐私预算、候选收件箱和失败行为。
