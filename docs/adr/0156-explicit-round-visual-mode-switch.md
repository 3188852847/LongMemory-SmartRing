# ADR-0156：圆屏动态壁纸与几何皮肤显式切换

## 状态

已接受，2026-09-14。

## 背景

0008 固件把有效动态壁纸设为待机、聆听、思考和说话时的主视觉，几何皮肤只在壁纸
缺失或解码失败时显示。控制台的“应用到真机”只写入 `round_skin` NVS 参数并完成回读，
不会停用动态壁纸。结果是操作技术上成功，但用户仍看到原壁纸，页面也没有说明当前显示
优先级。这把“参数已保存”误表达成了“屏幕已经切换”。

## 决定

1. 把真机视觉明确建模为“动态壁纸”和“几何皮肤”两种显示模式。皮肤参数与壁纸资源
   继续使用各自协议，不把媒体状态塞进 `skin_api=1`。
2. “应用到真机”仍只写入并回读皮肤参数；活动壁纸存在时，页面明确提示皮肤已写入但
   当前被覆盖。
3. 新增所有者工具 `self.screen.deactivate_round_wallpaper`。设备核对当前活动槽有效后，
   只把它保存为 `previous_slot` 并清空 `active_slot`，随后由控制桥执行一次重启。
4. 切换到皮肤模式不擦除 A/B 壁纸分区、不重新下载媒体，也不修改皮肤参数、应用分区、
   基础 assets、分区表或 OTA 数据。
5. 皮肤模式下状态回读允许 `active_valid=false` 且 `rollback_available=true`；既有回退入口
   在此状态下恢复保留壁纸。恢复后清空 `previous_slot`，避免把同一槽误报为可再次回退。
6. 重启回执丢失时，上层只等待新连接并核对“无活动壁纸且存在可恢复槽”，不重复发送
   NVS 写入或重启。

## 实现证据

2026-09-14 经用户明确授权，0011 的 3,983,664 字节应用镜像仅写入 COM3 的
`0x20000` 应用分区。设备身份仍为 ESP32-S3、MAC 尾号 `6d:38`；esptool
写入哈希和随后独立执行的 `verify_flash` 均通过。该操作没有写 NVS、分区表、基础
assets 或动态壁纸 A/B 槽。烧录前读取的完整 0010 应用分区继续作为回滚点。

烧录与二进制一致只证明设备运行所需代码已经写入；皮肤模式状态回读、屏幕实际显示和
保留壁纸恢复仍须在服务启动、设备重连后逐项验收。

## 权衡与失败预演

- 这次切换需要 0011 应用固件；旧固件会返回工具不可用，控制台必须保留壁纸并显示失败。
- NVS 指针写入成功但设备未重启时，当前画面可能短暂仍是壁纸；页面将操作描述为需要重启，
  并在重连后刷新状态。
- 保留壁纸会占用原 A/B 槽，但可快速恢复，也避免为了试皮肤重复擦写 Flash。
- 若保留槽损坏，状态不会声称可恢复；几何皮肤仍是固件内置回退。
- 回退 0011 应用代码即可移除新工具；现有皮肤和壁纸内容格式都没有变化。
