# ADR-0008：可替换记忆方法、实验协议与文字入口

- 状态：已接受；A/B 已实施，C 最小版已离线实现（由 ADR-0009 细化），D1/D2 未实施。
- 日期：2026-09-03。
- 部分替代 ADR-0007 的“四页完成后再做记忆研究”执行顺序；其本机访问、安全、受限设备控制与隐私边界继续有效。
- 保留 ADR-0001 的模块化组织原则，不据此新增服务、拆仓库或承诺单进程涵盖所有论文环境。

## 背景与用户决定

PC 与圆屏的合成记忆闭环已经验证，控制台已有设备和记忆管理页。用户明确要求：除了给小智增加记忆，还要能复现论文并与自己的方法比较；新增网页打字聊天，避免只能用语音体验。
此前按语义检索、分类、更新、遗忘、画像顺序扩展的是我们自己的方法，已有合成 runner 则是工程验收/上下文消融，并非跨论文比较平台。

用户已同意：一个仓库、三类职责；完整记忆方法可替换，内部结构不强制统一；实验协议决定可见信息、更新时间和评分方式。

## 决定

1. 区分研究平台（数据、协议、隔离、预算、评分与版本）、方法（形成/演化/检索及自身状态）、应用/任务执行端（网页、小智、任务环境）。我们自己的方法也作为被测对象，不享有固定 L1 格式或评分真值的特权。
2. 第一版只面向外置、显式记忆方法。参数记忆、隐藏状态/KV 注入、与执行策略深耦合的方法不承诺可直接替换；必要时以后按完整系统比较，并披露不止记忆不同。
3. 平台公共方法契约不依赖 AtomicMemory、SQLite、小智或某款模型。方法内部可复用已有核心组件或运行于独立环境；不动态加载用户输入的任意代码。
4. 首先支持整套方法，再按研究问题做内部组件消融。形成、演化和检索是职责，不强迫每种方法按每轮固定顺序执行。
5. 首个正式协议为历史回放与冻结问答：保留原始角色/会话/时间，不重新生成助手历史；等待记忆构建完成，隔离每道独立问题的临时上下文；参考答案/证据标签仅用于评分。冻结要求实际验证，不能只靠能力布尔值。
6. 反馈学习另立协议，明确反馈内容/时机、尝试预算、状态保留范围和冻结迁移阶段。独立运行隔离不等于持续学习的每道题清库。MemRL 是设计检验案例，不是已接入方法。
7. 实验运行记录区分 completed/failed/unsupported/interrupted，并单列覆盖率和故障；不能静默剔除失败样例。记录方法及其内部模型、回答/评分模型、数据/提示/代码版本、预算、顺序、时间和实际输入输出。
8. 日常网页和圆屏目标为同一用户/方法/长期记忆空间、独立当前会话，网页不默认驱动圆屏播放。实验空间始终独立，不能默认把日常对话变成研究数据。新会话不等于删长期记忆。
9. 不急于新增独立记忆服务。先复用业务逻辑，再根据双入口并发、配置一致性和连接所有权选择部署方式。未知值、不提供过程、无检索结果、调用失败必须区分。

## 执行路线与完成标准

- A：包装 `longmemory_v1`、增加方法级入口并保持旧 CLI/小智行为；旧测试与新方法契约回归通过。
- B：文字对话与每轮基础过程展示，检查共享长期记忆、独立会话、并发/重复提交和模型失败；不等待完整分析中心才提供文字入口。
- C：简单对话分块检索对照、完整历史元数据、冻结协议与逐题报告。先在合成数据验证隔离与防泄漏，再接核查过的公开基准。若选取新依赖，先说明用途和范围。
- D：选择共同任务适配第一篇论文；按可复现差距选择算法改进，不把候选功能当作必须依次完成的研究成果。

## 迁移与风险

不搬走或复制现有核心算法、不删除旧测试/报告，不以此次边界改造为由迁移个人库。未来新建会话或轨迹的持久化需要另行说明影响。
旧聊天/管理 DTO 仍围绕 L1；阶段 A 保留仅针对基线的兼容装配，不能向外宣称任意方法已能使用旧聊天管理 API。
接口设计可能过早抽象，因此用第二种实际方法检验，而非一次创建所有论文目录。预计先付出适配与协议实现成本，不承诺工期或算法收益。
错误反馈可能教坏方法；事实可信度不等于经验效用。模型、裁判或反馈差异必须披露，统计重复尝试和学习构建成本。

## 阅读依据与解释边界

- Hu 等，Memory in the Age of AI Agents，arXiv:2512.13564v2：形式/功能/动态过程帮助划定方法范围，不是必须实现的目录树或行业标准。
- Zhang 等，MemRL，arXiv:2601.03192v2：经验形成、选择与反馈更新说明只返回检索文本的固定流程不足以覆盖反馈学习。
- 以上是架构设计依据，不是已复现论文或已验证其全部结论；未下载/安装论文运行依赖。

## 阶段 A 实际实现

新增标准库中立契约、显式工厂、基线包装；拆分 observe 与 recall，旧 prepare 仍先写后查。
中立事件保存原 ID/角色/带时区的 L0 时间；L1 recorded_at 仍是本次提取时间，不伪装成事实生效时间。
现有 V3 L0 没有会话列，带 session_id 的调用明确拒绝；反馈学习和冻结评估能力均声明不支持。同步就绪不代表支持后台任务。
单次 observe 沿用旧存储的逐步提交，尚无整轮事务、幂等重试、并发快照或完成的实验 runner；失败不应自动重试。旧小智只保存用户 ASR 正文，尚未补齐双方历史。
无依赖/端口/schema 变更，未打开个人库、操作圆屏、调用校园模型或提交推送。

## 阶段 B 实施补记（2026-09-03，不改写阶段 A 的历史限制）

为避免自动迁移个人库，网页使用已有 V3 库的严格打开模式。短期会话暂存服务器内存、独立于小智连接；双方消息仍写入原 L0，网页会话映射/逐轮轨迹不持久化。刷新另开会话，服务重启不恢复列表；完整历史元数据仍属于 C。

新增每事件原子写事务、召回及证据读快照、网页会话内请求幂等缓存、并发及容量限制。故障分阶段报告，不把模型失败当成未记住，也不承诺跨崩溃 exactly-once。长期记忆的整个实验冻结仍未实现。

不新增依赖、不改本机监听范围，沿用纯文本渲染和 CSRF 防护；网页写入需显式开启，不驱动设备播放。模型使用已有环境配置，助手角色使用现有提示文件；小智 YAML 与网页环境/启动参数尚未自动同步，不宣称已实现统一配置中心。
