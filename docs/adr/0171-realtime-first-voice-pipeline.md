# ADR-0171：实时优先的圆屏语音链路

- 日期：2026-09-15
- 状态：已实施并完成隔离性能验证，圆屏实机验收待完成
- 决定来源：用户明确要求以实时性为第一目标优化当前 CosyVoice 模式。

## 背景

HighQoS 修复使本地声音生成明显改善，但首句仍有等待。当前控制桥可取得的一轮
无正文 V6 记录中，记忆准备 1ms、回答首字 2397ms、TTS 开始 2429ms、首音频发送
3852ms，首段生成 1447ms、可播放 1980ms。该记录没有输入时序，不能直接称为
“停嘴到首声 3.85 秒”，也不能证明它就是用户最后一次测试。

检查源码确认，上游已经关闭官方 DeepSeek 深度思考、使用流式响应，并复用 SDK
客户端；这些不能重复算成本轮优化。客户端空闲连接期限与客户端对象寿命不同，
仍需实测跨语音轮次是否重新建立连接。

## 范围与完成条件

本轮包含：语音专用表达规则、有限的一次提前听写、原策略对照入口、无正文观测、
合成输入和真实官方接口的受控性能验证。保留自然 CosyVoice 声线、自然标点分段、
既有播放和取消机制。新增的优化只在 Xiaozhi 适配进程生效。

不包含：新增依赖或模型、校园接口、个人记忆库或私人音频访问、固件更换、记忆算法
调整、自动切换豆包、缩短完整停嘴确认阈值。供应商响应速度和真实扬声器体验需要
分别验收，不能用提示词改动或单项测试声称“已经实时”。

软件完成条件：正常和失败回退、续说废弃、reset/close、共享模型串行、启动模式
透传、敏感字段拒绝及原链路回归通过；同样合成输入的完整转写不变、正式端点前
提交数为零；真实测量记录环境和边界。日用验收须另由圆屏测试确认。

## 决定

1. 启动面板提供 `voice_latency_mode=realtime|original`，缺省实时优先，停止重启
   后生效。原策略恢复此前请求表达与输入处理，保留此前已验证的 CosyVoice 修复。
   豆包完整语音模式独立，不使用本地预识别或此表达策略。
2. 回答请求临时追加口语表达偏好：首句直接给有用信息，以简短完整自然句收束；
   普通问题默认 1–3 短句。复杂问题、用户详细要求、证据与工具条件继续保留。
   不硬截回答、不篡改原会话、不先播放无内容的垫话，不改网页策略。
3. 预识别只面向当前本地 SenseVoiceSmall、16kHz 单声道 60ms PCM。静音约 300ms
   时对 1–8 秒快照每轮至多计算一次；不改变原 600–700ms 停嘴档位。手动模式、
   声纹、保存原始音频等不满足既有边界的路径继续原行为。
4. 正式端点仍是唯一提交入口。复用须验证连接代次、最后发声及音频前缀；续说、
   reset、close 或快照不匹配均废弃。候选只存在内存，不写音频、转写或记忆。
   失败和空结果退回完整识别。
5. FunASR `generate` 会修改共享 kwargs，正式与提前推理必须使用同一实际线程锁。
   忙时跳过预取；取消 asyncio 等待不等于取消底层推理。误触发后尚未完成的任务
   仍可能让正式识别短暂排队，必须观察失效率与排队耗时。
6. 保留 V6 的正式端点后等待指标，另提供预取耗时、重叠量与复用次数。端点后的
   `asr_processing_ms=0` 只能表示结果已经准备好，不能宣称模型推理耗时为零。
7. 实际 SDK 空闲七秒对照确认 HTTP/1.1 仅延长连接期限仍会重新建连，而 HTTP/2
   加 120 秒期限能够复用，TCP/TLS 新建事件均为零。因此只对官方 DeepSeek
   圆屏 provider 启用这一组合；使用公开客户端构造，保留认证、代理和超时默认，
   缺少 HTTP/2 可选依赖时回到原客户端。不安装依赖、不发送后台预热请求。

## 取舍与回退

提前听写可将已经发生的计算与等待重叠，代价是停顿后继续说话可能浪费一次识别。
如果 VAD 漏检轻声尾音，较早快照也可能丢掉尾字；需以真实轻声和续说测试验收。
短句表达主要控制首段和整体音频长度，不能消除云端首字波动。保留短开头合并保护，
不为抢首声重新放出很短的寒暄而造成下一段长停顿。
HTTP/2 复用主要改善连续聊天；首次、长时间空闲或远端断连仍可能重新建连。

切回启动面板“原策略（对照）”并停止重启，恢复此前语音行为。所有优化位于适配层，
LongMemory 仍只接收正式识别完成的一次文本，不知道预取候选或声音供应商。
