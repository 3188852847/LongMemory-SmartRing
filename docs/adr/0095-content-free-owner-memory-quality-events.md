# ADR-0095：不保留正文的所有者记忆质量事件

- 状态：已接受
- 日期：2026-09-09

## 背景

所有者现在可从未关联的用户 L0 显式补成 L1。仅查看 `memory_evidence` 无法区分该证据来自日常提取还是人工补救；若不保留这个信号，后续就无法用真实样本定位提取漏记。

把原话或规范化事实再复制到质量日志会扩大个人信息留存面，也会产生第二份难以同步删除的数据。

## 决定

SQLite V29 新增 `memory_quality_events`：

1. 当所有者明确执行“补成 L1”且 L1/证据写入成功时，同一事务记录 `owner_confirmed_missed_extraction`。
2. 事件只保存事件 ID、L0 ID、L1 ID、解决方式（新建或追加证据）和 UTC 时间，不保存原话或 L1 正文。
3. 每条 L0 对该类事件最多一条；页面 revision 和事务内关联复核继续防止重复操作。
4. V28→V29 只创建空表和索引，不根据历史证据时间猜测或回填漏记。
5. 每日回顾只显示当天明确确认数；该数字不是自动提取错误率。

## 后果与边界

- 后续可按 L0 ID 回到唯一原话做离线错误分析，不需要在事件表再存正文。
- 事件证明“所有者当时确认并执行补录”，不证明模型必然应在原轮写入，也不自动给定错误原因。
- 后续删除 L1 不删除该质量事件；事件仍可用于统计历史质量行为，但不能用它恢复被删正文。
- 纠正、事实变化和删除继续使用各自的证据或审计语义；本表不成为泛化产品分析埋点。
