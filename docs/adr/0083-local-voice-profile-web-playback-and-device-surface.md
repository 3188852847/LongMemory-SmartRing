# ADR-0083：本机声音方案、网页朗读与圆屏受控能力面

## 背景

VoxCPM2 已通过固定环回服务接入 Xiaozhi，但此前只能使用固定默认参数；控制台也只能调圆屏音量。日常试听必须反复唤醒圆屏，无法快速比较声音。固件通用 MCP 实现还注册了设备状态、亮度和主题，只是本项目的窄桥未放行。

## 决定

1. VoxCPM2 声音方案保存在被 Git 忽略的 `data/audio/voxcpm-settings.json`。方案只包含受控参考 WAV 的相对标识、最长 100 字的表达指令、1–3 的 CFG 和三档推理步数；不接受浏览器提供的模型路径或任意磁盘路径。
2. 参考 WAV 决定音色，表达指令影响语气/风格，CFG 与推理步数分别表示指令强度和质量成本。界面不得把后三者误称为“音色滑块”。
3. 网页回答可通过当前 TTS 后端在电脑播放。按钮停止与浏览器本地麦克风能量打断均不写记忆、不保存录音；麦克风必须由用户显式授权。网页结果不等于圆屏播放或圆屏全双工打断验收。
4. 圆屏控制桥新增显式设备快照、亮度和明暗主题；仍只执行设备实时上报且模式匹配的 MCP 工具。写操作先读、调用、再回读，不自动重试。状态投影删除 SSID，只展示电量/充电、信号强弱和温度等必要字段。握手中的 AEC 只作为诊断能力显示，不据此宣称自由说话打断已经可用。
5. 重启、配网、OTA、任意 MCP 调用和固件写入不进入本次控制面。

## 后果

- 网页和圆屏下一次 VoxCPM2 合成共享同一声音方案，无需重启模型或 Xiaozhi。
- 参考音频和声音配置属于本机私有运行数据，不提交仓库；声音克隆素材的授权与质量仍由用户负责。
- 圆屏 B V2 为预编译固件，本地只有旧源码快照；页面能力必须以实时握手为准，源码审计只作为候选能力证据。
- 圆屏“直接说话打断”是否可用取决于设备上报 AEC、监听模式和固件构建，需实机单独验收。
- 网页打断开关不代表持续录音：权限检查后立即释放，只有实际朗读期间才占用麦克风；停止、结束、失败、关闭和卸载都释放音频资源。
- 网页朗读采用浏览器进程内单实例租约；新朗读开始前停止上一条并走同一资源释放路径，避免多个历史回答叠音或同时占用麦克风。该租约不跨浏览器，也不控制圆屏播放。
