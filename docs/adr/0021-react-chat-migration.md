# ADR-0021：P2 聊天前端采用 React 与 Ant Design

状态：已被 ADR-0032 部分取代；聊天迁移决策继续有效，“不整体迁移”边界不再有效。日期：2026-09-04。

## 背景与决定

用户已选择 React，并同意采用 antd。P2 将继续加入角色编辑与声音设置，需要明确管理编辑值、生效值、请求状态和共享组件。采用 React + TypeScript + Vite + antd，先迁移聊天页，不整体重写控制台。不引入 Ant Design X、全局状态库、SSR 或独立 Node 服务。

本决定取代 ADR-0020 对后续聊天页继续使用原生前端的选择；保留其历史记录和已完成外观功能。采用框架是维护成本取舍，不意味着原生实现不能完成这些功能。

## 边界

- 既有 Python API、认证、CSRF、记忆算法和数据库不变；不读写真实数据验证迁移。
- 设备、记忆、实验页面保留原实现。前端打包资源仍由本机 Python 服务提供，日常启动不增加终端。
- 不使用 CDN、远程字体或统计；密钥始终留在后端。
- 新页面先以独立入口验证，验收前不替换 `/chat`。旧页保留回退能力。
- 依赖安装前说明用途与影响，安装后提交锁文件；不将开发环境的机器专属绝对路径写入项目配置。

## 风险与验收

antd 动态样式与现有 CSP 存在适配工作。官方提供 nonce 配置，但不能据此宣称全部组件、主题和弹窗已兼容。不为迁移启用不受限的内联脚本或关闭安全头。具体检查与交付顺序见[迁移清单](../architecture/react-chat-migration.md)。

收益是组件与状态职责更清晰；代价是增加构建、依赖升级和前端测试成本。迁移只做功能对齐，不同时改进记忆质量，避免无法定位行为差异。
