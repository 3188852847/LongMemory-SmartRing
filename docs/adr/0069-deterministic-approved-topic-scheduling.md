# ADR-0069：确定性投递已批准的记忆话题

## 背景

ADR-0068 建立了所有者明确批准的话题素材，但保存素材本身不会投递。P4.6 下一步需要把素材接入已经验证的定时链，同时保留默认关闭、来源追溯和无模型选择，避免升级后突然朗读个人信息。

## 决定

1. SQLite V18 为主动设置增加独立 `topic_enabled`，默认关闭。它只有在总许可与后台定时问候都开启时才允许开启；关闭上层开关会同时关闭它。
2. 到达显式定时点后，系统仅从 `active` 素材和当前有效的 `active` L2 场景中选择。选择规则固定为“最久未使用优先，未使用素材优先”，以创建时间和 ID 稳定破平局，不调用模型。
3. 没有可用素材时回退到用户原本填写的固定问候，不将缺少素材视为错误，也不临时读取其他 L1/L2/L3 编造话题。
4. `proactive_outreach` 保存可空的 `topic_seed_id` 与 `topic_seed_revision`，两者必须同时存在或同时为空。素材来源与候选、初始事件在同一数据库事务中形成，后续历史接口一并展示。
5. 话题消息继续使用 `explicit_schedule` 触发种类和当地日期幂等键，只把原因标记为 `approved_memory_topic`。既有当天已聊天、勿扰、频率、会话活跃、设备状态、过期与不补发规则全部保持。

## 理由

可播短句已经获得明确许可，因此无需再让模型判断隐私。确定性轮换比临时生成更可复现，也能在较少素材下避免永远重复第一条。把来源直接放入主动消息投影，可以保证运行记录不依赖当前页面状态才能解释。

## 后果

- 数据库升级与新增素材都不会自动启用记忆话题；必须由所有者显式开启并保存。
- 第一版只改变同一个固定定时点的内容来源，不增加额外每日联系次数。
- 素材文字更新采用新素材或后续版本机制；已经生成的账本记录继续指向当时 revision。
- 当前仍只能证明服务端排队，不能自动声称圆屏完成播放。

## 验证

- V17→V18 合成迁移验证新增开关关闭且来源字段存在。
- 真实临时 SQLite + 模拟设备验证已批准短句取代固定问候，并把素材 ID/revision 写入账本。
- 原固定问候、当天聊过跳过、每日幂等、手动测试和历史接口回归保持通过。
