# ADR-0027：网页与圆屏共享常驻 Memory Runtime

- 日期：2026-09-05
- 状态：已实现并通过真实圆屏双入口验收
- 取代范围：仅取代 ADR-0006 在统一启动模式下“每轮启动子进程”的传输决定；旧管道入口继续作为显式回退

## 背景

网页聊天与小智虽然指向同一个 SQLite 文件，但此前各自装配记忆引擎：网页每轮新建连接，小智每句话再启动一个 Python 3.12 子进程。这样可以完成最小演示，却不适合后续常驻语义模型、记忆整合和日常状态观察，也容易让“共享数据库”被误解为“共享运行时”。

## 决定

1. 控制台进程持有一个 `MemoryRuntime` 和一个长期存活的 `longmemory_v1` 实例；网页与圆屏都调用它。
2. Runtime 对 SQLite 操作加进程内互斥锁。用户写入与本轮召回不可交错，模型回答不占用该锁。
3. 小智只经 `127.0.0.1` 内部 HTTP 接口调用 Runtime。统一启动器每次生成随机令牌，并以环境变量同时传给两个受管进程；令牌不进入浏览器、命令行、YAML、数据库或 Git。
4. 内部写入请求失败后不自动重试，也不自动切换到子进程，因为服务端可能已经提交但响应丢失，重试会产生重复 L0/证据。
5. 未通过统一启动器运行时，原 stdin JSON 子进程仍是明确的 `subprocess` 回退；不是后台自动容错。
6. 本切片不改 schema、规则提取、关键词召回、上下文格式或实验方法。

## 安全与失败边界

- 内部接口同时要求回环来源、精确 Host 和 Bearer 令牌；浏览器会话/CSRF 与内部进程令牌是两套不同用途的边界。
- 令牌只证明调用者拿到了同一次启动环境，不构成多用户认证，也不防御已能读取同进程环境的本机恶意程序。
- Runtime 串行化记忆操作，适合当前单用户日常规模；不是多进程数据库服务或高并发架构。
- Runtime 或内部网络失败时，本轮圆屏记忆调用明确失败。不会用空上下文伪装成功，也不会猜测写入是否发生。

## 后果

- 圆屏刚写入的 L0/L1 可被网页同一 Runtime 立即召回，反向亦然；两端当前短期会话仍相互独立。
- 后续本地 Embedding、L2 整合和 L3 画像可以挂在一个生命周期上，不必每句话重新加载。
- 小智提供器模板升级后需执行一次受控 `update-memory`；工具只覆盖已知旧版本，拒绝覆盖陌生或用户修改过的文件。
- 圆屏助手回答仍由小智保存其短期上下文，当前 LongMemory 只接收圆屏用户 ASR 正文；这不是完整双向 L0 会话统一。

## 验收记录

2026-09-06，用户按“网页写入后由圆屏召回、圆屏写入后由网页召回”的双向步骤完成实机测试并确认通过。该结果证明统一启动路径共享 Runtime 已生效；不证明当前规则提取、关键词召回或回答质量已经满足长期日常使用。
