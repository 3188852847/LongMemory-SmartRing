# ADR-0064：控制台手动主动问候验证

- 状态：已接受并实现；圆屏实机播放待用户验收。
- 日期：2026-09-07。
- 承接：ADR-0058、ADR-0059、ADR-0060、ADR-0061、ADR-0062、ADR-0063。

## 背景

P4.4 已分别具备持久许可设置、事件账本、确定性策略、可信运行状态和小智投递适配器，但缺少一个安全的运行入口验证这些组件确实能连成一条链。直接先做后台定时器会同时引入触发时间、内容生成、重启恢复和真实设备副作用，失败时难以判断是哪一层的问题。

## 决定

1. 在 React 主动交流设置页提供“发送一次测试问候”。它只能由已建立本机同源会话的用户显式点击，不由页面加载、轮询或后台任务调用。
2. `POST /api/proactive-outreach/test` 使用严格完整契约、同源 Cookie、CSRF、当前设置 revision 和规范 UUID 请求 ID。相同请求 ID 命中已有账本结果后直接返回，不再次探测或调用设备。
3. 测试文本限制为去除不了歧义的 1–80 个单行字符，不调用模型，不读取 L0–L3，也不把内容写入个人记忆。
4. 入口仍执行完整确定性策略：总开关、允许时段、勿扰、频率、待回应和用户当前会话均可拦截。页面有未保存设置时禁用测试，避免“看见的规则”与实际执行规则不一致。
5. 允许后先写候选和 `queued` 事件，再调用既有小智窄适配器；离线、忙碌或队列失败写为稳定失败状态，不重试。当前成功只表示小智服务端接受排队，不表示圆屏已经播放。
6. 该入口与设备写操作共享互斥锁。本切片不新增定时器、后台扫描、模型话题生成或自动重试。

## 后果与局限

现在可以在不引入后台自主行为的前提下，验证 P4.4 的完整工程链和幂等边界。它会产生真实主动交流账本记录并参与每日次数与最短间隔，因此是一次真实策略尝试，不是无状态试听按钮。由于小智协议尚无播放回执，实机是否发声仍需用户观察；不能把 `queued` 写成 `played`。

## 验证

- HTTP 回环测试覆盖 CSRF、严格输入、设置 revision、成功排队、重复请求不重播和稳定失败记录。
- SQLite 集成测试覆盖按主体和幂等键重开读取。
- React 测试覆盖只有显式点击才写请求，并确认页面不把排队描述成已播放。
- 测试使用合成数据库和模拟控制桥，不读取个人数据库、不连接模型或圆屏。
