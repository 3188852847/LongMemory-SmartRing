# ADR-0115：圆屏当前回答的确定性中止

日期：2026-09-10
状态：接受

## 背景

圆屏语音回答可能过长，自然说话打断又尚未建立可靠的 AEC 双工链路。等待这项算法问题解决之前，日常使用仍需要一个不依赖语音识别的确定性停止入口。

## 决定

复用当前 Xiaozhi 服务端已有的 `handleAbortMessage`，由本机控制桥暴露单一白名单操作“停止当前回答”。该操作设置 `client_abort`，清空 LLM/TTS 与音频流控队列，并向当前唯一、已完成绑定的圆屏连接发送 `tts stop`。

控制台按钮不进行二次确认，不重试，不删除对话或记忆。当前已空闲时返回 `already_idle`，不发指令。

当前设备协议没有“扬声器已停止播放”回执，因此成功结果只表示服务端队列已中止且停止指令已发出，显式标记 `device_acknowledgement=unavailable`。

## 后果

- 在自然说话打断尚未可靠时，用户可从本机控制台确定性结束过长回答。
- 这不等于 AEC、自然插话或设备播放回执已完成；三者仍是独立的后续问题。
- 页面和客户端只接受严格的两种结果，未知字段不会向上层扩散。
