# ADR-0005：提前圆屏演示，优先验证私有部署模型

- 状态：已接受
- 日期：2026-09-03
- 依据：用户明确要求提前圆屏演示，并提供私有部署模型接口。
- 关联：ADR-0001、ADR-0002、ADR-0004；不改变独立 Memory Core 边界。

## 背景与事实

PC 确定性闭环已经实现，但真实模型和 Xiaozhi 适配器仍为占位文件。
圆屏已有基础硬件识别记录，录音、播放、Wi-Fi 和端到端记忆演示尚未验证。
原路线把基础设备接入放在较晚研究版本之后，不利于尽早检验真实交互链路。

用户提供模型标识 `DeepSeek-V4-Flash`，作为优先接入候选。
它是服务请求中的模型名称，不据此断言模型实际身份、能力或部署实现。
服务在远程主机上，当前提供 HTTP 地址；私有部署不等于本机离线运行，
也不保证数据不被服务端记录。地址与密钥不写入可提交配置。

本次无鉴权、无个人数据的探测中，标准 `/v1/models` 和
`/v1/chat/completions` 均返回 HTTP 404。随后用户确认该服务必须连接校园网，
并说明连接校园网与当前助手会话不能同时进行。上述探测不能用于判断校园网内
接口是否正常；助手停止网络探测，由用户在校园网内负责真实调用验证。
路径、鉴权和响应格式仍待用户验证，不能宣称已经接入成功。

## 决定

1. 优先完成模型接口的合成请求验证和回答适配器，再补齐 V0.1 最小日志与评估。
2. 在 V0.1 PC 最小验收后，立即执行独立的 V0.1-Demo 圆屏演示里程碑。
3. 不以语义检索、冲突更新、遗忘和整合作为圆屏演示前置条件。
4. 优先复用 Xiaozhi 的语音和设备通信能力，所选实现和具体版本需先检查再确定。
5. Memory Core 不依赖固件或 Xiaozhi。通过适配层接入经核实的记忆接口，
   不直接把包含回答生成的整个 ChatService 塞进记忆插槽，避免重复生成回答。
6. SQLite 与原始对话仍位于电脑或服务端，不迁移到 ESP32-S3。
7. 模型配置从本地环境读取；Key 不进入源码、测试集、日志、Git 或固件。
   助手不经 HTTP 发送 Key；校园网本身不等于传输加密，真实数据使用前先确认
   HTTPS 或受保护网络通道及服务方权限。
8. 保留 Fake 回答生成器作为离线回归替身；真实模型连接失败必须明确报错，
   不暗中回退为 Fake 并宣称成功。
9. 采用离线开发与校园网验证分离的协作方式：助手实现适配器、配置校验、模拟
   HTTP 响应测试和可重复的验证入口；用户切换校园网后执行真实验证，再提供脱敏结果。
   模拟测试通过不等于真实服务验证通过，不要求用户同时连接两种网络。

## 最小演示验收

- 圆屏能够经选定服务端输入和输出，基本语音/显示链路可用。
- 使用明确标记的合成数据，通过圆屏陈述事实、结束会话、重启记忆服务，再提问回忆。
- 可以核对保存、检索和上下文使用的记忆及来源；无依据的问题不编造个人事实。
- 记录代码与固件版本、模型服务标识、配置和运行条件。
- PC 对照测试仍可独立运行；硬件演示成功不能替代记忆评估。

## 收益、成本与回退

收益是提前暴露设备和服务端接口问题，并尽早得到可展示的完整链路。
成本是提前承担网络、ASR/TTS、音频、固件和服务器配置工作，可能推迟后续研究版本；
在选定服务端和确认网络前，不给出未经验证的工期承诺。

设备链路阻塞时继续完成 PC 模型与评估工作，保留 PC 演示作为降级路径，
但圆屏里程碑保持未完成。硬件接入必须保留原固件恢复方式，不覆盖唯一备份。
