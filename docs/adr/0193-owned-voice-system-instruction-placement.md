# ADR-0193：圆屏公共动态约束放在前导system

2026-10-20。状态：候选，待精确提交审查及受控真实回答验证。

## 事实与决定

`34f9022` 的 `voice_web_search.web_response` 在普通回答/联网决策前，把本模块的日期、搜索和隐私约束追加为最后一条system；搜索完成后又追加另一条system。调用者普通对话原本以user结束，第一处追加会改变其末尾角色；第二处则把工具结果从末尾移开。该构造点为项目自身所有，不依赖对学校后端类型的推断。

只调整这两个自有追加点：复制消息列表及顶层字典，首消息为文本system时将本模块约束合入该文本；否则新增前导system，不转换结构化content。搜索完成约束采用同一规则；assistant工具调用和tool结果保持相邻、ID/参数/结果及原消息顺序不变。生成二次回答用独立消息快照，不能反向修改第一阶段请求或调用者对话。

不是全局消息规范化：原有中途system、角色/记忆文本、user/assistant/tool和未知字段都不搬动、不删改。无用户输入时不伪造用户消息。保留原日期与约束、每轮至多一次搜索和只上传当前原问句的行为；不改模型/供应商、stop、特殊token参数或已有显式think解析器。

## 机制解释与验证边界

[vLLM的V4编码源码](https://docs.vllm.ai/en/v0.23.0/api/vllm/tokenizers/deepseek_v4_encoding/)在相应用户/开发者末尾路径添加Assistant生成前缀。它说明末尾角色可能影响模板转移，不证明学校部署了此版本或存在该具体故障。项目离线对照可证明本次消息形状修正；合成角色编码器只建模此分支，不是学校tokenizer。

真实异常目前仅依据根会话转交的X单轮元数据：model路径、Unicode EOS、未检出think标签，未复制个人全文。完整问候内容是否恢复相关性、EOS是否消失仍需单独验收；“有首content”不足以通过。发布由主会话确认，任何真实合成请求仍须用原未重置的共享调用门，不新增池或自动重试。回退仅撤销这两个构造点，不迁移数据库或改变正式配置。实现与证据见[V交付记录](../development/parallel/V-system-message-order-20261020.md)。
