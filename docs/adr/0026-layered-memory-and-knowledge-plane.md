# ADR-0026：四层个人记忆、可信性边界与独立知识平面

- 日期：2026-09-05。
- 状态：已接受（用户同意四层目标及知识库联动方向）。
- 补充 ADR-0002、ADR-0004 和 ADR-0015；不把本决定解释为相关功能已经实现。

## 背景

当前日常 `longmemory_v1` 只形成 L0 原始消息与 L1 原子记忆，提取仍以规则为主，召回仍以关键词为主。网页和圆屏虽可指向同一数据库，但小智仍以逐轮子进程调用，不是统一常驻的 Memory Runtime。产品目标还要求长期认识用户的偏好、生活场景和行为模式，并能把个人背景与外部文档知识结合起来回答。

讨论参考了 TencentDB Agent Memory 的 L0 对话、L1 原子记忆、L2 场景、L3 用户画像分层，以及 Semantica 的知识摄取、来源、双时间、冲突、实体关系和 GraphRAG 模块。参考项目的命名和实现不自动成为本项目事实，也不构成直接引入依赖的决定。

## 决定

### 1. 四层个人记忆是目标抽象

- L0：原始对话与必要上下文，是不可原地改写的证据。
- L1：由 L0 提取的原子事实、偏好、事件和约束。
- L2：由一组 L1 组织出的场景、主题或阶段性记忆。
- L3：由长期、多来源证据支持的用户画像、稳定偏好和行为模式。

“双层表示”不作为另一套层级，而定义为可信性边界：L0 属于证据层；L1/L2/L3 属于可重新生成、可失效和可纠正的派生层。每个派生结论必须保留向下追溯关系。上层不得覆盖下层历史来制造一致性。

### 2. 个人记忆与知识库并列

外部论文、说明书、网页和其他文档进入独立知识平面，不作为 L4，也不自动成为用户事实。未来通过中立 `KnowledgeProvider` 契约提供摄取、检索和证据读取；个人记忆继续通过 `MemoryMethod`/Memory Core 管理。上下文编排层根据问题分别调用个人记忆、知识库或两者，并保留来源类别。

至少区分 `user_stated`、`system_observed`、`model_inferred`、`document_claim` 等来源。文档主张不得无证据转换成个人属性；模型推断不得伪装成用户陈述。

### 3. 渐进落地，不直接引入大型框架

P3 先建立框架无关的统一常驻 Memory Runtime，再完善 L0/L1、日常语义/混合召回和纠正；之后才增加 L2、L3 与轻量知识库。当前不以 LangChain、LangGraph、Deep Agents 或 Semantica 作为 Memory Core 地基，也不安装这些依赖。

Semantica 只作为未来可选的 `KnowledgeProvider` 或独立实验实现。只有真实数据证明需要实体消歧、多跳关系检索、图冲突或标准化来源图时，才做隔离验证；不得让其类型侵入个人记忆领域模型。LangGraph 仅在 P4/P5 出现跨重启恢复、人工中断、复杂分支、取消或补偿等持久工作流需求时重新评估，并应位于编排层。

## 派生数据约束

- L1/L2/L3 需要来源、生成器版本、记录时间、适用时间、状态和必要置信信息；具体 schema 另行设计并迁移。
- 纠正与事实变化优先产生版本/取代关系，不原地掩盖旧事实。
- L2/L3 低频聚合，不在每句话后重建；触发条件和证据门槛需先通过合成测试。
- 删除或纠正 L0/L1 后，必须能找到受影响的上层派生项并使其失效或重建。
- 助手角色 `assistant_persona` 与 L3 用户画像 `user_profile` 永久分名。

## 后果与边界

收益是个人事实、生活场景、长期模式和外部知识各有明确职责，既能支持陪伴产品，也保留方法比较和替换空间。成本是需要新增统一运行时、分层 schema、聚合调度、来源图、迁移与控制台分层视图；错误也可能从 L1 逐层放大，因此 L2/L3 不得先于可靠 L0/L1 上线。

知识图谱不是默认前置条件。第一版知识库可只做文档、切片、向量和引用；关系图必须以具体检索失败为依据。GraphRAG 只能改善关系检索与可追溯性，不承诺消除模型幻觉。
