# ADR-0122：圆屏模型提取改为回答后受管补写

- 状态：已接受并实现
- 日期：2026-09-12

## 背景

圆屏真实时序显示，关键词或混合召回通常只需约 1–17 ms，而日常模型辅助 L1 提取常在回答模型启动前同步占用 2–5 秒。当前用户陈述尚未成为可跨轮使用的长期记忆，本轮回答通常不需要等待这次派生；继续同步会把记忆整理成本直接叠加到每次首声延迟。

## 决定

1. 只对圆屏入口和明确声明 `deferred_observation` 能力的方法启用延后提取；网页聊天、实验入口和规则提取保持原语义。
2. 收到圆屏用户文本后先同步归档 L0，再只用此前已经完成的 L1/L2/L3 召回并进入回答链。
3. 小智完成回答文本并提交助手 L0、召回索引后，由 Runtime 的单工作线程执行候选模型；模型调用不持 SQLite 互斥锁，最终 L1 与证据补写才进入互斥区。
4. 自然语言记忆操作、纠正、删除、陪伴设置及一次性互动设置继续同步执行，不进入延后队列。
5. 重复完成回执不重复提交；关闭 Runtime 时停止接收新任务、取消尚未开始的任务并等待已运行任务收尾，再关闭数据库连接。
6. Runtime 状态只暴露等待数量、运行数量和稳定失败代码，不暴露用户正文或供应商错误体。

## 理由

- 保留最不可替代的 L0 来源，同时把昂贵的派生步骤移出首声关键路径。
- 单工作线程限制模型并发；受管关闭比不可追踪的临时后台线程更安全。
- 明确能力门禁避免根据方法名称做产品特判，也不改变冻结实验条件。

## 后果与限制

- 当前这句话产生的 L1 不参与同一轮回答；它在回答完成后才对后续轮次可见。
- 如果进程在回答完成回执之前退出，L0 仍保留，但该条 L1 不会自动补写。历史 L0 重处理队列仍未实现。
- 回答刚结束便立刻发起下一轮时，补写可能仍在进行；此时只能使用此前已经完成的记忆。
- 这项优化减少的是回答前等待，不会加快回答模型、EdgeTTS 网络合成或设备播放本身。

## 回退

圆屏调用恢复为普通 `prepare_user` 即回到同步提取；数据库结构和已有 L0/L1 无需迁移或回滚。
