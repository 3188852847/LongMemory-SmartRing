# ADR-0144：默认关闭的日常 L1 证据充分性影子审计

- 状态：已接受
- 日期：2026-09-13

## 背景

冻结开发集已经证明当前复核契约值得进入真实分布观察，但小型合成集的 16/16 不能证明日常对话中可以安全过滤 L1。关键词、向量和融合分只表示相关性；主题相近的原子记忆仍可能没有回答问题所需的具体属性。

直接把模型判断接入正式上下文会同时改变回答行为、增加故障面并破坏与既有样本的可比性。日常观察还必须避免再复制一份私人问题和记忆正文。

## 决定

新增独立、默认关闭的 L1 证据充分性影子链路：

1. 只有显式开启时，共享 Runtime 才在正式 L1 召回刚完成时冻结候选快照；该快照早于 L2、L3 和临时互动指令拼接，因此只评价 L1。
2. 正式回答立即沿原路径继续。候选由单个后台工作线程提交给版本化充分性判定器，每个非空问题至多一次请求，失败不重试；任何旁路故障都不得使聊天失败。
3. SQLite V45 只追加运行身份、L0/L1 ID、排名、关键词/余弦/融合分、内容 SHA-256、封闭支持判断、原因码和模型/提示版本，不复制问题或候选正文。
4. 无候选时不调用模型，但仍记录确定性的完成状态，以区别“确实没有候选”和“功能没有运行”。
5. 控制台按需从既有 L0/L1 表读取当前正文，并核对当前指纹。所有者可对整轮支持集合追加“正确、错误、暂不确定”复核；修订号阻止陈旧页面覆盖新结论。
6. 影子结果不删除、不降权、不重排 L1，不修改回答、记忆或提取策略，也不自动成为训练标签。
7. 启动面板把开关保存为不含密钥的本机首选项，并明确提示开启后会增加后台模型调用。

## 后果

- 可以用真实日常样本测量主题相关但证据不足、漏掉支持证据和正文后来变化等现象，同时保留正式回答基线。
- 开启时，每个有 L1 候选的普通用户问题最多增加一次后台模型请求；这仍有成本和隐私影响，因此不能默认开启。
- V45 是只增表迁移；旧记录不回填，新账本从空表开始。
- 在形成带人工复核的足量样本、预先定义门控指标并完成回放前，仍不得把影子判断升级为正式过滤策略。
