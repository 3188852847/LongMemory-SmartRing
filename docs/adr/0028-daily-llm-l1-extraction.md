# ADR-0028：日常模型辅助 L1 提取采用 L0 优先与显式降级

- 状态：已接受，首个可选切片已实现；真实模型质量待验收
- 日期：2026-09-06

## 背景

P3.1 让网页与圆屏共用常驻 Runtime，但日常 `longmemory_v1` 仍靠规则提取。隔离实验已有严格 JSON 候选提取器，不过实验方法在候选失败时把 L0/L1 整批回滚。这保证冻结实验原子性，却会让日常产品在校园模型暂时不可用时丢失原始对话。

同时，“模型判断为 NOOP”和“模型根本没有完成提取”不能都表现为空写入。否则用户无法判断一条信息是不值得记，还是系统漏处理。

## 决定

1. 保留 `longmemory_v1` 规则提取作为默认稳定基线，不修改已有个人记忆。
2. 增加可选 `longmemory_daily_llm_v2`。复用实验版的来源绑定、严格 JSON、逐字摘录、整批校验和一次请求边界，不复用其 L0 回滚策略。
3. 日常模型模式先用独立事务提交 L0，再在事务外生成并校验 L1 候选，最后以另一个事务完成去重、L1 和证据写入。
4. 候选连接或格式失败时不自动重试、不静默切回规则：返回 `source_only / l1_extraction_failed`。L1 写事务失败则返回 `source_only / l1_persistence_failed`。两者都保留 L0；数据库仍可读取时允许本轮继续使用既有记忆回答。
5. 正常“不该记”返回 `completed` 与空写入；与失败状态分开。
6. 启动面板提供明确策略选择，初始值仍是规则基线。React 页面展示实际方法，并在 `source_only` 时显示警告。
7. 第一版仍只允许 `ADD/NOOP` 和 `user_stated`；不在此阶段实现 SUPERSEDE、语义去重、L2/L3 或语义召回。

## 理由

- L0 是后续重建 L1 的证据，日常使用中比一次派生结果更不可替代。
- 显式失败便于用户理解、后续重处理和故障统计，也避免规则降级掩盖模型质量。
- 策略可选并共用现有存储/召回，使提取升级可以独立回退，减少同时改变多个变量。

## 后果与成本

- 网页聊天仍在回答前完成一次模型提取；圆屏入口后来由 [ADR-0122](0122-defer-round-screen-l1-extraction.md) 调整为先保存 L0、回答完成后受管补写 L1。问句与助手消息仍由本地边界直接跳过。
- L0 与 L1 不再是一个数据库事务：进程可能在两者之间退出，结果是可识别的“只有来源”，不是丢失来源。当前尚无后台重处理队列。
- 模型候选通过结构和摘录校验不等于语义正确。合成日常开发集仅定义验收类别，真实学校模型仍需用户在校园网试用和人工查看。
- 检索仍为关键词，因此提取成功不保证“我叫什么”等跨表达问题能召回；这由 P3.2 下一切片的混合召回处理。

## 回退

停止服务，在启动面板改回“规则提取（稳定基线）”后重新启动。两种策略使用同一 V3 数据结构；回退不删除 L0/L1，也不批量重跑历史。
