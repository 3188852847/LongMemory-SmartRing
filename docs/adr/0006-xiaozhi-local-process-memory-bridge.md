# ADR-0006：小智通过本机子进程接入独立记忆用例

- 状态：已接受，V0.1-Demo 临时适配，依据用户授权继续接入长期记忆。
- 日期：2026-09-03；承接 ADR-0005，不替代 PC 历史验收。

## 已核实事实

本地小智快照 `eb4b28c59ed7ed885258498cf757ce14352d620e` 的 memory/base.py 定义 init_memory、query_memory、save_memory；connection.py 在回答前查询，断线守护线程保存，且非智控台模式共享初始 Memory 对象。
utils/dialogue.py 通过正则替换 `<memory>`，无标签时不插入；替换串需要处理反斜杠。实际 ASR 日志含 content/language/emotion JSON 封装。
小智 Python 3.10，本项目 Python 3.12（使用 StrEnum/datetime.UTC），不能直接混装。
用户 13:03 日志显示圆屏 ASR 输入、回复语音生成发送和再次监听，不代表记忆演示已经通过。

## 方案与决定

- 直接导入需要调整稳定环境/依赖，不采用。
- HTTP 服务可复用进程，但增加端口和服务生命周期，演示暂不采用。
- 采用本机 JSON 子进程：两套解释器独立，无新依赖或网络端口。代价是每轮启动进程的开销，完整语音延迟尚未测量。

抽出 MemoryTurnService 负责保存 L0、提取、去重、检索和上下文构造。PC ChatService 委托该用例后才生成回答；小智只调用记忆用例，不重复调用大模型或使用 Fake 答案充当记忆。

## 明确的契约与限制

1. 适配器 query_memory **先写后查，有副作用**；此特性仅属于小智适配层，不冒充纯查询接口。
2. ASR 正文以 USER 来源写入 L0；语言、情绪不当作个人事实。不保存原音频。
3. 断线 save_memory 显式空操作，避免重复提取历史及守护线程来不及保存。此阶段不归档小智助手回复到 LongMemory L0；PC 仍保存双方消息。
4. 每次调用独立打开/关闭数据库，20 秒超时失败即中止本轮，不自动降级/重试。失败或超时可能已保存部分记录，不能声称事务回滚；重说可能新增 L0 来源，正常精确重复不新增 L1。
5. 单个指定圆屏、独立演示库，主体仍为 user:self；不支持多人声纹或并发多设备。MAC 是自报标识、可冒充，不是安全认证。
6. 启动包装 launch_with_memory.py 为每个连接创建独立提供器，再调用上游初始化；不改上游源码。直接启动 app.py 会绕过包装，不是受支持的启用方式。
7. 数据和审计放 data/databases/xiaozhi-demo*.db 与 data/logs/xiaozhi-demo*.jsonl，Git 忽略，不沿用个人 PC 库。通过既有 PC CLI 查看来源和删除。
8. 新日志只有 ID/数量；上游日志仍可能有识别正文，不宣称全系统已脱敏。上下文标记为不可信用户陈述、转义标签和正则反斜杠，不宣称完整提示注入防御。

## 范围与验收

In Scope：单圆屏合成闭环、本机过程通信、来源/删除、失败可见和回退。
Out of Scope：助手完整归档、ASR 纠错、LLM 提取、事实冲突、多人、公开部署、语音删除命令。

离线验收：真实 3.10 → 3.12 → SQLite、重开召回、问句过滤、去重、删除、无结果、错误设备、失败不回退、上游提示替换和 PC 回归。
实机验收：说合成事实观察 added；重启小智清空会话后再问猫名、观察 retrieved/回答；未知毛色不猜测。目前实机记忆验收待用户执行。
