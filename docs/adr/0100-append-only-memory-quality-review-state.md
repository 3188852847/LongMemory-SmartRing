# ADR-0100：记忆质量样本使用只追加复核状态

## 背景

网页人工标记和圆屏明确反馈已经能形成跨日期诊断样本，并可定位当轮回答和召回证据。此前“需要核对的问题”会永久保留在默认列表中；即使所有者已经纠正记忆或确认它不是记忆问题，也无法区分待办与历史样本。

## 决定

1. SQLite V33 新增 `memory_feedback_review_events`，保存样本来源、目标 ID、反馈修订号、复核动作、固定原因码、复核修订号和 UTC 时间。
2. 复核状态由事件投影得到：没有事件为“待处理”，`resolve` 为“已处理”，`dismiss` 为“不是记忆问题”，`reopen` 重新进入待处理。历史事件不被覆盖。
3. 网页样本以回答 `request_id` 定位，圆屏样本以反馈事件 ID 定位；两者都绑定反馈修订号。网页反馈后来改标时，新修订自然重新进入待处理，不继承旧结论。
4. 写入使用预期复核修订号防止旧页面覆盖新操作，并在写入前确认目标仍是当前的“没想起”或“错误记忆”样本。
5. 事件不保存问题、回答、记忆或备注正文；原因只能从受控枚举选择。
6. “已处理”只是所有者对内部队列的管理结论，不自动修改 L0–L3，不重答、不调用模型，也不证明算法已经普遍修复。

## 后果

- 默认问题页成为真正的待处理队列，同时保留已处理、非记忆问题和重新打开的审计历史。
- 后续可以基于原因码统计常见处理路径，但在形成采样协议前不得把队列比例当作准确率。
- 当前没有自由文本备注和批量关闭；这是降低隐私副本、误操作和错误归因的有意限制。
