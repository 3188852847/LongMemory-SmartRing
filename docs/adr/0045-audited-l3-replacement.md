# ADR-0045：L3 更新采用候选式追加与事务性取代

- 日期：2026-09-06
- 状态：已接受；代码与个人数据库迁移完成，真实页面体验待确认
- 接续 ADR-0044

## 背景

统一画像会逐渐出现需要更新的认识，例如偏好发生变化、旧断言表达过宽，或多条同类断言需要收敛。直接编辑旧行会破坏历史和来源；仅追加新断言又会让新旧内容同时进入正式画像。

## 决定

1. 用户从一条当前有效画像发起“更新这项画像”，编辑内容并重新核对 L1/L2→L0 来源。第一版一次更新一个旧画像；数据结构允许未来明确合并多个同类画像。
2. 新内容先保存为普通 `candidate`，同时记录拟取代目标、目标当时的 revision 和创建时间。创建候选不会改变旧画像。
3. 候选被拒绝时，旧画像继续 `active`，取代意图保留但不生效。
4. 接受候选时，服务再次验证旧画像仍为同一主体、同一类型、`active` 且 revision 未变化。新画像激活、旧画像转为 `stale`、修订号递增及 `applied_at` 写入必须在同一 SQLite 事务中完成；任一步冲突则整体回滚。
5. 统一画像只读取 `active`，因此成功接受后立即只显示新画像。新旧详情都能查看取代关系，不物理删除来源、复核和历史内容。
6. V8→V9 只新增空的 `persona_replacements` 表和索引，不扫描、不生成、不改写既有 L0–L3。
7. 本切片不自动发现冲突、不定时调用模型、不允许模型自动接受更新，也不把 L3 注入回答。自动整合必须另行设计操作契约与触发条件。

## 后果

画像可以安全演化，并能区分“新候选提出了变化”和“变化已经由用户接受”。代价是更新比原地编辑多一步复核；这是为防止模型或旧页面静默覆盖个人画像而保留的产品约束。

## 回退

在尚未使用取代功能时，V9 新表为空。代码可停止暴露更新入口；既有画像内容不受影响。数据库降级不自动执行，若确需回退应从迁移前一致性备份恢复。
