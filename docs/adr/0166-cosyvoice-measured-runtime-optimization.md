# ADR-0166：以实测选择 CosyVoice 本地运行优化

- 状态：已接受；代码与隔离基准通过，日用进程重启及圆屏听感待验收
- 日期：2026-09-14

## 背景

用户授权修复实时对话，同时保留自然声音、现有依赖和独立 Memory Core。
V6 一轮五段共生成 16.08 秒音频，TTS 调用累计 25.747 秒，整体实时率 1.601。
在相邻请求没有额外空档的假设下，三处服务端供给缺口约为 5.559、3.204、1.909 秒；
这些是估算，不是扬声器测量。已有播放和下一片段合成并发，不能靠增加普通预取线程解决。

## 本阶段范围

- 使用既有 CosyVoice 环境与固定合成文本，测量内部阶段和真实生成耗时。
- 在项目适配层验证完整片段生成与 Qwen 未使用文本输出层优化。
- 仅在基准和正确性检查通过后接入独立声音服务；保留明确恢复原路径的选项。
- 修复语音消费者对过期话轮的识别，避免打断后迟到音频继续占据新话轮。

不新增依赖、不下载模型、不更换声音供应商、不降低 F0 精度，不访问校园接口或个人库。
本阶段不承诺回答模型首字或扬声器端到端延迟已经达标，不直接并行多个模型请求。

## 验收

1. 同一模型、参考条件、固定文本、关闭回复缓存，对照原路径与候选路径。
2. 记录完整音频时长、首块和完整片段耗时、块到达曲线、显存及实现身份。
3. 未使用输出层优化验证隐藏状态、缓存语义与同种子音频一致性；不改变 F0。
4. 定向自动测试通过；未实测的音质、圆屏首声和插话体验明确保留为用户验收。
5. 未通过的候选不进入日用默认，实验产物只保存到忽略目录，不覆盖旧结果。

## 决定与结果

1. 当前消费者已经收齐自然标点片段后连续播放，因此服务默认以 `stream=False`
   完整生成这个片段，省去内部流式 Flow/HiFT 对累计前缀的重复计算。HTTP 协议、
   文本切段、参考声线、FP16、Flow 步数和 Opus 60 ms 帧均保持原值。
2. 严格核对 Transformers 4.51.3 与上游 Qwen2Encoder 方法后，跳过未使用的文本
   词表输出与中间隐藏状态。32 轮交替基准的 16 对音频 SHA-256 完全相同；
   本项主要收益是约 0.29 GiB 峰值显存，耗时收益较小且有波动。
3. 同一新进程、四类固定合成句、两轮交替、无回复缓存、包含 WAV 服务包装：
   原内部流式整体实时率 0.791，完整片段加输出层优化为 0.653，耗时下降约 17.5%；
   峰值已分配显存由 4.876 GiB 降至 3.955 GiB。这是合成测试结果，不是圆屏实测。
4. 最终默认服务通过真实 HTTP、重采样和真实 60 ms Opus 编解码八轮验证；
   短句首个 Opus 可用约 1.35～1.44 秒，各例实时率 0.579～0.807。
5. 流式、预置与完整 WAV 回退均拒绝过期话轮音频。完整片段模式在写 HTTP 前
   耗尽模型迭代，避免客户端此刻断开时跳过上游放在最后一次 yield 后的清理。
   阻塞中的 HTTP 读取和 GPU 合成仍不能即时抢占。
6. F0 实测只有毫秒级，撤掉该候选；不安装 TensorRT/vLLM，不改采样和音频精度。

`--model-streaming --no-hidden-only` 恢复本轮以前的模型执行方式。健康检查新增
实际模式、优化是否生效、版本和服务源码指纹，避免用磁盘代码冒充进程已加载的代码。
当前受管服务没有 TTS 单独重启入口；本轮没有停止整个日用系统或访问个人库，
因此需要在启动面板停止并重新启动后，再做真实圆屏复测。

旧日用进程明显慢于相同源码的新进程，差异原因尚未确定；不能把这部分两倍左右
的差异归因于本轮代码。新进程测试并未证明长期运行后不会退化。
基准身份、分项证据、回退与剩余验收见[运行优化记录](../research/cosyvoice-runtime-optimization-2026-09-14.md)。
