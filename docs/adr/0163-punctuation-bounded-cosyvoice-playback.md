# ADR-0163：按标点边界连续播放 CosyVoice

## 状态

已接受，2026-09-14。用户明确选择自然停顿优先；部分取代 ADR-0161 的 CosyVoice
首段 14 字提前提交，并补充 ADR-0162。

## 背景

真实圆屏体验出现“说几个字就明显停顿”。固定合成基准证明当前普通 PyTorch 后端产生
后续模型音频块的速度低于播放速度，长句内部会发生秒级欠载。等待三个 Opus 帧只能提供
180 ms 库存，固定小步长与减少 Flow 步数也未消除欠载。

用户明确要求以逗号或其他标点作为可接受的停顿位置，不能在词语或语义片段中间突然停。

## 决定

1. CosyVoice 不再把首段回答固定按 14 个字符硬切；Edge 的既有策略不变。
2. 除句号、问号、感叹号、分号和冒号外，CosyVoice 后续文本也接受逗号、英文逗号和
   顿号作为自然切段边界。
3. 本机服务仍以模型分块生成并支持取消，但 Xiaozhi 适配器先收齐当前标点片段的 PCM，
   再连续编码并送入圆屏播放队列。模型块边界不再成为可听停顿位置。
4. 发生打断时丢弃尚未播放的整个标点片段并重置残余 PCM，不播放过期半句话。
5. 保留 V5 时序。首声和标点间等待可能增加，属于用响应速度交换句内连贯性的明确取舍；
   后续仍通过隔离加速运行时消除这一取舍。

## 后果

- 同一标点片段开始播放后应保持连续，停顿位置与书面/口语边界一致。
- 这不是性能加速；较长、缺少标点的片段必须全部生成后才开始播放。
- 大模型输出标点质量会直接影响语音节奏，后续需要用真实回答检查逗号密度和过长片段。

## 回退

恢复逐模型块立即编码，并重新安装 CosyVoice 首段固定字符策略即可；不涉及模型、固件、
配置、记忆或数据库迁移。
