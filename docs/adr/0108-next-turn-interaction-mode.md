# ADR-0108：进程内一次性下一轮互动方式

## 背景

当天临时互动方式适合持续倾诉或集中解决问题，但短暂需要“下一轮只倾听”时，建立一条整日有效的 L1 再恢复默认过重。把这种控制写成长期记忆还会污染 L2/L3；让用户把控制句和正文拼在一起，又会让提取边界变得含糊。

## 决定

1. 首版只接受四条固定完整表达：“下一轮只听我说”“下一轮先问我要不要建议”“下一轮直接给我建议”“取消下一轮互动方式”。
2. 设置句只归档为 L0 控制证据，不生成 L1，也不进入 L2/L3；系统直接返回确定性回执，不让模型改写设置结果。
3. 待用选择保存在网页与圆屏共享的 `MemoryRuntime` 中。下一条普通用户输入在进入模型调用前原子消费它；模型失败、中断或入口切换都不得让同一选择重复作用。
4. 一次性选择优先于当天模式，仅覆盖一轮；消费后当天模式自动恢复。取消下一轮选择不会取消当天模式。
5. 一次性选择不依赖“使用已有记忆”开关，因为它是用户刚刚给出的交互控制，而不是从长期记忆推断出的行为。

## 后果

- 用户可以低成本改变下一轮回应方式，不会产生虚假的长期偏好。
- 进程重启会清除尚未消费的一次性选择；这是当前有意采用的安全失败方式，不能宣称跨重启保持。
- 共享 Runtime 的互斥锁决定多个入口同时请求时只有最先进入的普通消息消费该选择。
- 本切片不迁移数据库，不修改圆屏固件，也不改变冻结实验方法。
- 自由表达和在同一句中携带控制前缀及正文仍不支持，避免误吞正文或形成提示注入通道。
