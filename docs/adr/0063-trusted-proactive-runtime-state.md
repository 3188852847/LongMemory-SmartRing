# ADR-0063：主动交流可信运行状态汇总

- 状态：已接受；历史读取器与小智状态探针完成，运行入口尚未接线。
- 日期：2026-09-07。
- 承接：ADR-0059、ADR-0060、ADR-0062。

## 背景

确定性联系策略需要当天尝试次数、最短间隔、上一条是否仍待回应以及用户是否正在语音会话。它们来自不同系统：尝试与回复是持久历史，小智忙碌是瞬时连接状态。若把这些值交给模型推断，系统会把猜测当成控制事实；若把设备离线等同于用户忙碌，又会污染用户行为解释。

当前协议只能证明主动文本进入服务端队列，不能证明用户听见。因而“待回应”只能是保守的防追问护栏，不是对用户心理或行为的判断。

## 决定

1. SQLite 历史读取器只查询时间和状态，不读取 L0 或主动消息正文。最近八天的 `queued` 事件构成尝试时间，覆盖策略最大七天间隔及固定偏移跨日。
2. 最近一个仍处于 `queued / transport_sent / device_acknowledged / played` 的主动项之后若没有更晚的真实 `role=user` L0 消息，则 `awaiting_user_response=true`。已失败的尝试仍计入频率限制，但不等待回应。
3. 任意新的真实用户消息解除“待回应”；这只说明用户重新发言，不声称该消息是对主动问候的语义回复。
4. 小智控制桥状态增加 `user_session_active`，仅由正在说话、收到语音或通话状态得出；TTS 队列忙碌仍可阻止投递，但不自动解释成用户会话。
5. 小智状态探针把离线、忙碌、TTS 未就绪等投影为设备可用性和稳定原因。设备离线时 `user_session_active=false`，不能据此生成用户习惯或画像。
6. 应用汇总器组合持久历史与瞬时设备状态，输出策略状态和独立设备状态。本切片不创建候选、不运行调度器、不调用模型，也不联系真实设备。

## 后果与局限

该设计让频率和防追问规则可审计，同时保持设备故障与用户行为分离。局限是没有设备播放回执，所以 `awaiting_user_response` 是安全侧近似；将来获得真实播放/回应事件后，应以更强证据替代，而不是继续扩大推断。

## 验证

- SQLite 集成测试覆盖排队尝试、用户后续消息解除等待、失败尝试计数但不等待。
- 应用与小智适配测试覆盖实时会话合并、忙碌、离线和就绪投影。
- 所有测试使用合成数据库和模拟客户端，不访问个人记忆、模型或圆屏。
