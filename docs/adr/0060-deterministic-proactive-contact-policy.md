# ADR-0060：默认关闭的确定性主动联系策略

- 状态：已接受；纯策略内核已实现，尚未接入产品调度。
- 日期：2026-09-06。
- 承接：ADR-0015、ADR-0047、ADR-0059。

## 背景

主动交流直接影响用户是否被打扰。大模型适合在受限证据内生成自然话题，但不应自行决定联系时间、频率、勿扰和失败重试。用户暂时不在圆屏旁边也不妨碍先定义这些规则，因为策略判断应与具体设备和传输通道解耦。

## 决定

1. 新增纯领域 `proactive-contact-policy-v1`，不访问数据库、记忆、模型或设备；调用方只能提供明确配置和从可信运行状态汇总的数据。
2. 总开关默认关闭。启用后仍必须同时满足：候选已到期但未过期、消息有效期不超过上限、当前不在勿扰期、星期与允许时段匹配、用户没有正在进行的会话、没有等待用户回应的上一条主动消息、未达到每日次数且满足最短间隔。
3. 决策只有 `ALLOW / WAIT / BLOCK`：尚未到计划时间可以等待；其他不满足条件的当前候选直接阻止，不移动到下一个窗口补播。
4. 每个决定返回稳定原因码和策略版本，以后由 P4.4 编排器写入 P4.2 账本。模型不得填写次数、会话状态或勿扰状态。
5. 允许时段开始包含、结束不包含，并支持跨午夜；跨午夜的凌晨部分归属窗口开始日。第一版配置使用显式固定 UTC 偏移，默认中国标准时间 `+08:00`，不自动猜测所在地。若以后支持旅行或夏令时，另由配置适配层引入 IANA 时区并记录迁移。
6. 每日计数和最短间隔基于真正进入 `queued` 的尝试事件汇总，不能用候选数量代替；单次无回应只阻止后续催促，不能写成 L3 用户习惯或情绪结论。

## 理由与后果

确定性策略便于解释、测试和回滚，也能保证更换小智、TTS 或模型后打扰边界不变。默认值是产品安全护栏，不是从用户行为研究得到的最优参数。控制台持久设置、账本查询、后台唤醒和设备投递仍属于下一阶段，当前代码不会主动联系用户。

## 失败预演与回退

- 系统时间或时区配置错误会造成错误窗口；第一版显示固定偏移，不宣称自动随旅行切换。
- 服务停机期间错过的候选到期后 `BLOCK/expired`，不在重启时集中补播。
- 正在聊天、上一条等待回应或频率超限时直接阻止，不排队催促。
- 若运行状态来自未来时间则拒绝计算，避免时钟异常绕过频率限制。
- 回退只需不装配该策略；总开关默认关闭，P4.2 空账本和 L0–L3 均不受影响。

## 验证

- 单元测试覆盖默认关闭、允许、未到期、过期、有效期上限、勿扰、会话占用、未回应、每日次数、跨日最短间隔、星期、普通与跨午夜窗口、时区和未来时间拒绝。
