# ADR-0067：默认关闭的显式定时问候

## 背景

P4 已经验证 SmartRing-Plus 圆屏终端可以接收手动问候，并具备许可策略、运行状态、幂等账本和所有者运行记录。下一步需要把用户明确设定的时间规则接成后台闭环，但不能把原有“允许主动联系”总开关静默解释为自动发送，也不能在重启、离线或设备忙碌后补发已经失去语境的问候。

## 决定

1. SQLite V16 在 `proactive_policy_settings` 增加 `automatic_enabled`、`scheduled_minute` 和 `greeting_text`。迁移保留原许可设置，但自动开关一律为关闭；原有行的默认时刻取原允许窗口起点。
2. 后台定时问候拥有独立开关。只有总许可和自动开关同时开启，且当前当地分钟正好等于设定分钟时，才进入候选创建判断。
3. 触发器使用用户显式固定 UTC 偏移和星期设置。当日已经存在真实 `role=user` 对话、当天已经评估过、星期不匹配、尚未到点或已经错过该分钟时均不创建候选。
4. 每个当地日期使用稳定幂等键 `explicit-schedule:YYYY-MM-DD`。候选一旦创建，无论随后排队、拦截或失败，当天都不再创建第二条。
5. 候选仍经过既有确定性许可策略和小智窄适配器。离线直接记录为 `blocked`；会话活跃、待回应、勿扰、频率和允许窗口由既有策略拦截；投递失败不重试。
6. 控制台进程用本地 `asyncio` 低频循环每 15 秒评估一次，不引入新的调度依赖。设备探测后必须重新读取时钟与数据库，防止探测跨分钟或聊天并发造成补发。
7. 第一版内容是用户填写的固定短文本，不调用模型、不读取 L1–L3 生成话题，也不从行为习惯推断时间。

## 理由

独立自动开关避免升级后意外发声；精确分钟和不补发规则比持久任务队列更符合日常问候的时效性。复用现有策略、账本和投递端口，可以让定时触发只新增一个可替换职责，同时保持设备、记忆和主动交流解耦。

## 后果

- 电脑控制台、小智服务和圆屏连接必须在设定分钟同时可用；错过不会补发。
- 当前只能证明服务端 `queued`，不能自动声称圆屏已播放；用户仍可在运行记录里补充亲耳观察。
- 当天“聊过”按个人数据库中的真实用户消息判断。第一版单用户成立；多用户前必须把对话显式绑定主体。
- P5 的习惯发现只能将建议交给用户确认，不能绕过这个显式规则直接激活。

## 验证

- 纯触发测试覆盖精确分钟、提前等待、错过不补发、当天已聊和每日幂等。
- SQLite 合成迁移验证 V15 设置得到保留且自动开关关闭。
- 真实 SQLite 与模拟设备桥验证同一分钟只排队一次，当天聊过时不创建账本记录。
- React 测试和生产构建覆盖新增设置契约；真实圆屏定时验收留待个人数据库迁移并由用户显式开启后进行。
