# ADR-0170：独立的豆包实时语音备用模式

- 日期：2026-09-15
- 状态：已接受；账号联调与圆屏验收待完成
- 决定来源：用户明确要求新增完整实时语音备用模式，尚未开通服务，先完成模式和配置入口。

## 背景

现有语音链路由 Xiaozhi 编排识别、LongMemory、回答模型与 CosyVoice。Windows
调度修复已降低本地合成耗时，但用户仍希望保留一条可切换的实时对话路线。
本决定新增独立选择，不取代现有 CosyVoice 决策，也不引入 LiveKit 或改变记忆核心。

## 范围与完成条件

本阶段包含启动面板模式选择、本机凭据入口、官方实时客户端、圆屏音频桥和离线
测试。只有明确选择备用模式才会使用云端；切换在停止并重新启动后生效。
缺少有效配置时在创建服务前提示，不使用演示 Key，不尝试付费连接。

不包含开通账号、购买额度、自动安装、模型下载、私有记忆读写、校园接口、固件修改、
跨模式热切换、自动故障转移或联网性能承诺。本阶段完成标准是离线契约、队列、取消、
配置保护与原模式回归通过；真实服务和扬声器验收是独立关卡，不能由模拟测试替代。

## 决定

1. 使用 `voice_mode=pipeline|doubao_realtime` 表达完整语音模式，保留独立
   `tts_backend`。豆包并非第五个只读文字的 TTS 后端。
2. 新接入固定使用官方 3.0 全双工接口、模型 `1.2.6.1`。协议实现在项目侧
   `scripts/development/xiaozhi/doubao_realtime/`，不复制到 Memory Core。
3. 圆屏仍通过现有 Xiaozhi WebSocket 握手、Opus 和设备控制协议连接。桥接层负责
   解码、音频包对齐、实时发送节拍、云端事件与下行 Opus；不让设备理解供应商协议。
4. 豆包模式不初始化本地 ASR、回答 LLM、TTS 或圆屏 Memory 提供器，不启动本地
   CosyVoice。网页控制台继续沿用其独立模型和记忆设置。
5. 凭据保存在 Git 忽略的 `.env.doubao.local`。面板只展示是否已配置；不回显
   Key、不放入命令行、非敏感首选项或错误正文。地址固定为官方加密 WebSocket。
6. 取消要同时停止本地输出、清理待播库存并通知云端；按话轮/响应身份丢弃旧输出。
   收音上传、云端接收和设备播放分别运行，均有容量限制。失败停止当前连接，不把
   旧音频或整段录音自动重放到新连接。
7. 本版明确不接个人长期记忆，也不向豆包注入现有小智私人提示或历史。只提供
   独立、通用的中文语音提示。豆包会话内上下文不等于 LongMemory 的长期记忆。

## 为什么暂不接个人记忆

官方新版有函数调用：工具返回后可继续生成回答，但未公开每轮强制检索的可靠开关。
旧版 `ChatRAGText` 是已有回复的替换路径，同样不能据此宣称模型会自动等待记忆。
而现有 Xiaozhi 的 `query_memory` 还包含写入/回执生命周期，不能简单挂到任意
增量转写或工具请求上。

先验证无个人记忆的完整语音基线，之后再通过独立适配接口设计明确的检索、话轮与
完成回执。不能为“低延迟”绕过来源、隐私或完成语义。

## 取舍与回退

收益是可独立比较实时语音体验，且备用模式无需本地 GPU 语音模型。代价是依赖
公网和服务额度，声线与 CosyVoice 不同，本版没有长期记忆及其主动播报。
不承诺低于某个首声数字，也不宣称云端不会欠载。

回退只需停止服务，选择现有语音链路，再启动。保留原模型、TTS 与记忆设置，
不进行数据库迁移、不转换对话数据、不重刷圆屏。

当前取消协议存在一个待联调边界：官方取消回执不携带回答 ID，且未保证 ASR
`item_id` 与回答 `question_id` 的等值关系。若上一轮已有最终转写、尚无回答 ID，
又开始新语音，客户端发出固定 `realtime_turn_ambiguous` 错误，由桥结束设备连接。
这是避免误播的暂时处理，会影响“模型思考时追加一句”的体验，不能作为完整自然
打断的验收结果。开通后须优先验证实际事件次序，再决定如何保持连接。
