# ADR-0033：按问题与触发条件分阶段采用技术

- 状态：已接受
- 日期：2026-09-06
- 取代范围：取代 ADR-0032 第 2 项中“不新增路由库”的限制；不取代其渐进迁移、安全和回退约束。

## 背景

控制台已从单一设备验证页扩展到聊天、L0/L1 记忆管理、助手角色、声音和实验任务。React 页面仍在渐进统一，前端开始重复处理路由、服务器状态、加载、错误和刷新；Python API 则存在较多手写 JSON 校验。

与此同时，当前系统仍是单用户、本机部署。已有 aiohttp API、本机会话、CSRF、Host/Origin 校验、CSP、静态资源白名单、小智回环接口和配套测试均已运行。为了获得开发便利而一次性替换后端框架，会产生确定的迁移成本，但不会直接改善记忆质量或日常体验。

技术选型必须区分“增加现有能力”和“替换稳定基础设施”。候选技术不能因为流行、方便或未来可能有用就直接进入主线。

## 决定

1. React 控制台现在引入 React Router，建立统一路由、导航和页面外壳；旧入口保留兼容跳转，逐页迁移而非一次重写。
2. React 控制台现在引入 TanStack Query，统一读取、缓存、刷新和 mutation 状态。删除、纠正、设备控制等副作用操作默认不自动重试，继续依赖请求 ID、版本核对和事后读回。
3. 前端现在引入 Vitest 与 React Testing Library，补足组件交互测试；React 页面基本统一后再加入少量 Playwright 端到端流程。
4. Python API 近期以 Pydantic 建立严格的请求/响应契约，但仅放在入口和外部适配边界，不侵入 Memory Core。先选一个小接口验证错误兼容和实际收益，再渐进覆盖。
5. LongMemory API 继续使用 aiohttp。当前不迁移 FastAPI；通过薄路由、框架无关应用用例和独立数据契约控制未来迁移成本。
6. SQLite、pytest、uv、React、TypeScript、Vite、Ant Design、本地 BGE 与现有适配器边界继续保留。
7. FTS5、持久化向量缓存、APScheduler、SSE/WebSocket、Hypothesis、pydantic-settings、OpenTelemetry、PWA/桌面封装及模型推理优化，只在各自触发条件满足后评估，不构成当前实现授权。
8. 当前不引入 LangChain、LangGraph、Deep Agents、Redis、Celery/RQ、独立向量数据库、图数据库、GraphRAG、SQLAlchemy/Alembic、Docker、Kubernetes或微服务拆分作为核心地基。

完整状态、触发条件和退出条件维护在[技术策略与雷达](../architecture/technology-strategy.md)。

## FastAPI 重新评估条件

出现下列至少一类真实需求时再立项比较，不自动迁移：

- API 要提供给手机端、第三方或其他主机；
- 需要稳定 OpenAPI、自动生成客户端或正式多用户权限；
- HTTP 手写校验和依赖装配持续成为缺陷主要来源；
- 路由规模继续增长，薄路由和独立契约仍不能控制维护成本。

评估必须包含现有安全中间件、静态资源、启动器、小智 Runtime 接口、错误码和测试的迁移清单。便利性本身不足以通过评审。

## 触发式候选

- FTS5：冻结数据证明中文词面召回或查询延迟优于现有实现，并验证索引与 SUPERSEDE/删除一致性。
- 持久化向量：启动重建或增量编码成为可测瓶颈，并已定义模型指纹、失效和重建语义。
- APScheduler：先证明圆屏待机主动投递可达，再定义勿扰、频率、过期、取消、幂等和重启恢复。
- SSE/WebSocket：轮询已造成可测延迟、重复请求或状态错乱。
- Playwright：主要日常页面统一到 React 后，用少量关键路径做浏览器验收。
- Hypothesis：L2/L3、事实变化或复杂 SUPERSEDE 状态使手写组合测试不足。
- pydantic-settings：LongMemory、启动器和小智私有配置的权威来源先明确。
- OpenTelemetry：现有 request ID 和结构化事件不足以定位跨进程问题。
- PWA/Tauri：网页和启动面板的真实使用仍无法满足安装、通知或后台体验；不默认选择 Electron。
- ONNX Runtime/TensorRT：先测得 BGE/TTS 的加载、显存或延迟瓶颈。

## 后果

收益：现在承担低风险、会随页面增长而变贵的前端基础改造；后端保留稳定性，同时建立可迁移契约；技术候选有明确触发条件，不随讨论任意扩张。

成本：新增前端依赖、查询缓存语义和组件测试环境；团队需要明确区分浏览器本地状态与服务器状态。Pydantic 试点也必须维护现有 API 错误兼容，不能把默认 422 等框架行为直接泄漏给前端。

## 实施记录（2026-09-06）

Pydantic 2.13.5 首个试点落在聊天消息提交：严格拒绝额外字段、错误类型、空白/超长正文和非规范 UUID，并把所有验证失败继续映射为原有 `400 invalid_chat_message`。契约位于 HTTP 入口目录，不进入 Memory Core；aiohttp、响应结构、请求幂等和数据库均未改变。全量回归通过后接受该试点，后续仍按接口风险逐条迁移，不据此触发 FastAPI。

## 实施顺序与回退

先建立 Router、QueryClient 和共享外壳，再以“设备与状态”作为首个完整迁移页；随后迁移设置和实验页面。每一页通过构建、组件测试和原有 Python 回归后才切换默认入口。旧页面在功能和实机体验对齐前保留。

若新前端基础导致无法修复的行为回归，可将对应路径恢复到旧页面；不迁移数据库、不改 Memory Core、不改小智协议。依赖下载由用户按项目约定执行，仓库只提交锁定后的清单和锁文件。
