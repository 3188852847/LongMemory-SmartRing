# ADR-0034：区分错误纠正与后来发生的事实变化

- 状态：已接受，第一切片已实现
- 日期：2026-09-06

## 背景

ADR-0030 已支持“旧 L1 从一开始就是错误的”人工纠正，但日常生活还会出现另一类情况：旧事实曾经正确，只是后来换了工作、宠物改名或偏好改变。如果把后者也标成纠错，就会错误地抹去旧事实曾经成立的时间语义；如果只追加新事实，旧事实又会继续参与召回并造成冲突。

V4 数据库已经包含 `recorded_at`、`valid_from`、`valid_to`、`retired_at` 和 `superseded_by_id`，所以本切片不需要修改 schema 或迁移个人数据。

## 决定

1. 管理界面把“纠正错误”和“记录变化”作为两个独立操作，不根据自由文本自动猜测用户意图。
2. 记录变化时，用户必须输入变化后的完整 L1 和已经发生的生效时间。
3. 新 L1 的 `recorded_at` 是系统收到操作的时间，`valid_from` 是用户声明的现实生效时间；旧 L1 的 `valid_to` 使用同一生效时间，`retired_at` 是系统实际完成取代的时间。
4. 旧 L1 通过 `superseded_by_id` 指向新 L1，仍保留 L0、证据和历史有效期；当前检索继续只读取未退役 L1。
5. 新输入作为 L0 用户消息保存，证据类型仍是 `user_stated`。`user_corrected` 专门表示旧事实原本有误，不能复用来表示正常变化。
6. L0、新 L1、证据、旧 L1 的 `valid_to` 和取代关系必须在同一个 SQLite 事务中提交；详情 revision 已变化、旧 L1 已退役、内容未变或出现当前精确重复时拒绝操作。
7. 第一切片拒绝无时区时间、早于已知 `valid_from` 的时间和未来时间。未来生效属于计划或提醒，不在当前记忆生命周期范围内。
8. 事实变化暂时复用 `--allow-memory-correction` 的显式启动能力；API 单独公开 `allow_change`，为以后拆分权限保留稳定边界。

## 后果

- 系统可以准确表达“过去是什么、何时变成现在这样”，而不是把所有更新误记为纠错。
- 现有 V4 个人库无需升级；实现和测试只创建合成数据库，不自动修改真实记忆。
- 当前只支持用户从管理页显式记录变化；聊天自动识别变化、撤销、L2/L3 传播及时间范围问答仍未实现。
- 旧 L1 会退出当前召回，因此日常回答优先使用新事实；历史问题能否正确使用旧事实仍需要未来的时间感知检索。
