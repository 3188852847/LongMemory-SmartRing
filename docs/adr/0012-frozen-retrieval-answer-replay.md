# ADR-0012：冻结检索结果的回答对照

- 日期：2026-09-03。
- 状态：接受；实现与离线重放验收通过，新增 17 项测试，全量 367 项 Python、11 项 Node 通过；真实模型结果尚待用户运行，单独记录。
- 延续 ADR-0011，不改写其“仅检索”范围；新增协议 `frozen-retrieval-answer-replay-v1`。

## 背景

首次 BGE 实验中姓名排名改善，但“检索到了”不等于“回答正确”。重新运行全部提取与检索会改变多个变量，也产生不必要的请求。故单独重放已保存的召回结果，验证其对最终回答的影响。

## 决定与范围

- 新入口 `evaluation/comparison/retrieval_answers.py`，必须同时指定检索报告与原比较报告。仅接受同一合成数据集、已完成且来源冻结的检索实验；不读取日常个人库。
- 校验原历史/数据集/方法状态、索引与语料一致、所有题唯一完整、原关键词结果一致、向量条目及来源属于冻结库、分数有限且降序、上下文与条目匹配。无模型权重加载、无向量重新计算。
- 向量排名沿用原报告，不重新证明查询向量与分数关系；哈希绑定字节版本，不证明生产者身份，不防御可同时伪造整套产物的恶意参与者。
- 两份语料 × 两种检索器，各题独立生成回答，默认本次 dev 4 × 8 = 32 次；只沿用输入报告的 split，不隐式运行留出题。失败不重试，全部题预登记并保留失败/中断分母。
- 所有组使用同一回答配置与现有中立 system prompt，不加入爱莉希雅角色，不传历史、答案标签或评分来源。每题轮换组执行顺序并记录，降低固定时间顺序偏差，但不是随机盲评。
- 统一字符上限（默认 4000，含公共标题和列表标记），仅保留完整排名前缀条目，不切半句、不越过放不下的条目择取后面短条目。记录实际注入项；分别评价全召回来源与注入来源。
- 新结果独立目录、独立 manifest，记录上游 manifest/报告哈希、两份冻结目录摘要、代码、回答模型白名单、系统提示哈希、预算、尝试次数与逐题耗时。源目录变化后停止后续请求；不把冻结违规后的分数计入成功。
- 复用词面初筛与离线复核；用“原方法/检索器”作为唯一实验组 ID，保留原方法字段。旧比较协议和 runner 不变。

## 代价与限制

不新增依赖，不迁移数据库，不替换网页或圆屏算法。已有 `semantic` extra 可保留，但这一步本身不需要 Torch/Transformers。

统一上限不是强制相同上下文长度，更不是相同 token 数；不填充无关字符凑长度。当前 5/7 条语料、top-5 与 4000 字符上限下基本不截断，排名改善未必带来回答差异。噪声、重复、拒答须逐题复核。后续扩展带干扰事实的开发集，不能用反复调预算刷当前成绩替代泛化验证。

采样参数仍为兼容服务默认值、未独立验证，单次调用存在随机性；当前非 token 成本或显著性评估。Fake 只测工程，词面初筛不是语义评分，更不是论文性能排名。纯向量失败时不自动回退关键词掩盖失败。

## Definition of Done

- 合成测试：来源错误先于模型调用被拒；标签不入模型；相同提示/预算、独立请求；空召回/完整条目预算；失败/中断/冻结违规保留全部题且不重试；密钥不进产物。
- 复用真实冻结检索报告做 Fake 离线流程验证；不将其分数记录为模型质量。
- 校园模型验证由用户执行，助手不探测网络；用户报告到达后再独立复核回答与来源。此项未完成前不宣称实际问答提升。
