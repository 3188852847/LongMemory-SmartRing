# ADR-0132：L1 重复合并的逐条证据账本

- 状态：接受
- 日期：2026-09-13

## 背景

SQLite V39 能审计一次 L1 重复合并的保留项、退役项和复制证据数量，但没有记录具体哪些 `memory_evidence` 关联是由该次合并新增的。数量不足以唯一还原来源集合，因此旧事件不能被安全地完全撤销。

## 决定

SQLite V40 新增 `l1_duplicate_merge_evidence`，为今后每次合并逐条保存：

- 合并事件 ID；
- L0 来源消息 ID；
- 证据类型；
- 原始关联时间。

合并事务先比较保留项和退役项的现有证据，只把真正新增到保留项的关联写入账本。账本不复制对话或记忆正文，与合并事件、L1 状态变更和证据汇入位于同一事务。

V39 已有合并不根据计数或当前关联猜测回填。控制台明确区分“账本完整”与“旧合并无逐条账本”。

## 后果

未来的恢复操作可以准确知道某次合并当时新增了哪些来源关联。但本切片仍不提供一键撤销：还需定义恢复退役 L1 后如何处理已失效的 L2/L3，以及合并后又发生的新变更。系统不把“有账本”冒充为“已可安全完全回滚”。
