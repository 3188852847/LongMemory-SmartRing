# ADR-0056：自动整理候选必须经过独立的失败关闭风险复核

- 状态：已接受并实现执行器边界
- 日期：2026-09-06
- 关联阶段：P3.9

## 背景

ADR-0055 已禁止调用方用缺省布尔值冒充风险评估，但若继续让 `run_once` 接受
`risk=True` 一类对象，后台装配仍可能绕过真实检查。另一方面，只靠敏感词未命中
不能证明个人记忆安全；让候选生成响应同时声明自己安全，也存在明显的自我评审问题。

## 决定

1. 从 L1→L2 与 L2→L3 的 `run_once` 删除外部风险布尔参数，改为构造时注入独立
   `ConsolidationRiskReviewer`；未装配或未就绪时在读取正文和调用模型前 HOLD。
2. 候选生成成功后，系统重新封装已经过白名单来源校验的候选、证据和当前画像，
   发起一次独立风险复核。候选响应中即使夹带安全字段也不会被读取。
3. 复核只接受封闭 JSON：敏感性、未解决冲突、是否允许以后自然澄清及简短原因码。
   缺字段、额外字段、重复字段、截断、网络异常或非布尔类型全部失败关闭，不激活、
   不推进游标且不重试。
4. 来源角色仍由 SQLite 白名单查询和应用层复算负责；复核模型不能把非用户来源改成
   用户事实。UPDATE 目标是否仍为 current 继续由当前画像和 revision 契约验证。
5. 一次非 NOOP 整理按最坏情况预留两次模型调用预算：一次候选生成、一次独立复核。
   NOOP 只消耗实际发生的一次调用，但同日下一次运行仍按两次预算预留。
6. 第一版提供 OpenAI-compatible 复核适配器，版本为 `consolidation-risk-review-v1`。
   它可与候选模型使用同一供应商，因此不是独立模型家族或形式化安全证明；独立的是
   请求、提示、响应和失败边界。无法接受这一剩余风险时应保持后台整理关闭。

## 后果

- 普通调用方不再能直接宣称风险评估完成，后台调度只能装配明确的复核实现。
- 自动激活项的生成版本会同时记录候选器与复核器版本；运行账本继续记录实际调用数和
  稳定结果码。失败运行尚未单列持久化复核器版本，这是后台装配前需要补齐的审计字段。
- 本切片不改变数据库结构、不启动后台、不扫描个人库，也不调用真实模型。
- 下一步是为运行账本补足复核器版本并确定单一调度所有者，再把两个执行器以非阻塞、
  默认关闭的方式接入常驻 Runtime。
