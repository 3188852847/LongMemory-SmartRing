# ADR-0149：只读的 L1 语义关系发现

- 状态：接受
- 日期：2026-09-13

## 背景

现有 `l1-quality-heuristic-v1` 能发现规范化重复、高字面重合和少量结构几乎一致的肯定/否定冲突，但无法覆盖“以前住在南京 / 现在住在合肥”等措辞和取值均发生变化的关系。直接让大模型扫描个人库并执行更新，会把候选发现、事实真值判断和数据库写操作耦合，也无法公平替换为未来的论文方法。

## 决定

采用三个相互隔离的步骤：

1. 本地向量模型只在同一主体的当前有效 L1 中产生有界的相似配对。余弦分数是召回信号，不是冲突概率。
2. 独立语义关系复核器把每对分类为 `equivalent`、`possible_conflict`、`possible_change`、`compatible` 或 `uncertain`。一次最多 20 对，温度为 0，失败不重试。
3. 只有非 `compatible` 的结果可以进入人工候选收件箱；仍由既有“纠正错误”或“记录变化”事务执行写操作。复核器没有自动纠正、取代、删除或选择真值的权限。

模型响应必须按输入顺序返回全部配对 ID、固定关系、与关系匹配的原因码，以及能在双方输入正文中逐字定位的摘录。缺项、额外项、顺序变化、重复字段、越权 ID、伪造摘录和非法关系组合全部视为失败。记录时间只是系统写入时间，不能单独证明事实变化。

首个切片实现领域契约、OpenAI 兼容适配器和可替换编码器驱动的本地配对。配对层一次编码最多 500 条输入，只比较同一主体，按稳定余弦顺序最多保留 20 对；当前不设置未经校准的相似度阈值。它不读取个人数据库、不调用真实模型、不改变现有质量候选 API。下一切片建立冻结合成集和隔离评估；只读预览、持久化与控制台接入必须在误报可核对后单独决定。

## 后果

语义模型可以提高候选覆盖，但不能污染记忆生命周期。以后替换嵌入模型、分类模型或复现外部论文方法时，只需实现候选召回器或关系复核器接口。

代价是需要额外模型调用与独立误报评估；喜欢多个事物、不同属性和不同时间阶段尤其容易被错误地解释为冲突，因此必须在冻结数据中单列负例，不能直接在个人库上试错。
