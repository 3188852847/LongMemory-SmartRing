# ADR-0085：本机控制台显示实际模型配置摘要并保持显式检测

- 状态：已接受并实现
- 日期：2026-09-08

## 背景

学校模型可能重新部署并同时改变地址或密钥。控制台服务能够正常启动并不代表模型可用；如果页面只在回答失败后显示笼统错误，使用者需要在终端和多个环境文件之间排查。另一方面，自动探测会在每次启动时产生网络请求，且把密钥、合成内容或个人记忆暴露给页面都没有必要。

## 决定

1. 设置中心新增“模型与服务”入口，显示当前服务进程实际读取的 provider、模型名、无凭据服务地址、HTTP/HTTPS 状态及本进程最近检测结果。
2. API 只返回已经通过配置校验的模型根地址，不返回 API Key，也不返回上游响应正文。
3. 启动和打开页面不自动访问模型；只有使用者点击检测时，才复用现有最小探针发送固定合成短句。
4. 探针不读取或写入个人记忆、不自动重试，结果只属于当前服务进程；重启后恢复“尚未验证”。
5. `.env` 和 `.env.deepseek.local` 仍是彼此隔离的本地配置档。修改文件不会热加载，必须重启服务，再由页面核对实际配置。

## 后果

- 模型重新部署、地址填错、HTTP 明文和鉴权失败更容易被识别，不必先用真实个人对话试错。
- 页面知道服务地址，因此该入口继续限定为本机所有者控制台；地址不得含用户信息、密码、查询参数或片段。
- 连接检测成功不代表回答质量、记忆质量、小智配置或圆屏语音链路通过。

## 验证

- 后端测试确认端点和明文标记可见，序列化响应中不存在 API Key 字段。
- React 测试确认页面加载不自动检测，只有点击后才调用一次现有探针。
- 所有检测使用合成数据库或固定合成短句；未调用学校或官方模型。
