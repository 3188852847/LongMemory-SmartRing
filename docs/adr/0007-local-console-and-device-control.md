# ADR-0007：本机控制台与受限设备控制通道

- 状态：已接受；执行顺序与页面范围已由 ADR-0008 部分替代，本机安全和设备控制约束保留。初始记录及实施历史见下文。
- 日期：2026-09-03；承接 ADR-0005/0006，不改变记忆数据模型。
- 用户决定：先完成基础控制台，再继续 V0.2 语义检索；暂缓 TTS 音色优化。

## 背景与事实

PC 记忆闭环和圆屏合成演示已完成最低验收；用户已体验并暂时接受助手角色提示词。
目前没有网页管理入口。`web/README.md` 和 Python `entrypoints/api/` 是已有预留位置。
实际小智配置使用 nointent，因此没有语音调音量能力；这不妨碍固件 hello 后交换 MCP 工具列表。
本地小智快照为 eb4b28c59ed7ed885258498cf757ce14352d620e，连接由认证后的 ConnectionHandler 持有。
源码检查只证明调用和回执机制存在，不能证明当前厂家 B V2 实机已提供或执行音量工具。

## 决定

1. 先做独立进程 → 本机控制入口 → 小智已认证连接 → 设备回执的技术验证；通过后再做页面。
2. 验证期通过现有启动包装启用控制通道，不改上游源码、不改固件、不修改 nointent、不向大模型暴露任意工具。
3. `--device-control` 显式开启 `127.0.0.1:8766`，复用小智现有 aiohttp 3.13.2，不给 LongMemory 安装依赖。
4. 独立客户端持有本地文件令牌；Host 固定，拒绝 Origin/浏览器 Fetch Metadata 和未授权请求，不启用 CORS。令牌不进命令行/浏览器/日志/Git。此阶段不是网页可用的管理 API。
5. 只允许两个固定设备工具：读取设备状态（返回时仅保留音量）、设置扬声器音量。范围先限为 5–60，禁止任意工具名/参数透传。仅操作既有 LongMemory 指定的单个设备，多条同标识连接时拒绝控制。
6. 设置前读值，设置后等待明确 true 回执并再次读回；超时结果未知，不重试、不自动恢复旧值。不把设备读回当作听感验收。
7. 固定审查过的关键上游文件哈希，升级或改动后拒绝开启控制，需重新审查。绑定或端口失败不自动换端口。
8. 控制页面后续使用静态 HTML、原生 JS 模块、JSON API 和本地 CSS，由 Python 后端提供；沿用 web/，不引入模板、CDN或前端框架。

## 控制台边界

首版四页：设备与状态、记忆管理、助手角色、运行记录。不是完整智控台、模型部署中心、多用户平台或刷机工具。
助手角色（assistant_role）与 L3 用户画像（user_profile）严格区分；已有 personas 候选路径暂保留兼容，不表示用户画像实现。
记忆页复用应用用例；来源查看和删除保留现有语义，删除 L1 不等于删除 L0。SUPERSEDE 未实现，不将纠正功能伪装成普通字段编辑。
“报告错误/纠正建议采集”保留为候选，不在音量验证阶段新增持久化，不默认收集个人研究数据。

普通运行记录默认只保留必要元数据。完整实验轨迹必须显式启用并使用合成或授权内容，区分输入/写入/检索/实际注入/回答完成状态及版本信息；不能把日常日志自动混入固定评估集。
现有固定数据集和上下文消融 runner 已实现，本里程碑不把它们重复表述为“尚未开始”。

## 安全与框架再评估

- 不可信记忆、来源、模型输出只用 textContent/value 等纯文本入口显示；禁止 innerHTML 富文本渲染和把文本插入脚本/事件处理器。
- JS/CSS/字体/图标本地托管；控制台浏览器不得因显示记忆访问外网，模型/TTS 服务外网依赖不在“页面离线”承诺内。
- 页面上线前另补同源会话、写操作防 CSRF、Host 校验和 CSP，不把 CLI 令牌直接嵌入网页，不用 CSP 替代安全渲染。
- 框架评审触发：跨页面共享可变状态、实时更新与编辑冲突、反复出现 DOM/状态同步缺陷，或抽取模块后组件复制仍难以维护。触发评审不是自动迁移。
- 四页完成后固定回顾选型，收尾控制台，再回到语义检索。禁止无限扩张基础设施。

## 局限、失败预演与回退

设备可能只在唤醒/对话时保持连接，不能承诺待机随时远控。工具缺失或断线时控制失败，不猜测 MQTT/HTTP 替代能力。
上游设备身份仍有自报 MAC/令牌准入局限；本机文件令牌不能防止同一 Windows 账号下的恶意程序，暂不公开部署。
上游日志可能包含设备响应或握手头，本接口不新增原文日志，不承诺整个上游已脱敏。
回退只需停止服务并去掉 --device-control 重新启动；记忆、人格和数据库不动。

## 实施追加记录（2026-09-03）

用户提供唤醒后 connection_count=1、ready/read/set 三项 true 的状态，并确认随后音量操作可用。该反馈通过技术验证关卡，未留存完整设备回执日志，不能扩大为常在线或所有固件通用能力。

开始页面阶段，原第 3 项“不给 LongMemory 安装依赖”仅适用于通道验证阶段。本机网页现在以可选 `console` extra 固定安装 aiohttp 3.13.2，锁定传递依赖；不变更小智虚拟环境。选择它是为了复用已熟悉的异步 HTTP 行为和操作锁，替代方案是增加 FastAPI/ASGI 栈或自行扩展标准库 HTTP 服务；本阶段无需后一组额外组件。

“设备与状态”页由独立 Python 3.12 进程监听 127.0.0.1:8765；浏览器使用有上限、8 小时过期的内存会话，Cookie 为 HttpOnly、SameSite=Strict。写请求必须匹配 Origin 和会话 CSRF 令牌；拒绝跨源 Fetch Metadata、错误 Host 和非回环访问。HTTP 回环不使用 Secure Cookie，因而只限同一受信任本机账号，不构成多用户认证。静态文件白名单、CSP 和纯文本插入共同限制暴露面，禁止把项目目录整体映射为网页资源。

后端单独持有 8766 令牌，只转发三个固定 API；禁用代理、重定向和自动重试。前端每 5 秒只查询缓存连接状态，读音量与设置均需明确点击；目标范围 5–60。设备离线或读数超过 30 秒时清除旧读数，收到回执但未读回一致时仍标记未核对成功。禁止自动恢复旧音量。

本阶段不打开记忆库、无迁移、不写实验轨迹，其他三页明确标为待接入。代码通过 HTTP 与状态映射测试；未进行浏览器交互/视觉检查，也未代用户发送实机音量指令。可选 WebMCP 仅注册只读连接状态查询，未取得支持上下文验证，不影响普通浏览器功能；不开放音量写工具。

### 记忆管理页实施追加（2026-09-03）

用户随后确认网页能够控制圆屏，设备页实机操作验收通过。现在新增 `/memories` 与认证后的记忆管理 API，不更改前述设备链路。

- `--database` 指定唯一已有数据库，浏览器不能提交文件路径或切库；默认未配置，不自动猜测个人库。默认只读，`--allow-memory-delete` 才启用单条删除。
- 控制台用 SQLite URI `mode=ro/rw` 和现有 V3 版本校验，不调用会创建文件、建表或迁移的通用装配入口。缺失路径或旧版本时报错；不增加 schema、索引或记忆字段。
- 列表在 SQL 中分页并进行参数化字面筛选，每页默认 25、最大 100；仅返回摘要，不加载全部 L0。详细来源与删除复用现有 MemoryManagementService。每个请求在工作线程内独立打开、关闭连接，不与异步音量操作共用数据库连接。
- 删除是原有 L1 物理删除，不是 SUPERSEDE：级联移除来源关联、解除指向本条的取代链接，但 L0 不动。界面在原文内容、ID 和影响提示后要求勾选并确认；服务端在 `BEGIN IMMEDIATE` 事务内核对内容和来源快照，再调用既有删除用例。变更冲突拒绝执行，传输失败可能结果未知，不自动重试。
- 新 API 复用现有会话、Host、Origin、CSRF、CSP 和无访问原文日志策略。所有记忆与来源通过 textContent 展示，不作为 HTML；不在 localStorage 保存记忆，不增加导出或任意 WebMCP 记忆读取/删除能力。
- 单条来源当前完整返回，超大来源集合的分页及大规模文字查询性能待后续研究；当前字面搜索不是语义召回，已退役视图也不表示自动退役机制实现。

223 项 Python 与 9 项 Node 前端测试通过；用户实际数据库未用于开发测试，没有替用户执行真实删除。新页面的真实浏览器交互仍未验证。完整范围与验收见 `docs/requirements/local-console.md`。
