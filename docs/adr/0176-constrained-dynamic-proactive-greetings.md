# ADR-0176：动态主动问候只改写已批准公开播报的话题

- 状态：已接受
- 日期：2026-09-17

## 背景

周期问候已经能轮换所有者明确批准的 L2 话题短句，但实际内容仍会重复。直接把任意 L0、L1 或 L3 交给模型生成圆屏文案，会绕过 ADR-0068 的公开播报许可，并可能把私人事实念给旁人听见。

## 决定

1. SQLite V50 增加默认关闭的 `dynamic_greeting_enabled`；只有周期问候、记忆话题和动态改写依次开启时才生效。
2. 模型只能看到本次确定性选中的已批准短句，不读取原始对话、任意 L1、L3 或其他候选素材，也不决定是否联系用户。
3. 输出必须单行、最多 80 字并逐字完整保留获批短句；不得添加用户事实。模型 HTTP 超时最多 2.5 秒，编排等待最多 3 秒。
4. 超时、服务失败、格式越界、获批原句缺失、设置或素材并发变化时，立即回退获批原句。没有可用素材时仍回退固定问候。
5. 主动账本继续绑定话题素材 ID 和 revision，并用原因码区分模型生成、模型回退与原始素材。模型文案不会写回 L0–L3，也不会修改素材。

## 理由

调度许可和内容表达分离后，模型只能改善一句已经获准播出的表达，不能扩大主动交流范围。严格回退使模型延迟与故障不会阻塞既有链路；保留原句和来源 revision 使播报内容仍可审计。

## 后果

- 第一版能减少话题短句的机械感，但不会利用未获公开播报许可的个人事实预测用户下一句话。
- 开关默认关闭，升级数据库不会改变现有问候内容。
- 模型仍可能产生不理想的通用措辞；所有者可关闭动态改写，继续使用确定性原句。

## 验证

- 单元测试覆盖合规改写、模型错误和未保留原句时的回退。
- 临时 SQLite 与模拟圆屏覆盖动态文案投递、话题 ID/revision 和生成原因码。
- 原有定时、间隔、缺席策略、设备门控和 181 项 React 回归保持通过。
