# ADR-0101：长期事项先形成 L1 可追溯跟进候选

## 背景

现有主动话题素材绑定 L2 场景，适合反复找话题；它不能准确表达“根据一条明确计划，在未来某个时间只跟进一次”。直接复用固定问候或把任意聊天自动变成提醒，都会混淆记忆、提醒和主动联系的边界，并可能把误提取放大为打扰。

## 决定

1. SQLite V34 新增 `companion_follow_up_candidates`，保存所有者明确创建的一次性候选、计划时间、跟进短句、L1 来源 ID、来源内容指纹、状态和 revision。
2. 第一版只能从当前 L1 创建，并校验详情 revision、主体、当前状态和内容指纹；来源纠正或事实变化后，旧候选不可继续启用。
3. 候选状态仅有 `candidate` 与 `cancelled`。到达计划时间不会创建 `proactive_outreach`，不会调用模型或向圆屏投递。
4. 控制台可以建立、查看和取消候选，并明确显示“未启用”。取消采用 revision 防止旧页面覆盖新状态。
5. 删除来源 L1 时级联删除派生候选，避免所有者删除记忆后，跟进表仍保留另一份个人正文或待办线索。
6. 后续启用与一次性投递必须新增独立状态和审计事件，并复用 P4 的总许可、勿扰、频率、等待回应、设备状态和过期门控；不能由本 ADR 暗示已经实现。

## 后果

- 系统首次能区分“值得以后问一次”的事项和“可以反复使用”的生活话题，同时保留 L1 来源。
- 当前仍是所有者工具，不是普通用户必须逐条确认的产品流程；自动提取要等误触发协议和真实样本验证后再做。
- 已到时间但尚未启用的候选只作为过期候选展示，不补发、不冒充提醒成功。
