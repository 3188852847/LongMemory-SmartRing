# ADR-0135：冻结 L2 召回开发集与留出集

- 日期：2026-09-13
- 状态：已接受
- 补充 ADR-0134；不改变个人库和日常圆屏召回策略。

## 背景

V1 合成集只有 6 个场景和 13 道题，足以否决无阈值的纯向量 top-k，但不足以调整两阶段门控。如果不区分开发题与留出题，每次根据全部结果修改规则，会把针对小样本的调参写成一般性改进。

## 决定

1. 保留 `l2_retrieval_v1.json` 原样；新增 V2，修改数据时必须另建版本。
2. V2 包含 `dev` 与 `holdout` 两个显式分区；命令行默认只运行 `dev`。
3. `holdout` 只在候选策略、阈值与实现全部冻结后显式运行；不根据留出结果继续调当前版本。
4. 语料中保留已过期场景，但召回候选只包含 `active`，用于固定生命周期边界。
5. 无答案题继续进入分母。多场景问题除 Hit@k 外，还报告证据覆盖率和全覆盖数，避免“命中任意一条”冒充完整召回。
6. 该工具不打开个人数据库、不调用回答模型，不更改日常检索器。

## 后果

收益是后续可以在开发集上比较候选门控，再用一次留出检查发现过拟合。代价是当留出集失败时，不能原地修改 V2 或反复试阈值；需要保留失败结果，另建数据或策略版本。
