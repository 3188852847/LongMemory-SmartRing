# ADR-0029：日常混合召回采用可选排名融合与显式降级

- 状态：已实现，待日常体验验收
- 日期：2026-09-06

## 背景

P3.2 的模型辅助提取能保存规则遗漏的表达，但关键词召回仍可能找不到已经保存的姓名、偏好或习惯。隔离实验已校验固定版本的 `BAAI/bge-small-zh-v1.5`，但纯向量检索在未知问题和小语料中也会返回看似相关的噪声。一次本地校准检查还显示，不同问题的余弦分数不可直接解释为“事实存在概率”。

## 决定

1. 新增日常 `keyword_dense_rrf_v1`，将现有关键词排名与本地 BGE 稠密排名用 Reciprocal Rank Fusion（倒数排名融合）合并。常数 60 只是排名平滑参数，不是置信阈值。
2. 该策略是启动时显式选择的试用项；默认仍为 `keyword_v1`，不批量重写旧记忆，也不迁移数据库。
3. 复用已有固定模型快照和 `semantic` 可选依赖，只在 CPU 推理；不在启动时联网下载，不允许远程代码。
4. 索引仅驻留进程内存。纯追加 L1 时只编码新增项；删除、退役、纠正或正文变化导致活动语料不再是原前缀时完整重建。当前不另外持久化个人文本或向量副本。
5. BGE 编码或检索失败时，本轮显式返回 `keyword_fallback / dense_retrieval_failed` 并继续使用关键词结果。SQLite、来源完整性等存储错误不作为模型故障吞掉。
6. 网页与圆屏继续复用同一个常驻 Runtime，因此使用同一检索策略。聊天 API 和 React 页面展示实际策略与降级警告。

## 后果与限制

- 改写提问有机会召回关键词不重叠的 L1，同时保留关键词对专名和精确词的贡献。
- 首次启动需要加载约 96 MB 的模型权重；CPU、内存和首轮延迟会增加。VoxCPM2 使用 GPU 的事实不代表 BGE 没有额外资源成本。
- 当前精确扫描适合个人小库，不代表可扩展到大规模语料；达到真实性能瓶颈后再评估持久向量索引。
- 没有经过日常真实数据校准的拒答阈值。混合召回会给出候选证据，但不能证明候选足以回答，也不能解决语义重复、冲突、SUPERSEDE、L2/L3 或事实可信度。
- 实现回归和本地模型加载通过后，仍需用户观察跨表达召回、无答案噪声和实际延迟，才可将其升为默认。

## 回退

在启动面板选择“关键词召回（稳定基线）”并重启受管服务即可回退；数据库内容和 schema 不变。
