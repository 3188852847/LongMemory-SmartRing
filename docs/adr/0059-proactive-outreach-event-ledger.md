# ADR-0059：主动交流当前投影与只追加事件账本

- 状态：已接受并实现基础账本。
- 日期：2026-09-06。
- 承接：ADR-0047、ADR-0058。

## 背景

P4.1 证明固定小智快照可以把短文本放入活动设备连接的 TTS 队列，但当前协议没有播放完成回执。主动交流还会经历策略允许、排队、传输、设备确认、过期和失败等不同事实。如果只保存一个“已发送”布尔值，系统会把服务端接受、网络写入和用户实际听见混为一谈，也无法解释一次问候为什么没有发生。

结果记录也不能写入 L0–L3：它描述的是系统行为及投递观察，不是用户事实。以后 P5 可以从多次结果中提出陪伴策略候选，但不能把单次无回复直接推断成用户习惯或情绪。

## 决定

1. SQLite V14 新增 `proactive_outreach` 当前投影和 `proactive_outreach_events` 事件历史。迁移只建空表，不生成候选、不启动调度、不调用模型也不投递。
2. 当前投影只保存一份消息正文、触发类型、稳定原因码、计划/过期时间、状态、策略版本、revision 和失败原因。事件表引用该记录，只追加状态变化和证据类型，不重复正文。
3. 第一版状态为 `candidate → queued → transport_sent → device_acknowledged → played`，并允许在适当阶段终止为 `blocked / expired / cancelled / failed`。状态只能沿允许的边前进，终态不能重新打开。
4. 每次变化使用预期 revision 做乐观并发检查；当前投影更新和事件追加在同一 SQLite 事务中完成。`(subject_id, idempotency_key)` 唯一，防止同一次触发被重复创建。
5. 状态必须有相称证据：服务端队列只能证明 `queued`，WebSocket 写入只能证明 `transport_sent`，设备回执才能证明 `device_acknowledged`。`played` 只接受设备播放回执或明确人工观察；当前 P4.1 没有这些证据，因此不能写成后两种状态。
6. 账本是内部领域与应用接口，当前不接调度器、控制台或圆屏桥。后续切片分别实现确定性策略和投递编排，不能让传输适配器自行决定用户是否应被联系。

## 理由与后果

“当前投影 + 事件历史”让产品读取最新状态时保持简单，同时保留完整审计链。它比只追加一张表更容易查询待处理项，又比反复覆盖一行更能解释历史。正文只存一份减少敏感内容复制；日志和 Git 不保存个人主动消息。

代价是后续所有投递实现都必须明确上报它真实观察到的阶段，不能用一个成功返回值跨越多个状态。当前账本不证明设备具有回执能力，也不表示 P4 已启用。

## 失败预演与回退

- 服务重启时遗留的非终态不能擅自标为播放；以后恢复器只能依据时间和可验证证据标记过期或失败。
- 两个执行者竞争同一记录时，只有匹配 revision 的事务成功；失败方不得自动重放。
- 幂等键复用时拒绝新建，不能覆盖旧正文或改变旧事件。
- 若未来设备仍无播放回执，记录诚实停在 `queued` 或 `transport_sent`，产品页面必须显示“结果未知”。
- 回退代码时 V14 两张空表可以保留；旧程序会因数据库版本较高而拒绝，需使用迁移前一致性备份，而不是手工降低 `user_version`。

## 验证

- 领域测试覆盖单向状态、终态、失败原因、时区和时间窗口。
- SQLite 集成测试覆盖创建/变化原子性、revision 冲突、幂等冲突、重开持久化和证据门槛。
- V13→V14 合成迁移证明原有 L1 不变、新表为空且外键有效。
- 个人库已在一致性备份后升级到 V14；现有业务表计数保持不变，新账本为空。
