# ADR-0077：先离线回放日常时段缺席草案，再允许版本化激活

- 状态：已接受
- 日期：2026-09-07

## 背景

V24 的日常交流时段候选只证明用户曾在相近时刻主动出现，不能直接推出“某天没出现就应该联系”。如果把候选直接接到定时投递，会绕过用户当天已经聊天、勿扰、上一条待回应、会话活跃、频率和设备状态等已验收边界。

## 决定

新增纯领域 `routine-absence-trigger-v1` 草案决策。草案默认不启用，在候选期望时刻之后等待显式宽限期，只在宽限期结束的唯一当地分钟判断一次；提前则等待，错过则跳过，绝不补发。当天已观察到常见时段、已有其他聊天或已经评估时不创建候选。第一版拒绝跨午夜检查，避免把缺席归到错误日期。

新增固定合成回放 `companion-absence-offline-replay-v1`。回放先执行缺席判断，再复用 P4 确定性联系策略，最后检查设备是否就绪。任何被标记为不得联系的样例如果得到 `would_queue`，安全门控立即失败；所有动作和原因也必须与冻结预期逐条一致。

## 理由

纯函数和固定时间线能在不连接模型、数据库或设备时重现决策，并让新策略只能缩小而不能绕过 P4 许可。把“会排队”作为回放终点，也避免伪造设备播放结果。

## 后果

- 这是工程回归门控，不是真实世界的策略质量、用户满意度或因果效果评估。
- 当前数据集只有合成边界，不能据此激活个人策略。
- 本轮不新增数据库表、不修改个人库、不启动后台扫描，也不向圆屏投递。
- 下一步才设计保存草案版本、回放报告、显式激活和原子回滚；激活仍必须默认关闭并保留 P4 门控。
