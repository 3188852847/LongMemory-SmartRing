# ADR-0072：只记录可观察的陪伴互动结果

- 状态：已接受
- 日期：2026-09-07

## 背景

P4 已能按显式规则向 SmartRing-Plus 圆屏终端主动问候。P5 若要识别习惯或改进陪伴策略，必须先积累结果证据；但“问候后出现用户消息”只能证明时间先后，不能证明用户是在回应问候，更不能证明问候有效或用户情绪发生变化。

## 决定

1. 新建独立的 `companion_interaction_events`，不放入 L0–L3，也不写入 L3 用户画像。
2. 第一种事件仅为 `subsequent_user_message_observed`：正式自动问候后首次保存的真实用户 L0 与该问候建立引用，并记录时间与秒级延迟。
3. 证据固定为 `temporal_order`。代码、API 和页面必须明确它不代表语义回应或因果效果。
4. 事件不复制用户消息正文，只保存原问候 ID 和 L0 消息 ID；正文仍受原有 L0 管理与隐私边界约束。
5. `manual_test` 与 `development_*` 触发的问候属于开发行为，不进入未来习惯学习样本。
6. 每次问候最多记录一个此类事件；后续消息不覆盖首条记录。
7. 当前只观察并展示，不自动打分、不生成习惯、不修改策略或模型权重。

## 后果

- SQLite 升级至 V20；旧库迁移只增加空表，不回填或推断历史结果。
- 网页与圆屏共享的记忆归档入口都会触发同一观察器，因此以后不依赖网页测试入口。
- 控制台可显示“已观察/尚未观察”和延迟，但不能把它命名为“回复率”或“满意度”。
- 下一切片可在同一独立边界补充服务/设备可用性与明确否定反馈，再讨论跨次经验或候选策略。

## 未采用

- 用用户消息正文做在线情绪分析：证据和隐私风险均不适合当前阶段。
- 一次未回应即降低某类话题权重：单次样本无法区分设备离线、服务停止、用户忙碌或不喜欢。
- 直接把结果写进 L3：L3 描述用户，互动结果描述系统行为后的观测，两者语义不同。
