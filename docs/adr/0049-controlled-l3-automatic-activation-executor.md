# ADR-0049：L3 自动生效采用确定性门控执行器

状态：已接受

日期：2026-09-06

## 背景

`persona-activation-v1` 已能把整理建议分成 `AUTO_ACTIVATE / HOLD / ASK_NATURALLY / BLOCK`，V10 也能区分用户和策略复核，但两者此前没有应用层连接。直接让整理模型写库会绕过真实证据复算、UPDATE revision 校验和策略审计；把现有网页“接受”按钮自动点击也无法保证候选创建与接受处于同一个事务。

## 决定

1. 新增技术中立的 `PersonaActivationService`。它接收已经通过严格解析的 `ADD / UPDATE / NOOP` 建议和模型之外提供的风险事实，不负责调用模型或安排运行时间。
2. 执行器从当前存储重新解析来源并计算来源数、用户 L0 数和观察日数，不接受模型自报的证据计数。
3. 只有 `AUTO_ACTIVATE` 创建候选并立即以 `policy` 身份接受；策略版本和稳定原因码写入 V10 复核记录。
4. `HOLD / ASK_NATURALLY / BLOCK / NOOP` 均不创建 active 画像。自动路径不支持 DELETE。
5. UPDATE 必须只有一个取代目标，并继续复用现有候选式取代、目标 revision 和原子状态切换。ADD、UPDATE 与载荷不一致时在写入前拒绝。
6. SQLite 调用方必须使用外层事务和 `commit_changes=False`，只在整个执行成功后提交，使候选、复核和旧画像失效一起成功或一起回滚。
7. 本切片不扫描个人数据库、不增加后台任务、不调用模型。P3.9 的低频整理器以后负责产生和触发建议；该触发器不能绕过本执行器。

## 后果

低风险自动接受现在拥有一条可测试、可追溯且不依赖网页审批的应用路径，后续圆屏用户无需参与逐条确认。当前产品仍不会自行扫描历史或定时生成 L3，因为触发与预算尚未实现；这是避免刚接好执行器就意外改写个人画像的有意边界。

如果自动路径出现问题，可以停止调用执行器；已经自动生效的画像可通过 `reviewer_type=policy`、策略版本和原因定位，并沿现有取代与来源链检查。数据库结构无需回退。
