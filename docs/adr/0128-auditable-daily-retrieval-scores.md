# ADR-0128：保存日常召回策略与分量分数

## 状态

已接受，2026-09-13。

## 背景

冻结开发集的阈值回放表明，8 道合成题不足以决定日常语义门槛。此前圆屏回答回执只保存 L1/L2/L3 条目、排名和内容指纹，无法把用户后续给出的“没想起／错误记忆”反馈与当轮实际相关度联系起来。混合检索已经计算余弦分，但返回前丢弃；关键词分与 RRF 分也没有进入审计记录。

## 决定

1. `RetrievedTrace` 增加可空的 `keyword_score`、`dense_score` 和 `fused_score`。三者分别表示词项重合数、余弦相似度和 Reciprocal Rank Fusion（倒数排名融合）排序分，不合并成统一置信度。
2. SQLite V37 在圆屏召回回执保存当轮策略，在每条 L1 召回证据保存上述三个可空分量。L2/L3 当前没有同类评分契约，保持空值。
3. 旧回执迁移后保持空值，并在控制台显示“历史未记录”；禁止根据排名或正文反推旧分数。
4. 小智薄适配器只转发 Runtime 已验证的策略和分数，不自行计算。协议继续兼容不带新字段的更新期旧端。
5. 记忆质量详情解释分数量纲；任何分数都不得显示为事实可信度或答案存在概率。

## 后果

- 后续可把真实圆屏反馈与当轮分数关联，形成阈值、拒答和排序分析样本。
- 当前只增加观测，不启用阈值、不切换个人检索策略，也不改变回答结果。
- 不同策略的分数不可直接横向比较；校准必须按策略、模型版本和使用入口分层进行。
