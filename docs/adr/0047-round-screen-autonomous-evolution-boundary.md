# ADR-0047：圆屏产品采用受控自主记忆与独立陪伴策略演化

状态：已接受

日期：2026-09-06

## 背景

网页聊天和控制台主要用于开发、观察、纠错与回滚。真实产品用户只通过 SmartRing-Plus 圆屏终端进行语音交流，不能依赖网页逐条接受 L2/L3 候选。现有人工复核闭环证明了来源、生命周期和取代关系可审计，但若把它当成日常必经流程，产品无法自然积累长期记忆。

同时，用户希望系统不只更新“对用户的认识”，还能够从长期互动中改善陪伴方式。二者都可称为自进化，却修改不同对象，若共用一套层级或让模型直接修改生产状态，会混淆用户事实、助手策略和模型生成判断。

WikiSkill 提供了可借鉴的控制结构：保留原始轨迹，把经验整理为持久模式，再提出可执行候选；候选只有通过验证才激活，失败可回滚。但该工作使用任务得分验证技能，而日常陪伴没有同等可靠的标准答案，因此不能直接照搬其自动验收条件。

## 决定

### 1. 两个入口平面

- **产品交互平面**：SmartRing-Plus 圆屏终端是最终用户的主要入口。正常记忆积累不得要求用户打开网页逐条审批。
- **内部控制平面**：React 控制台用于开发观察、证据核对、纠正、停用、版本查看和回滚。控制台审批是内部保护工具，不是产品交互前提。

### 2. 两条相互隔离的演化回路

**个人记忆演化回路**回答“系统怎样认识用户”：

1. 先保存不可原地改写的 L0 交互证据。
2. 提取或整理得到 L1/L2/L3 的 `ADD / UPDATE / NOOP` 候选。
3. 确定性策略根据来源类型、证据数量、跨日覆盖、敏感性、冲突和风险作出 `AUTO_ACTIVATE / HOLD / ASK_NATURALLY / BLOCK` 决定。
4. 只有符合低风险规则的候选可自动生效；UPDATE 继续使用候选式取代和原子状态切换。
5. 不足证据使用 NOOP 或 HOLD，不为追求“成长感”强行生成画像。
6. 用户可在圆屏对话中自然纠正；控制台提供事后审计与回滚。

**陪伴策略演化回路**回答“助手应该怎样陪伴”：

1. 保存最小化、可追溯的交互结果与反馈事件，不把它们伪装成用户事实。
2. 从多次事件中形成经验模式，再提出原子的陪伴策略候选，例如回应顺序、主动交流时机或表达偏好。
3. 候选先经过离线回放、固定安全规则和质量门控；通过后才生成版本并低频激活。
4. 每次激活记录版本、原因和影响范围，并支持回滚。

陪伴策略不存入 L3。L3 永久只表示用户画像；助手角色与可学习陪伴策略属于独立的 assistant policy 边界。

### 3. 不可跨越的安全边界

- 模型不得直接修改生产数据库状态，只能输出严格契约候选。
- 自动路径不支持 DELETE；删除和彻底擦除保持独立管理语义。
- 敏感事实、身份归因不清、来源角色冲突或高影响策略默认 BLOCK/HOLD，不能仅凭模型置信度自动激活。
- “继续聊天”“回复更久”等参与度信号不能单独作为陪伴策略变好的证据，避免用黏性替代用户福祉。
- 当前不训练或在线修改模型权重；自进化首先发生在可审计的记忆状态和策略版本。
- 自动整理必须有调用预算、失败不重试、幂等、版本核对和审计记录；持久调度另行设计。

## 当前实现与后续顺序

当前已实现人工 L2/L3 候选、严格整理契约、来源追溯、复核、失效和取代；确定性自主记忆决策契约已作为纯领域策略落地，但尚未接入数据库自动接受。圆屏自然纠正、结果事件、陪伴策略存储或策略门控仍未实现。

接下来按以下顺序推进：

1. 已实现不调用模型、不写数据库的自主 L3 决策契约和合成测试；后续扩展到 L1/L2 时分别定义风险规则。
2. 将低风险 L1/L2/L3 候选接入受控自动生效，保留内部收件箱和审计。
3. 增加圆屏自然语言纠正入口。
4. 记录回答、使用的记忆、结果和显式/隐式反馈事件。
5. 再建立独立的陪伴经验、策略候选、离线门控、版本与回滚，不提前引入通用智能体框架。
6. 最后才评估低频调度与主动交流。

## 后果

收益是产品用户无需网页操作，同时仍保留错误可发现、可解释和可回退的“玻璃盒”能力；个人画像与助手行为不会混成一个不可审计提示词。代价是自动化上线前必须补风险分类、敏感字段、事件数据和离线门控，不能简单地把当前“接受”按钮改为默认通过。
