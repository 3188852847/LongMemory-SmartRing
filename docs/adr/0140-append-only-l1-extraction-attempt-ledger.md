# ADR-0140：日常 L1 提取采用脱敏、追加式尝试账本

- 状态：已接受
- 日期：2026-09-13

## 背景

日常聊天已经区分 L0 原始记录与 L1 原子记忆，但“没有形成 L1”过去只能从进程日志推测。正常问句、模型提取失败和 SQLite 落库失败对所有者表现相近，既不利于产品排障，也无法可靠积累提取质量样本。

## 决定

SQLite V44 新增 `l1_extraction_events`。每次用户 L1 提取先追加 `started`，再追加 `completed` 或 `failed`；终态固定区分 `noop`、`added`、`reused`、`extraction_failed` 和 `persistence_failed`。事件保存 L0 ID、候选/新增数量、耗时、方法、输入预处理、提示词、供应商和模型版本，不复制用户原文或模型响应。

审计写入是主聊天的旁路能力。失败时回滚审计事务但不撤销已经保存的 L0，也不让回答一起失败；只有 `started` 而没有终态代表进程中断或审计终态写入失败，不能伪装为正常不记。控制台只在所有者主动打开 L0 时读取原文。

## 边界

- V44 之前的历史对话不猜测、不回填提取结果。
- 账本不计算准确率；`noop` 只表示当时策略没有产生候选，不证明判断正确。
- 不保存 API Key、自由文本错误、模型响应或提示词正文，只保存固定版本与 SHA-256。
- 本切片只增加观测，不修改提取策略、召回、回答和 L2/L3 整理。

## 后果

“未记住”可以被可靠分成正常决策与工程故障，并可按版本追踪回归。代价是每次用户提取增加两次很小的本地 SQLite 追加写；若进程在两阶段之间退出，账本会保留可见的未完成尝试。
