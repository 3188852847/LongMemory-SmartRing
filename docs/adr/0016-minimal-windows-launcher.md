# ADR-0016：最小 Windows 启动面板与进程所有权

- 日期：2026-09-04。
- 状态：已实施最小入口；真实校园模型/圆屏与可见交互验收待用户执行。
- 属于 ADR-0015 的 P1 子步骤，不宣称 P1 全部完成。

## 决定

复用当前环境自带 Tkinter，不添加依赖、不改前端框架。根目录 ASCII `Start.cmd` 调用项目 pythonw，显示一个小面板；默认文字，显式选择后同时启动小智。每次确认写入及当前 HTTP 风险。

控制台仍用现有 uv `--offline --no-sync --env-file` 入口，不安装依赖、不调用模型预检。小智仍用自己的环境和原 setup 启动工具，额外只读核对共享路径，不覆盖 YAML。

## 所有权与故障

本机 18767 绑定作为单实例锁，进程退出释放；未知占用直接拒绝，不按 PID 文件接管。服务启动前检查端口，仍通过每次随机实例响应头核对控制台就绪，防止预检后竞争造成误判。响应头不是认证能力，不扩大现有 API 权限。

每个服务创建 Windows Job（关闭时结束后代）；门控 worker 在加入 Job 后才运行真正服务。停止只处理自己创建的 Job，不运行按名称批量 kill、外部 PID 或修改防火墙。整树退出确认不等于网络栈瞬间完成端口回收。

第一版停止会中断进行中的请求，不实现优雅排空。用户须先结束聊天；原子事务保护不等于整轮未写入。部分服务退出则清理其他受管服务，不伪装为整体成功。语音只显示进程运行，设备和模型状态仍需实际验证。

## 限制与替代方案

不选常驻服务/桌面框架，减少当前部署变更；代价是必须保留面板。无自启、设置保存、会话恢复、完整配置同步、模型热切换或任意程序管理。删除和新实验作业不默认开启。服务输出不另存，故障用固定阶段提示和原终端排障入口。

后续可增量改进设置、优雅停止与状态，但不以启动器为由变更个人库、监听范围或固件。
