# ADR-0080：当前缺席策略复用 P4 后台调度与投递链

- 状态：已接受
- 日期：2026-09-07

## 背景

V26 已能原子选择和回滚策略版本，但当前指针尚未影响运行。若为习惯问候另建调度器、账本或投递器，会复制 P4 已验证的勿扰、频率、待回应、设备状态和幂等约束，容易产生两套安全语义。

## 决定

既有后台循环每次先评估用户显式定时；该分钟若已创建账本，则不再评估缺席策略。否则读取唯一当前版本，把冻结参数转换为启用的 `AbsenceRoutineDraft`，并从可信数据库事件计算“当天主动出现、当天聊过、当天已评估”。

缺席判断只在期望时刻加宽限后的唯一当地分钟创建候选，错过不补发。候选使用现有 `ProactiveOutreachLedger`、`ProactiveOutreachDispatcher`、P4 当前设置、设备探测和小智投递；触发类型为 `habit_candidate`。不调用模型，也不修改版本或用户画像。

## 理由

同一账本和投递链保证主动交流的许可与停止规则只有一套。显式定时优先避免同一分钟发出两条消息；版本 revision 写入策略标识，便于从运行记录追溯当时使用的选择。

## 后果

- 只有明确选为当前、且离线门控通过的版本能进入运行检查。
- 主动交流总开关关闭、勿扰、待回应、频率受限、会话活跃或设备离线仍会阻止投递。
- 当天已经出现或聊天、时刻尚未到、已错过或已评估都不会创建第二次候选。
- 当前仍使用已批准话题素材或固定问候，不让模型临场生成不可审计内容。
