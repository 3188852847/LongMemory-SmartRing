# ADR-0133：用追加式状态事件恢复 L1 重复合并

- 状态：接受
- 日期：2026-09-13

## 背景

V39 可以把所有者确认的重复 L1 合并，V40 又为新合并保存了逐条来源账本，但控制台仍不能纠正一次误合并。直接删除合并审计或删除保留项上的来源，会改写历史并可能破坏合并后形成的溯源关系；把此前失效的 L2/L3 一并复活，也可能重新启用已经陈旧的派生结论。

## 决定

SQLite V41 新增 `l1_duplicate_merge_state_events`。首次合并是隐含的状态修订 1，后续恢复和重新合并分别追加 `restore`、`reapply` 事件，不改写原合并事件与证据账本。

只有 V40 起账本至少包含一条、数量完整匹配，且保留项仍为当前、被合并项仍精确指向该保留项的合并可以恢复。V39 的零复制事件与 V40 的真实零复制事件无法从现有结构可靠区分，因此两者都保守地保持只读。恢复重新启用被合并 L1，但保留已经复制到保留项的 L0 来源，不自动复活 L2/L3。恢复后，质量扫描可再次显示这对候选；为保持历史和来源语义一致，只允许按原保留方向重新合并，并且被恢复项不能存在尚未覆盖到原保留项的新来源。

状态写入使用单调修订号和预期修订，陈旧页面不能覆盖较新的恢复或重新合并操作。V39 的旧合并因没有逐条账本，只能查看，不能冒充可安全恢复。

## 后果

误合并现在可以在记忆页的合并历史中纠正，同时保留完整审计。该操作是“恢复 L1 当前状态”，不是数据库时间旅行或完全抹除合并痕迹；复制来源、合并历史和派生记忆失效历史均继续存在。若需要恢复 L2/L3，应由之后的整理流程基于当前来源重新生成或复核，而不是隐式复活。
