# ADR-0096：回答级记忆反馈保存在网页会话旁库

- 状态：接受
- 日期：2026-09-09

## 背景

每日回顾已经能发现提取漏记，但仍无法区分一次不满意回答究竟是没有召回、召回了错误记忆，还是问题本来就与记忆无关。只保存“回答好/坏”也无法定位记忆链路中的故障阶段。

## 决定

1. 内部网页聊天为已完成回答提供四种所有者标记：`memory_ok`、`recall_miss`、`wrong_memory`、`memory_irrelevant`。
2. 标记关联现有 `chat_id + request_id`。回答、召回项、注入上下文和 L1/L2/L3 轨迹继续只保存在网页会话旁库，不复制进主记忆库或质量汇总。
3. 每轮保存一个当前标记，并追加不可变的修订事件。写入携带 `expected_revision`，旧页面不能覆盖较新的判断；每轮最多 32 次修订。
4. 每日质量接口只返回标记类别、时间、修订号和会话/轮次定位信息，不返回问题、回答或记忆正文。
5. 标记不会调用回答模型、重新执行回答、修改 L0–L3、训练模型或自动调整策略。它首先是人工诊断证据，后续是否用于算法学习另立协议。
6. 该入口属于所有者/开发者控制台。普通圆屏用户不需要打开网页逐轮确认；未来自然语言反馈需经过独立、高精度的解释契约。

## 理由

- 回答质量问题天然属于某个具体回答及其检索轨迹，放入主记忆事实表会混淆“用户事实”和“系统评价”。
- 复用现有旁库避免复制敏感正文，深链接仍能在本机核对完整上下文。
- 追加式修订允许修正误点，同时保留研究所需的判断变更历史。

## 后果与限制

- 删除整个网页会话档案时，对应回答反馈也会一并删除；L0–L3 不受影响。
- 当天计数是“人工复核动作数”，不是独立回答数或准确率；同一轮改标会产生多次动作。
- 当前没有自由文本理由、自动故障归因或跨设备反馈合并。
