# ADR-0025：本机 VoxCPM2 与 Xiaozhi 的可替换 TTS 适配层

状态：接受，2026-09-05。

## 背景

VoxCPM2 固定权重已在独立 Python 3.11/CUDA 环境完成离线试听，用户当前偏好默认 `plain.wav`。主项目、小智和 VoxCPM2 使用不同 Python 环境；把模型直接导入小智会耦合依赖，并在连接初始化或逐句调用时承担重复加载风险。

本机检查确认：当前 Xiaozhi 快照通过 `selected_module.TTS` 动态载入 Provider；已有 `CustomTTS` 支持 POST JSON 并接收音频字节。其基础层会把 WAV 转为单声道、设备协商采样率、16 位 PCM，再编码为 Opus。因此无需修改圆屏固件，也无需新建 Xiaozhi 专用 Provider。

## 决定

采用进程边界适配：VoxCPM2 在自己的 Python 3.11 环境中作为常驻本机 HTTP 服务；Xiaozhi 继续使用上游 `CustomTTS`，请求服务并取得 WAV。服务固定监听 `127.0.0.1:18768`，只暴露 `GET /health` 与 `POST /v1/audio/speech`，不接受模型路径、上传文件、参考音频或浏览器 Origin。

第一版只提供 `plain` 参数组、整句非流式合成、单路 GPU 推理与有限内存缓存。权重加载前仍校验固定 SHA256，推理禁止自动联网。EdgeTTS 保留为明确回退项；私有配置切换需要摘要复核、原文备份与原子替换，不因启动服务自动改写。

## 后果与边界

- 长程记忆核心、聊天数据库、学校 LLM 与圆屏固件均不依赖 VoxCPM2。
- 以后替换 TTS 时，只要实现相同“文本到 WAV”契约，小智链路无需变化。
- 本地 HTTP 不传校园模型密钥，也不经过局域网；但同机进程仍属于信任边界。服务拒绝 CORS 和非环回绑定，不等于对本机恶意程序的强认证。
- 当前实测整段合成接近实时但不是流式首包，圆屏首句延迟可能明显。先做端到端体验，再决定流式、并行或量化，不把试听性能写成产品性能。
- Xiaozhi 基础类在 TTS 失败时最多重试五次。服务通过单路门控和重复文本缓存降低堆积风险，但真实超时行为仍须实机验证。
