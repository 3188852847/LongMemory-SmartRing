# ADR-0055：自动记忆生效必须显式证明风险评估已完成

- 状态：已接受并实现契约门控
- 日期：2026-09-06
- 关联阶段：P3.9

## 背景

L1→L2 与 L2→L3 一次性执行器原本要求调用方传入风险对象，但空对象会把所有标记默认为 `False`。这只能表示“没有提供风险”，不能证明内容不敏感、来源没有混淆或不存在冲突。若后台调度器直接传空对象，证据门槛再严格也可能把未知风险误当成低风险。

只用敏感词黑名单不能解决这个问题：未命中关键词不是安全证明，且个人偏好、健康、关系和位置等内容高度依赖上下文。

## 决定

1. L2 和 L3 风险对象都必须显式携带 `assessment_complete`，不再提供可被误用的默认值。
2. 已知敏感、角色混淆和冲突仍优先 BLOCK/HOLD；其余情况下，只要评估未完成，就以稳定原因 `risk_assessment_incomplete` 进入 HOLD。
3. 一次性执行器在风险评估未完成时于读取来源和调用模型之前返回，不创建运行记录、不消耗预算、不推进游标。
4. 当前不实现一个冒充完整判断的关键词分类器。后续后台装配必须接入可测试的受信风险评估器，并把它的版本与边界记录在运行结果中。
5. 本决定只收紧自动生效契约，不改变人工创建、人工复核、L0/L1 存储或现有 active 记忆。

## 后果

- 新调用者若遗漏风险评估完成状态会在构造阶段失败，而不是静默自动接受。
- 现有测试和显式合成执行必须写明 `assessment_complete=True`，表示该测试已经固定风险前提；这不等于生产分类器已经实现。
- P3.9 仍不能直接打开常驻后台。下一步先定义调度所有权，再实现一个保守且有版本的风险评估输入；无法判定的建议允许不生效。
