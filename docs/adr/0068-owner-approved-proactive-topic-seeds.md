# ADR-0068：所有者明确批准的主动话题素材

## 背景

P4.5 已能在固定时间播报用户填写的问候，但它不读取记忆。P4.6 需要让主动交流与长期记忆产生联系。直接把 L1、L2 或 L3 交给模型生成并自动朗读存在两个问题：圆屏声音会被旁人听见，而当前记忆没有“允许公开播报”的隐私标记；模型分类也不能等同用户许可。

网页控制台是所有者的观察和配置平面，不是普通圆屏用户每次聊天的批准入口。因此第一步应提供低频配置能力，而不是要求用户逐轮审核。

## 决定

1. SQLite V17 新增 `proactive_topic_seeds`。一条素材引用一个已接受且当前有效的 L2 场景，并保存所有者明确填写的单行短句、状态、时间和 revision；它不属于 L0–L3，也不更新 L3。
2. 第一版只允许 L2 作为来源。L2 已具备 L1→L0 证据链，比直接选择自由文本 L1 或聚合 L3 更适合作为可审计的话题上下文。
3. `prompt_text` 是“允许圆屏在他人可能听见时念出”的文本，不是把场景摘要自动复制过去。创建时必须再次核对场景 revision，且场景不是 `active` 或现实有效期已结束时拒绝创建。
4. 素材可停用但不物理删除；来源场景失效或过期后，读取结果自动标记为不可用。停用使用 revision 防止旧页面覆盖。
5. 本切片只做创建、查看来源和停用，不调用模型、不创建主动联系账本、不接调度器、不向圆屏播报。后续接入仍必须经过 P4 的总开关、勿扰、时段、频率、设备忙碌和幂等门控。

## 理由

关键词黑名单或模型敏感度判断都无法替代明确的可播许可。把“安全播报文本”与个人记忆分开，既能保留来源，也避免把主动交流文案反向污染用户画像。先限定 L2 能收紧第一版边界，未来若需要 L1/L3 来源，可在有独立隐私分级后扩展，而不改变调度接口。

## 后果

- 初次配置需要所有者在控制台选择场景并写一句安全话题；普通圆屏聊天不需要网页确认。
- 当前素材不会自动发声，因而不能把控制台中的“可用”解释为已投递或已播放。
- V17 迁移只创建空表，不自动把已有记忆转换成可播素材。
- 场景被物理删除会因外键受到保护；正常生命周期应先使场景失效，素材随即不可用。

## 验证

- 领域测试覆盖短句边界。
- 临时 SQLite 覆盖 V16→V17 空迁移、有效来源创建、未接受/冲突来源拒绝和 revision 停用。
- 回环 HTTP 覆盖 CSRF、来源展示、零设备调用与停用。
- React 测试覆盖显式选择 L2、填写安全短句及“保存不等于播报”的提示。
