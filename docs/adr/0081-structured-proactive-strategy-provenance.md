# ADR-0081：主动问候结构化绑定策略运行来源

- 状态：已接受
- 日期：2026-09-07

## 背景

第七切片虽然把选择 revision 拼入 `policy_version` 文本，但文本不能可靠表达策略版本、来源候选和本次评估日期，也无法通过外键保证版本真实存在。版本切换后若只能看到一段原因文字，所有者无法还原某条主动问候当时采用了哪份冻结策略。

## 决定

SQLite V27 在 `proactive_outreach` 当前投影增加三个可空字段：策略版本 ID、选择指针 revision、评估当地日期。三项只能同时为空或同时存在；存在时触发类型必须是 `habit_candidate`。策略版本 ID 以外键指向不可变缺席策略版本。

运行时在创建候选的同一次账本写入中冻结这三个值。控制台沿版本读取来源候选 ID/revision、冻结的期望时刻、宽限、时区和触发器版本；最终门控与投递结果仍读取账本事件，不从来源字段推断。

## 理由

结构化绑定可以在版本切换或回滚后保留历史语义，并让页面和未来分析无需解析字符串。复用既有投影避免建立第二套运行账本；外键防止运行记录指向不存在的策略版本。

## 后果

- 旧记录和非习惯触发记录保持空来源，迁移不回填或猜测历史。
- 新习惯问候能够回答“哪个版本、哪次激活、哪天评估、来源候选是什么”。
- 来源只解释触发依据，不代表圆屏已播放，也不代表用户喜欢这次问候。
- 本切片不改变触发时刻、安全门控、消息内容或设备投递行为。
