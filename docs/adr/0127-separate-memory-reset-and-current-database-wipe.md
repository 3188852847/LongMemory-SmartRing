# ADR-0127：区分长期记忆重置与当前数据库 L0–L3 清除

## 背景

原控制台把“删除全部 L1、保留 L0”称为“清空记忆”。这适合开发期重新提取，
但名称容易让所有者误以为原始对话也已经消失。L0 仍可查看，也可能在未来重新派生
L1，因此不能把原操作描述成彻底忘记。

## 决定

1. 原操作改名为“重置长期记忆”：删除全部 L1，让关联 L2/L3 失效，保留 L0。
2. 新增独立的“清除 L0–L3”：删除当前主 SQLite 库里的 L0、L1、L2、L3，
   同时删除回答证据、质量事件、整理记录和从个人互动派生的陪伴学习记录。
3. 模型、声音和主动交流规则等产品设置不属于本次记忆清除，继续保留。
4. 执行前以不含正文的数量和覆盖全部待删行的 revision 供所有者核对；任何并发变化
   都使旧确认失效。请求必须带本机会话、CSRF、删除能力和固定确认短语。
5. 执行前创建 SQLite 一致性恢复点并校验 `quick_check`，清除在单一事务内完成并复核
   外键。恢复点的路径与 SHA-256 返回给控制台。
6. 网页聊天会话旁库和已有备份不删除，因此该入口明确不称为磁盘级或账号级隐私擦除。

## 后果

所有者可以选择保留证据重新开始，或阻止当前主库从 L0 再次派生旧内容。代价是产品
现在有两个看似相近但语义不同的危险操作，页面必须持续展示差异。真正覆盖旁库、备份、
日志和外部供应商数据的隐私擦除仍需单独设计，不能由本功能冒充。
