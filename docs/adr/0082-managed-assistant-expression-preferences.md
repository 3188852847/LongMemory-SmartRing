# ADR-0082：在版本化角色提示词中嵌入可移除的结构化表达偏好

- 日期：2026-09-07
- 状态：已接受并实现
- 接续 ADR-0021、ADR-0022；不改变 L3 用户画像语义

## 背景

现有助手角色设置允许编辑完整系统提示词并保存版本，但普通使用者需要理解提示词才能调整称呼、回答长度、互动方式和表情频率。为这些选项另建一套独立配置，会造成网页角色、圆屏角色和结构化偏好之间的优先级与同步问题；直接改变角色旁库结构则需要迁移已有版本。

## 决定

1. 在现有角色编辑器中增加可显式启停的“结构化表达偏好”，第一版包含：用户称呼、回答长度、互动方式和表情频率。
2. 偏好由前端编译成一段带固定起止标记、机器可回读元数据和自然语言约束的受管提示词区块，随现有角色版本一并保存。
3. 旧提示词没有受管区块时默认关闭且原样保留；启用后保存只追加一个区块，重复保存替换原区块；关闭后保存只移除完整受管区块，不删除其他手写提示词。
4. 完整角色提示词仍受现有 12000 字符限制、版本冲突保护、本机认证与 CSRF 约束。称呼限制为 20 字符并拒绝换行、空字符及受管标记括号。
5. 网页下一轮和圆屏显式同步继续读取同一个角色版本。结构化偏好不是 L3 用户画像、不是事实证据，不进入长期记忆库，也不自动覆盖当前对话中的明确要求。

## 后果

用户无需修改整段提示词即可完成常用表达设置，同时已有自定义角色无需数据库迁移。代价是角色提示词内包含一段项目管理的文本格式；其起止标记和版本属于兼容契约，未来修改格式必须保留旧版读取与移除能力。模型是否完全遵循偏好仍需真实对话体验，保存成功只证明配置版本生效。

## 回退

在角色设置中关闭“结构化表达偏好”并保存，即可移除受管区块并生成新版本；旧版本仍留在角色旁库中。也可以载入原角色预设后保存并按既有流程同步圆屏。
