# ADR-0125：共享 Xiaozhi 配置的顺序刷新写入

日期：2026-09-13
状态：接受

## 背景

启动器会在语音启动前同步网络、TTS、模型、记忆后端和 VAD。五个配置域虽然在产品中彼此独立，却共同保存在 Xiaozhi 的 `data/.config.yaml`，各写入工具都使用整文件 SHA-256 摘要防止覆盖并发修改。

旧流程先取得五个摘要，再依次写入。前一个域成功改写同一文件后，后一个域仍携带预检时的旧摘要，会把启动器自己的前序修改误判成外部并发修改。用户切换多个启动项时，失败提示可能落在 VAD 等最后一个域，掩盖真正原因。

## 决定

1. 端口空闲后仍先对五个配置域完成全量只读预检，避免写到一半才发现后续域结构不受支持。
2. 第一项实际写入后，后续每个域在写入前重新只读检查共享 YAML，使用最新摘要和最新匹配状态。
3. 若前面没有发生写入，继续复用首次预检结果，不增加无意义子进程调用。
4. 每个写入工具原有的字段白名单、备份、摘要检查和原子替换保持不变；该流程不合并为一个能任意改 YAML 的通用写入器。

## 后果

- 一次启动可以安全同步多个配置域，不再由启动器自己制造陈旧摘要。
- 全量预检与逐项新鲜摘要同时保留，但发生改动的启动会增加少量本机只读检查。
- 真正由其他程序并发修改配置时，最新摘要保护仍会拒绝覆盖。
