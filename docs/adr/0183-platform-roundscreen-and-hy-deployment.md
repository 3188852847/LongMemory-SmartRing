# ADR-0183：平台圆屏轮次与可信 Hy 日用装配

日期：2026-10-19。状态：接受本轮实现边界；真实模型组合、正式构建、日用切换和所有者体验仍待验。

## 背景与决定

用户授权独立会话完成真实模型验证及圆屏适配，通过后切换日用记忆层，管理前端全部按 Hy 重设计。V 负责模型和整轮十元预算，X 负责圆屏与可信装配，Y 负责管理。此授权有明确验收门槛，不把旧阶段“未授权切换”改写为当时已经授权。

在 [ADR-0181](0181-neutral-memory-backend-and-platform-sources.md) 的平台来源边界上扩展圆屏轮次。新来源库内增加 `platform_rounds/platform_round_feedback`；不把 Hy 内部层号映射成旧 L1/L2/L3。用户事件保存连接会话、客户端轮次、服务端请求及可用的语音观测轮次。最终助手来源与完成关联同事务提交，助手不进入事实提取。网页与圆屏共享同一 Runtime/Hy 用户空间，短期会话独立；原角色、声音和网页会话旁库继续沿用。

准备时先归档用户原文、将投递状态置为 pending，再检索此前已完成的记忆。完成回执提交助手/关联后，持久声明本轮后台投递已认领，然后排队完整 `observe`；不拆 Hy 内部事务。认领后、调用前崩溃可能留下 pending，必须显式恢复，不重放所有完成轮次。引擎失败为 failed；跨引擎/来源提交窗口仍可能 uncertain，不宣称 exactly-once（恰好一次）。

重复准备返回冲突，避免重新召回/重新提取造成内容或费用变化；重复相同完成回放原助手 ID，异载荷拒绝。取消/被替代/回答失败不归档虚假的最终助手，不自动提取该 pending 用户事件。五分钟完成期限在新准备、状态查询和完成时执行，不增加后台调度器。重启不自动重放；prepared 可以接受期限内的明确完成，preparing 变 uncertain。已完成之后的取消观察保留原助手档案，不能撤销真实生成，也不证明设备曾播放。

新协议以 `memory_protocol=2` 和中立 `memory_receipt` 表示条目数量、策略、内容摘要及来源；未知为 None，空集合为确实无结果。完成回执必须与准备时持久保存的凭据一致。旧层级协议只服务旧后端。来源侧严格反馈只关联同一连接会话十分钟内的上一条已完成回答，不反馈学习、不自动修改 Hy。

正式装配只读取固定 `local/config/hy-memory/deployment.json` 与 `settings.json`，HTTP 只选择 `hy_memory` 枚举。解释器摘要、已验收Python3.12.13、设置身份、精确状态目录和平台来源路径必须匹配，初始化后再核对真实SDK/Python版本；路径局限项目 data/local 所有权且拒绝联接。Runtime状态提供同一`state_identity`摘要。普通启动只重开已初始化库，首次新库须由受控切换所有者显式创建。模型/维度/端点身份继续由 V 的设置实现校验，不能用选择枚举代替真实效果、预算及本地 BGE 验收。

## 代价、替代与回退

来源优先让失败可检查，但与 Hy 状态仍没有跨存储事务。Hy 整流程串行期间可能阻塞后续召回和状态；仅延后首轮提取不能证明持续低延迟。用户本轮的新事实在后台完整流程成功后才进入长期召回；本轮原话仍在小智当前对话中。

用共享对话尾部切片识别助手会在重叠话轮中串答。薄包装器改为按调用上下文捕获实际 `dialogue.put` 助手正文，显式轮次键跨异步/线程交接；后来的顶层话轮将旧调用标记 superseded。无来源的内部结束提示继续按可信调用边界排除。无法观察的回执或播放保持未知，不造成功。

新后端旧主动交流能力暂停，保留原设置与旧库，不开调度、不借旧表伪装可用。回退通过后端选择重开旧算法，保留新 Hy 目录和来源库；不会自动把新事实迁回旧库，更不将备份回刷覆盖新增对话。

## 验证与后续

合成状态覆盖重复、失败、并发、跨线程、重启、超时、取消、来源角色、反馈及旧后端。真实 Hy SDK/Chroma 使用禁网模型替身并经 Python 3.10 → HTTP 3.12 → 专属 SDK 进程验证，不代表真实模型质量或设备体验。实际结果与逐阶段授权见 [X 记录](../development/parallel/X-hy-roundscreen-20261019.md)；切换操作见 [Hy 日用装配指南](../guides/Hy-Memory圆屏与日用装配-20261019.md)。
