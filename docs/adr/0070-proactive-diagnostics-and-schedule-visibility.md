# ADR-0070：手动诊断与自动追问规则分离

- 状态：已接受并实现。
- 日期：2026-09-07。
- 修订：ADR-0064 第 4 条对手动诊断的 `awaiting_user_response` 约束。

## 背景

实机验收中，用户当天已经聊天，因此 13:02 的自动问候按设计以 `user_already_chatted_today` 跳过；同时，较早一条已播放问候之后没有更新的用户消息，使手动验证被 `awaiting_user_response` 拦截。两个原因都没有在设置页预先显示，表现为定时点无动作、诊断按钮也不能验证设备，难以区分安全规则与故障。

## 决定

1. 自动定时继续执行“当天聊过则跳过”和“上一条仍待回应则不追问”。这两项保护不因测试困难而放宽。
2. 所有者显式点击的手动圆屏验证不再受 `awaiting_user_response` 限制。它不是后台自主追问，仍遵守总许可、允许星期和时段、勿扰、每日次数、最短间隔、有效期及设备会话状态。
3. 新增只读定时状态接口，返回当天是否已有真实用户消息、是否仍等待上一条回应、是否已有当天定时账本，以及当前纯触发决定。接口只读取时间和状态，不返回聊天正文，也不投递消息。
4. React 设置页每 30 秒刷新该状态，优先用中文说明“今天聊过会跳过”和“上一条仍待回应”；不能再要求用户通过无记录的沉默猜测原因。

## 后果

- 手动验证仍产生真实账本并占用频率预算，不是无限制试听。
- 进入“聆听中”本身不是用户回应；只有实际用户消息写入 L0 后，自动联系的待回应状态才解除。
- 变更不涉及数据库迁移，也不清理或改写既有主动交流事件。

## 验证

- HTTP 测试先创建并确认一条已播放问候，在没有新用户消息时确认状态接口报告待回应，再验证第二次显式诊断仍可排队。
- React 测试验证当天聊天和待回应提示同时可见。
- 自动定时策略测试保持原有跳过行为。
