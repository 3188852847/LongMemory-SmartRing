# ADR-0044：统一用户画像采用原子断言之上的聚合投影

- 日期：2026-09-06
- 状态：已实现第一切片
- 接续 ADR-0039、ADR-0042、ADR-0043

## 背景

现有 L3 将每项偏好、习惯、互动方式或行为模式保存为独立断言。这有利于来源追溯、逐项复核、上游失效传播和未来纠正，但直接把全部断言作为“用户画像列表”展示，会让用户感觉系统维护了许多彼此割裂的画像。

产品目标是让用户看到一份随使用逐渐丰富的个人档案，同时不能用一个不断覆盖的大文本块换取表面简洁。整块覆盖会使局部纠正、删除、来源失效、并发修订和模型漏写都难以审计。

## 决定

1. 对当前单用户主体 `user:self`，控制台只呈现一份“统一画像”。未来多用户时是一位主体一份，而不是整个系统只有一个全局对象。
2. `persona_memories` 中独立、已复核的原子断言仍是事实来源；统一画像是读取时生成的投影，不新增持久化大文本，也不迁移或回写数据库。
3. 聚合投影只包含 `active` 断言。`candidate`、`rejected` 和 `stale` 留在“画像依据与候选”工作区，不能混入正式画像。
4. 第一版按偏好、习惯、互动方式、行为模式四类组织；每个展示条目保留原断言 ID，可打开 L1/L2→L0 证据链。
5. 未来的自动画像整理必须产出显式的增量操作（如新增、取代、失效或无操作），不能让模型无条件重写整份画像。
6. 长期规划、价值观、兴趣、关系等新栏目尚未实现。增加它们前需单独定义敏感性、证据门槛、有效期和迁移影响。
7. 本切片不触发模型、不自动接受候选、不把 L3 注入回答，也不改变 L2 自动整理状态。

## 后果

用户获得一份连续、分栏的画像视图；底层仍可独立纠错和追溯。统一画像会随断言的接受或失效即时变化，不需要维护第二份容易漂移的副本。代价是当前投影仍可能出现同类重复或冲突断言；这些问题由后续“画像整合操作”解决，不能靠展示层静默合并。

## 回退

移除 `/api/persona-profile` 和 React 的统一画像页签即可回到原断言列表。数据库结构和个人数据未改变，无需数据回滚。
