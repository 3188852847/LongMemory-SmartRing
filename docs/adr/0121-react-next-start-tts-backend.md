# ADR-0121：React 管理下次启动的圆屏 TTS 后端

## 状态

已接受，2026-09-11。

## 背景

EdgeTTS、VoxCPM2 和 sanoTTS 已经接入统一启动面板，但切换入口只在 Windows 面板中。React 设置中心能够试听和调整当前后端，却不能选择下一次圆屏语音使用哪个后端，容易把“正在试听什么”与“下次会启动什么”混为一谈。

TTS 切换还会改变外部本地服务和显存占用，因此不能在回答中途热切换，也不能由网页擅自启动或终止模型进程。

## 决定

1. React 设置中心增加 EdgeTTS、VoxCPM2、sanoTTS 三选一入口，只保存下次统一启动的后端 ID。
2. 选择保存到 Git 忽略的 `data/control/tts-backend.json`；文件不含密钥、模型路径、声音参数或私有配置正文。
3. 统一启动面板继续拥有进程生命周期，并在启动瞬间读取共享选择。若用户已在面板中亲自改过下拉框，则以面板的显式选择为准。
4. 运行中的语音不会热切换。页面同时显示本次启动后端、下次启动后端和是否等待重启。
5. 启动器最小状态快照升级为 V3，只增加本次 TTS 后端 ID；V1、V2 保持可读。快照不冒充圆屏播放回执。
6. 旧 `launcher.json` 中的 TTS 选择只作首次兼容回退；后续网页与面板共用独立指针，避免其他面板首选项覆盖它。

## 后果

- 用户可以在同一个设置中心完成后端选择、当前后端参数调整和固定测试，但三类操作仍有明确生效范围。
- 切换到 VoxCPM2 或 sanoTTS 时，启动器仍会执行既有目录、指纹和服务就绪检查；保存选择不等于模型已成功启动。
- 无需为了读取网页选择关闭并重新打开启动面板，但必须停止并重新启动语音服务才能生效。
- 未来新增 TTS 必须先进入白名单和能力契约，不能通过网页提交任意命令或路径。
