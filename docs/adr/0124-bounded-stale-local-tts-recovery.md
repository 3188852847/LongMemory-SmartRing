# ADR-0124：受限的遗留本地 TTS 清理

日期：2026-09-13
状态：接受

## 背景

ADR-0114 的“清理遗留语音”只识别 Xiaozhi 的 8000/8003/8766 三端口。独立验证或启动器异常退出后，VoxCPM2、sanoTTS 或 CosyVoice3 也可能继续占用 18768–18770；此时原按钮会报告 Xiaozhi 无需清理，却无法解决真正阻止启动的端口。

只根据端口或 `python.exe` 结束进程不安全，因为同机其他服务也可能使用 Python 或 Node。

## 决定

1. 按钮更名为“清理遗留服务”，继续执行 ADR-0114 的 Xiaozhi 三端口核验，并额外检查当前明确选择的本地 TTS；EdgeTTS 没有本地进程。
2. 本地 TTS 只接受固定映射：VoxCPM2/18768/Python、sanoTTS/18769/Node、CosyVoice3/18770/Python。
3. 停止前必须同时满足：环回端口只有一个监听者；`/health` 返回 `ready=true`；顶层 `provider` 与能力中的 `provider_id` 都等于所选后端；健康检查后监听 PID 未变化；进程类型在该后端白名单内。
4. 任一条件不满足即拒绝，不批量扫描或结束 Python/Node。停止后再次确认固定端口已无监听。
5. 启动面板自己仍拥有服务时，必须使用正常“停止服务”结束 Windows Job 中的整棵进程树，不能走遗留清理旁路。

## 后果

- 独立测试留下的本地 TTS 可以从同一个面板安全恢复，不再要求用户手工查 PID。
- 健康接口身份核验比单端口判断严格，但它仍是本机开发工具，不是跨用户鉴权机制。
- 当前按钮只处理面板选择的 TTS，不擅自停止其他后端端口上的服务。
