# ADR-0164：合并短标点片段

## 状态

已接受，2026-09-14。部分取代 ADR-0163 的“每个逗号都形成播放片段”。

2026-09-15：下述首段决定已由 [ADR-0168](0168-cosyvoice-short-opening-continuity.md)
部分取代；后续 18 字自然标点合并和完整片段播放继续保留。

## 背景

ADR-0163 消除了模型块边界造成的词中停顿，但首轮真实体验仅改善少量，整体仍慢。V5
显示该回答首包约 4.04 秒，却被细分为 33 个 TTS 请求；除一个 4.84 秒片段外，每次生成
约 1.46～2.93 秒。每个逗号和顿号立即切分会反复支付模型请求固定成本。

用户要求所有可听停顿仍落在逗号或其他自然标点，不能重新使用固定字符硬切。

## 决定

1. 第一个自然短句继续使用上游首逗号/句末边界，保留当前约 4 秒的首包表现。
2. 第一段之后至少累计 18 个字符，再选择随后遇到的第一个逗号、顿号、句号、问号、
   感叹号、分号或冒号形成 TTS 片段。
3. 如果超过 18 个字符仍没有标点，继续等待自然边界，不按固定字数切开词语。
4. 每个合并片段仍完整生成后连续播放，保持 ADR-0163 的句内连贯性。

## 后果

- 可显著减少逗号密集回答的 TTS 请求次数和重复固定成本。
- 首段速度保持不变；后续单片段生成时间会增加，但上一段播放可与其生成重叠。
- 极长且没有标点的模型输出仍会等待到最终剩余文本处理，需依靠回答提示和质量观察避免。

## 回退

恢复 ADR-0163 的逐标点切分即可；不涉及模型、配置、固件、记忆或数据库迁移。
