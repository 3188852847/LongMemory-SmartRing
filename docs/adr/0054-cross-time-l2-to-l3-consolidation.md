# ADR-0054：L2→L3 自动整理只使用当前有效场景和可回溯跨日证据

- 状态：已接受
- 日期：2026-09-06
- 关联阶段：P3.9

## 背景

L3 用户画像表示较稳定的偏好、习惯、互动方式和行为模式，不能由一轮对话或单个 L2 场景直接推断。已有 L3 整理契约和自动生效门控可以处理显式来源，但缺少低频、可续跑的 L2 批次与调用账本。

## 决定

1. L2→L3 只选择当前 `active` 且在有效时间范围内的 L2；候选、拒绝、失效和过期场景不能进入模型输入。
2. 每个 L2 必须沿来源解析到用户 L0 原文和 UTC 观察日。模型看到的证据仍是数据而非指令；门控使用数据库复算的来源数、用户原话数和观察日数。
3. L2 游标按 `generated_at + scenario_id` 从最老新来源无缺口推进；有新 L2 时，批次余量可带入最近的旧有效 L2，用于更新已有画像或形成跨时间模式。没有新 L2 时不单独重放旧上下文。
4. 首版 L2→L3 运行护栏为至少 2 个新 L2、24 小时冷却、每天最多 1 次模型调用、单批最多 12 个 L2。它只控制成本和频率，不降低 `persona-activation-v1` 的 3 来源/5 原话/3 观察日自动生效门槛。
5. 模型只返回 `ADD / UPDATE / NOOP` 建议。NOOP 正常推进游标；建议仍由既有 L3 风险门控、来源复算、候选式取代和 `policy` 审计执行。
6. 当前是显式一次性执行器，不挂入对话线程或定时器，不自动扫描个人库。

## 后果

- L3 不会因为“模型觉得像习惯”就自动生效，必须有可回溯的跨时间用户证据。
- 同一旧 L2 可以在出现新场景后再次作为上下文，支持画像累积与 UPDATE；成功游标只表示已观察，不等于永久排除该来源。
- 下一步需要在常驻运行时提供非阻塞低频触发、受信风险标记、遗留 running 恢复和控制台可观测状态。
