# ADR-0141：按结构化调用来源排除小智内部结束提示

- 状态：已接受
- 日期：2026-09-13

## 背景

固定小智快照在长时间无语音时，由 `no_voice_close_connect()` 读取服务配置中的 `end_prompt`，再调用 `startToChat()` 生成告别回答。上游随后把这段服务端提示放入普通 `chat(query)`，Memory 插槽只收到字符串，无法区分它与 ASR 用户输入。实机曾因此多出一条用户 L0，虽然输入门没有生成 L1，来源仍然错误。

## 决定

启动适配器在固定上游的 `no_voice_close_connect -> startToChat` 调用边界设置任务局部标记。LongMemory 提供器据此登记一次性跳过项；该项到达 `query_memory` 时返回空记忆上下文，不调用 Runtime，因此不归档 L0、不提取 L1、也不建立回答回执。

标记通过 `ContextVar` 隔离并发任务，不读取或匹配 `end_prompt` 正文。ASR 和设备文字处理模块在导入时持有原始 `startToChat` 引用，不经过内部结束边界；即使真实用户说出与结束提示完全相同的文字，也仍按用户输入处理。

## 边界

- 只适配当前已检查的固定小智源码结构；上游升级后必须重新核对调用边界。
- 不修改厂商源码，不改私有 YAML、模型、TTS、数据库或圆屏协议。
- 只排除服务生成的静默超时结束提示；真实退出话语仍是用户 L0。
- 一次性标记使用有限队列，异常堆积会显式失败，不退化为按文案猜测。

## 后果

新的静默结束会话不再污染 L0，长期记忆来源更接近真实用户陈述。现有历史脏 L0 不自动删除或回填来源；若将来上游提供正式的消息来源字段，应以新 ADR 取代此兼容边界。
