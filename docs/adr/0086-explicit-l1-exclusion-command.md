# ADR-0086：显式跳过本轮 L1 采用带内容的高精度命令

- 状态：已接受并实现
- 日期：2026-09-08

## 背景

日常聊天并非每句话都适合形成长期事实。仅依赖提取策略判断会让使用者缺少即时控制；但用户在下一轮只说“这句不要记”时，可能指当前命令、上一条用户消息、上一条助手回答或整段话题。系统若自行猜测并回删，风险高于漏处理。

## 决定

1. 第一版只执行带具体内容的固定格式：`不要记住：具体内容`，兼容“别记”等少量同义前缀。
2. 命令原文仍作为 L0 保存，用于来源审计和真实交互分析；本轮不运行规则或模型提取，因此不生成 L1。
3. 单独的“这句不要记”“这件事不要记”等表达只返回 `content_required`，不修改上一轮已经形成的 L1。
4. 跳过 L1 不等于删除、隐私擦除或不留日志。已经形成的错误记忆继续使用纠正、事实变化或双轮删除契约。
5. 本切片不实现“强制记住”：它涉及如何规范化、去重、识别主体和抵抗把指令文本当事实，需要单独设计，不能直接绕开记忆提取契约。

## 后果

- 网页和圆屏共用同一 Runtime，因此固定格式在两个入口语义一致，不需要网页审批。
- 网页将结构化操作回执显示在模型回答之外；模型回答属于陪伴表达，不能替数据库宣称操作成功。
- 网页命中后同时直接用应用层固定回执作答，不调用模型。圆屏因小智 Memory 插槽限制仍需模型转述，适配器使用独立命令提示，但这不是确定性直答。
- 用户可以明确阻止本轮形成 L1，但敏感内容仍不应因该命令而误以为已从 L0、备份或日志彻底消失。
- 后续若支持回溯上一轮，必须引入明确会话绑定、目标回读和确认，不能复用当前无目标命令。

## 验证

- 合成测试确认带内容命令只写 L0、L1 数量保持为零。
- 合成测试确认含糊表达不会删除上一轮已经存在的 L1。
- 隔离 Fake 浏览器验收确认命中命令后可直接看到结构化操作回执；即使 Fake 回答措辞与操作不一致，数据库真相仍被单独呈现。
- 后端合成测试确认命中命令时回答生成器不会被调用；小智薄适配器测试确认命令回执不会被包装成普通事实证据。
- 不调用模型、网络或个人数据库。
