# ADR-0110：动态壁纸使用独立 A/B 槽与短时投递 URL

- 状态：已接受（服务端投递原语已实现；固件加载器与真机发布尚未完成）
- 日期：2026-09-10

## 背景

控制台已经能把用户视频裁成经过尺寸、时长和 SHA-256 校验的 360×360 GIF。0007/0008 固件也证明圆屏能从 `assets` 分区播放这种 GIF，但当前壁纸仍在构建时写入资源包；每次更换都重刷应用或整个 `assets`，不适合日常使用。

厂家固件已有 `self.assets.set_download_url`，但它会解除唯一 `assets` 映射并原地擦写整个 8 MiB 分区。下载中断时既没有旧资源槽，也没有 SHA-256 和原子激活，因此不能把这个接口直接开放给控制台。

## 决定

1. 基础字体、提示音和系统资源继续位于只读 `assets` 分区；动态壁纸不再作为资源包的一部分更新。
2. 16 MiB Flash 的原 8 MiB 资源区在后续固件中改为：`assets` 2 MiB、`wallpaper_a` 3 MiB、`wallpaper_b` 3 MiB。构建前必须证明移除内嵌 GIF 后基础资源小于 2 MiB。
3. 壁纸槽采用“先写非活动槽、再校验、最后激活”的顺序。下载失败、大小不符或 SHA-256 不符时，当前活动槽和 NVS 指针保持不变。
4. 每个槽前 4 KiB 留给版本化头部；正文从下一扇区开始写。正文完整校验后才写头部，半写槽不会被识别成有效壁纸。
5. 固件启动时复核头部、长度、GIF 签名、360×360 尺寸和 SHA-256。活动槽无效时尝试另一有效槽；都无效时回退到设备内置几何状态界面。
6. 控制台不向设备发送本机路径或任意外部 URL。项目在选定的局域网地址上临时开放独立的 `8768` 单文件服务，URL 含 256 位随机票据、默认 180 秒过期、成功读取一次即失效。
7. 投递服务没有目录浏览、控制 API、网页、CORS 或原视频路由；签发与读取前都复核文件长度和 SHA-256。Windows 防火墙仍须限定本机监听地址和圆屏来源地址/网段。
8. 设备 MCP 只增加固定的 user-only 操作：读取壁纸状态、暂存到非活动槽、激活已校验槽和回滚。LLM 不可见，也不存在任意工具执行入口。
9. 控制台分别显示 `ready`（仅本机素材）、`staged_verified`（设备备用槽已校验）、`active_verified`（重启后回读一致）和失败状态；HTTP 请求完成、MCP 排队或设备断线都不能写成“发布成功”。

## 失败预演与回退

- 下载中断：备用槽头部无效，旧活动槽继续工作；用户可重新签发票据。
- 下载内容被替换：服务端读取前和设备写入后两端 SHA-256 不同，拒绝激活。
- 激活后资源无法解码：设备启动验证失败并回退另一槽或几何界面。
- 服务端或网络离线：已激活壁纸继续从本机 Flash 播放，不依赖实时像素流。
- 新分区固件异常：仍可使用已有 16 MiB 原厂完整备份经串口恢复；首次改分区必须成套烧录分区表、应用、基础 assets，并保留精确读回记录。

## 当前实现边界

本次只实现并测试短时、单文件、一次性投递票据和独立 HTTP 应用。它尚未绑定真实 LAN 端口、未修改防火墙、未注册发布 API，也未写圆屏 Flash。只有固件 A/B 加载器、设备回执和端到端恢复演练完成后，控制台才会开放“发布到圆屏”按钮。
