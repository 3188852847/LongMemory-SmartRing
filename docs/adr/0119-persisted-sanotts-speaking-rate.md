# ADR-0119：sanoTTS 受控语速持久化

## 状态

已接受，2026-09-11。

## 背景

ADR-0118 完成 sanoTTS 中文小雅的隔离服务和整段 WAV 适配，但第一版没有把其已有的语速能力暴露给日常使用。用户需要在控制台调整陪伴语音节奏，同时不能让任意浏览器参数绕过小智配置、混入其他 TTS 后端，或把提高播放速度描述为流式合成。

同日考察的 AuK-Flash 在 RTX 4080 上成功生成 2.3 秒合成音频，但首次端到端约 92.17 秒，运行期显存约 13.9 GB。该单次冒烟足以把它排除出当前实时默认候选，但不足以评价其离线音质和编辑能力。

## 决定

1. sanoTTS 的可保存语速限定为 0.75–1.5 倍，默认 1.0；旧配置没有该字段时按 1.0 解释。
2. 设置写入固定的小智 `CustomTTS.params.speed`。写入前校验整个私有 YAML 的 SHA-256 摘要，只替换已有标量或插入一行，并沿用 TTS 配置备份。
3. 网页朗读在每次合成前读取当前配置并显式传递语速；小智 Provider 在启动时加载配置，因此圆屏需要重启语音服务后生效。页面必须说明二者差异。
4. 该设置不改变角色、记忆、模型、参考音色、扬声器音量、VAD 或其他 TTS 后端。
5. 能力目录继续声明 sanoTTS 为 `buffered` 且不支持取消。语速提高只表示生成/播放参数变化，不得宣传为首块流式交付。
6. TTS 测试历史升级到 V3，每条记录显式保存语速，并按“后端、固定用例、缓存策略、语速”隔离汇总。旧 V1/V2 记录按当时不可编辑的默认 1.0 向前解释，不改写原始测量值。
7. AuK-Flash 不加入当前 TTS 正式目录；以后若作为离线编辑或高质量素材生成器评估，必须使用独立任务和资源预算。

## 后果

- 用户可以从控制台预览不同语速，并在同一配置来源下让网页和圆屏保持一致。
- 运行中的圆屏不会被网页配置热改，避免直接触碰第三方 Provider 生命周期；代价是保存后需要重启语音服务。
- 私有配置仍不进入 Git；测试使用合成 YAML，不读取个人对话、记忆或密钥。
- 后续若实现真正流式 TTS，应新增适配器能力与端到端测量，不能用本 ADR 的语速控件替代。
