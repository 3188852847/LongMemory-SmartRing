# ADR-0130：所有者确认的 L1 重复合并

- 状态：接受
- 日期：2026-09-13

## 背景

质量候选收件箱可以发现疑似重复并保存误报判断，但还不能安全处理用户确认的真实重复。直接删除其中一条会丢失其 L0 来源；原地改写又会破坏 L1 的可追溯历史。矛盾事实还可能分别表示纠错或随时间变化，不能与重复合并共用语义。

## 决定

只对 `normalized_duplicate` 和 `lexical_near_duplicate` 提供人工合并，明确排除 `possible_conflict`。用户必须选择保留 A 或 B，并再确认一次影响。

合并在同一个 SQLite 写事务中完成：

1. 重新运行当前检测器，确认候选仍存在、类别未变且复核修订号没有过期；
2. 将被合并项尚未关联到保留项的 L0 证据复制到保留项；
3. 把被合并 L1 标记为已退役，并令 `superseded_by_id` 指向保留项；
4. 由既有来源生命周期触发器将依赖被合并项的当前 L2/L3 标为失效；
5. SQLite V39 追加不含正文的合并事件，记录保留/退役 ID、检测器、类别、复制证据数和时间。

## 后果

合并后当前召回只看到保留项，但两条 L1、双方原始来源和取代关系都继续可审计。操作不是物理删除，也不把模型判断当成用户事实。

第一版没有一键撤销。若候选属于矛盾，应分别使用“纠正错误”或“记录变化”；系统不会根据新旧时间替用户选择真值。
