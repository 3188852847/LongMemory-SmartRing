# ADR-0136：分离 L2 主题召回与作答证据充分性

- 日期：2026-09-13
- 状态：已接受
- 补充 ADR-0134 与 ADR-0135；当前只建立合成标注和门控契约，不接入日常回答。

## 背景

V2 开发基线将所有无答案题都按“应当完全空召回”评价。这个前提对近主题问题不成立：问“豆包是什么毛色”时，“用户养了一只叫豆包的猫”是主题相关上下文，但它缺少被问的毛色属性，不能支持一个具体答案。

将这两件事都压缩为一个相似度阈值，会在主题召回和证据支持之间制造不可解释的取舍。

## 决定

1. 冻结问题和场景文本不修改；用与数据集 SHA-256 绑定的独立标注层增加 `topical_ids`。
2. 原 `expected_ids` 继续表示能明确支持答案的场景。`topical_ids` 只表示主题相关，可包含证据不足或已过期场景。
3. 召回器评价主题覆盖与无可用主题时的空召回；证据充分性门控评价候选是否明确包含被问信息。
4. 门控以候选为单位返回封闭 JSON，必须按输入顺序完整回答每个 ID。主题相关、名词重合和可猜测不等于支持答案。
5. 网络、截断、结构或 ID 不对齐时失败关闭，不重试、不自动放行。
6. 当前门控已有核心契约、OpenAI 兼容适配器和仅运行 `dev` 的隔离评估器；未运行真实模型评估，未改变日常 L2 上下文。
7. 隔离评估每题最多一次请求，全部题目预先进入固定分母；逐题持久化结果，失败不重试，不允许选择 `holdout`。

## 后果

评估能够分辨“召回不相关”与“召回相关但证据不足”。代价是运行语义门控会增加模型请求和延迟；因此必须先在合成开发集测量误放行、误拦截和成本，再考虑影子运行。
