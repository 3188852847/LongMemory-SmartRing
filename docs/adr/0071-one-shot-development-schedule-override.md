# ADR-0071：一次性开发定时验证授权

- 状态：已接受并实现。
- 日期：2026-09-07。
- 承接：ADR-0067、ADR-0069、ADR-0070。

## 背景

正式自动联系会在当天已经聊天或上一条主动问候仍待回应时停止，这是合理的产品安全规则，却会让开发阶段无法在同一天反复验证真实后台计时器。永久关闭这些规则会把测试便利泄漏进日常行为，也可能在忘记恢复设置后造成意外播报。

## 决定

1. SQLite V19 新增独立的 `proactive_schedule_overrides` 审计表，同一主体最多只有一条 `armed` 授权；迁移不自动创建授权。
2. 所有者只能为“今天、当前设置中尚未到达的定时时刻”显式授权一次。总许可、后台定时开关、星期和设置 revision 必须有效。
3. 到点时，该授权只绕过 `user_already_chatted_today` 与 `awaiting_user_response`。允许时段、勿扰、每日次数、最短间隔、消息有效期、设备在线/空闲及投递失败规则全部保留。
4. 授权在真正尝试前先标记 `consumed`；若设备随后拦截或投递失败也不恢复。错过时刻、跨日、设置时刻变化、关闭自动开关或撤销同样结束授权。
5. 开发验证使用独立幂等键，并以 `development_fixed_schedule` 或 `development_approved_memory_topic` 写入主动账本，不能与普通定时结果混为一谈。
6. 控制台显示授权目标日期和时间，并提供显式撤销。页面刷新、轮询和服务重启不会自动创建新授权。

## 后果

- 开发阶段可以在已有聊天记录的当天验证真实后台计时与记忆话题投递。
- 授权仍受频率预算约束；若当天次数已经用尽，应调整开发设置或等待，而不是静默突破限制。
- 产品成熟后可以隐藏或禁用该管理入口，正式自动联系策略与历史账本无需迁移。

## 验证

- 合成链覆盖“当天聊过且仍待回应”时的一次性话题发送、消费后不复用和错过即失效。
- HTTP 覆盖 CSRF、明确确认、设置 revision、重复授权冲突、状态读取和撤销。
- React 覆盖显式授权后展示目标日期与时刻。
- 2026-09-07 实机验收通过：授权到点后账本记为 `development_approved_memory_topic`，保留素材 ID/revision，用户确认圆屏实际发声并以 `USER_OBSERVED` 证据记为 `played`。
