# ADR-0093：版本化圆屏皮肤包与本地渲染

- 状态：已接受（第二切片运行时闭环已验收，逐态视觉观察未完成）
- 日期：2026-09-08

## 背景

浏览器 `/display-preview` 已能模拟圆屏状态，但 0004 真机界面仍编译在 `xiaozhi.bin` 中。用户希望以后不必为每次外观变化重刷完整固件，同时保留高度自定义能力。

对厂家 B V2 源码的只读审计确认：

- 设备有一个 8 MiB `assets` 分区，默认资源包可包含字体、表情、背景和额外文件；
- 固件已有 `self.assets.set_download_url`，下次激活时可通过 HTTP 下载并覆盖 `assets` 分区；
- 下载实现会直接解除映射、逐扇区擦除并写入唯一的资源分区；失败后没有第二份资源分区可原子回滚；
- 现有资源格式只有长度和 16 位加和校验，能发现部分意外损坏，但不是密码学完整性或来源认证；
- 当前 0004 状态脸由本地 LVGL 控件绘制，状态机和安全提示仍应在设备上工作。

因此，“服务端实时发送整个界面像素”并不会真正节省设备显示栈，反而会让断网、延迟和服务故障直接破坏基本交互；直接开放任意 `assets.bin` URL 又缺少可靠回滚与强校验。

## 决定

采用“服务端管理、设备端渲染”的混合方案：

1. 固件保留 LVGL 渲染器、状态优先级、配网/升级/故障回退界面和至少一个内置安全皮肤。
2. 服务端保存版本化皮肤清单、选择状态、资源包身份和设备应用结果；不持续传输屏幕像素。
3. `skin_api=1` 首先只开放可映射到固定控件的声明式参数：调色板、眼睛/嘴部尺寸和动画节奏。它不允许脚本、HTML、任意路径或 URL。
4. 浏览器模拟器复用同一份清单。网页选择立即生效于预览，但在设备安全加载器完成前不得标为真机已应用。
5. 图片、GIF、字体等大资源以后仍可编译进厂家 `assets.bin`，但服务端必须同时维护 SHA-256、目标板型、尺寸上限和兼容版本。
6. 真机安装必须增加：下载前清单校验、下载后 SHA-256、失败回到内置皮肤、明确的安装/应用回执。不能只依赖现有 16 位加和。
7. 原厂单资源分区意味着资源二进制自身无法可靠 A/B 回滚。首个设备实现优先让声明式皮肤保存在 NVS，并继续使用内置控件；是否改分区表增加双资源槽必须另做容量与恢复评估。

## 第一切片范围

- 两个版本控制内置清单：`rose-night-v1`、`mint-calm-v1`；
- 严格字段、数值范围、板型与 360×360 RGB565 校验；
- 每份原始清单计算 SHA-256；
- 本机受 CSRF 保护的查询和选择 API；
- React 圆屏模拟器读取清单、即时比较并原子保存非敏感选择；
- API 明确返回 `device_apply_supported=false` 和阻塞原因。

不包含资源上传、外部 URL、真机下载、固件写入、远程主题市场或任意代码执行。

## 后果

- 外观设计可以先在 PC 上快速迭代，协议稳定后再做一次固件加载器改造。
- 设备离线时仍有可理解的状态界面；皮肤损坏不会成为配网和故障恢复的唯一界面。
- 首版的定制范围比任意图片包窄，但更容易测试、回退和审计。
- 若以后引入资源图片，`assets.bin` 是传输容器，不应被当作皮肤业务契约本身。

## 2026-09-08 实现更新：第二切片

0005 补丁已实现最小运行时设备闭环，但不扩大到资源包安装：

- 固件内置安全皮肤，从独立 NVS 命名空间读取严格的 `skin_api=1` 子集；无效或部分写入时回到内置值。
- 两个圆屏皮肤 MCP 工具标记为 user-only，不进入普通大模型可见的工具列表；服务端只调用固定名称与固定契约。
- 控制台不能提交自由参数，只能选择服务器已经校验、版本控制内的皮肤清单；设备支持的颜色和脸部尺寸由服务端投影。
- 设备控制桥写入后再次读取，完整字段相同才报告已验证；网页预览选择与真机已应用状态继续分开。
- 浏览器动画、渐变和布局不进入设备子协议；资源分区、应用更新和远程 URL 仍不属于本阶段。

ESP-IDF v5.5.4 构建、补丁干净应用、反向检查、仅应用分区烧录和独立读回均已通过。设备能力探测与“薄荷微光”完整字段回读通过，用户按完整清单报告 NVS 重启保持成功；真实五类状态的逐态视觉仍明确标为待验收。

## 2026-09-08 实现更新：第三切片

控制台新增单一本机自定义档案，而不是开放任意皮肤文件上传：

- 只能调整 0005 真机已经支持的九种颜色和三项脸部尺寸；身份、目标、字段集合及说明由服务端生成。
- 档案原子保存在 Git 忽略的本机控制目录，并以原始 JSON 的 SHA-256 作为版本身份。
- 保存携带期望指纹，拒绝陈旧页面覆盖新编辑；内置皮肤继续只读。
- 浏览器即时预览、本机保存和真机应用是三个独立动作；保存不会隐式写设备。

此更新不修改固件协议、Flash、资源分区、个人数据库、模型或记忆。

2026-09-08 用户已确认更新后的编辑器入口可用。五类对话状态继续在日常使用中自然观察，不以一次页面确认替代逐态真机结论。

## 2026-09-10 后续决定

动态壁纸不再沿用本 ADR 中“是否增加双资源槽”的开放问题，也不直接开放厂家 `self.assets.set_download_url`。已由 [ADR-0110](0110-a-b-round-wallpaper-delivery.md) 确定为“基础 assets + 独立 wallpaper A/B 槽 + 短时单文件投递 URL”。声明式 `skin_api=1` 仍继续使用 NVS，两条能力互不替代。
