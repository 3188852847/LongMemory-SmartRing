# ADR-0152：圆屏回答回执持久化历史证据角色

## 状态

已接受

## 背景

ADR-0151 让明确历史问题可以补充退役 L1。网页会话轨迹保存了 `temporal_role` 和事实有效区间，但 V37 圆屏回执只保存层级、条目 ID、排名、内容指纹和召回分数。若进程结束，事后复核只能知道某条退役 L1 曾被召回，无法证明它当时是作为历史证据而非当前事实注入。

## 决定

1. SQLite V48 在 `round_screen_retrieval_evidence` 增加可空的 `temporal_role`、`valid_from`、`valid_to`。
2. 只有 L1 可使用 `temporal_role=historical`；历史条目必须有带时区的 `valid_to`。普通 L1、L2、L3 三项均为空。
3. 字段保存回答当时的角色与区间快照，不复制记忆正文。旧回执不回填、不推断，迁移后保持空值。
4. 圆屏质量详情显式显示“回答时作为历史事实”和当时区间；当前内容与回答时内容仍用既有 SHA-256 指纹核对。

## 后果

- 圆屏历史回答在服务重启后仍能区分“引用旧事实回答历史问题”和“错误地把旧事实当作当前事实”。
- 数据库只增加三个可空元数据列；现有回答和旧记录语义不变。
- 该回执仍不能证明模型正确使用了证据，也不等于设备已经播放完成。
