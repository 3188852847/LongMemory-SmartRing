# ADR-0039：L3 用户画像采用原子候选与分级证据门槛

- 日期：2026-09-06
- 状态：已接受并完成基础切片；个人数据库已备份迁移至 V7

## 背景

L2 已能把多条 L1 组织为可复核的生活场景，但陪伴产品还需要表达跨场景的稳定偏好、互动方式、习惯与行为模式。不能把一次场景直接升级为“用户总是如此”，也不能把助手或模型的推测伪装成用户明确表达。

L3 在本项目中专指**用户画像**，与助手角色提示词无关。L3 是可重新生成、可失效的派生层，必须能够向下追溯到 L1/L2，再追溯到 L0 原话。

## 决定

1. 一条 L3 只表达一个可独立核对的画像断言，不把整份用户档案保存为一个自由文本文件。
2. 第一版类型为：偏好 `preference`、习惯 `habit`、互动方式 `interaction_style`、行为模式 `behavior_pattern`。
3. 依据性质必须显式区分：
   - `user_declared`：用户明确表达；至少一条可追溯用户原话。
   - `system_inferred`：系统跨记录归纳；默认至少两个派生来源、三条不同用户原话并覆盖两个观察日。
4. 上述门槛只是防止单次偶然行为被过度概括的保守下限，不是统计显著性，也不等于画像真实。
5. 自动生成只能产生 `candidate`；只有用户接受后才可成为 `active`。候选、拒绝或失效画像不得进入回答。
6. 来源允许引用 L1 或 L2，并保存来源层级、稳定 ID、内容快照和关联时间。第一切片不把外部知识文档作为个人画像证据。
7. 保存生成器身份、版本、生成时间、来源数量、底层用户原话数、观察日数和人工复核；不把模型自报置信度作为真实性证明。
8. V7 第一切片只增加领域类型与空表，不扫描个人历史、不生成画像、不提供 API/UI，也不让 L3 参与回答。
9. 在真正开放画像写入前，必须实现来源资格复核、原子事务、来源变化后的失效传播及合成测试。

## 后果

收益是明确声明和系统推断不会混为一谈，习惯候选有最低跨时间证据门槛，未来控制台可展示“为什么系统这样认识我”。代价是画像生成比简单摘要更慢，且来源变化传播需要专门设计。

个人 V6 数据库必须在服务停止、创建一致性备份并核对后显式迁移到 V7；迁移只建空表，不允许自动回填画像。
