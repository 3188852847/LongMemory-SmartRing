# ADR-0162：CosyVoice 连续 PCM 帧对齐

## 状态

已接受，2026-09-14。补充 ADR-0126。

## 背景

CosyVoice3 本机服务会逐块返回独立 WAV。圆屏适配器此前把每个 WAV 分别交给小智通用
转换函数；该函数把每次调用的最后一段 PCM 都视为流结束，并把不足 60 ms 的部分补零。
因此模型分块边界可能被误当成音频结束边界，跨块残余样本无法拼成完整 Opus 帧。

小智发送层已经对开头五个 60 ms Opus 包采用立即发送，之后按播放时钟流控。额外规定
“收到前三帧才开始发送”会增加最多约 180 ms 的首包等待，尚无真机证据证明收益大于成本。

## 决定

1. 每个模型 WAV 块仍独立解码并统一为圆屏采样率、单声道 PCM16。
2. 所有 PCM 块连续进入同一个 Opus 编码器；中间块一律不设置流结束，凑满 60 ms 就立即
   产出，只有整段模型流结束时才补齐一次最后帧。
3. 只有编码器实际产出首个完整 Opus 帧后才发送 `FIRST`，避免空块形成假开始状态。
4. 用户打断、协议错误或解码失败时重置编码器，禁止残余 PCM 混入下一句话。
5. 保持首个完整帧立即发送。是否使用 1 帧、3 帧或自适应启动缓冲，必须基于真机首声、
   欠载和卡顿数据单独比较。

## 后果

- 模型块边界不再制造额外补零，播放时间线和 Opus 编码状态更连续。
- 该修改只能减少适配与播放抖动，不能缩短模型产生首个 PCM 块之前的推理时间。
- 仍需真机验证首声、连续播放、句间停顿和打断；单元测试只证明帧边界行为。

## 回退

恢复逐 WAV 调用小智通用转换函数即可；不涉及模型、配置、固件、记忆或数据库迁移。
