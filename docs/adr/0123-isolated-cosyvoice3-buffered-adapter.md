# ADR-0123：隔离的 CosyVoice3 缓冲式语音适配器

## 状态

已被 ADR-0126 部分取代，2026-09-13。完整 WAV 兼容接口与隔离部署决定继续有效；
“圆屏只能整段缓冲”的结论由后续专用分块通道取代。

## 背景

用户已在 RTX 4080 上完成 Fun-CosyVoice3-0.5B 的独立固定句试验，并确认声音质量高。源码、模型和依赖位于项目外的独立目录，不能把约 5 GiB 显存占用及复杂推理依赖并入 LongMemory 主环境。

固定 Xiaozhi 快照的通用 `CustomTTS` 会等待 HTTP 响应完整内容后才继续处理。即使 CosyVoice 底层生成器按块产出，当前圆屏链路也不能据此宣称已经实现边生成边播放或自然说话打断。

## 决定

1. 新增只监听 `127.0.0.1:18770` 的 CosyVoice3 常驻适配服务，提供健康检查、实际能力声明和 `POST /v1/audio/speech`。
2. 服务由统一启动面板管理，并使用 `D:\ESP32-Workspace\CosyVoice\.venv`；LongMemory、Xiaozhi 与 CosyVoice 三套 Python 环境保持隔离。
3. 启动时加载并预热一次 Fun-CosyVoice3-0.5B；首版固定使用上游自带的零样本参考声音，不开放浏览器任意文件路径或上传。
4. 服务内部可以消费模型生成块，但对当前 Xiaozhi 返回完整 WAV；TTS 能力目录明确声明 `buffered`、无协作取消、无可编辑声音参数。
5. 统一启动顺序为控制台 → CosyVoice3 就绪 → Xiaozhi。启动器状态快照升级到 V4，旧 V1–V3 继续可读。
6. React 与启动面板允许把 CosyVoice3 保存为“下次启动”后端；运行中的语音不热切换。EdgeTTS 仍是日常默认和安全回退。
7. 重复短语可命中进程内小容量 WAV 缓存；固定测试台显式绕过缓存，不能把缓存命中当作模型生成速度。

## 后果

- 用户可以在现有控制台试听、测试并把高质量本地声音接入圆屏，而无需手工启动第四个终端。
- 本机探索性服务测试中，预热后首次短句完整 WAV 约 2.05 秒，重复缓存约 4 毫秒；这些数字不包含回答模型、Opus、网络和圆屏播放，只用于工程定位。
- 模型底层流式能力暂时被 Xiaozhi `CustomTTS` 的整段读取截断。真正首块播放与说话打断需要新增 Xiaozhi 专用流式 Provider 和取消传播，不能通过修改能力标签解决。
- 首版不支持自定义声线、风格或语速。开放这些能力前必须先定义受控素材库、许可边界、版本化配置和回退路径。

## 回退

在设置中心或启动面板把下次后端改回 EdgeTTS，停止后重新统一启动。切换只改变 TTS 运行与 Xiaozhi 私有配置指针，不修改记忆、角色、聊天或模型配置。
