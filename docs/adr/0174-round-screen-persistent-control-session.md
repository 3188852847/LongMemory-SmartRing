# ADR-0174：圆屏采音状态与控制连接分离

## 背景

2026-09-16 的真实使用中，SmartRing-Plus 圆屏在一段时间后断开，随后长期停在“连接中”。
服务端日志证明，上游会在 120 秒无语音后生成结束语并主动关闭 WebSocket；当次连接关闭后，
0011 固件的一次失败重连又可能把界面留在连接态。电脑端服务仍健康，设备 IP 仍可达，因而
问题不等同于服务崩溃或 Wi-Fi 完全掉线。

长期保留麦克风采集会增加隐私、带宽和 AEC 负担；完全关闭 WebSocket 又会增加下次唤醒握手
延迟，并使主动交流失去在线控制通道。旧固件不能理解新增会话消息，因此服务端不能直接改变
所有设备的超时行为。

## 决定

1. 固件在 hello 的 `features` 中显式声明 `persistent_session=true`。服务端只对声明该能力的
   设备启用新行为；没有声明的旧固件继续执行原 120 秒结束和断开逻辑。
2. 120 秒没有用户语音后，服务端发送一次无正文的 `session.idle`。设备停止聆听并返回待机，
   但保留 WebSocket；这使“麦克风正在工作”和“控制通道在线”成为两个独立状态。
3. 服务端每 45 秒发送 `session.heartbeat`。固件在协议层消费该消息，不显示文字、不改变表情、
   不触发 TTS。链路心跳不得改写用户最后语音时间，否则会阻止空闲停采。
4. 唤醒或触摸继续复用仍然健康的连接；真实断线仍由现有 WebSocket 回调释放并回到待机，下一次
   唤醒再建立连接。本阶段不增加无限后台重连循环。
5. `OpenAudioChannel` 失败时显式关闭残留对象并回到待机；用户在“连接中”再次触发切换时可以
   取消本次连接，避免界面永久卡住。
6. 固件补丁仍只写应用分区。分区表、NVS、基础 assets、壁纸 A/B 槽、皮肤设置、记忆库和模型
   配置均不改变。

## 后果

- 圆屏静默后不再为了保活持续上传麦克风音频，下一次唤醒也不必在正常情况下重新握手。
- 新旧固件可以同时连接同一服务端，能力声明是行为切换门槛。
- 45 秒心跳只能降低由空闲代理和服务端超时造成的断线，不能修复路由器掉线、设备断电或物理
  Wi-Fi 信号问题；这些真实断线仍须靠设备状态和日志判断。
- 离线构建只能证明协议和状态机能够编译。烧录后仍需等待超过 120 秒，验证设备回到待机、
  服务端连接数保持为 1、再次唤醒可以直接对话，并补做真实断网后的恢复测试。
