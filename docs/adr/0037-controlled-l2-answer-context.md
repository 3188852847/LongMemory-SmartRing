# ADR-0037：已接受 L2 通过独立开关受控参与回答

- 状态：已接受并实现
- 日期：2026-09-06

## 背景

L2 候选、模型预览和人工复核已经跑通，但“接受”不应自动等于“以后每轮都注入”。当前页面也还不能可靠填写现实有效时间；若把全部 active L2 塞给模型，会产生无关场景污染，并掩盖检索质量。

## 决定

1. L2 回答使用与候选管理分开，增加独立运行期开关；默认关闭，服务重启复位。
2. 网页与圆屏共享同一个 `MemoryRuntime`，因此开关和召回行为一致；关闭已有记忆使用时，L2 同样不参与。
3. 只有 `active`、当前处于 `valid_from/valid_to` 区间且标题或摘要与问题有关键词重叠的 L2 才能召回，最多 3 条。
4. L2 上下文使用独立标签，并在回答轨迹中单独记录场景 ID、标题、摘要、来源 L1 与来源 L0；不能和 L1 检索条目混成一个不可解释列表。
5. `candidate`、`rejected`、`stale` 和无关键词重叠的场景不得参与回答。接受、打开页面或模型预览都不会自动打开使用开关。

## 暂不包含

- 自动创建或自动接受 L2。
- L2 向量/语义召回、时间推理和历史时点问答。
- L2 使用策略持久化、按入口分别配置或由模型自行决定是否读取全部场景。

## 后果

这一切片可以低风险体验“生活场景是否改善陪伴回答”，且出现错误时能定位具体 L2 及底层证据。关键词重叠会漏掉改写问题，因此它是安全基线，不是最终智能程度；真实体验后再决定是否引入语义检索与上下文编排。
