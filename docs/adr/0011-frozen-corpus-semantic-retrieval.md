# ADR-0011：冻结既有事实语料的本地语义检索消融

- 日期：2026-09-03。
- 状态：实现与离线验证完成（全量 350 项 Python、11 项 Node 通过）；用户已授权本地模型及可选依赖，真实模型检索尚未验收。
- 延续 ADR-0010 的提取实验，不替代原方法，不迁移个人库。

## 背景与决定

真实 D1 实验发现姓名已保存却未召回，也发现重复原文经模型改写形成重复事实。
下一步只改变检索。若重新运行提取，即使提示相同也可能形成不同语料，不能把差异单独归因于检索器。

因此新增独立检索消融入口，读取已有已完成比较报告与冻结 L1 状态。分别在原规则事实、模型提取事实上，比较原关键词与余弦向量检索。原始报告和数据库只读；新索引与新报告存到新运行目录。先不再生成答案，不产生学校模型请求。

## In Scope

- 仅导出已注册的两个 L1 方法的活动事实和全部来源，不强迫任意论文方法输出原子事实。
- 校验数据集/完整历史/来源状态摘要；不接收任意个人数据库。
- 独立编码器接口、精确余弦扫描、来源绑定索引、重开与编码器身份校验。
- 固定 top-5，默认不设置未经校准的相似度阈值；允许显式阈值但必须入报告。
- 来源覆盖、首次凑齐充分证据的排名、来源命中比例、重复来源占用、上下文长度和单次耗时。
- 所有题预登记，失败/中断保留分母；错误正文不写报告；冻结变化阻断该语料后续查询。

## 模型与依赖

初始编码器选择 `BAAI/bge-small-zh-v1.5`，固定 revision
`7999e1d3359715c523056ef9478215996d62a620`。这是中文、小规模本地实验起点，不是已证明最优或所有论文的统一模型。

- 官方 MIT；权重文件实测 95,827,648 bytes，保留上游 README。
- Transformers 4.57.6 / PyTorch 2.8.0 使用可选 `semantic` extra，传递依赖锁在 uv.lock。
- Windows/Linux 优先官方 CPU wheel；本机 torch 2.8.0+cpu 下载约 590.7 MiB，不包含 CUDA 构建。模型小不等于全部运行依赖小。
- CPU FP32、CLS pooling、L2 归一化；查询前缀为官方建议中文指令，事实正文不加前缀。
- 最长 512 tokens，超出时明确失败，不静默截断。长历史分块需独立设计。
- 推理只读本地快照，禁止 remote code 和隐式下载，safetensors 优先；模型文件与运行库版本入报告。
- 模型目录 data/models 被忽略提交，源码中不保存密钥或校内服务设置。

候选替代：远程向量接口需要新增可用服务与隐私边界，不能假设学校聊天 API 支持；SentenceTransformers 可简化装配但增加封装；ONNX 可减少运行负担但需要明确导出模型与数值一致性。首轮选择官方 Transformers 示例路径，以少一个转换环节换取较大的 CPU 运行依赖。

## Out of Scope

不修改日常网页/圆屏算法；不再提取、不调用回答模型、不做混合检索/重排/语义去重/冲突更新；不安装独立向量数据库；不使用真实个人数据；不重跑留出题调参。

## 验收与解释限制

工程验收：异常/空语料/维度/零向量/非有限值/重复 ID 校验，索引重开和身份不匹配拒绝，原实验字节不变，标签不送编码器，原关键词结果不变，失败和中断记录。

真实模型验收：完整官方快照校验、CPU 编码、在既有合成开发实验上生成检索报告并检查逐题来源。下载未完成前不声明通过。

当前语料很小，top-5 可能覆盖几乎全部事实，单独来源覆盖改善不能证明检索精准；必须同时检查排名、噪声和注入长度。`source_hit_fraction` 只是标签来源代理，不是语义 precision；同一来源也可能含多个事实。重复来源占用不能识别来自不同原文的同义事实。

只读盘点源实验：原规则库有 5 条活动事实，模型提取库有 7 条；读取前后整个旧实验摘要一致。原规则库若无阈值取 top-5，会覆盖所有事实，因此其覆盖提升不能当作排名有效性的证据。

未知题可能召回相关但不足以回答的事实，不能按“有没有召回”判定拒答质量。没有答案生成时更不能宣称问答或抗幻觉改善。后续再在冻结语料下加入相同回答模型与上下文预算的对照，并扩展开发集干扰事实。
