# ADR-0181：显式记忆后端与平台来源所有权

日期：2026-10-19。状态：接受本轮接口与隔离实现；Hy 专用运行、日用切换与个人库迁移未验收/未执行。

## 背景与决定

用户决定以 Hy-Memory 为长期主要后端，可从新库积累；现有引擎保留作对照/回退。不为旧派生层的完整迁移引入复杂兼容。“一切重来”不授权删除、清空或覆盖个人数据。U 只用隔离合成库，V 独占 Hy 专用适配。

原 MemoryMethod 已中立，但 server/bootstrap、管理、自然纠错和历史/情景/画像仍默认 SQLite L1。采用显式 BackendAssembly：中立 MemoryMethod、可选 MemoryAdministration 和文件/目录资源列表。管理条目保留方法表示、来源、时间和原子修订检查，不要求 AtomicMemory、旧层级或同量纲检索分数。

新装配由平台掌握原文审计边界：复用 SQLiteConversationStore 的原角色/时间/来源 ID 存储，独立新来源库只增加投递状态，不建旧派生层。用户事实引擎只接用户消息，助手仅归档。旧引擎继续使用已有 L0/L1 事务与旧功能适配器，不复制个人原文为第二份新库。

引擎 observe 可以是完整 add 组合流程，不要求替换其私有内部组件。新平台先归档再调用，延后只改变调度时机，不假称跨存储原子性。completed 结果可持久回放；failed/uncertain 仅在真实持久幂等能力允许时显式重试。尚未调用引擎的 pending 可显式恢复，暂停/排除的 archived 不自动投递。来源库采用 OS 生命周期独占锁，重启接管后才把残留 running 判为 uncertain。

旧自然纠错/历史/画像/情景和主动控制属于旧派生/关联能力；没有新适配就返回 unsupported/501。平台一次性下一轮互动、运行期开关、网页会话和助手角色与引擎分离。旧低频整理和影子维持原显式开关，不自动接入新引擎。圆屏旧完成关联/质量审计对新后端暂拒绝；新后端设备链路须后续适配验收，不能由网页替身测试推出。

## 替代、代价与回退

让所有后端读写旧 L1 DTO 会把 Hy 的表示压扁，继续绑定 SQLite；让引擎独占原文又会让失败归档和管理追溯随供应商改变。独立来源账本增加一个受控文件与投递一致性窗口，但职责清楚、可检查，且不创建无需求的分布式事务框架。

新组合调用保守串行，未提供 DailyLLM 的事务外候选生成延迟保证。幂等性取决于具体适配器，能力声明本身不构成真实保证。管理纠正来源先归档，管理失败不能承诺跨存储回滚。无权限/无能力明确拒绝，删除条目不删平台原文。清空和全隐私擦除没有通用协议，须另定目标和授权。

本轮无新依赖、锁升级、个人 schema 迁移、配置切换或数据迁移。回退只改可信装配选择并重开旧运行时，保留新来源/引擎目录，不覆盖个人库。单纯切回旧引擎不会自动搬回新事实。

## 验证边界

旧 LongMemory 与目录/图节点替身经相同 Runtime/管理调用，验证来源、修订、拒绝、并发、失败恢复、重启与随机回环 HTTP。替身不是 Hy 实现、质量或性能证据。具体数量、提交与限制见 [U 记录](../development/parallel/U-memory-boundary-20261019.md)；现行接口见 [方法边界](../architecture/method-boundary.md)。
