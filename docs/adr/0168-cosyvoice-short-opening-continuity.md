# ADR-0168：短开头合并与已就绪片段调度

- 日期：2026-09-15
- 状态：软件与隔离合成验收通过；真实圆屏连续性待验收。
- 部分取代 ADR-0164 的首段策略，保留自然标点、完整片段播放和后续短句合并。

## 问题与证据

用户确认运行优化后声音明显改善，但第一小句说完仍停一下。当前已经存在
“上一段播放、下一段合成”的并行关系，不能把新增并行队列写成尚未具备的能力。

已定位三个适配层问题：

1. 首段沿用上游快速切法，允许把“可以呀，”独立生成；几百毫秒到一秒的开头
   往往覆盖不了下一段的生成。即使整体生成实时率小于 1，也可能在这里断流。
2. 上游每个 TEXT 只取一个片段。一次文字增量已包含多段时，其余闭合片段仍会
   等待下一条 TEXT 或 LAST/FILE。ADR-0167 只处理了最终清空旁路。
3. 上游首段使用各类标点的 `rfind`，切点受增量大小影响；固定寒暄也会被逗号
   拆成两次合成，无法匹配已经存在的整句预置音频。

首轮无条件合并到 16 字能消除两种短开头样本的约 1.8–2.1 秒供给缺口，
但原本连贯的数字句首声额外多等 0.60–1.04 秒，因此不采用统一延长所有首段。
详细对照与局限见[实测记录](../research/cosyvoice-short-opening-2026-09-15.md)。

## 范围、决定与完成条件

本阶段只修改项目的 Xiaozhi 语音适配层和隔离测试；不修改上游仓库、固件、模型、
依赖、配置或 Memory Core，不运行校园接口，不读取个人库。

1. 首个自然分句少于 8 个字符时，合并到累计至少 16 字后的首个自然标点；
   首分句已有至少 8 字时直接放行。后续保持至少 18 字后的首个自然标点。
   字符数包含标点；这是有限固定句验证支持的启发式，不是音频时长预测。
2. 不足阈值的完整短回复在 LAST/FILE 完整送出，保留标点。没有自然边界时不
   按字数硬切。四条固定寒暄必须各命中一次整句资产，不发起 HTTP 合成。
3. 合成返回后，立即依次处理同一文本缓冲中已闭合的片段。仍只保留一个活跃
   GPU 请求；每一段独立进入 V6 计时，不把排空整个缓冲记作一个片段。
4. 用话轮编号、打断标记和连接停止状态拒绝旧轮；最终清空与普通排段有重入保护。
   FILE 后偏移对齐真实末尾，重复清空不重播；不同文字增量大小不得改变切点。
5. 保留模型和声线，用重复、交替、关闭缓存的固定句合成验证供给缺口；真实
   Opus 编解码必须覆盖生成片段。扬声器连续性、自然度和停嘴到首声另行验收。

## 取舍与后续架构

短开头会晚一点出声，以获得有意义、能够覆盖后续合成的首段；不能把这项收益
称为模型加速。自然句内仍完整播放，不插入填充寒暄，也不暴露模型内部块边界。
极长无标点文本、模型再次慢于实时、回答模型迟迟不给文字仍可能产生等待。

LiveKit 是可选的会话编排框架，替换框架本身不会加速现有模型。本轮已有更小、
有证据的适配层修复，故不直接迁移框架或引入新的云端回答链路。若真实日用仍持续
欠载，先用现有 health 和 V6 复核慢在哪一段；需要新服务时在独立语音适配层验证，
再决定是否接入启动面板。LongMemory 只提供独立上下文能力，不承担播放调度。

软件停止旧音频和停止 GPU 推理仍是两件事：本轮没有改变阻塞 HTTP 内的模型取消。
已停止的旧慢进程无法复测，不把它与新进程的速度差归因于本轮分段改动。

## 回退

如首声或自然度出现不可接受的回归，用正常向前修订恢复 `c487bb5` 的
`voice_latency.py` 分段接入即可；服务仍保留完整片段和输出层优化，不需要
回退模型、精度、配置、固件或数据库。不要使用硬重置清理工作区。

## 验证状态

`tests/unit/development` 共 418 项通过，覆盖边界、FILE/LAST、不同增量、取消、
预置命中与 V6 分段计数；独立复核未发现新的漏读、复播或其他 TTS 后端回归。
真实编解码检查 42 段、2147 个 60ms Opus 包均可解码，包数与供给估算一致。
未启动整套日用服务，不把自动测试或服务端供给估算当作圆屏扬声器验收。
