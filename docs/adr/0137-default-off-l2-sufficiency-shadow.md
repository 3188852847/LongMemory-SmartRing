# ADR-0137：默认关闭的 L2 证据充分性影子记录

- 日期：2026-09-13
- 状态：已接受
- 补充 ADR-0134–0136；不替换当前日常 L2 算法。

## 背景

冻结合成开发集证明 `l2-evidence-sufficiency-v2` 能在固定候选上区分“主题相关”和“足以回答”，但这不能直接证明它适合个人日常对话。直接接入正式回答会同时改变上下文、延迟和费用，出现误判时也难以与旧行为比较。

## 决定

1. 增加显式启动参数 `--enable-l2-sufficiency-shadow`；默认关闭，且仅允许在共享聊天 Runtime 使用 OpenAI 兼容模型时开启。
2. 影子模式复用该轮 L2 关键词召回器的候选快照。正式 L2 关闭时也可旁路读取候选，但绝不把旁路结果加入 `memory_context`。
3. 模型复核在独立单线程执行器中运行，不占用聊天 Runtime 锁，不增加回答首句的模型等待；每个有候选的问题最多一次请求，不重试。
4. 影子读取、提交、模型或存储失败只丢失/标记该条研究记录，不改变正式回答的成功、失败、证据或记忆写入。
5. SQLite V42 追加运行表和候选表。它们绑定已有用户 L0 ID，保存 L2 ID、排名、关键词分数、内容指纹、封闭判定、提示/模型版本和稳定错误码；不重复保存问题、场景正文、模型解释或密钥。
6. 无候选时记录一次完成观测但不调用模型、不伪造候选决定。进程中止遗留的 `pending` 记录保持原样，不猜测补全。
7. 当前结果只用于观察门控若生效会怎样。未经真实样本复核、成本统计和独立启用决策，不得据此过滤正式 L2。

## 后果

可以在完全相同的日常问题和候选上积累离线可比证据，同时保持当前产品行为稳定。代价是显式启用后会产生额外模型调用与少量审计写入；因此仍需提供可见状态、记录查看和关闭能力，并且不得默认开启。
