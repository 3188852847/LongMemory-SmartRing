# ADR-0142：已有 L0 的失败 L1 提取采用显式单次恢复

- 状态：已接受
- 日期：2026-09-13

## 背景

日常模型辅助提取已经保证 L0 优先保存，并用 V44 账本区分正常不记、失败和进程中断。但只观察故障仍会留下无法进入长期召回的原始证据。后台自动重试会隐藏模型故障、不可控地消耗请求，并可能在服务恢复后批量改变个人记忆。

## 决定

记忆质量页只为同一来源的**最新** `extraction_failed`、`persistence_failed` 或无终态尝试提供“重新提取一次”。请求携带页面看到的 `attempt_id` 做并发检查，在常驻 Runtime 的单工作线程中执行一次；模型调用不持 SQLite 互斥锁，最终写入仍通过统一 L1 存储和去重入口。

恢复复用原始 L0 的 ID、正文和时间，不再归档消息。发起时先追加新的 `started`，之后照常得到新增、复用、正常不记或失败终态。旧页面、重复点击、正在处理、正常 NOOP、已成功尝试及没有 V44 账本的旧 L0 均不能触发恢复。

## 后果

- 临时模型或数据库故障不再要求用户重新说一遍，也不会制造重复 L0。
- 每次恢复的模型、版本、结果和耗时独立留痕；不会改写原失败记录。
- 操作是控制台所有者的诊断/恢复能力，不是圆屏最终用户的确认流程。
- 当前不自动重试、不批量补跑旧对话，也不把恢复成功等同于候选事实正确。
