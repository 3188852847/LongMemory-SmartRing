# ADR-0046：L3 低频整理先采用显式操作契约

- 日期：2026-09-06
- 状态：已接受；领域契约与显式模型预览已实现，自动调度待后续切片
- 接续 ADR-0045

## 背景

用户希望 L3 表现为一份持续累积的统一画像，而不是聊天越多就无限增加互相矛盾的画像断言。现有模型草稿只能返回“一条候选”或拒绝，无法区分它是在补充新认识，还是在更新已有认识。直接把这种接口用于低频整理会让新旧事实并存，也无法审计模型为何改变画像。

## 决定

1. L3 整理建议使用 `ADD / UPDATE / NOOP` 三种显式操作。`NOOP` 是一等结果，证据没有形成新认识时不得勉强写入。
2. `ADD` 必须产生一条可核对候选且不指定取代目标；`UPDATE` 必须产生候选并明确指向一条当前有效、同类型的旧画像；第一版不允许一次模糊改写多条画像。
3. 建议只能引用本次调用明确提供的 L1/L2 来源和当前画像白名单。额外字段、重复字段、越权来源、未知目标、跨类型更新以及操作与载荷不一致均拒绝。
4. 操作契约只描述建议，不直接写库。后续装配仍须先展示可编辑草稿，再调用 ADR-0045 的候选式取代；用户接受前旧画像保持有效。
5. 整理接口不提供 `DELETE`。删除和纠正仍走已有的显式管理语义，模型不得借整理过程抹除个人记录。
6. 控制台可由用户明确选源、二次确认后调用一次当前模型。模型同时只看到本次来源及当前有效画像的最小字段；结果填入可编辑表单，不自动创建候选。
7. 不增加定时任务、不后台扫描个人数据库、不自动接受建议，也不让 L3 参与回答。

## 后果

人工触发预览已经可以在不改变 L3 持久化语义的前提下提出新增、更新或不处理。代价是正式低频自动整理前仍需定义触发条件、运行预算、去重和失败隔离；这些不能从当前显式按钮默认推导出来。

## 回退

当前契约不改变数据库结构。若后续实验证明三种操作不足，可以停用整理预览并以新 ADR 扩展版本，不影响现有 V9 个人库或人工管理入口。
