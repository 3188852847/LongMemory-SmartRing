# ADR-0010：来源绑定的语义提取候选边界

- 状态：接受首轮候选边界，候选服务及兼容模型适配器离线实现；实验新方法装配、持久化接入与真实提取质量验收未完成。
- 日期：2026-09-03。
- 延续 ADR-0008 的 D1，保留 ADR-0009 和两个 v1 方法不变。

## 背景与选择

首次真实开发集显示：规则提取遗漏非第一人称事实，关键词检索又无法召回已保存的姓名。两者需分开升级。直接改旧规则会破坏基线；直接把模型文本入库则缺少来源和失败边界。因此先新增一个可注入候选生成器的独立服务，不修改现用聊天/圆屏或注册一个尚未完整的新方法。

## 决定

1. 输入一条带真实 ID/角色的 L0 消息；候选生成器只看当前用户正文，不接收助手历史、参考答案、数据库或其他消息 ID。跨消息指代/摘要后续单独设计，本轮不猜。
2. 首轮保留旧问句过滤，空输入和 assistant 消息直接 NOOP、不发模型请求。它不是完备语义过滤，混合问答和疑问词可能造成漏记；实验必须披露该限制。
3. 输出严格 JSON：`schema_version: 1`、`operation: ADD 或 NOOP`、`facts: [{content, quote}]`。ADD 非空，NOOP 必须空；未知字段、重复键、来源摘录缺失、重复候选、畸形数据整批拒绝，不自动修复/重试/切回规则。
4. 原文摘录必须逐字存在于该用户消息。程序绑定 source_message_id 与 user_stated；模型不能指定来源 ID、修改既有事实或执行删除。user_stated 仅表示用户声称，不等于现实真实。
5. 来源正文最多 16000 字符、响应最多 64000 字符、单批最多 8 个候选、单条内容最多 1000 字符/摘录最多 4000 字符。属于首轮资源界限，不是调优结果或 token 预算。
6. 候选层只返回不可变数据，不写库。全部校验后才能交后续应用事务；未来模型调用必须在 SQLite 写事务外，持久化另做原子事务。当前不能宣称完成了这些集成能力。

代码核对：原 `MemoryTurnService.observe` 在 `_write_transaction()` 内调用 `_memory_extractor.extract`。因此不能将网络候选生成器直接注入原提取器位置。后续新方法必须在事务外先生成整批候选，再由只处理已验证数据的写入步骤完成 L0/L1/来源的原子提交；不能改变旧 v1 作为消融基线的行为。

独立 `OpenAICompatibleCandidateProducer` 已实现，用单独的版本化提取提示、JSON 编码用户正文和既有传输层发送一次非流式请求。它不带回答器角色/历史、不假设供应商支持 response_format，截断/非 200/空响应均报错。离线 HTTP 替身测试通过；尚未通过实验入口发起真实提取请求。

## JSON 示例（合成格式，不是模型测试结果）

```json
{"schema_version":1,"operation":"ADD","facts":[{"content":"用户是园艺师。","quote":"职业：园艺师。"}]}
```

## 后果和失败预演

- 无新增依赖、schema 或个人库迁移，v1 提取/召回未改变；可删除新模块而不影响现用方法。
- 真正语义蕴含没有被确定性校验解决：模型可以引用正确片段但改写出错误事实；用户原文还可能包含假设、引用或提示注入。必须用单独开发样例检查，不把 JSON 通过当成提取质量通过。
- 暂不自动推断主体、置信度、valid_from 或 SUPERSEDE；这些不得由模型随意写入。候选集接入新 L1 版本时另说明主体语义与存储影响。
- 后续先接独立提取模型适配与隔离实验方法，再做检索升级；记录额外构建调用成本和失败，分别开展提取/检索消融。Embedding 服务和模型选择仍未确定，不默认使用学校接口或安装大型依赖。
