# ADR-0116：自然说话打断的能力门槛

日期：2026-09-10
状态：接受

## 背景

控制台“停止当前回答”已经通过圆屏实机停播验收，但它是显式按钮操作。自然说话打断要求圆屏在播放期间持续拾音，并避免把自己的扬声器回声误判为用户插话。

当前固定版本中，圆屏通过直连 WebSocket 连接小智。设备只有在 `CONFIG_USE_SERVER_AEC` 打开时才在握手中声明 `aec`；小智服务端则只在 MQTT 网关路径解析带时间戳的二进制音频头、缓存播放参考帧并执行服务端 AEC。直连路径直接把二进制消息作为 Opus 解码。因此，仅修改握手声明或单独打开配置不能证明链路成立。

## 决定

先建立只读能力门槛，不直接启用自然打断。诊断同时检查：

1. 设备握手是否声明服务端 AEC；
2. 当前服务端传输路径是否实际支持带时间戳音频；
3. 服务端 AEC 是否处于活动状态；
4. 圆屏是否进入实时拾音模式。

四项同时成立时，只标记为“可进入受控试验”，仍不宣称自然打断已验收。任一项不成立时返回稳定阻塞原因。控制台不提供绕过门槛的强制开启按钮。

## 后果

- 当前 B V2 直连链路会如实显示具体阻塞层，而不是笼统写成“不支持”。
- 后续需要协调修改固件协议与小智直连 WebSocket 的时间戳收发语义，并保留原固件和服务端回退路径。
- 受控实机试验至少覆盖安静环境、扬声器仅回声、近距离插话和较远距离插话；在此之前不把 AEC 声明或一次成功当作功能完成。
- 本决策不修改圆屏固件、不启动模型、不写个人记忆数据库。
