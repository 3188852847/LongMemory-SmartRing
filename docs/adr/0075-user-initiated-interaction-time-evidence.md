# ADR-0075：用户主动出现时间使用独立、保守的可审计证据

- 状态：已接受
- 日期：2026-09-07

## 背景

P5.3 第一切片只能观察“系统问候后出现用户消息”，无法发现用户本来就经常在某个时段主动交流。当前 L0 又没有可靠会话 ID，不能把每条消息武断称为一次新会话。

## 决定

新增独立的 `user_initiated_interaction` 时间事件。只有上一条用户消息不存在或至少早 4 小时，且此前 30 分钟没有任何主动问候排队时才记录。事件引用 L0 消息 ID，但不复制正文；保存静默长度、证据类型和检测器版本。网页与圆屏共用入口以及自然命令入口都在原事务中调用观察器。

SQLite 升级至 V23；迁移只创建空事件表，不回填历史数据。控制台只读展示最近观察。该事件暂不进入联系时刻候选生成，不修改 P4 设置、L3 用户画像或模型权重。

## 理由

把“问候后回应”和“用户主动出现”分开，才能在后续比较两种信号，而不把相关性写成因果。4 小时静默与 30 分钟排除窗口是版本化启发式，可被回放和替换；它比假装已有精确会话边界更诚实。

## 后果

- 第一条历史后消息可能成为起点观察，但不能单独证明习惯。
- 连续多轮聊天不会重复产生事件。
- 主动问候后的用户消息仍可进入互动结果事件，但不会同时成为主动出现证据。
- 后续需要跨日聚类、最小样本门槛和离线回放，才能让该类证据形成未生效候选。
