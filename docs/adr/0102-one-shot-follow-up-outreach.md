# ADR-0102：显式启用的长期事项复用一次性主动交流账本

## 背景

V34 只建立带 L1 来源和未来时间的跟进候选。要让圆屏在未来主动追问，不能在后台到点后直接调用 TTS；那会绕过现有总许可、勿扰、频率、等待回应、设备状态、过期和结果证据，也无法区分“所有者保存了候选”和“所有者允许这次联系”。

## 决定

1. SQLite V35 为 `proactive_outreach` 增加跟进候选 ID 与候选 revision，并要求两者成对存在；同一候选最多绑定一条主动交流账本。
2. 所有者只有在主动交流总许可已开启、候选仍为当前、L1 来源未变化且计划时间仍在未来时，才能显式“启用一次跟进”。启用只创建未来 `candidate`，不会立即探测设备或播报。
3. 启用时冻结候选 revision、P4 策略版本和基于当时最大存活期计算的过期时间。之后总许可或其他设置变化仍按执行时的当前 P4 设置重新判断。
4. 后台优先级为：已到时间的明确事项跟进、固定定时问候、习惯缺席问候。同一分钟处理过事项后，不再让较低优先级来源追加第二条联系。
5. 到点后只尝试一次：来源退役/变化则取消；超过窗口则过期；设备离线或策略阻止则记为阻止；允许时复用既有投递器并最多记录为服务端排队。失败和错过均不补发。
6. 启用后、尚未执行的事项仍可由所有者取消；取消同时推进候选和主动账本。已经开始尝试的账本不允许伪装成“尚未执行”后再取消。
7. 删除来源 L1 时，候选、对应主动账本及事件随派生链级联清除，避免删除个人记忆后仍保留可播出的私密副本。

## 后果

- 长期事项形成“L1 来源 → 所有者候选 → 显式启用 → P4 门控 → 圆屏队列”的可审计闭环。
- 当前仍不自动从普通聊天启用跟进，也不调用模型决定时间或措辞；网页是所有者配置面，不是最终用户必须审批的入口。
- `queued` 仍只代表小智服务接收，不能冒充设备已播放；互动结果沿用既有 P5 时间证据语义。
