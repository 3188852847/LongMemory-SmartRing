# ADR-0120：React 拾音档位设置

## 状态

已接受，2026-09-11。

## 背景

小智 SileroVAD 已有普通、嘈杂、近讲严格三档安全预设，但只能在 Windows 启动面板中选择。用户主要在 React 控制台管理声音，因此需要统一入口。这个能力只能减少误触发，不能被描述为声纹或所有者识别。

## 决定

1. React 设置中心复用现有三档预设，不建立第二份阈值表。
2. 新增窄 HTTP 边界只接受预设 ID 和 64 位配置摘要；不接受任意 YAML 路径、字段或数值。
3. 读取只返回三个受控数值、匹配档位和摘要，不返回私有配置内容、密钥或路径。
4. 写入继续由小智自身 Python 环境执行，复用严格 YAML 结构校验、并发摘要、排他锁和 `.vad-*.bak` 原文备份。
5. 如当前数值不匹配预设，页面显示 `custom`，不自动猜测或就近归档。
6. 配置不热加载；页面保存后明确提示停止并重启圆屏语音。
7. 统一启动器的最小快照升级为 V2，只新增“是否启动语音”和“启动时 VAD 档位”。当前实例且快照新鲜时，页面可用它区分磁盘档位与本次启动档位。这只是启动证据，不是设备端实际加载回执。V1 快照继续可读，但不提供该证据。

## 后果

- 声音设置中现在同时有 TTS 输出与 VAD 输入两类设置，但两者仍保持独立配置域。
- 启动面板与 React 页面不会产生不同的预设语义。
- 保存后页面能判断是否需要重启当前受管语音；手动终端启动或过期快照时保持未知，不猜测。
- 更严格的档位可能造成轻声或远距离语音漏检；只听主人仍需后续声纹、唤醒词/按键门控或硬件改造。
