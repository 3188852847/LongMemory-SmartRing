# ADR-0188：同声线等待缓存与真实答案优先

- 日期：2026-10-20。
- 状态：隔离实现/合成验证通过；待 X 部署、Z 组合审查与所有者听感验收。
- 范围：补充 ADR-0172 的等待提示，保持 ADR-0178 的声线隔离、ADR-0166 的当前合成策略；不改变记忆或费用协议。

## 问题与证据

基线 `84048dc` 中，实时模式仍安装等待提示，但非默认声线给空包；计时又在 Memory 查询返回、模型请求开始时才启动。当前只读配置为 realtime、声音档案有效、default_voice_active=false，可解释当前路径为什么静默，不能倒推昨日每轮现场状态或证明 Hy 变慢。

另一个确定问题是：固定小智 `eb4b28c59ed7ed885258498cf757ce14352d620e` 的流控器在回调前增加虚拟播放位置。仅拒发过期/已被答案取代的提示包，仍会让后续答案耗掉这些包的 60ms 时间槽。

## 决定

1. 固定提示离线准备为私有、可校验缓存。身份由 CosyVoice 的标准 model_context 摘要（含参考录音摘要、原文、style 等）和固定模型/编码版本共同确定；清单只存摘要、固定提示摘要、长度和格式，不存参考正文或音频。
2. 明确维护窗口中使用现有本地 TTS、显式 voice_profile 快照和独立 Opus 编码器生成两条固定提示；整套通过后原子发布清单。用户问话时只读已准备缓存，不现场生成、不调用额外 LLM、不回退为其他声线。旧默认素材仅供确实默认的声线使用。
3. 在现有语音适配层包裹 query_memory，先启动话轮等待，再调用原 Memory；模型/工具递归复用同一计时和状态。来源归档、提取、检索、预算与重启语义均保持。
4. 每轮最多一次提示；真实答案 Opus 就绪后废弃未发提示尾包。流控回调中只退还该次已丢弃提示占用的虚拟帧配额，保留真答案与消息顺序。已发送或正在发送的帧、设备已缓存音频无法凭软件标记撤回，仍需设备验收。
5. 提示首包和答案首包分别计时；工具调用增量不冒充答案首字。严格 v6 设备协议不扩字段，新增固定阶段先留进程内快照与无正文日志，后续面板接线另审。

## 代价、替代与回退

维护窗口要求由 X 在独占交接期间隔离语音生产者，仅启动所需 TTS。命令的维护标志是执行前提确认，不是运行中抢占调度器。没有窗口时不准备，缺缓存安静降级；不能为了提示阻塞真实答案或占用当前 GPU 合成。

不选择运行中临时合成、默认声线顶替自定义声线或在记忆之前先给不依赖记忆的通用回答。前两者会争用资源/混音色，后者改变事实一致性。Hy 延后提取、闭合寒暄快路径与内部流式策略均需另评估，不能借本 ADR 默许。

物理缓存路径用摘要短前缀以兼容 Windows 深目录；完整身份和内容摘要仍在清单校验，前缀冲突拒绝。缓存属于 `local/runtime/voice-waiting/` 的私有派生音频，随声线切换隔离，不提交 Git。损坏缓存不由问话路径修复。

本适配绑定上述固定上游调度语义。升级流控器后必须重验“回调前增加播放位置”，不能将这段配额修正泛化到任意调度器。回退可在隔离分支撤回本轮语音提交，保留私有缓存不读取；不删除库/声线/原资产，不重刷设备。

## 验证与边界

146 项定向回归通过；真实 Python 3.10.20 已验证语法、导入和合成缓存辅助函数。延迟注入覆盖快答、慢记忆/模型/TTS、声线变化、档案丢失、缺缓存、取消/换轮；固定上游调度器的同条件注入对照证明丢弃提示不再消耗剩余虚拟时间槽。

上述均未调用真实模型/TTS、未播放设备。不能称当前日用端到端已达到某秒数、已恢复听感或已改善长期尾延迟。详见 [V 报告](../development/parallel/V-voice-latency-20261020.md)及[维护指南](../guides/语音等待提示与首答时长-20261020.md)。
