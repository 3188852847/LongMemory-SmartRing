# ADR-0065：所有者控制台主动交流运行记录

- 状态：已接受并实现。
- 日期：2026-09-07。
- 承接：ADR-0059、ADR-0064。

## 背景

主动交流已经用事件账本区分候选、策略拦截、服务端排队和失败，但若这些事实只能通过 SQLite 或终端查看，日常使用者无法判断一次测试为什么没有发生，也容易把 `queued` 误解成圆屏已经播放。

## 决定

1. 所有者控制台读取当前主体最近 10 条主动交流投影；HTTP 上限为 100 条，不提供跨主体或任意数据库选择。
2. 列表显示短文本、触发类型、创建/过期时间、当前状态、最后稳定原因、事件数量和稳定失败原因。它不返回幂等键、内部连接信息或第三方异常正文。
3. 记录按创建时间倒序，只读现有账本，不调用模型、不接触设备、不改变状态。
4. 手动测试完成后只刷新记录查询，不自动重新提交测试请求。
5. 第一版在设置页内展示简洁列表；事件逐条展开、筛选和取消操作留到真实需要出现后再设计。

## 后果与局限

用户可以区分“被策略挡住”“服务端排队”和“投递失败”，P4 的可解释性不再依赖终端。当前仍没有播放回执，因此列表不会出现未经证据支持的 `played`；列表也不等同于完整运行日志浏览器。

## 验证

- SQLite 集成测试覆盖最近投影读取。
- HTTP 测试覆盖排序结果、稳定字段和严格数量参数。
- React 测试覆盖手动发送只调用一次，成功后刷新只读记录。
