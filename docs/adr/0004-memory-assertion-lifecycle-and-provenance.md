# ADR-0004：记忆声明、来源证据与生命周期分离

- 状态：已接受
- 日期：2026-09-03
- 关联：ADR-0002、ADR-0003

## 背景

V0.1 已经能够把 L0 原始消息提取为 L1 原子记忆，并通过
`source_message_id` 追溯到一条来源消息。精确重复处理进一步暴露出两个问题：

1. 同一事实被多次陈述时，只保留第一条来源会丢失后续证据。
2. 未来的事实纠正、用户删除和时间变化具有不同语义，不能都实现为覆盖或删除。

如果继续让一条 L1 记忆同时承担“事实内容、唯一来源、当前状态和删除历史”，
后续加入冲突更新时会迫使存储接口和历史数据一起重构。

## 决定

### 1. 区分记忆声明与来源证据

L1 记忆表示一条规范化的事实声明；来源证据表示哪些 L0 消息支持这条声明。
两者采用一对多关系，而不是在记忆记录中永久保存唯一的
`source_message_id`。

记忆声明的最小语义包括：

- 稳定标识符；
- 主体标识，例如当前单用户使用 `user:self`；
- 可独立理解和检索的规范化内容；
- 系统记录时间；
- 可选的事实有效时间；
- 可选的取代关系。

来源证据的最小语义包括：

- 记忆标识符；
- 来源消息标识符；
- 来源类型，例如 `user_stated`；
- 建立关联的时间。

V0.1 只授权用户消息生成用户事实。助手消息可以保存在 L0，但不能默认成为
可靠用户事实。

### 2. 显式区分记忆写入决策

记忆写入策略使用显式操作结果：

- `ADD`：创建新的记忆声明并关联来源证据；
- `NOOP`：不创建新的记忆声明；精确重复时仍可给已有记忆追加来源证据；
- `SUPERSEDE`：创建新声明并将旧声明退出当前有效集合；
- `ERASE`：用户明确发起的管理操作，不由普通提取策略自动决定。

V0.1 只执行 `ADD` 和 `NOOP`。`SUPERSEDE` 先保留领域语义，到冲突更新版本
再实现。模型或规则提取器不得自行发起 `ERASE`。

### 3. 区分事实时间与系统时间

早期 `AtomicMemory.created_at` 的实际含义是系统记录时间。当前领域模型与
SQLite V3 已将其明确命名为 `recorded_at`。

为未来的时间事实和冲突更新预留以下可空语义：

- `valid_from`：事实在现实世界中开始成立的时间；
- `valid_to`：事实在现实世界中结束成立的时间；
- `retired_at`：系统何时停止把该声明当作当前有效记忆；
- `superseded_by_id`：哪条新声明取代了该声明。

V0.1 不从自然语言自动推断这些时间，不把消息发送时间误当作事实生效时间，
也不宣称已经实现完整的双时间查询。

### 4. 事实取代与用户删除不是同一操作

事实纠正使用 `SUPERSEDE`，保留历史和来源关系。用户在 V0.1 执行
`delete_memory` 时，物理删除指定 L1 记忆及其证据关联，但保留 L0 原始对话；
CLI 和文档必须明确这一边界。

删除 L0 原始对话、账户级擦除和保留策略不属于 V0.1，后续必须作为独立的
隐私管理能力设计，不能用 `SUPERSEDE` 冒充删除。

## V0.1 实现边界

本 ADR 会在 V0.1 中落实：

- 单用户主体标识；
- `user_stated` 来源类型；
- 一条记忆关联多条来源证据；
- 精确重复对应 `NOOP`，但保留新的证据关联；
- 无可用记忆时的拒答测试。

本 ADR 不在 V0.1 中实现：

- 语义重复判断；
- 通用主体、谓词和冲突键抽取；
- 时间表达抽取与双时间查询；
- 自动冲突识别与 `SUPERSEDE` 执行；
- 助手陈述自动升级为用户事实。

## 备选方案

### 继续使用单一 `source_message_id`

实现简单，但精确去重后会丢失后续来源，不满足审计和重新提取要求，因此拒绝。

### 直接采用完整知识图谱或双时间数据库

能够表达更复杂关系，但会显著扩大 V0.1 的依赖、实现和评估范围，因此拒绝。

### 把更新和删除都实现为原地覆盖

短期代码较少，但会破坏历史可追溯性，并混淆事实变化与隐私删除，因此拒绝。

## 后果

- 精确重复不再只是“少插入一行”，而是“复用声明并保留新证据”。
- 存储层需要增加来源证据表，并调整记忆领域模型和存储契约。
- 当前开发数据库需要非破坏性的结构迁移；不得通过删除真实数据库规避迁移。
- 后续冲突更新可以新增策略实现，而不必重新定义用户删除语义。
- 结构更清晰，但 V0.1 会增加少量模型、迁移和测试代码。
