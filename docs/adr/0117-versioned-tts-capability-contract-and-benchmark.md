# ADR-0117：版本化 TTS 能力契约与固定合成测试台

## 状态

已接受，2026-09-11。

## 背景

项目已经接入 EdgeTTS 和 VoxCPM2，也在考察 sanoTTS、CosyVoice、GPT-SoVITS 等候选。不同后端对“流式、取消、音色、情绪”的定义不同，而当前小智适配链会等待完整音频再交付。若直接使用模型宣传能力，控制台会把“模型可能支持”误写成“产品已经实现”。仅凭一次主观试听也无法区分模型生成慢、适配器缓冲、网络传输慢和圆屏播放慢。

## 决定

1. 建立框架无关的 TTS V2 契约，统一描述请求、音频块、协作取消和当前适配器实际交付能力。
2. 能力目录只登记已经接通并验证的后端。候选项目在完成本机适配前不进入目录。
3. EdgeTTS 与 VoxCPM2 当前均声明为 `buffered`；即使底层模型或网络协议具备流式能力，也不能提前声明 `audio_stream`。
4. 控制台使用四条固定合成文本进行单次、串行、零重试测试，只记录首个可用音频、完成时间、字节数和有限 WAV 波形检查。
5. 测试不读取真实聊天、个人记忆或用户录音，不把结果写入 L0–L3。它只测控制台到 TTS 适配器，不冒充圆屏端到端指标。

## 后果

- 后续 sanoTTS、CosyVoice 或 GPT-SoVITS 可以复用同一契约和测试入口，比较时不会改页面语义。
- 当前缓冲式实现的“首个可用音频”与“完成时间”相同，这个相等本身会暴露首句等待问题。
- 下一阶段要获得可感知延迟收益，必须让至少一个提供器真正按音频块交付，并把取消信号传到生成或编码边界；只替换模型名称不足以证明流式体验改善。
- 自然说话打断、回声消除和圆屏播放完成仍是独立链路，不由此 ADR 宣称完成。
