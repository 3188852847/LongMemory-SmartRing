# ADR-0155：明确日期约束的历史事实召回

## 状态

已接受，2026-09-13。

## 背景

ADR-0151 至 ADR-0153 已允许明确历史问句沿当前 L1 的精确变化链读取旧事实，但会把
链上所有旧事实作为补充，不能回答“2026 年 4 月时住在哪里”。直接从日期搜索全部
退役记忆会绕过当前主题召回，也容易把没有可证起点的事实推广到任意过去时间。

## 决定

1. 在应用层把同一问句中的唯一明确日期解析为 UTC+8 左闭右开区间；日期无效、缺少
   年份或出现多个日期时保持关闭。
2. 日期召回继续要求正式当前 L1 锚点和精确事实变化链，不建立独立全历史入口。
3. 只补充可证区间与目标相交的退役 L1；未知 `valid_from` 以 `recorded_at` 作为保守
   可证起点，不向首次记录之前外推。
4. 自然日若跨越事实变化时刻，允许变化前后的证据同时出现；回答按各自有效区间解释。
5. 日期问题只向回答保留可证区间与目标相交的当前 L1；不相交的当前 L1 从上下文和
   回执证据中移除。目标区间无匹配时只注入证据不足约束，不依赖模型自行忽略现状。
6. 新策略标识为 `explicit_temporal_date_v1`，普通历史策略和 SQLite V48 保持不变。
7. L2/L3 当前没有与这套日期区间等价的证据契约，因此明确日期问题不注入 L2/L3；
   普通当前问答和宽泛历史问答保持原行为。

## 权衡与失败预演

- “去年”按服务端 UTC+8 当前日期解释，不声称自动知道用户旅行时区。
- 只凭年月可能跨越多个事实区间，返回多个有边界证据比猜一个答案更安全。
- 首次记录时刻只是可证下界，不等于现实事实真正开始的时间。
- 当前适配器仍物化单用户 L1 快照；若真实准备耗时显示问题，再以索引和定向查询
  优化，不在无数据依据时增加数据库迁移。
- 回退日期分析和目标过滤即可恢复 ADR-0153；不修改已有记忆、回执或数据库结构。

范围与验收见[明确日期历史召回](../requirements/temporal-date-recall.md)。

## RC 边界修正

2026-09-14 的最终回答级合成验收发现：早期实现虽然加入“不得用现状替代”的文字
约束，却仍把不相交的当前 L1 正文交给回答器，确定性 Fake 已能复现错误替代。实现
现按第 5、7 项在 Runtime 过滤实际注入与回执证据；L1 影子候选继续保留原始正式召回
快照，避免改变旁路评估口径。该修正不迁移数据库，也不读取个人库。
