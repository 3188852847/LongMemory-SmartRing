# ADR-0031：运行期记忆写入与使用独立控制

- 状态：已接受
- 日期：2026-09-06

## 背景

日常助手需要允许用户临时决定“这段对话不要形成新的长期事实”，也需要允许用户在不删除记忆的情况下临时进行一次不带长期记忆的交流。把两种意图合成一个总开关会造成歧义：停止写入不应自动让已有个性化消失，停止使用也不应自动丢失本轮来源。

网页与圆屏已经共享一个常驻 `MemoryRuntime`。如果分别在两个入口保存开关，会再次产生两套行为，用户难以知道实际生效范围。

## 决定

在共享 Runtime 中维护两个独立布尔状态：

1. `write_enabled` 控制用户输入是否生成新的 L1；关闭时仍将双方对话归档为 L0。
2. `use_enabled` 控制本轮是否检索并注入已有长期记忆；关闭时返回空上下文和显式策略 `disabled_by_user`。

控制台通过受现有会话与 CSRF 保护的本机 API 一次提交两个值。网页聊天和统一启动的小智从下一轮开始共享该状态。设置不写入数据库或配置文件，服务重启恢复两项开启。

## 理由

- 写入、使用与删除是三种不同意图，必须解耦。
- 保留 L0 才能解释暂停期间发生过什么，也为以后经用户确认的补提取留下来源；这不是“完全不留痕”模式。
- 先采用易回退的进程内状态，避免尚未定义作用域、到期和隐私语义时过早引入持久策略迁移。
- 共用 Runtime 保证网页与圆屏行为一致，不修改 Xiaozhi 协议或 Memory Core 的检索算法。

## 后果与限制

- 已经开始的一轮按其准备阶段读取到的状态执行；切换不追溯修改历史轮次。
- 重启后恢复开启是明确行为，不是配置丢失故障。
- 关闭 L1 写入不等于不保存原始对话、删除信息或完整隐私模式。
- 本切片不提供按话题禁记、“只有明确说记住才写”、定时恢复、持久用户预设或多用户作用域；这些能力需要另行定义并用新 ADR 扩展。
