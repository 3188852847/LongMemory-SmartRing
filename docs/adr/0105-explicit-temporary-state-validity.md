# ADR-0105：明确临时状态使用 L1 有效期

## 背景

系统已经用 L0 保存原话、用 L1 保存可召回的原子记忆，并为 L1 预留 `valid_from` 与 `valid_to`。但此前日常提取不会给“我今天很累”这类状态设置期限，关键词与本地 BGE 召回也没有读取有效期。结果是一次短期状态可能长期参与回答，甚至被低频整理成 L2/L3，与“今天的我”和“长期的我”应当分离的产品目标冲突。

## 决定

1. 临时状态仍属于 L1，不新增 L4 或另一套临时数据库。L0 原话和 L1 派生记录继续承担来源审计。
2. 第一版只接受以“我今天”或“我这两天”开头、并命中少量状态词的明确自述；包含“以后、一直、每天、通常、习惯、长期”等持久含义时不套用临时期限。低覆盖是有意的保守边界。
3. “今天”使用当前 UTC+8 自然日的左闭右开区间；“这两天”从前一自然日开始，到当前自然日结束。到达 `valid_to` 即停止使用，但不删除 L0/L1。
4. 规则提取与日常模型辅助提取共享同一确定性时间后处理器；冻结的论文比较方法不改，避免静默改变既有实验条件。
5. 关键词召回与本地 BGE 混合召回在同一查询时刻过滤尚未生效和已经到期的 L1。相同临时内容在后续自然日再次出现时创建新的 L1，而不是给过期记录追加证据。
6. 有限 `valid_to` 的 L1 暂不进入自动 L1→L2 整理，避免期限在尚未支持时间传播的 L2/L3 中丢失。以后若设计跨层有效期传播，以新 ADR 取代此限制。
7. 长期事项跟进只能在计划触发时刻仍受来源有效期支持时建立；已启用跟进在到点执行前再次核验来源有效期。
8. 管理 API 增加读取时计算的 `effective_state`，页面区分当前、未生效、已到期和已退役；这不是新的数据库状态，也不迁移旧数据。

## 后果

- 明确的当天或近日状态到期后不会继续影响日常回答，历史证据仍可核对。
- 短期情绪和身体状态暂时不会被自动放大为生活场景或用户画像。
- 当前仅使用固定 UTC+8，适合现阶段单用户环境；跨时区配置属于后续能力。
- 模糊时间、复杂持续时间和模型隐含推断仍不会自动获得期限，需要真实样本后再扩展。
- 本切片复用既有字段，不提高 SQLite schema 版本，也不需要迁移个人数据库。
