# ADR-0015：日常陪伴产品优先，研究能力保留

- 日期：2026-09-04。
- 状态：已接受（用户同意整理产品路线与文档）；具体候选设置并非全部承诺开发。
- 部分替代 ADR-0008 的研究优先执行顺序，不替代其方法边界、隐私和实验协议。

## 背景

用户希望长期记住偏好、习惯，提供定制化陪伴，并在允许时主动联系。当前不愿日常使用的原因是页面与声音不合喜好、启动依赖多个终端、自定义操作不足。已有小规模研究实验没有自动升级日常规则提取和关键词召回。

## 选择与决定

选择按 P1 日常入口、P2 个性化体验、P3 日常记忆、P4 可控主动交流、P5 习惯驱动陪伴推进，而非继续先扩实验集或重建全部架构。

1. 保留现有代码、实验中心、方法接口和历史报告；暂停新增论文复现和大规模研究专项。
2. 优先最小启动入口，不先引入桌面框架或前端全面迁移。Python 后端、小智独立环境、本机控制台边界保持。
3. 必要工程与合成质量回归继续；日常数据不自动变成实验数据。
4. 记忆核心不承担设备控制或主动联系调度。主动联系需独立触发、投递、取消职责，具体实现后续决定。
5. 助手角色、用户明确偏好、推测习惯分开。推测允许确认/否认，不能解释为确定事实。
6. 先用户明确规则，再习惯驱动。默认不自动启用主动联系、开机启动、扩展数据采集或公网访问。
7. 文档归档：操作指南、需求、架构、流程分别维护；旧决策保留历史，当前说明纠正过期能力描述。

## 后果与边界

产品反馈成为近期排序依据，但不承诺这些能力构成论文贡献。前端选型、统一配置存储、会话 schema、TTS 与后台调度尚未定案，需要实现前说明依赖与迁移影响。电脑/服务不在线不能保证主动联系；已有音量桥不证明待机播报可用。

本次只改文档，不启动服务、不新增依赖、不修改配置、不迁移或读取个人对话，不改固件。后续的实机和校园模型验证由用户执行。
