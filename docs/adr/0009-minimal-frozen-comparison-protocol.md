# ADR-0009：最小历史回放与冻结问答协议

- 状态：已接受并实现最小版；用户于 2026-09-03 完成首次真实回答模型开发集运行，见独立复核记录。协议未改变。
- 日期：2026-09-03。
- 细化 ADR-0008 的阶段 C；不修改原 smoke 协议或日常记忆 schema。

## 背景与范围

用户确认先让差距可测，再升级 LongMemory，随后与适合共同任务的论文方法交替比较。当前规则基线不是成熟研究方法，姓名召回失败不在本阶段加特例修复。

本阶段做可执行的小规模比较，不建设完整实验平台、图表中心、向量服务或论文训练环境。只使用新建实验目录，不能输入日常数据库路径作为方法状态。

## 协议决定

1. 输入为显式合成 v1 数据：历史事件具有唯一 ID、user/assistant 角色、session_id、带时区时间和原文，按时间排序。题目含独立 ID、分类、dev/holdout 划分、答案词面参考、拒答标签和充分证据集合。
2. 方法只接收历史事件；构建阶段不调用回答模型，不重新生成助手历史。参考答案和证据标签仅评分可见，不传入 observe/recall/回答器。
3. 历史回放一次、等待构建完成并关闭。每题重新打开冻结方法；回答器也每题重新创建，不带之前的问题/答案或日常短期上下文。
4. 当前两种方法：原规则 `longmemory_v1`；同一会话内按连续两条原消息分块的 `dialogue_chunks_v1`。后者保留助手原文及角色，可能检索到助手错误推测，不冒充已验证事实。两者暂共享原关键词词项函数、最多召回五条；不声称隔离了全部变量的严格单因素消融。
5. 旧 V3 表不保存 session_id，算法也不利用会话分组。平台独立保存完整 history.json，给旧方法的输入明确移除它不支持的 session_id；事件 ID、角色、正文、时间不改。此处是披露过的适配，不是声称日常库已支持会话列，也不升级旧方法能力声明。分块方法实际使用会话边界。
6. 原子基线使用 `mode=ro` 和 `query_only` 打开冻结 SQLite；分块状态封存后不接受 observe。每题前后检查方法全部状态文件摘要；变化则该题 failed、余题 interrupted，不把被污染状态继续当成正常冻结问答。机制面向当前白名单方法，不是任意恶意插件的安全沙箱。
7. 两组用相同回答器参数、系统提示、最大 4000 Unicode 字符记忆上下文，原文与截断后注入都入报告。字符预算不等于 token 预算；固定五条也不等于相同信息量。裁剪后的证据是否充分目前需人工检查。
8. 检索指标按原始来源 ID 判定是否覆盖至少一组充分证据，不按 L1 规范化文本相等判分。多处重复陈述可列多个替代证据集；多会话问题可要求同一集合内的多个来源。未知信息题不要求零召回，因为相关片段也可能不含所问属性。
9. 答案用既有拒答模式与所需词语作初筛，多事实题要求多个词语，不强制固定回答格式。否定关系、幻觉混入、语义同义仍需人工复核；Fake 是猫名/拒答工程替身，不是比较质量的裁判或真实回答模型。
10. 每运行独立 UUID 目录，保留 manifest、完整历史、各方法状态、逐题 report。每题完成检查点写入，Ctrl+C 保存中断状态；强制终止或断电不保证最后 JSON 完整。保留所有问题分母，区分构建、召回、回答、评分失败，错误正文脱敏且不自动重试。

## 复现与限制

记录数据与源码哈希、Git 提交/脏状态、系统提示哈希、方法版本/设置、回答模型参数、运行顺序、起止时间、延迟、冻结状态摘要。未测 token、费用或服务端采样种子，字段不填虚构数值。单次按固定方法顺序运行，存在服务端波动与缓存影响，不能推导显著性。

当前数据为 14 条历史、3 个会话、8 个开发题、4 个留出题。留出题共用历史、源码可见，只是开发流程中的保留验收题，不是盲测或论文公开基准。默认只运行 dev，本轮不运行留出题，不自动收集个人信息。

无新增依赖、不迁移个人库、不改变现有提取/检索规则。原 smoke runner 和报告保留，不重命名冒充跨方法比较。

## 后续
