## 背景

用户确认 ADR-0166 后体验明显改善，但第一小句说完后会停一下再继续。
本轮从 Xiaozhi 内存状态读取 V6 脱敏时间，不读取个人库、问题或回答正文。
日用 health 已确认加载完整片段模式及 Qwen 输出层优化。

按片段完成即入队、音频以实时速度播放估算，第一段后缺口约
`13222 - (6043 + 2580) = 4599 ms`；第二段后暂时无缺口。
首个 Opus 实际早于片段完成约 35 ms，发送与设备库存也会影响结果，不能当作扬声器实测。

这轮不只是首句太短：日用每段生成仍慢于播放，而同机隔离服务固定测试更快。
在真正日用环境确认原因前，不把更长固定首播缓冲、缩小第二段或增加 GPU 并发写成解决方案。

## 范围与决定

1. 修复确定的切段旁路。上游每个 TEXT 增量只取一个片段，LAST/FILE 则把所有余文
   直接合成，可能让一次到达较多文字时的第二段明显变长。项目适配器在最终清空前
   先耗尽现有自然标点片段，再交回不足阈值或无标点尾文；保留顺序、取消和后端隔离。
   尾文成功处理后将已消费偏移对齐到本次缓冲末尾，纠正上游重复累加前缀的行为，
   避免 FILE 插入音频后继续到达的文字被跳过。
   不改首句长度，不退回逐逗号合成，也不改 Memory Core。
2. 给日用声音进程增加仅保存在内存中的阶段累计计时，允许健康检查前后取差值。
   只记录次数和墙钟毫秒，不记录文本、音频、账号或密钥，不主动调用任何模型接口。
3. 补齐离线资源保护。既有 WeText 初始化会调用 ModelScope 查询远程资源，
   `HF_HUB_OFFLINE` 没有覆盖这条路径。本轮发现元数据联网尝试后，在项目适配层
   只读解析现有中英文 FST；不调用会重写缓存的 `local_files_only` 路径，缺少文件时
   保留上游可选前端回退。未安装依赖，不修改外部源码与模型缓存。
