# ADR-0097：圆屏回答完成后通过本机窄接口回执

- 状态：接受
- 日期：2026-09-09

## 背景

LongMemory 的小智 Memory 插槽在回答生成前收到用户文本并返回记忆上下文，但原先看不到随后真正生成的助手回答。因此网页可以把质量反馈绑定到完整回答轨迹，圆屏却只能猜“你刚才没想起来”指向什么，不能安全接入同一质量闭环。

小智会在顶层 `chat()` 返回前把最终助手文本写入当前会话对象。项目启动适配器已经负责固定版本的非侵入式包裹，可在不修改厂商源码的前提下取得本轮新增助手文本。

## 决定

1. 内部 Runtime 新增 `POST /api/internal/memory/complete`。它继续只允许正确的本机 Runtime 令牌，并严格接收 `turn_id`、最终助手文本及 L1/L2/L3 召回数量。
2. SQLite V30 新增 `round_screen_turns`，把既有用户 L0 与新助手 L0 原子关联，同时保存三层召回数量和完成时间。它不表示音频已经在设备播放。

实现说明：厂商 `chat()` 的 `direct_answer` 正常路径会在完成回答后返回 `None`，因此适配器不把其内部返回值当作完成协议；只有顶层调用确实新增了非空助手消息时才发送回执。这样既覆盖普通回答与 `direct_answer`，也避免异常且无回答的调用被误记。
3. 相同用户轮次和完全相同内容的重复回执幂等返回；内容或计数不同则冲突，绝不覆盖旧回答。
4. 小智提供器在记忆准备成功后只保留一个待完成 `turn_id`。启动适配器包裹顶层 `chat()`，只收集本轮新增的助手文本并回传一次；失败只记录固定错误且不自动重试，不阻断已经进入播放队列的回答。
5. 本切片只建立回答证据。它不识别自然反馈、不计算错误率、不修改 L1–L3，也不把“生成完成”冒充“用户听到”。

## 理由

- 使用真实完成点比在 Memory 插槽中推测回答可靠。
- 项目侧启动包裹可回退，不形成对厂商仓库的永久分叉。
- 用户问题、助手回答和召回摘要有稳定关联后，后续自然反馈才能指向确定轮次。

## 后果与限制

- 助手回答属于个人对话内容，会像网页助手 L0 一样保存在个人数据库，仍不得提交 Git。
- 工具调用可能产生多段助手文本；第一版按会话中新追加的顺序以换行连接，保留实际文本但不声称等同于音频分段。
- Runtime 或回执暂时失败时不补发；该轮不会拥有圆屏回答关联，后续质量统计必须显示证据缺失，而不能猜测。
- 圆屏自然反馈仍需下一切片定义高精度短语、最近轮次时效和可修订事件契约。
