# ADR-0112：可查看但不直接回滚的助手角色历史

- 状态：已接受
- 日期：2026-09-10

## 背景

助手角色设置每次保存都会在独立旁库中生成递增修订，旧版本没有被覆盖，但控制台此前只能读取最新版本。用户无法确认过去保存了什么，也无法低风险地恢复一份旧草稿。

助手角色描述的是助手的表达方式，不是 L3 用户画像。它也分别作用于网页和圆屏服务，因此“选择旧版本”不能被页面包装成已经完成数据库回滚或真机同步。

## 决定

1. 控制台只读展示最近 20 个已保存的助手角色快照，按修订号从新到旧排列。
2. 选择历史版本只把名称、完整提示词和受管表达偏好载入编辑草稿。
3. 草稿只有经过现有的显式保存操作才生效；保存会基于当前最新修订创建一个新版本，不移动历史指针，不覆盖或删除旧版本。
4. 历史读取不创建角色旁库。尚未保存过自定义角色时返回空列表。
5. 载入或保存网页角色不会自动同步圆屏。圆屏仍须通过独立检查与同步流程处理。

## 理由

- 保留追加式版本记录，便于审计实际使用过的角色配置。
- 复用现有并发修订检查，避免旧页面静默覆盖新保存内容。
- 用“旧版本作为新草稿”代替数据库指针回滚，减少当前版本、回答追溯和圆屏状态之间的歧义。
- 限制为最近 20 个版本，满足日常恢复需求，同时避免把长提示词历史一次性无限发送到浏览器。

## 后果

- 用户可以查看并恢复近期角色设置，但这不是任意历史管理器。
- 本决定不提供历史删除、版本改名、差异比较或多套自定义命名预设；这些仍属于后续体验优化。
- 本决定落实 ADR-0022 中曾延后的历史查看能力，不改写 ADR-0022 的既有记录。
