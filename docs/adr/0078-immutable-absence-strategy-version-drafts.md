# ADR-0078：缺席策略先保存不可变版本草案，不以建档代替激活

- 状态：已接受
- 日期：2026-09-07

## 背景

ADR-0077 已建立固定合成回放，但命令行结果本身不会说明某条个人候选当时采用了什么时刻、宽限、时区、星期和数据集。如果以后只修改一份可变配置，将无法复原旧策略，也不能可靠回滚。

## 决定

SQLite V25 新增不可变的缺席陪伴策略版本表。每个版本绑定日常时段候选 ID 与 revision，并冻结期望分钟、60 分钟宽限、固定 UTC 偏移、允许星期、触发器版本、回放协议、数据集名称/版本/SHA-256、匹配数、不安全放行数和回放时间。

候选参数与数据集哈希共同形成 `parameter_fingerprint`；只有整套输入完全相同才幂等复用。候选已忽略、revision 变化或宽限跨午夜时拒绝建档。控制台可生成和查看版本，但 V25 不建立激活指针，不接后台调度。

## 理由

把“候选证据”“离线验证版本”和“当前运行策略”拆开，能在未来激活或回滚时保留准确依据。先保存不可变版本，可避免页面上的一次点击直接改变圆屏行为。

## 后果

- 数据库迁移只新增空表，不回填历史版本，不修改 P4 设置。
- 合成门控未通过的报告也允许保存用于审计，但后续激活层必须拒绝它。
- 当前页面上的“未激活”是事实；即使回放通过也不会自动联系。
- 下一切片新增单一当前版本指针、只追加切换事件和原子激活/回滚，再将当前版本接入后台触发。
