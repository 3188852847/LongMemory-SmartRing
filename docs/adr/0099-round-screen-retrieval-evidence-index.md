# ADR-0099：圆屏回答回执保存无正文召回证据索引

## 背景

SQLite V30 能把圆屏用户 L0、最终助手 L0 和 L1/L2/L3 召回数量关联起来，V31 还能保存用户对上一轮的明确质量反馈。但“召回了 2 条”不足以判断具体用了哪条记忆，因此无法区分检索、内容时效、排序和回答采用证据等故障。

## 决定

1. SQLite V32 新增 `round_screen_retrieval_receipts` 和 `round_screen_retrieval_evidence`。前者区分“新回执确认零召回”与“旧回执没有索引”，后者按用户轮次保存 `layer`、条目 ID、层内顺序和内容 SHA-256 指纹。
2. 索引不复制 L1 正文、L2 标题/摘要或 L3 标签/断言。L1 指纹基于正文；L2 基于“标题＋换行＋摘要”；L3 基于“标签＋换行＋断言”。
3. 回答与证据索引在同一事务提交；证据数量必须与三层回执计数一致，层内顺序必须从 1 连续递增。重复回执只有在回答、数量和证据完全一致时才幂等。
4. 内部 Runtime 协议把证据作为向后兼容的可选字段传递。更新期间的旧提供器仍可只提交数量；新提供器会严格校验并回传索引。
5. 旧 V30/V31 回执不做推测回填。控制台明确显示旧记录只有数量，不能冒充知道当时条目。
6. 质量列表只显示层级和顺序，并深链接到当前 L1/L2/L3 详情；索引接口仍不返回对话或记忆正文。所有者主动打开单条详情后，独立接口才读取问题、回答、反馈和条目当前内容，并与回答时指纹比较。

## 后果

- 新圆屏问题样本可以定位到实际召回条目，为后续区分检索失败、陈旧记忆和回答整合失败提供证据。
- 指纹可以支持以后检测条目是否变化，但当前页面不把指纹相同或不同自动解释为根因。
- 条目后来被删除时，历史索引仍可能只剩 ID 和指纹；这是避免保存隐蔽正文副本与完整历史可读性之间的明确取舍。
