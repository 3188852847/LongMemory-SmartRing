# ADR-0032：Web 控制台渐进统一到 React

- 状态：已接受
- 日期：2026-09-06

## 背景

聊天已经采用 React、TypeScript、Vite 与 Ant Design，设备、记忆和实验页面仍使用原生 HTML/CSS/JavaScript。产品主线需要继续增加 L0/L1 分层、记忆策略、角色、声音和主动交流设置。两套前端长期并存会重复实现导航、状态、错误反馈和安全写操作，也让用户误以为页面属于不同系统。

本决定取代 ADR-0021 中“只迁移聊天、不整体迁移控制台”的范围限制，不否定其 React 选型、安全约束和已完成聊天实现。

## 决定

复用现有 `web/react-chat/` 工程，按“记忆 → 设备 → 设置 → 实验”逐页迁移 Web 控制台：

1. 第一切片将 `/memories` 切换为 React，原生页暂留 `/memories-legacy`。
2. 页面按路径动态加载；不为当前规模新增路由库、全局状态库、SSR 或常驻 Node 服务。
3. Python API、回环认证、CSRF、CSP、数据库与记忆算法继续作为稳定边界。
4. 所有文本由 React 默认转义，不使用 `dangerouslySetInnerHTML`；资源继续本地构建和白名单提供，不使用 CDN。
5. 每个旧页面只有在功能对齐、自动回归和用户体验通过后才移除。
6. Python Tk 启动面板不是 Web 页面，不纳入本轮迁移。

## 第一切片的记忆语义

- L1 页签显示规范化原子记忆、状态、来源、纠正和受限删除。
- L0 页签只读显示用户与助手原文，并从 L0 反查是否派生了 L1。
- L0 列表接口只接受固定筛选和分页参数，不开放任意数据库选择或 SQL。
- 查看 L0 不改变数据库；删除 L1 仍保留 L0，页面必须继续明确提示。

## 后果与限制

- 收益是统一组件、导航和后续设置承载方式；代价是前端构建与包体积上升。
- 记忆页使用动态导入，聊天入口不加载其约 170 KB 未压缩页面块；现有聊天主包仍有构建器体积提醒，后续按真实性能再拆分。
- `web/react-chat/` 的目录名暂不重命名，避免为命名进行无功能价值的路径迁移；它实际上开始承担控制台应用职责。
- 第一切片不迁移设备和实验页面，也不改变 L0/L1 算法、schema 或个人数据。
