# ADR-0114：受限的遗留语音进程清理

日期：2026-09-10
状态：已被 ADR-0124 扩展；本 ADR 的 Xiaozhi 三端口约束继续有效

## 背景

启动面板正常拥有的服务由 Windows Job 清理；但排障终端或异常父进程可能留下小智子进程，使 8000 再次启动时被占用。要求用户手工查 PID 容易误杀其他 Python，也违背日常一键启动目标。

## 决定

启动面板增加“清理遗留语音”。端口本身不能单独关闭，因此操作只在以下条件同时成立时终止一个进程：所选局域网地址的 8000 恰有一个监听者；同地址 8003 与回环地址 8766 各有一个监听者且 PID 完全相同；进程名为 `python` 或 `pythonw`。

检查和停止在同一个本机 PowerShell 进程中完成。任一条件不满足即拒绝；不批量查杀 Python，不停止 8767 控制台、8768 壁纸投递或 18768 VoxCPM2。面板自己仍有受管服务时要求使用原“停止服务”，不走旁路清理。

## 后果

- 已知小智遗留进程可从面板一键恢复，不再要求复制终端命令。
- 外部终端中仍在正常聊天、但符合相同契约的小智也会被终止；按钮名称和结果必须明确这是进程终止。
- 未启用 8766 控制桥的其他小智实例不会被自动接管，需要人工核对。
