# ADR-0190：CosyVoice 连续音频交付与协作取消

- 状态：待 Z 整合审查；GPU 对照完成，保留 buffered 默认，增量仅显式试验
- 日期：2026-10-20
- 对应阶段：[X 流式优化记录](../development/parallel/X-cosy-streaming-20261020.md)

## 背景与适用范围

正确 OTA 路由后的既有一轮记录中，TTS 开始到首个 Opus 为 4575 ms。
服务默认完整生成自然片段，消费者又收齐 WAV 块后才编码。
这两个屏障意味着 HTTP 分块本身不能提早交付有效回答。
这些是既有软件阶段记录，不是本候选的性能结果或扬声器测量。

[ADR-0166](0166-cosyvoice-measured-runtime-optimization.md) 基于当时的完整片段消费者，
选择关闭模型内部流式以改善吞吐，并规避提前关闭时跳过上游清理的问题。
本轮实测不支持全面改为增量默认，因此保留其第 1 项完整片段默认选择。
本候选拟替代第 5 项的生成器清理和阻塞读取取消实现，并新增显式增量试验入口；
原实测数字、隐藏输出层优化、声音与精度约束继续保留。
本记录当前不表示日用默认已经切换，也不改写历史测量。

## 候选决定

1. 默认连接没有 `_longmemory_cosy_delivery_mode` 属性时使用 `buffered`。
   只有明确设置为 `incremental` 才启用增量；基准工具显式设置，日用装配不设置。
   不根据字符数、标点、寒暄匹配或缓存命中自动打开，也不把少量自然段样本泛化为安全阈值。
   使用固定 `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc` 的 CosyVoice3
   原生音频流。保留训练的首块长度及后续 25→50→100 策略，
   不修改权重、FP16、F0、采样步数、声线、文字自然分段和 60 ms Opus 帧。
2. 项目侧以完整函数 AST（抽象语法树）指纹核对固定模型，将请求字典清理放入
   `finally`，在原 LLM token 边界检查取消，等待原生产线程退出后再释放字典和模型锁。
   外部源码不落盘修改；合同不匹配时拒绝增量模式，保留完整片段路径。
   未安装适配器时，不向 guard 挂入取消事件；所有模型流式请求降为完整片段，
   取消或消费端关闭先耗尽上游、完成 yield 后的清理再释放锁，不承诺即时中止模型。
   若模型自身失败而无法确认清理，当前实例标记 requires_restart，所有合成和缓存入口
   拒绝复用；健康检查 ready=false，须重启重新构造。只对已适配且只读核对请求状态
   全空的失败/取消保留复用能力，不盲清未知版本字典。
   Python 3.10/3.12 仅规范无语义的空 `type_params` AST 字段，不忽略实际控制流。
3. 新增本机长度前缀协议第 2 版，零长度块表示正常结束。EOF（输入结束）缺少该块
   视为截断，不冲刷伪造尾音。第 1 版仍可供既有消费者使用。
4. 显式增量消费端立即把每块 PCM 送进持久 Opus 编码器；默认仍收齐自然片段。
   24→16 kHz 的 FIR（有限脉冲响应）
   历史和分数相位跨块保留，只有正常段尾才补滤波尾样本及不足一帧的零填充。
   24 kHz 输入直接保留。连续结果与整段参考误差至多 1 个 PCM 最小单位。
5. 每个请求持有自己的环回 socket，取消或轮次失效可中断阻塞读取；服务观察该连接
   关闭并协作停止生产。取消检查覆盖发送前后，清除编码器残留，不让旧轮次进入新轮次。
   已交付音频后不重播整句；尚未交付时可回退既有完整 WAV。
6. 就绪前另用固定合成句准备当前选中声线及真实流式路径。健康检查分别报告
   默认暖机、当前声线暖机和身份；声线改变后标记未暖机，不在健康读取中暗中合成。
7. 继续使用有限进程内精确回复缓存，键覆盖模型实例/版本/实现、声线摘要、文本、
   采样/编码和交付模式；不持久化个人回答。已有声线特征缓存、回复缓存和等待提示
   缓存不计为本轮新收益。普通性能对照关闭回复缓存。

## 验收与回退

自动测试覆盖正常与截断协议、任意 PCM 切块、真实 Opus 帧、取消清理、
生产者异常、当前轮次失效、同一编码器的新轮次及实际 Python 3.10 指纹兼容。
第二次 GPU 窗口完成 46 个调用；普通完整文本每模式 15 个样本，自然分段每模式
6 个样本，另列首次声线、暖态、缓存命中及取消后的新轮次。
完整文本首个可解码 Opus P50 为 buffered 4442.866 ms、增量 1330.046 ms；
增量累计供给缺口最大 1563.203 ms，RTF 中位数从 0.59337 升为 0.73325。
自然分段增量仍有最大 282.879 ms 缺口，不能据此全面默认开启。
具体样本数、分组和原始证据见阶段记录，不把软件曲线当成扬声器测量。

首个有效 Opus ≤1 s 为工程目标，当前没有本机成功测量证明达标；整链路 ≤2 s
还涉及识别、记忆、模型和播放，不由本记录验收。声学差异、听感与设备插话另验。
当前仅提交默认保护、选中声线预热、协议和清理能力供 Z 审查，尚未部署候选。
服务 `--force-buffered-audio` 可覆盖显式请求，严格指纹不支持时保留原完整 WAV 路径。
初始缓冲 360 ms 在已测六条自然分段曲线的离线回放中消除估算缺口，但增加首包延迟；
它未实现、未重新测 GPU，也没有成为自动放行策略。

## 成本与后续

模型原生流式可能增加累计解码计算；更早首包必须同时检查持续供给和总耗时。
协作取消不能即时中止正在执行的 CUDA kernel，线程退出前不并行下一次合成。
新协议和固定版本 AST 适配增加维护成本，外部升级必须重新核对和测量。

CosyVoice 的文字/音频双流，以及 TensorRT-LLM、vLLM-Omni 属于下一阶段候选。
官方公开硬件数字不作为本机 RTX 4080 的结果；需要新模型、引擎或容器时先另行安排
固定来源下载和隔离验收，不修改当前依赖、Docker 服务或日用声线。
