# ADR-0113：圆屏首句分阶段时序

日期：2026-09-10
状态：接受

## 背景

真实使用中 EdgeTTS 与 VoxCPM2 都被感知为“回答慢”。单一总耗时无法区分记忆、模型、首句分段、TTS 与设备发送，也容易让一次主观体验驱动错误优化。

## 决定

在项目侧小智启动适配器包裹固定上游快照，不修改厂商源码。每个设备连接只在内存保留最近一轮的七个相对时间点：记忆完成、模型请求、模型首个有效输出、TTS 首段开始、首个音频包就绪、首包发送返回、模型响应完成。

本机令牌控制桥按固定白名单契约返回该快照，React 设备页展示派生等待区间。日志和接口不含问题、回答、记忆、音频、模型地址、设备 ID 或句子 ID。

计时从小智顶层回答入口开始，此时 ASR 已经完成；首包发送返回也不等于圆屏扬声器实际开始播放。页面必须持续展示这两个边界。

## 后果

- 可在同一链路公平比较 EdgeTTS 与 VoxCPM2，并先定位再优化。
- 数据不持久化，服务或设备重连后只保留新连接产生的最近一轮；当前不是性能实验仓库。
- 后续若需要跨轮统计，应另建脱敏、显式授权的测量数据模型，不能直接扩大本接口。
