# ADR-0175：主动交流采用用户可调周期

## 背景

V16 的自动问候每天只在一个固定分钟检查一次。真实日用反馈表明，这个频率过低，且原设置页把
许可、时间边界、测试、记忆话题、跟进、习惯候选和运行记录同时展开，用户难以找到最常用的开关。
既有“最短间隔”和“每日次数”是安全护栏，不是自动问候调度器；单纯放宽它们不会增加问候频率。

用户还希望直接对圆屏说出频率。让回答模型口头确认而不修改数据库会重现“模型说成功、后台没有
变化”的问题，因此语音设置必须由确定性命令和真实持久化完成。

## 决定

1. SQLite V49 在主动交流设置中增加 `automatic_interval_seconds`。只接受 60～86400 秒且必须是
   整分钟；V48 及更早记录迁移为 86400 秒，保持原每天一次行为，升级不会提高现有用户的频率。
2. 用户可在控制台设置 1～1440 分钟。首个检查时刻作为当日周期锚点，之后在允许星期和允许时段内
   按周期形成唯一时间槽；24 小时继续使用原每天固定时刻语义。
3. 短周期不因“今天已经聊过”跳过余下整天，但每次仍受总开关、周期问候开关、勿扰、允许时段、
   上一条待回应、每日上限、设备离线或忙碌等护栏。用户没有回应上一条时不会按分钟连续追问。
4. 每个周期时间槽使用包含 UTC 分钟的幂等键。防抖比自动周期少一分钟，用于吸收后台轮询落在
   时间槽不同秒数的误差；真正的重复约束由唯一时间槽负责。设置保存时刻早于当前分钟边界后
   才允许创建，避免一分钟周期在命令落库后同一分钟立刻发声。
5. 自然对话只接受带“主动交流/主动联系/定时问候”对象及明确整数分钟或小时的设置句，例如
   “把主动交流频率改成每十分钟一次”。解析、范围校验和数据库更新由应用层完成，不调用回答模型
   猜测。命令只修改频率，不暗中打开总开关或周期问候开关。
6. 主动交流页面首屏只保留状态概览、总开关、周期问候开关、频率、问候内容和保存。允许时间、
   勿扰、手动诊断、记忆话题、一次性跟进、习惯学习和运行记录按任务折叠。1～5 分钟显示高频提醒，
   所有写操作回执显示在首屏可见位置。

## 后果

- 用户可以在一分钟到二十四小时之间自主试出合适频率，并可用网页或语音修改。
- 高频设置代表“最多按该周期尝试”，不承诺每个时间槽一定发声；待回应等护栏会主动停止追问。
- 24 小时模式继续兼容“今天聊过则跳过”和一次性开发验证；短周期不使用每日验证豁免。
- 这是日用反馈驱动的 V1 主动交流范围修正，相关 RC 固定路径需要按新频率设置重新观察；它不增加
  新模型、自动习惯学习或新的个人事实推断。
