# ADR-0158：启动面板受令牌保护的本机控制接口

- 状态：已接受
- 日期：2026-09-14

## 背景

Windows 启动面板使用 Tk 构建。当前自动化环境不能稳定取得这个原生窗口，因而无法可靠查询或点击“启动服务”“停止服务”。直接结束进程会绕过启动面板拥有的 Windows Job 进程树和停止语义，也无法复用面板当前选择及启动前检查。

启动器已经监听 `127.0.0.1:18767` 作为单实例锁。增加另一个常驻端口没有必要，也会扩大诊断和冲突面。

## 决定

在既有 `127.0.0.1:18767` 监听 socket 上增加按行 JSON 控制协议，并遵守以下约束：

1. 每次打开启动面板生成新的随机令牌，并把主机、端口、令牌和允许操作原子写入 Git 忽略的 `data/control/launcher-control.json`。
2. 只接受回环连接和 `status`、`start`、`stop` 三个白名单操作。`status` 可返回当前面板选中的非敏感枚举，但不返回路径或令牌；令牌错误、未知操作、过大或无效请求一律拒绝。
3. 网络线程只做读取、鉴权和排队；真正的查询、启动与停止由 Tk 主线程轮询执行，避免跨线程操作界面或进程管理器。
4. `start` 复用面板当前可见选择以及原有路径、端口、配置与风险检查；`stop` 复用启动器已有 Windows Job 停止流程。
5. 控制接口不接受配置值、路径、网址或命令，不开放遗留进程清理、防火墙、数据库、固件烧录和关闭面板。
6. 启动面板退出时删除仍属于本实例的发现文件。旧文件、错误令牌或未运行面板均视为接口不可用。

命令行客户端读取本机发现文件但不输出令牌：

```powershell
.\.venv\Scripts\python.exe scripts\development\launcher\control.py status
.\.venv\Scripts\python.exe scripts\development\launcher\control.py start
.\.venv\Scripts\python.exe scripts\development\launcher\control.py stop
```

## 理由与边界

这个接口让自动化沿用启动面板已经验证的进程所有权和安全检查，而不是模拟不稳定的鼠标点击。回环绑定、随机令牌和固定操作集合限制了调用范围；发现文件属于本机单用户运行数据，不进入 Git。项目仍按单用户本机场景设计，不把该协议视为跨账号权限系统。

`stop` 会中断正在生成的回答或音频，语义与面板“停止服务”一致。已有启动面板实例必须关闭并重新打开一次，才会加载这项能力。

## 后果

- 自动化可以可靠取得面板管理状态，并执行受限启动或停止。
- `launcher-status.json` 继续是给 React 系统总览使用的只读状态快照；它不承担命令协议。
- 单实例锁和控制通道共用端口，仍只能同时打开一个启动面板。
- 如果后续需要增加操作，必须逐项评估输入、影响和回退，不允许演变为任意命令执行。

2026-09-16 的实现复核补充了超时语义：等待主线程超过期限、但尚未开始的请求会被
取消，不能在客户端收到 `launcher_busy` 后延迟执行；已经进入主线程执行的请求不会
假称未执行，而是返回结果未知，调用方应先查询状态，不得自动重试写操作。

## 回退

移除控制桥及发现文件发布即可恢复为纯单实例锁；启动面板原有按钮、进程管理、状态快照和配置文件均不需要迁移。
