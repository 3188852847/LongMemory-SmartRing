# 圆屏皮肤架构与流程

## 当前实现

当前有三层必须区分：

| 层 | 位置 | 当前能力 |
|---|---|---|
| 交互状态协议 | 项目文档与 0004 固件补丁 | 待机、聆听、思考、说话、错误等状态语义由设备本地解释 |
| 皮肤清单 | `firmware/smartring_plus/skins/*.skin.json` | 描述颜色、脸部比例与动画；严格校验、可计算指纹 |
| 资源二进制 | 厂家 `assets.bin` | 可装字体、表情和背景；原厂支持 OTA，但安全回退尚不满足本项目要求 |

网页控制台当前完成的是前两层的设计管理：打开“圆屏预览”，选择皮肤后画布立即变化，点击“保存预览选择”会把皮肤 ID 原子写入被 Git 忽略的 `data/control/round-skin-selection.json`。

这不会修改个人记忆、模型、声音、小智配置或真机 Flash。

## 皮肤清单 v1

清单固定目标为 `viewe-smartring-plus`、360×360、RGB565、`skin_api=1`。允许字段只有：

- `palette`：背景、文字、状态脸、警告、错误和充电颜色；
- `face`：眼睛宽高和嘴部宽度，均有像素范围；
- `motion`：眨眼与说话动画周期，均有秒数范围；
- 名称、说明和版本身份。

情绪仍能临时改变强调色，故障状态仍优先于普通对话状态。皮肤不能修改业务状态机、命令处理、记忆或网络行为。

## 目标真机流程（尚未实现）

1. 控制台选择一份兼容皮肤。
2. 服务端生成设备可理解的受限配置；若包含大资源，则另外生成固定格式 `assets.bin`。
3. 设备下载前核对板型、Skin API、内容长度和期望 SHA-256。
4. 设备下载并校验；任何失败继续显示固件内置皮肤。
5. 设备仅在完整校验后切换当前皮肤，并回传“已下载 / 已校验 / 已应用”中的真实阶段。
6. 控制台根据设备回执显示状态，不能把“服务器已选择”写成“设备已应用”。

## 为什么不使用实时界面流

服务器可以决定角色配置和提供资源，但 ESP32-S3 仍需本地驱动屏幕、处理触摸并维持配网/更新/错误界面。持续传图会增加带宽、延迟和断网故障面，也无法消除 LVGL 与显示缓冲。因此本项目只传低频配置或资源包，不传每帧 UI。

## 下一实现门槛

- 在短路径固件实验副本中增加只读的 `skin_api=1` 解析器；
- 先使用内置默认值和 NVS 配置验证回退，不改资源分区；
- 将服务器选项通过窄设备工具发送，并获取可核对回读；
- 构建、补丁反向检查、应用镜像余量和只写应用分区验证均通过后，才安排实机烧录；
- 大资源下载在上述闭环之后单独评估。

架构决定见 [ADR-0093](../adr/0093-versioned-round-screen-skin-packs.md)，状态语义见[圆屏状态协议](round-display-state-protocol.md)。
