# 圆屏皮肤架构与流程

## 当前实现

当前有三层必须区分：

| 层 | 位置 | 当前能力 |
|---|---|---|
| 交互状态协议 | 项目文档与 0004 固件补丁 | 待机、聆听、思考、说话、错误等状态语义由设备本地解释 |
| 皮肤清单 | `firmware/smartring_plus/skins/*.skin.json` | 描述颜色、脸部比例与动画；严格校验、可计算指纹 |
| 运行时设备子协议 | 0005 固件补丁与设备控制桥 | `skin_api=1` 固定白名单参数、NVS 回退、所有者工具、写后完整回读；运行时闭环已验收 |
| 资源二进制 | 厂家 `assets.bin` | 可装字体、表情和背景；原厂支持 OTA，但安全回退尚不满足本项目要求 |

网页控制台打开“圆屏预览”后可比较完整设计清单，也可从任一皮肤派生一份 `local-custom-v1` 本机档案。编辑器只开放九种真机颜色和眼睛/嘴部尺寸，修改即时预览；保存后原子写入被 Git 忽略的 `data/control/round-skin-custom.skin.json` 并生成新指纹。点击“保存预览选择”另把皮肤 ID 写入 `data/control/round-skin-selection.json`。检测到已经烧录 0005 且在线的圆屏后，还可把设备支持的子集应用到真机。

网页保存不会修改个人记忆、模型、声音、小智配置或真机 Flash。真机应用只改圆屏 NVS 中的 `round_skin` 命名空间，不改应用与资源分区。

## 皮肤清单 v1

清单固定目标为 `viewe-smartring-plus`、360×360、RGB565、`skin_api=1`。允许字段只有：

- `palette`：背景、文字、状态脸、警告、错误和充电颜色；
- `face`：眼睛宽高和嘴部宽度，均有像素范围；
- `motion`：眨眼与说话动画周期，均有秒数范围；
- 名称、说明和版本身份。

情绪仍能临时改变强调色，故障状态仍优先于普通对话状态。皮肤不能修改业务状态机、命令处理、记忆或网络行为。动画周期、渐变与浏览器排版目前不下发给设备，因此网页是真实协议预览，不是逐像素真机模拟。

## 当前真机流程（代码、烧录和运行时闭环已完成）

1. 控制台选择一份兼容皮肤。
2. 用户手动检测设备能力；普通旧固件或离线设备不能启用应用按钮。
3. 服务端从版本控制清单生成严格的设备子集，不接受浏览器提交任意颜色或路径。
4. 设备核对 Skin API、ID、清单 SHA-256、颜色和尺寸范围，再把完整配置写入 NVS；无效或不完整配置使用固件内置皮肤。
5. 控制桥立即读取同一个所有者工具，所有字段逐项一致才返回 `verified=true`；只有此时服务端才同步保存本机选择。
6. 设备重启后从 NVS 加载；主题发生变化时重新覆盖皮肤颜色。

这条流程不使用 `assets.bin`。图片、字体等大资源仍属于以后单独设计的安全资源安装阶段。

## 本机自定义档案

- 只保存一份 `local-custom-v1`，避免日常试色产生无界版本垃圾；内置皮肤仍保持只读。
- 身份、名称、说明、板型和协议版本由服务端固定，浏览器只提交明确的颜色与尺寸白名单。
- 新档案从所选基础皮肤继承浏览器专用的背景边缘和动画周期；这些继承字段不会下发真机。
- 保存请求携带当前自定义档案 SHA-256。另一个页面已经修改时返回冲突，不用陈旧草稿覆盖新档案。
- 保存不会自动选中为默认，也不会自动下发设备；两种操作继续由用户分别触发。

## 为什么不使用实时界面流

服务器可以决定角色配置和提供资源，但 ESP32-S3 仍需本地驱动屏幕、处理触摸并维持配网/更新/错误界面。持续传图会增加带宽、延迟和断网故障面，也无法消除 LVGL 与显示缓冲。因此本项目只传低频配置或资源包，不传每帧 UI。

## 动态壁纸资源层（0007 技术验证中）

动态壁纸不会扩充 `skin_api=1`，而是在皮肤参数之上增加独立、可选的媒体资源层。0007 已实现首个离线固件切片：服务器侧生成受限 GIF，构建时把它打入 assets 分区，设备待机时使用已有 GIF 解码器播放；尚未实现控制台上传、运行时资源安装和版本回读。

1. 控制台接收本机视频并只保存在 Git 忽略的数据目录；上传不自动发布到设备。
2. 服务器校验文件类型、大小和时长，去除音轨，按 360×360 的圆形安全区裁剪、降帧并生成轻量短循环资源包。
3. 资源包带格式版本、板型、内容哈希、帧率、尺寸和完整性信息；设备先下载到非活动位置，校验成功后再原子切换。
4. 设备本地解码和循环播放，不依赖服务器持续推帧；断网时继续使用已缓存资源。
5. 配网、OTA、低电量、过热、错误等系统覆盖层始终高于壁纸。聆听、思考和说话状态至少保留清晰的状态环或状态脸，不能被视频遮蔽。
6. 解码失败、资源损坏、内存不足或语音链受影响时立即回退到固件内置状态脸。

实际 B V2 配置使用 16 MiB Flash，两个应用 OTA 槽各 `0x3f0000`，另有 8 MiB `assets` 分区；这为可替换媒体资源提供了位置，但不代表 8 MiB 都能交给单个壁纸。360×360 RGB565 一帧为 259,200 字节，10 fps 裸帧每秒约 2.47 MiB，因此必须验证压缩格式和解码开销。0007 已证明 SmartRing-Plus 专用 GIF 接入能够构建，应用与 assets 均未超分区；设备能否在语音同时稳定播放，仍须实机测量，不能用构建成功代替运行时结论。

详细范围和验收见[动态壁纸需求](../requirements/round-screen-dynamic-wallpaper.md)。

## 剩余验收与后续边界

- 已只写 0005 应用镜像，未覆盖 NVS 或资源分区；
- 能力探测、“薄荷微光”切换与完整回读已经验证；用户报告重启保持成功；
- 本机受限参数编辑器已由用户确认可用；不把这项页面验收扩写为全部自定义皮肤均已完成真机视觉核对；
- 仍需在自然对话中逐项观察待机、聆听、思考、说话和明确错误状态；
- 验收失败时恢复 0004 应用镜像，不把服务端响应冒充真机成功；
- 大资源下载继续留在上述闭环之后单独评估。
- 0007 已完成动态壁纸离线构建，后续实机写入需成对更新应用与 assets；真机性能和回退仍未验收。

架构决定见 [ADR-0093](../adr/0093-versioned-round-screen-skin-packs.md)，状态语义见[圆屏状态协议](round-display-state-protocol.md)。
