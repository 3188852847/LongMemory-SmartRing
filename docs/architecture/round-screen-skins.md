# 圆屏皮肤架构与流程

## 当前实现

当前有三层必须区分：

| 层 | 位置 | 当前能力 |
|---|---|---|
| 交互状态协议 | 项目文档与 0004 固件补丁 | 待机、聆听、思考、说话、错误等状态语义由设备本地解释 |
| 皮肤清单 | `firmware/smartring_plus/skins/*.skin.json` | 描述颜色、脸部比例与动画；严格校验、可计算指纹 |
| 运行时设备子协议 | 0005 固件补丁与设备控制桥 | `skin_api=1` 固定白名单参数、NVS 回退、所有者工具、写后完整回读；运行时闭环已验收 |
| 资源二进制 | 厂家 `assets.bin` | 可装字体、表情和背景；原厂支持 OTA，但安全回退尚不满足本项目要求 |

网页控制台打开“圆屏预览”后可比较完整设计清单；选择皮肤会立即改变画布，点击“保存预览选择”会把皮肤 ID 原子写入被 Git 忽略的 `data/control/round-skin-selection.json`。检测到已经烧录 0005 且在线的圆屏后，还可把设备支持的子集应用到真机。

网页保存不会修改个人记忆、模型、声音、小智配置或真机 Flash。真机应用只改圆屏 NVS 中的 `round_skin` 命名空间，不改应用与资源分区。

## 皮肤清单 v1

清单固定目标为 `viewe-smartring-plus`、360×360、RGB565、`skin_api=1`。允许字段只有：

- `palette`：背景、文字、状态脸、警告、错误和充电颜色；
- `face`：眼睛宽高和嘴部宽度，均有像素范围；
- `motion`：眨眼与说话动画周期，均有秒数范围；
- 名称、说明和版本身份。

情绪仍能临时改变强调色，故障状态仍优先于普通对话状态。皮肤不能修改业务状态机、命令处理、记忆或网络行为。动画周期、渐变与浏览器排版目前不下发给设备，因此网页是真实协议预览，不是逐像素真机模拟。

## 当前真机流程（代码、烧录和运行时闭环已完成）

1. 控制台选择一份兼容皮肤。
2. 用户手动检测设备能力；普通旧固件或离线设备不能启用应用按钮。
3. 服务端从版本控制清单生成严格的设备子集，不接受浏览器提交任意颜色或路径。
4. 设备核对 Skin API、ID、清单 SHA-256、颜色和尺寸范围，再把完整配置写入 NVS；无效或不完整配置使用固件内置皮肤。
5. 控制桥立即读取同一个所有者工具，所有字段逐项一致才返回 `verified=true`；只有此时服务端才同步保存本机选择。
6. 设备重启后从 NVS 加载；主题发生变化时重新覆盖皮肤颜色。

这条流程不使用 `assets.bin`。图片、字体等大资源仍属于以后单独设计的安全资源安装阶段。

## 为什么不使用实时界面流

服务器可以决定角色配置和提供资源，但 ESP32-S3 仍需本地驱动屏幕、处理触摸并维持配网/更新/错误界面。持续传图会增加带宽、延迟和断网故障面，也无法消除 LVGL 与显示缓冲。因此本项目只传低频配置或资源包，不传每帧 UI。

## 剩余验收与后续边界

- 已只写 0005 应用镜像，未覆盖 NVS 或资源分区；
- 能力探测、“薄荷微光”切换与完整回读已经验证；用户报告重启保持成功；
- 仍需在自然对话中逐项观察待机、聆听、思考、说话和明确错误状态；
- 验收失败时恢复 0004 应用镜像，不把服务端响应冒充真机成功；
- 大资源下载继续留在上述闭环之后单独评估。

架构决定见 [ADR-0093](../adr/0093-versioned-round-screen-skin-packs.md)，状态语义见[圆屏状态协议](round-display-state-protocol.md)。
