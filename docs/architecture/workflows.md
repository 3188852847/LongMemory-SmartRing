# 系统运行流程

## P3.1：统一启动后的共享记忆流程

1. 启动面板生成仅本次运行有效的随机 Runtime 令牌，不写磁盘。
2. 控制台打开明确选择的已有 SQLite，并创建一个常驻 `MemoryRuntime`。
3. 网页文字输入直接调用该 Runtime：规则模式在一笔事务中保存 L0/L1；显式模型模式先提交 L0，再在事务外生成严格候选并提交 L1。召回可选关键词基线，或关键词＋固定本地 BGE 排名融合；随后模型回答，助手回答再归档为 L0。
4. 圆屏语音先由小智完成 ASR；小智适配器携带同一次启动令牌，请求控制台的回环 Runtime 接口。
5. Runtime 对圆屏文本执行相同写入与召回，将受控记忆上下文返回小智；小智再生成并播放回答。
6. 两端下一轮都能看到同一 Runtime 已提交的长期记忆，但各自最近对话仍由各自会话系统管理。
7. 内部请求结果不确定时停止本轮，不自动重试或切到旧子进程。停止统一启动器后，Runtime 关闭连接但不删除 SQLite。

手动单独启动小智时，未注入 Runtime 环境变量，提供器继续使用旧 `subprocess` 管道。这是排障回退，不是与常驻模式并行运行的第二套日常服务。

音色流程：读取当前磁盘配置 → 选择音色 → 用户点击联网生成固定文本试听 → 浏览器手动播放 → 确认保存 → 校验配置摘要并备份、仅替换音色 → 用户重启小智 → 圆屏验证。配置或网络失败不自动重试，配置状态不等于运行状态。

VoxCPM2 流程：启动面板选择本地后端 → 显式检查/同步私有 TTS 覆盖并备份 → 启动独立 Python 3.11 模型服务 → 校验固定权重并常驻 GPU → 本机健康检查通过 → 启动 Xiaozhi → `CustomTTS` POST 句子 → 返回 WAV → Xiaozhi 重采样并编码 Opus → 圆屏播放。停止面板会停止三个受管服务并释放显存；失败不自动切回 Edge。

更新：2026-09-05。当前流程与拟议流程分开；本文解释执行顺序，不是命令手册。可复制命令见[使用说明](../guides/使用说明.md)，模块归属见[架构总览](overview.md)。

## 1. 当前：启动与停止

网页角色修改：读取当前版本 → 编辑草稿/载入预设 → 明确保存 → 事务检查版本 → 返回保存版本 → 下一轮固定并记录该版本。圆屏另行检查 → 明确确认 → 版本/配置摘要复核 → 原目录备份 → 仅写 prompt → 回读。用户重启小智后实机确认，失败先重新检查、不自动重试。见[角色设置指南](../guides/助手角色设置.md)。

React 日常入口：前端构建产物由同一个 Python 控制台提供；统一启动面板默认直接打开 `/chat-react`，不需要手改网址或单独启动 Vite。若构建产物缺失，服务返回 503 并提示重新构建；原生页面只作为迁移期排障回退，具体见[指南](../guides/React聊天页.md)。

需要防火墙排障时：点击“网络与防火墙” → 只读检查 → 确需修改才填写来源并确认 → Windows 管理员授权 → 重新检查规则与圆屏在线。已有可用连接无需新增规则。

IP 变化时：刷新本机地址 → 选择圆屏可达网卡 → 显式确认同步三个小智网络字段（原目录备份）→ 启动 → 按指南配置项目防火墙与圆屏 OTA → 实机确认。普通启动只检查，不静默修改配置。

1. 文字使用按指南启动 LongMemory API，显式选择已有日常库、聊天回答器和助手角色。
2. 浏览器打开本机控制台；文字聊天不要求小智运行。
3. 要使用圆屏，再在小智独立环境启动服务；音量管理需设备控制桥开启。
4. 圆屏连接小智后才具备语音链路；待机无活动连接时设备控制可能不可用。
5. 结束实验先停止后续请求，再在各自终端停止服务。关闭网页不等于停止后端。

失败：端口冲突、模型不可达、设备离线分别处理，不自动改 IP、杀其他 Python 进程或重烧固件。现在也可使用下方第 7 节的最小统一启动面板；终端方式保留。

## 2. 当前：网页文字聊天

显示偏好独立流程：读取本浏览器主题/字号/动画偏好 → 校验枚举 → 渲染；用户选择时即时更新并尝试保存。存储被禁用只提示无法保存，不阻断聊天。此流程不经过记忆提取或模型，也不修改真实圆屏固件。

1. 后端检查聊天启用状态、会话与请求，使用显式日常库。
2. 将用户正文作为带角色的消息交给当前 Runtime 方法：默认 `longmemory_v1`，或启动时显式选择 `longmemory_daily_llm_v2`。
3. Runtime 读取本轮写入开关：开启时，规则模式原子保存 L0/L1，模型模式先提交 L0 再在事务外提取；关闭时只归档 L0，不调用 L1 提取器。
4. Runtime 读取独立的使用开关：开启时按启动配置进行关键词或关键词＋本地 BGE 召回；关闭时不检索、不注入，并报告 `disabled_by_user`。
5. 真实回答器使用当前问题、网页临时历史、角色与记忆上下文生成回答；Fake 仅用于工程验证。
6. 保存助手 L0，但不把助手回答再提取为用户事实。
7. 返回回答与各阶段实际结果，页面展示写入、召回、注入等信息。

失败：回答生成失败不会撤销已完成的用户消息/记忆写入。模型提取连接或结构失败返回 `source_only / l1_extraction_failed`，L0 保留、本轮可继续回答，不伪装成正常 NOOP，也不自动改用规则。数据库忙与模型失败分别报告，不承诺自动重试或跨崩溃恰好一次。

会话旁库现在持久化标题、请求和轮次，浏览器 Cookie 保留时刷新/重启可恢复列表。续聊最多最近六轮成功对话、24000 字符；旧无会话编号消息不回填。新聊天不删除旧档案或长期记忆。见 ADR-0019。

### 2.1 当日漏记的所有者补录

1. 每日回顾只计数当天未关联的用户 L0；该状态是核对线索，不是“必须记住”的自动判定。
2. 所有者打开其中一条原话，只有用户角色、尚无任何 L1 关联且启用纠正权限时才可进入补录。
3. 所有者手工填写以“用户”为主体的完整 L1；页面提交原 L0 的 revision 和显式确认，不调用提取或回答模型。
4. 事务内重新核对 revision 与关联状态；若其他页面已处理这条 L0，拒绝旧页面重复写入。
5. 没有同内容当前 L1 时创建一条，已有时只把原 L0 追加为 `user_stated` 证据；不复制 L0，也不复制 L1。
6. 同一事务写入不含正文的 `owner_confirmed_missed_extraction` 质量事件；它只证明所有者做过该操作，不自动归因。
7. 成功后页面直接打开实际 L1 与来源；读取或写入结果不确定时不自动重试。

## 3. 当前：圆屏语音聊天

1. 圆屏采集并发送语音，小智负责识别用户文本。
2. 统一启动时，小智 Memory 适配使用启动器生成的令牌调用控制台回环 Runtime；手动单独启动才使用旧子进程回退。
3. 共享 Runtime 对用户正文应用与网页相同的写入/使用开关、提取和召回策略。
4. Runtime 返回上下文、操作计数和实际模式；它不生成语音回答。
5. 小智按自身模型/角色/当前连接上下文生成回答，合成语音并发送给圆屏。

限制：当前桥没有归档小智助手回答；网页与小智短期会话独立。页面文字不会自动交由圆屏播放。失败时应查看对应阶段日志，不能凭无回答断定未写入记忆。

## 3.1 当前：运行期记忆模式（P3.4 第一切片）

1. 用户在“记忆管理”选择是否从新对话生成 L1、是否在回答时使用已有记忆，以及是否让已接受 L2 参与回答。
2. 本机 API 严格校验三个布尔值，在共享 Runtime 锁内一起更新，避免半配置状态；L2 开关默认关闭。
3. 下一轮网页或圆屏请求读取同一状态；已经开始的轮次不被中途改写。
4. 关闭 L1 写入仍归档 L0；关闭记忆使用返回空上下文并同时阻止 L2 使用，不删除或隐藏数据库里的记忆。
5. L2 开启时只召回 active、当前有效且与问题有关键词重叠的场景，最多 3 条；轨迹单独保存 L2、L1、L0 ID。
6. 状态只属于当前服务进程；重启恢复 L1 写入与使用开启、L2 使用关闭。

### L2 生命周期

1. 用户只能对 `active` 且 revision 未变化的场景执行“结束”。
2. 同一事务把状态改为 `stale`、修订号加一、在必要时收窄 `valid_to`，并写入 `manual_end/user` 事件。
3. L1 退役或删除触发场景失效时，数据库分别写入 `source_retired/system` 或 `source_deleted/system` 事件。
4. 失效不删除场景、来源快照或 L0 证据；详情页继续提供向下追溯。已经失效的场景不会因另一来源变化而重复制造事件。
5. V5→V6 迁移只增加空事件表并替换触发器，不为迁移前已经发生的状态变化伪造历史。
6. V6→V7 迁移只增加空的 L3 画像、来源、生成审计和复核表；个人库已在一致性备份后迁移，未扫描历史或回填画像。
7. V7→V8 迁移只增加 L3 生命周期表和上游失效触发器；个人库已在一致性备份和明确授权后迁移，没有生成或改写画像。
8. V8→V9 只增加空的 L3 取代关系表；个人库已在一致性备份和明确授权后迁移，未生成或改写画像。
9. V9→V10 重建 L3 复核表以增加 `policy` 身份、策略版本和决定原因；旧复核原样保留为 `user`。个人库已在一致性备份后迁移，业务表数量未改变。

本切片不是“仅在我要求时记”、话题级禁记或隐私擦除。L2 目前只是关键词安全基线，不是语义召回。见 ADR-0031 与 ADR-0037。

### L3 人工候选与复核

1. 页面只读列出当前有效 L1 与已接受 L2，不自动判断哪些来源应组成画像。
2. 用户选择来源并明确填写一个画像断言，或二次确认后调用一次模型生成不落库草稿；模型同时收到所选来源与底层用户 L0，不能引用白名单外来源。
3. 声明型至少追溯到一条用户 L0，推断型至少满足两个来源、三条不同用户 L0 和两个 UTC 观察日；模型调用前检查输入池，返回后检查最终子集。
4. 用户核对或修改草稿后另行创建；服务在同一事务保存候选、来源快照和生成审计，此时不会参与回答。
5. 用户在详情中沿 L1/L2 查看 L0 原话，并通过 revision 保护的确认接受或拒绝。
6. L1 退役/删除或 L2 失效时，相关候选/已接受 L3 自动转为 stale 并留下事件；来源快照和证据继续保留。
7. 当前没有后台自动整理或失效后重建；L3 回答注入已通过独立、默认关闭的运行期开关提供。
8. 对当前有效画像发起更新时，先创建带目标 revision 的新候选；只有接受候选，才在同一事务中激活新画像、失效旧画像并记录取代时间。拒绝或并发冲突不改变旧画像。
9. 人工复核记录为 `user`；后续确定性策略自动接受必须记录为 `policy` 并携带策略版本和原因。两者使用同一原子复核路径，不能让自动化冒充用户。
10. 开启 L3 使用后，只召回 active、当前有效且与问题关键词重叠的画像，最多 3 条并受 1200 字符预算限制；轨迹单独保留画像、上游来源和 L0 ID。

该流程是当前已实现的内部审计闭环，不是最终用户使用圆屏时的必经步骤。

### 拟议：圆屏无网页审批的记忆演化

1. 圆屏用户照常聊天，系统先保存 L0；模型或规则只能提出 `ADD / UPDATE / NOOP` 候选。
2. 确定性决策器检查来源角色、证据数量、观察日、敏感性、冲突、候选类型和目标 revision，不让模型自行宣布“低风险”。
3. 明确、低风险且满足证据门槛的候选进入 `AUTO_ACTIVATE`；证据可能继续积累的进入 `HOLD`；适合在对话中澄清的进入 `ASK_NATURALLY`；敏感或归因不明的进入 `BLOCK`。
4. `AUTO_ACTIVATE` 仍走原有事务、来源快照、生命周期和取代关系，不绕过审计；自动路径不执行 DELETE。
5. 用户说“不是旧值，是新值”或“我以前……，现在……”时，共享 Runtime 先按固定高精度契约寻找唯一当前 L1；唯一命中才执行纠错/事实变化，歧义时自然追问，不要求用户打开控制台。
6. 控制台只负责查看决定原因、纠正、停用和回滚。失败或未知执行结果不显示为已生效。

确定性决策器、策略审计、应用层自动生效执行器和圆屏自然记忆操作第一版已完成。圆屏还可明确记住/跳过一条事实和询问来源；单条 L1 删除必须先回读唯一目标，再由紧接着的一轮口头确认，且仍保留 L0。P3.9 两阶段执行器已接入可选低频调度，但个人库默认关闭，因此默认不会自行扫描或调用模型。

### 当前：低频整理运行账本（P3.9 第一切片）

1. 调用方分别计算 L1→L2 或 L2→L3 的待处理来源数，不把正文写入调度账本。
2. 纯策略先检查同阶段运行互斥、空输入、每日模型调用预算、最低新来源数和冷却时间，并返回稳定原因码。
3. 获准后先插入 `running` 记录；相同主体和阶段的并发抢占由 SQLite 唯一索引拒绝。
4. 后续执行器成功时必须写入来源数量、模型调用次数、结果码和“时间 + 来源 ID”高水位；只有 `completed` 推进游标。
5. `failed` 或 `skipped` 必须结束运行并留下原因，但不推进游标、不伪装成已整理。V13 起新运行还固定记录独立风险复核器版本。

聊天路径只在确有 L1 写入后向 `MemoryRuntime` 拥有的唯一调度器发送可合并信号；通知发生在聊天 SQLite 锁之外。默认关闭时不创建线程、不扫描数据库。显式开启后，每个周期自行打开连接，先运行 L1→L2，再用更新后的数据库检查 L2→L3；见 ADR-0057。

来源选择器已实现：先从游标之后按时间与 ID 升序取新 L1，保证游标不跨过未处理证据；批次有余量时再加入最近的旧未归组 L1，使旧事实以后仍有机会与新事实成组。当前尚无后台触发器或真实模型调用。默认 4 条来源、6 小时冷却、每阶段每日 2 次模型调用预算、单次最多 20 条均是可配置运行护栏，不是质量结论。非 NOOP 运行会为候选生成和独立风险复核预留两次调用。

### 当前：L1→L2 受控执行（可选低频触发）

1. 从 V11 成功游标读取新 L1，并在批次余量中带入最近的旧未归组 L1。
2. 触发策略获准后先占用运行槽位，再在数据库事务外调用一次 L2 候选模型；本轮不重试。
3. `candidate=null` 是正常 NOOP：记录 `no_coherent_group` 并推进到本批新来源游标。
4. 非空候选连同白名单来源进入一次独立风险复核；复核缺失、网络或结构失败都不激活、不推进游标。
5. 候选由 `scenario-activation-v1` 重新按实际白名单来源计数。至少 3 条 L1/3 条用户 L0 且复核通过时，才以 V12 `policy` 身份接受；否则 HOLD/BLOCK，不创建持久候选。
6. 网络、格式或事务失败记录稳定失败码且不推进游标；候选激活与账本完成使用同一提交边界。见 [ADR-0056](../adr/0056-independent-consolidation-risk-review.md)。

这一用例已有合成闭环，并由 P3.9 的单一所有者调度器按冷却与预算低频触发；个人库默认关闭。首版门槛不等于摘要已获语义蕴含证明，见 [ADR-0053](../adr/0053-policy-audited-l2-activation.md)。

### 当前：L2→L3 跨时间整理（可选低频触发）

1. 只选择当前 active 且处于有效期的 L2；按成功游标后的最老新场景前进，并用余量带入最近旧场景。
2. 每个场景沿 L1 继续解析到用户 L0 原文与 UTC 观察日，模型不能提供或篡改门控计数。
3. 默认至少 2 个新 L2 才触发，24 小时冷却、每天预留 2 次模型调用、单批最多 12 个；无新 L2 时不重放旧上下文。
4. 候选模型返回 `ADD / UPDATE / NOOP`。NOOP 记为完成；ADD/UPDATE 还要经过一次独立风险复核，再使用 `persona-activation-v1` 的 3 来源/5 原话/3 观察日强证据门槛、策略复核和候选式取代。
5. 失败不推进游标，不在同一运行中重试；P3.9 可选调度在新证据通知后按冷却运行，个人库默认关闭。见 [ADR-0054](../adr/0054-cross-time-l2-to-l3-consolidation.md)。
6. 生活场景页和用户画像页分别只读展示这两个阶段的门槛、预算、游标和最近结果；刷新页面不会触发整理。

## 3.1 当前：圆屏自然记忆操作（P3.8）

1. 普通语音仍按原路径归档、提取和召回；只有命中固定契约才进入操作路径。
2. `不是豆包，是年糕` 表示旧记录原本错误：旧值必须只命中一条当前 L1，新 L1 保存该变化，旧 L1 以 `SUPERSEDE` 退役，原句保存为 `user_corrected` 的 L0 来源。
3. `我以前喜欢喝咖啡，现在不喝咖啡了` 表示现实后来变化：旧片段必须唯一命中；旧 L1 写 `valid_to`，新 L1 写相同时间点的 `valid_from`。
4. `你怎么知道豆包` 只读取 L1 的来源证据并说明用户原话，不新增 L1。
5. `不要记住：具体内容` 保存整句 L0，但跳过本轮 L1 提取。单独说“这句不要记”不回删上一轮，只提示补全具体内容。
6. `请记住：我叫小林` 保存完整命令为 L0，并把自指陈述确定性规范化为单条 L1“用户叫小林。”；重复内容只增加证据。问题、主体不明片段和暂停 L1 时不强写。
7. `请忘掉豆包` 只建立内存中的短暂删除候选并回读目标；只有紧接着两分钟内说 `确认删除这条记忆` 才删除该 L1。任何其他对话、超时或目标变化都会取消；L0 不删除。
8. 操作结果会进入本轮上下文，并在内部接口返回独立 `memory_command` 轨迹；失败或歧义不显示为已生效。网页直接使用应用层固定回执，不调用模型改写；小智内部协议另传 `command_reply`，薄适配器要求模型准确转述。由于当前上游 Memory 插槽不能直接短路 LLM，圆屏语音仍不是确定性直答。

第一版有意不使用模型解释任意口语，也不根据“不是这样”猜目标。真实圆屏 ASR 的漏识别属于后续体验数据，不能通过放宽写入条件来掩盖。

## 4. 当前：记忆查看与单条删除

1. 页面请求已有日常库的分页列表或来源详情。
2. 用户选中具体 L1，查看原始来源。
3. 只有显式开启删除能力时才可发起单条删除；提交前确认并核对当前对象。
4. 删除对应 L1 及关联来源关系，刷新列表；原始 L0 仍保留。

这不是纠正流程，也不是完整隐私擦除。没有撤销或恢复入口时，不向用户承诺可一键恢复。

## 5. 当前：圆屏音量控制

1. 网页通过本机 API 查询受限设备状态。
2. API 使用后端令牌访问小智设备桥，浏览器不持有设备令牌。
3. 活动连接且能力可用时，允许在当前 5–60 范围内设置音量。
4. 根据回执和读值核对显示结果；离线、超时、未知执行结果不显示为成功。

这条通路只证明已支持的音量操作，不证明待机主动播报或亮度设置可用。

### 5.1 当前：运行时圆屏皮肤

1. 页面读取版本控制内的严格皮肤清单并在浏览器预览；保存预览选择只写本机控制文件。
2. 用户也可以从任一现有皮肤派生唯一的本机自定义皮肤；浏览器只能修改 9 个真机颜色字段和 3 个脸部尺寸字段，修改时仅即时更新预览。
3. 保存自定义皮肤时，服务端重新执行严格字段和范围校验，原子写入本机控制文件并计算新的 SHA-256；若另一页面已经修改过同一档案，旧草稿会被拒绝而不会覆盖新版本。
4. 用户手动检测真机能力；设备离线、旧固件或控制桥未更新时，应用按钮保持禁用。
5. 用户选择皮肤后，服务端生成 `skin_api=1` 固定白名单子集，浏览器不能自行提交颜色、路径或 URL。
6. 小智设备桥调用所有者专用工具；固件完整校验后写入独立 NVS 命名空间并立即更新 LVGL 状态脸。
7. 设备桥再次读取同一配置，所有字段逐项一致才返回已验证；失败不自动重试，也不把本机选择冒充设备成功。
8. 重启设备后再次检测，确认 NVS 保持；无效配置始终回退固件内置皮肤。

0005 已完成代码、补丁审计、构建、仅应用分区烧录、独立读回和运行时实机验收。该流程不写资源分区，浏览器动画与渐变不会下发；自定义档案保存也不会自动写入设备。

## 6. 当前：隔离实验

1. 选择已有冻结检索档案和回答器，不从日常库自动取数据。
2. 预检本地输入、来源与预算；不会调用回答模型。
3. 用户明确确认后运行回答重放，按题记录进度。
4. 新结果另存，原报告不变；人工复核另存附页。
5. 停止只阻止后续请求；已发出的请求可能继续完成。中断不自动续跑。

该流程不重新提取或编码，也不代表实验算法已接入日常聊天。Fake 和词面初筛不能作为语义质量结论。

## 7. 当前：统一启动与会话恢复（P1/P2）

1. 用户选择文字或文字＋语音模式。
2. 启动入口核对环境、网络/TTS 配置与端口，识别已有实例；配置同步必须由用户单独确认。
3. 仅启动明确归本工具管理的服务；VoxCPM2 模式依次启动控制台、模型服务，健康后才启动小智。
4. Windows Job 只管理本次创建的树，停止会中断在途请求；用户先结束聊天，再确认停止，不默认修改自启项。
5. 网页会话列表已持久化到独立旁库；恢复不等于圆屏短期对话共享。

已实现：门控子进程、Job 所有权、单实例锁、随机控制台实例标识、语音共享路径核对、网页会话恢复与可选 VoxCPM2 常驻服务；本地 HTTP 合成和真实统一启动通过，声音窗口可读磁盘后端、契约匹配与模型服务状态，圆屏 VoxCPM2 播放仍待用户听感验收。待设计：优雅排空和完整配置权威来源。操作见[统一启动](../guides/统一启动.md)。

## 8. 拟议：修改角色、外观和声音（P2）

1. 用户选择配置类型，查看当前有效值与适用入口。
2. 修改并预览；声音用合成文本试听，说明是否需外部请求。
3. 校验支持范围后保存，显示立即生效还是需要新会话/重启。
4. 提供恢复默认/上一版能力；不连带改写个人事实或实验提示。

## 9. 日常记忆纠正与事实变化（P3.3）

1. 建立统一常驻 Memory Runtime，使网页与圆屏通过同一应用服务访问同一日常库；先保持旧算法等价，避免同时改变运行形态和记忆质量。
2. 每轮先保存 L0 原始证据；按用户写入开关生成 L1 ADD/NOOP/UPDATE/DELETE 候选，并另行说明 L0 留存范围。
3. L1 候选在事务外提取，在事务内绑定来源、适用时间、状态和取代关系；新方法通过合成验证后显式启用，旧数据不默认批量重跑。
4. 通过关键词与向量形成日常混合召回，过滤不适用、已取代或低置信内容；无可靠结果时不强行注入。
5. 用户选择错误记忆，提供新内容，并区分纠错与事实变化；成功后找到受影响的 L2/L3，标记失效或排队重建。
6. 达到明确触发条件后，低频把多个 L1 组织为 L2 场景；再以更多、跨时间证据形成 L3 用户画像或习惯候选。L2/L3 均保留向下证据链。
7. 页面分层展示结果、来源和影响范围；失败不显示已纠正。助手角色与用户画像使用不同配置和名称。
8. 个人记忆稳定后再接轻量 `KnowledgeProvider`：文档摄取、切片、向量检索和引用优先；实体关系与 GraphRAG 只有在真实问题需要时增加。
9. 上下文编排器判断本轮使用当前会话、个人记忆、外部知识或组合，合并前保持 `user_stated`、`model_inferred`、`document_claim` 等来源隔离，并记录最终注入证据。

当前已实现的纠错路径：

1. 用户在记忆详情选择一条仍有效的 L1，查看内容和原始来源。
2. 用户输入纠正后的完整事实，并确认“旧记录本来就错误”。
3. API 在写事务内再次核对详情 revision；内容或来源变化时拒绝操作。
4. 系统保存一条 L0 用户纠正输入和一条 `user_corrected` 新 L1 来源。
5. 旧 L1 写入 `retired_at` 并用 `superseded_by_id` 指向新 L1。
6. 整个事务提交后，新事实参与召回，旧事实只在“已退役/全部”中保留审计。

当前已实现的事实变化路径：

1. 用户查看一条仍有效的 L1，选择“记录变化”，而不是“纠正错误”。
2. 用户输入变化后的完整事实和已经发生的生效时间；页面把本地时间转换为带时区的 ISO 时间。
3. API 在同一写事务中再次核对详情 revision，并拒绝未来时间、无时区时间和早于已知 `valid_from` 的时间。
4. 系统保存新的 L0 用户陈述和 L1；新 L1 的 `recorded_at` 是系统记录时间，`valid_from` 是现实生效时间。
5. 旧 L1 的 `valid_to` 写入同一生效时间，`retired_at` 写入系统操作时间，并通过 `superseded_by_id` 指向新 L1。
6. 事务成功后当前召回只使用新事实；旧事实的来源和历史有效区间仍可审计。

撤销、聊天自动识别变化、时间感知历史问答、自动冲突和 L2/L3 传播仍待设计。见 ADR-0026、ADR-0030 与 ADR-0034。

## 10. 当前技术验证：圆屏主动播报（P4.1）

1. 独立 CLI 读取本机控制令牌，生成最长 300 秒的绝对过期时间；令牌和文本不进入命令历史之外的配置文件。
2. 回环控制桥核对 Host、来源、令牌、JSON 字段、1–80 字符单行文本和有效期。
3. 只选择已认证、已绑定且唯一的活动设备连接；离线、多连接、TTS 未就绪或设备忙碌立即拒绝。
4. 桥复用该连接的既有 TTS `FIRST → TEXT → LAST` 队列；不调用模型、不写对话历史、不写 L0–L3。
5. 接口仅返回 `queued`。当前没有设备播放完成回执，真实是否播出必须单独实机验收。
6. 第一版不保存离线消息、不等待设备空闲、不自动重试，因此不会在重连后补播过期测试话语。

具体约束见 [ADR-0058](../adr/0058-round-screen-proactive-delivery-probe.md)。这仍不是主动问候产品功能。

## 11. 当前基础：主动交流结果账本（P4.2）

1. 应用层创建 `candidate`，一次保存触发类型、稳定原因码、计划/过期时间、幂等键及唯一一份消息正文。
2. 同一事务写入当前投影和序号 1 的 `system_created` 事件；重复主体＋幂等键拒绝，不覆盖旧记录。
3. 后续执行者携带预期 revision 和真实证据申请状态变化；投影更新与事件追加必须同时成功或同时回滚。
4. `server_queue` 只能支持 `queued`，`transport_write` 只能支持 `transport_sent`，设备回执才能支持 `device_acknowledged`；`played` 需要设备播放回执或明确人工观察。
5. 拦截、取消、过期和失败进入终态，不能重新打开；失败保留稳定原因码。事件不复制正文，也不写进 L0–L3。
6. 当前只提供领域、应用和 SQLite 存储边界，没有触发器、后台调度、控制台入口或设备连接，因此升级后两张表为空。

具体约束见 [ADR-0059](../adr/0059-proactive-outreach-event-ledger.md)。

## 12. 当前基础：确定性联系许可（P4.3）

1. 候选到达执行点后，把用户明确配置与可信运行状态交给纯策略；策略不读取记忆正文、不调用模型或设备。
2. 总开关默认关闭；关闭、过期、勿扰、非允许星期/时段、当前正在聊天、上一条仍待回应、每日超限或最短间隔不足均返回稳定阻止原因。
3. 只有尚未到计划时间返回 `WAIT`；其他被阻止的候选不顺延到未来窗口，避免停机或勿扰结束后补播旧问候。
4. 允许结果只代表策略许可。P4.4 仍需先写账本，再尝试投递，并按真实证据逐步更新状态。
5. 第一版按显式固定 UTC 偏移解释时段，默认 `+08:00`；不自动推断旅行位置或夏令时。

具体约束见 [ADR-0060](../adr/0060-deterministic-proactive-contact-policy.md)。

## 13. 当前基础：主动交流单次执行编排（P4.4）

1. 调用方指定一个已持久化 `candidate` 及其预期 revision；编排器核对主体、状态和并发版本。
2. 编排器把 V15 用户设置与可信运行状态交给确定性策略。`WAIT` 不写事件，`BLOCK` 和过期则进入对应终态，且不触碰设备。
3. 策略允许后，先以 revision 条件把候选推进到内部 `queued`，再调用窄投递端口，避免两个执行者同时播报同一内容。
4. 当前投递契约只表达接受或排队失败。接受后仍停在 `queued`；失败或异常进入 `failed`，不重试，也不把异常正文保存到数据库。
5. 小智适配器复用既有回环令牌客户端调用 `announce`，严格接受 `queued` 且无播放回执的结果，并保留离线、忙碌、TTS 未就绪和结果未知等稳定失败码。
6. 编排器与小智适配器先接入控制台手动测试；P4.5 后续已增加独立、默认关闭的固定时刻后台问候，P5.3 又接入当前缺席策略版本。两者继续复用同一策略和账本。

具体约束见 [ADR-0062](../adr/0062-proactive-outreach-dispatch-orchestrator.md)。

## 14. 当前基础：可信运行状态汇总（P4.4）

1. SQLite 读取器从 `queued` 事件得到最近尝试时间，不读取主动消息或 L0 正文。
2. 最近一个未失败的主动尝试之后若尚无更晚的真实用户 L0，则标记“待回应”，用于阻止连续追问；任何后续用户消息只解除该护栏，不被解释为语义回应。
3. 小智连接缓存单独报告当前用户语音会话和播报就绪状态；设备离线不是用户忙碌，也不能进入 L3 用户画像。
4. 应用汇总器组合历史策略状态与瞬时设备状态，供控制台手动测试、固定定时和习惯缺席调度共同使用。

具体约束见 [ADR-0063](../adr/0063-trusted-proactive-runtime-state.md)。

## 15. 当前验证入口：手动主动问候（P4.4）

1. 用户在 React 设置页打开并保存主动交流许可，输入不超过 80 个字符的短问候，再明确点击一次测试按钮。
2. 浏览器以同源会话、CSRF、设置 revision 和新的 UUID 请求 ID提交；未保存设置时按钮禁用。
3. 后端先按请求 ID 查账本。重复请求直接返回第一次结果，不再次调用小智。
4. 新请求读取可信历史和实时设备状态，创建手动候选并执行许可策略；因为它是所有者显式诊断，所以不受“上一条仍待回应”限制，但总许可、时段、勿扰、频率和设备会话仍可拦截。
5. 允许时通过小智适配器排队。页面只显示“服务端已接收并排队”，圆屏是否播放由实机验收，失败不自动重试。
6. 该入口不调用模型、不读取 L0–L3、不生成话题，也不启动任何后台定时器。
7. 设置页从只读历史接口加载最近投影，显示当前状态、最后原因和事件数量；一次测试结束只刷新该查询，不自动重发。
8. 圆屏实际发声后，所有者可显式“确认已听到”；后端以 revision 保护追加 `USER_OBSERVED` 事件并进入 `played`。没有点击或没有设备回执时继续保持 `queued`。
9. 设置页另读当天定时状态，显示当天是否已经聊过、是否仍等待上一条回应和当前调度决定；该查询不读取正文、不创建候选。

具体约束见 [ADR-0064](../adr/0064-manual-proactive-delivery-test.md)、[ADR-0065](../adr/0065-proactive-outreach-owner-history.md)、[ADR-0066](../adr/0066-user-observed-proactive-playback.md)和 [ADR-0070](../adr/0070-proactive-diagnostics-and-schedule-visibility.md)。

## 16. 当前实现：显式定时问候（P4.5）

1. 所有者在 React 设置页同时开启“允许主动联系”和独立的“后台定时问候”，选择星期、固定时刻和一条不超过 80 字的固定问候。
2. V16 设置持久化在个人数据库中；旧库迁移时保留许可边界，但自动开关强制关闭，不会因为升级开始发声。

3. 控制台后台每 15 秒进行一次无模型检查。只有当地日期、星期和分钟匹配，且当天没有真实用户对话时才创建一次 `explicit_schedule` 候选。
4. 候选使用当地日期幂等；同一分钟重复轮询或服务重启不会重复创建。早于时刻只等待，晚于该分钟直接跳过，不做追赶投递。
5. 设备状态探测后再次读取时钟、设置和当天对话，随后仍经过既有勿扰、允许窗口、频率、待回应与会话活跃策略。
6. 离线或不就绪记录为拦截；排队成功仍只记 `queued`。失败、忙碌和错过都不自动重试。
7. 开发阶段可显式授权今天下一次定时验证。它只绕过当天已聊和上一条待回应；授权在尝试、拦截、错过、设置变化或撤销后结束，并使用独立原因码和幂等键。

具体约束见 [ADR-0067](../adr/0067-explicit-scheduled-proactive-greeting.md)和 [ADR-0071](../adr/0071-one-shot-development-schedule-override.md)。

## 17. 当前实现：所有者批准的主动话题素材（P4.6 第一切片）

1. 所有者在控制台选择一条已接受、当前有效的 L2 场景，再自行填写不超过 120 字的“允许圆屏公开播出”短句；系统不会把 L2 摘要自动当作播报文案。
2. API 在同一写入前核对 L2 主体、状态、现实有效期和 revision。场景已失效、过期或被另一页面修改时拒绝创建，不猜测替代来源。
3. V17 只保存话题素材、L2 引用、状态和 revision。L1/L0 原文继续沿现有 L2 来源链查看，不复制进主动交流表，也不生成新的 L3 用户画像。
4. 控制台展示安全短句、来源 L2 的标题/摘要/状态和是否仍可用；素材可审计式停用，旧页面通过 revision 冲突保护。
5. 当前链路到此停止：保存或显示“可用”都不会创建 `proactive_outreach`、调用模型、启动调度或向 SmartRing-Plus 圆屏终端发声。
6. V18 新增独立且默认关闭的“优先使用记忆话题”开关；只有总许可和后台定时问候都打开时才能启用。
7. 到达原固定定时点后，从仍可用的素材中按未使用/最久未使用优先确定性选择；没有素材则回退固定问候，不读取其他记忆临时生成。
8. 候选继续使用同一天的显式定时幂等键和全部既有安全门控，不增加联系次数；账本同时保存素材 ID 与当时 revision。

## 18. 拟议：习惯驱动问候（P5）

1. P4 先由用户明确启用规则、允许时段、频率和投递入口。
2. 触发时检查勿扰、已联系情况、规则有效性与服务/设备状态。
3. 构建适当话题，不默认朗读敏感内容；向可用入口投递。
4. 区分生成成功、发送成功和设备确认；不把发出请求当作用户已听到。
5. 无回复不追问；取消、过期、断连后不积压补播。
6. P5 根据允许记录的互动提出用户习惯候选；低风险候选通过 P3 的证据/风险门控，否认或规律失效后停用。
7. 回答、实际使用的记忆、投递结果和反馈形成独立结果事件；结果事件不是 L3 用户事实。
8. 多次结果可整理成陪伴经验，并提出原子策略候选；只有离线回放、安全和质量门控通过后才生成新策略版本。
9. 新策略低频激活且可回滚；不在线修改模型权重，也不以单一参与度信号决定策略优劣。

待设计：服务/设备可用性与明确否定结果、习惯置信与撤销策略、陪伴策略门控。没有聊天不代表情绪低落，也可能是电脑或服务未运行。见 ADR-0047。

## 19. 当前实现：首个陪伴互动结果事件（P5.1）

1. 网页或圆屏把真实用户输入归档为 L0 时调用独立结果观察器：普通聊天由共享 `MemoryTurnService` 接线，自然纠错/来源/删除命令由其独立 SQLite 事务接线。
2. 观察器只查找该用户最近一条、早于本消息、尚未关联结果的正式自动问候；`manual_test` 与 `development_*` 被排除。
3. 找到时写入问候 ID、L0 消息 ID、发生时间、秒级延迟和固定 `temporal_order` 证据；不复制用户消息正文。
4. 同一主动问候只关联第一条后续用户消息，后续消息不覆盖事件。
5. L0 与结果事件位于同一写事务；任何约束错误都会整体回滚，不静默吞掉异常。
6. 控制台最近运行记录可显示该观察及延迟，并明确提示“仅表示时间先后”。
7. 控制台复用 P4 账本状态推导“投递未成立、等待后续消息、已观察”，并单列服务端排队、传输、设备确认或播放证据；不为此重复保存第二份设备状态。
8. 当前不据此生成习惯、判断满意度、调整问候时间或修改模型权重。来自用户自然语言的明确否定反馈留给下一切片。

具体约束见 [ADR-0072](../adr/0072-observed-companion-interaction-outcomes.md)。

## 20. 当前实现：圆屏明确拒绝主动话题（P5.2）

1. 用户在问候后的 30 分钟内明确说“以后不要主动聊这个话题”等受限表达；普通抱怨、沉默和模型推断均不触发。
2. 系统先归档该用户 L0，再寻找最近一次正式、已投递、绑定活动话题素材且非开发验收的问候。
3. 找不到唯一时间目标时只返回未处理说明，不停用任何内容。
4. 命中后在同一事务停用素材并追加 `user_explicit` 反馈事件；任一步失败都会整体回滚。
5. 该用户消息同时可成为问候后的首条时间观察，但明确反馈和时间先后保存在两种事件中，不能混为一个评分。
6. 控制台最近记录显示明确拒绝；L0/L1/L2/L3 和总主动交流许可不受影响。

具体约束见 [ADR-0073](../adr/0073-explicit-proactive-topic-rejection.md)。

## 21. 当前实现：联系时段策略候选（P5.3 第一切片）

1. 所有者在控制台点击“分析现有互动记录”；请求受本机会话和 CSRF 保护，不调用模型。
2. 候选服务读取 P5.1 互动事件与 P4 首次排队时间，不读取或复制用户消息正文；带 P5.2 明确话题拒绝的问候不作为本轮正向样本。
3. 只保留 30 分钟内出现后续用户消息的观察，按主动策略固定时区和半小时区间聚类；同一天同一区间只保留延迟最短的一条。
4. 最佳区间至少覆盖三个不同日期时，使用问候时刻中位数生成候选，并保存稳定来源指纹、算法版本和逐条投递证据。
5. 数据库同时最多存在一个当前候选；重复点击返回原候选。同一批已忽略证据不会再次创建候选。

## 22. 当前实现：用户主动出现时间观察（P5.3 第二切片）

1. 网页文字和圆屏语音仍先进入同一个用户 L0 归档事务；自然纠正、来源询问等命令路径也复用相同观察器。
2. 观察器查找本条之前最近的用户消息。没有历史消息，或两条消息间隔至少 4 小时，才继续判断。
3. 若本条消息前 30 分钟存在任何已排队主动问候，本条不计为“用户主动出现”，避免把系统引出的回应混作用户习惯。
4. 通过后写入独立事件，只保存来源消息 ID、发生时间、上一条用户消息时间、静默秒数和检测器版本，不复制消息正文。
5. 控制台按当前主动交流设置的时区显示最近观察。该启发式不等于真实会话 ID，目前也不生成、激活或修改联系策略。

## 23. 当前实现：日常交流时段候选（P5.3 第三切片）

1. 用户在控制台显式点击“分析主动出现规律”；过程不调用模型，也不修改 P4 设置。
2. 系统按当前固定 UTC 偏移把 V23 事件换算为当地日期与分钟，并按 30 分钟区间聚类。
3. 同一天同一区间最多保留一条；最佳区间至少覆盖三个不同日期才形成候选，期望时刻取来源分钟的中位数。
4. 候选与逐条 V23 来源保存在独立 V24 表中，不复制 L0 正文；相同证据指纹不重复创建。
5. 控制台展示“未生效”并允许忽略。它不会把没有事件的日期当成负面样本，也不会自动生成或执行缺席问候。
6. 候选固定返回 `active=false`，控制台标记“未生效”。忽略只改变候选状态，不修改定时问候、L3 用户画像或模型。
7. 本切片生成候选时并不直接激活；后续切片已依次接入离线回放、安全门控、不可变版本、激活/停用/回滚和后台读取当前版本。

## 24. 当前实现：日常时段缺席草案离线门控（P5.3 第四切片）

1. 输入只使用合成的草案时间、当前时间和可信布尔状态；不读取个人聊天正文、模型输出或个人数据库。
2. `routine-absence-trigger-v1` 在期望时刻后等待 60 分钟宽限，并只在宽限结束的唯一当地分钟判断。提前等待、错过跳过，第一版不跨午夜。
3. 当天已观察到该日常时段、已经发生其他聊天或已经评估时，草案不创建主动联系候选。
4. 草案若准备创建候选，继续通过既有 P4 总开关、勿扰、星期/时段、会话活跃、待回应、每日上限和最短间隔规则；之后再检查设备是否就绪。
5. 固定数据集包含 16 条时间线。所有动作与原因必须逐条匹配，且标记为“不得联系”的样例不允许出现任何 `would_queue`，否则门控失败。
6. 回放终点只是“理论上会进入队列”，不投递消息、不写数据库、不激活候选，也不证明真实用户满意。

## 25. 当前实现：不可变缺席策略版本草案（P5.3 第五切片）

1. 所有者在控制台对仍为 `candidate` 的日常时段候选点击“生成离线验证草案”；请求携带候选 ID 与当前 revision。
2. 服务先验证候选仍存在、未忽略且 revision 一致，再验证期望时刻加 60 分钟宽限不会跨午夜。
3. 系统离线运行冻结的 16 条回放，并冻结候选参数、允许星期、触发器版本、数据集 SHA-256、逐条匹配总数和不安全放行数。
4. 上述输入共同计算参数指纹；完全相同的再次请求返回原版本，不重复写入。允许星期等任何参数变化都会得到新指纹。
5. V25 版本行创建后不可编辑。页面显示“门控通过/未通过”和“未激活”，但没有激活 API、当前版本指针或后台调度接线。
6. 下一步以单一当前版本指针和只追加切换事件实现原子激活/回滚；未通过门控的版本永远不能成为当前版本。

## 26. 当前实现：缺席策略版本选择与回滚（P5.3 第六切片）

1. 控制台读取不可变版本、唯一当前指针和按 revision 倒序排列的切换事件。
2. 激活或回滚前，应用层重新读取目标版本；不存在或离线门控未通过时拒绝。
3. 请求携带当前指针 revision；SQLite 以立即事务检查 revision、更新唯一指针并追加切换事件。
4. 停用把指针目标置空但继续递增 revision，不删除版本或事件。
5. 第六切片本身尚未接线；第七切片已把当前版本转为缺席运行草案，并再次经过 P4 护栏，见下节。

## 27. 当前实现：缺席策略运行接线（P5.3 第七切片）

1. 后台循环先评估用户显式定时；若已经创建账本，本分钟不再评估缺席策略。
2. 否则读取唯一当前版本并转换为启用的领域草案；没有当前版本直接跳过。
3. 从用户主动出现事件、L0 用户消息和统一账本计算当天状态；只在宽限结束的唯一分钟允许创建候选。
4. 设备探测后再次读取当前版本和当天状态，防止等待期间版本或证据发生变化。
5. 候选以 `habit_candidate` 进入 P4 账本和投递器；固定问候或已批准话题仍受总开关、时段、勿扰、频率、待回应和设备状态约束。
6. 重复 tick 使用候选来源和当地日期构成的幂等键，不重播；错过时刻不补发。

## 28. 当前实现：主动问候的策略运行来源（P5.3 第八切片）

1. 只有 `habit_candidate` 创建账本时才携带策略来源；普通显式定时和手动验证不会被错误标成习惯策略。
2. 创建当前投影时，在同一条写入中保存不可变策略版本 ID、当时的唯一选择指针 revision 和本次评估当地日期；三项不能只写一部分。
3. 控制台读取运行记录时，沿策略版本外键补充来源候选 ID/revision、期望时刻、宽限、时区和触发器版本。
4. 为什么最终排队或被拦截仍读取只追加账本的最后事件；策略来源不能替代 P4 门控和设备投递证据。
5. 版本后来切换或回滚不会重写旧运行记录，因此可以还原“当时使用哪个版本、为何在那天检查、最后发生什么”。

具体约束见 [ADR-0074](../adr/0074-auditable-contact-time-strategy-candidates.md)和 [ADR-0081](../adr/0081-structured-proactive-strategy-provenance.md)。

## 29. 当前实现：圆屏记忆后端切换

1. 设置中心或启动面板只保存白名单中的下次启动项：LongMemory、小智本地摘要或无长期记忆。
2. 停止并重新启动时，启动器先核对小智端口空闲，再以原文摘要防并发覆盖、保存私有配置备份并只切换 `selected_module.Memory`；缺少内置提供器配置时补最小配置。
3. LongMemory 配置始终保留，用作共享 Runtime 返回路径和设备控制身份；当前算法不是 LongMemory 时，不查询其数据库。
4. Xiaozhi 当前连接的 `Dialogue` 继续提供短期上下文。`nomem` 不跨连接；`mem_local_short` 在关闭连接时异步把本轮与旧摘要压成一份 JSON，后续直接返回整份摘要；LongMemory 逐轮经过常驻 Runtime。
5. 三种提供器统一记录查询/保存毫秒数但不打印正文。切换不改变 ASR、回答模型、角色、TTS、固件或设备控制。
6. 当前网页聊天仍固定为 LongMemory。未来论文方法经白名单适配器加入，正式对比使用独立实验平台冻结条件。

具体边界见 [ADR-0092](../adr/0092-switchable-round-screen-memory-backends.md)，操作见[圆屏记忆后端切换](../guides/圆屏记忆后端切换.md)。

## 30. 网页回答的记忆质量复核

1. 所有者在已完成的网页回答下选择“记忆使用正常、没想起已有记忆、使用了错误记忆、回答与记忆无关”之一。
2. 浏览器提交当前 `chat_id`、回答的稳定 `request_id`、类别和预期修订号；不提交或复制问题、答案、召回正文。
3. 服务验证会话所有权、回答已完成且修订一致，然后在聊天旁库更新当前标记并追加一条 UTC 事件。
4. 标记不经过 Memory Runtime，不调用模型、不重答，也不修改 L0/L1/L2/L3。
5. 每日回顾按浏览器时区同时聚合当前有效判断与复核动作。详情链接回原聊天轮次，使用已保存的回答、召回项和注入上下文定位故障阶段。
6. 页面只按可见轨迹给排查入口：漏记且没有召回时先看检索，有召回时先看注入/采用；错误记忆有召回时核对内容、时效、主体和排序，无召回时先查短期上下文或回答模型。这些不是自动根因判定。
7. 同一轮改标会保留旧事件，因此复核动作数不是独立回答数；当前有效判断按轮次去重，但在形成准确率前仍须定义抽样和标注协议。
8. 跨日质量工作台默认只列当前有效的召回漏失与错误记忆；接口只返回定位元数据、各层召回数量和排查代码，正文必须经所有者会话深链接读取。

具体边界见 [ADR-0096](../adr/0096-owner-answer-memory-feedback.md)。

## 31. 当前实现：圆屏回答完成回执

1. 小智在回答前调用 Memory 插槽；LongMemory 返回记忆上下文和稳定用户 `turn_id`，提供器临时保存该身份及 L1/L2/L3 召回数量。
2. 顶层回答结束后，项目启动适配器只读取本轮新加入小智会话对象的助手文本，不修改厂商 `connection.py`。
3. 提供器以同一 `127.0.0.1` Runtime URL 和令牌调用完成接口；正文不进入命令行、日志或 Git 文件。
4. V30 在一个事务中写入助手 L0 和 `round_screen_turns` 关联；相同回执幂等，不同回执拒绝覆盖。
5. 回执只证明服务端形成了最终文本，不证明 TTS 成功、设备收到或用户听到；失败不自动重试。
6. 这一关联是后续圆屏自然质量反馈的先决证据，本阶段尚未解释“没想起/记错了”等用户表达。

## 32. 当前实现：圆屏明确记忆质量反馈

1. 圆屏用户的下一句仍先走统一 Memory Runtime，形成可追溯用户 L0。
2. 保守解释器要求句子同时包含助手指向、上一轮指向和明确失败描述；失败词的主语方向必须是助手。
3. 系统只查找十分钟内最近一次已经完成的圆屏问答。没有目标、目标过旧或表达歧义时不写事件。
4. V31 事件关联反馈 L0 与目标问答，只保存类别、解释器版本和时间，不重复保存正文。
5. 命中后小智只确认反馈已进入复核队列、尚未自动修改记忆；原回答和 L1–L3 保持不变。
6. 记忆质量页面把圆屏反馈和网页人工标记统一排序，但用来源标签和不同深链接保持入口边界。

具体边界见 [ADR-0098](../adr/0098-explicit-round-screen-memory-feedback.md)。

## 33. 当前实现：圆屏回答的实际召回证据索引

1. 共享 Runtime 在准备圆屏回答时，为实际返回的 L1、L2、L3 条目生成层级、条目 ID、层内顺序和内容 SHA-256 指纹；不在协议索引中复制正文。
2. 小智薄适配器校验索引结构和三层数量，在顶层回答完成后与最终文本一起回传；旧适配器缺少该字段时仍兼容。
3. V32 在同一事务中写入助手 L0、`round_screen_turns`、索引已记录标志和 `round_screen_retrieval_evidence`；数量、顺序或证据冲突时拒绝覆盖。“确认零召回”和“旧历史没有索引”因此不会混淆。
4. 圆屏明确质量反馈命中后，质量列表读取当轮索引并提供 L1/L2/L3 详情链接；列表接口仍不返回问题、回答或记忆正文。只有所有者主动打开单条诊断详情，系统才读取三条 L0 正文和召回条目的当前内容，并把当前指纹与回答时指纹比较。
5. 旧回答没有足够事实恢复当时条目，因此保持空索引并明确显示“只有数量”，不从当前数据库反推历史。

具体边界见 [ADR-0099](../adr/0099-round-screen-retrieval-evidence-index.md)。

## 34. 当前实现：记忆质量问题队列复核

1. 质量工作台为每个当前问题反馈投影一个独立复核状态；没有复核事件时为“待处理”。
2. 所有者可选择“已处理”或“不是记忆问题”及固定原因，也可把已关闭样本重新打开；这些动作不修改原反馈类别。
3. V33 把每次动作追加到 `memory_feedback_review_events`，只保存来源、目标 ID、反馈修订号、动作、原因码、复核修订号和时间，不复制正文。
4. 网页反馈的新修订与旧修订分别管理；圆屏反馈事件本身不可变。旧页面必须携带预期复核修订号，冲突时拒绝覆盖且不自动重试。
5. 默认“需要核对的问题”只显示仍为待处理的失败样本；已处理和非记忆问题保留独立筛选，不能从列表消失误解为历史被删除。
6. 复核状态是内部待办管理，不是训练标签、准确率或自动根因结论，也不会触发模型、重答或 L0–L3 变更。

具体边界见 [ADR-0100](../adr/0100-append-only-memory-quality-review-state.md)。

## 35. 当前实现：L1 可追溯长期事项跟进候选

1. 所有者在主动交流控制台选择一条当前 L1，填写一次性跟进短句和未来时间；页面先读取该 L1 的完整详情 revision。
2. 服务再次校验来源主体、当前状态、详情 revision 和内容 SHA-256，防止旧页面把已纠正或已变化的事实建立为候选。
3. V34 只保存候选、L1 来源、内容指纹、短句、计划时间、状态和 revision；正文在列表中沿 L1 读取，不额外保存来源快照。
4. 候选只有 `candidate` 和 `cancelled`。到达计划时间只显示“已到时间”，不会创建主动交流账本、调用模型或投递圆屏。
5. 来源 L1 被纠正或事实变化后，旧来源退役，候选不可启用；来源被所有者删除时，派生候选一并删除，避免遗留私人线索。
6. 启用和一次性执行已经由下一节及 ADR-0102 实现；候选本身仍不等于联系许可。

具体边界见 [ADR-0101](../adr/0101-l1-backed-follow-up-candidates.md)。

## 36. 当前实现：长期事项的一次性主动跟进

1. 所有者打开主动交流总许可后，可把一个仍有效且未来的跟进候选显式启用；服务核对候选 revision 和当前策略 revision。
2. V35 在启用时创建未来状态为 `candidate` 的 `proactive_outreach`，冻结候选 ID/revision、策略版本、计划时间和过期时间；此时不访问设备。
3. 15 秒后台循环优先取最早一条已到时间的跟进：来源退役或变化则取消，错过存活窗口则过期，设备离线则阻止，其他情况交给既有 P4 策略和投递器。
4. 同一分钟已经处理跟进后，不再运行固定定时或习惯缺席来源，避免配置较宽时连续联系两次；下一分钟恢复正常优先级检查。
5. 取消未执行跟进会同时把派生候选和账本推进为取消；服务端已开始尝试后不再允许假称“未执行取消”。
6. 每个候选只有一个账本，重复 tick 不重播；失败、阻止和过期不补发。`queued` 仍只证明服务端接收。

具体边界见 [ADR-0102](../adr/0102-one-shot-follow-up-outreach.md)。

## 37. 当前实现：明确对话形成一次性跟进

1. 网页或圆屏输入仍先通过统一 Runtime 保存 L0，并按当前方法形成 L1。
2. 只有同一句同时包含受支持的明确日期、明确时刻和“问我……”意图，而且本轮恰好新增一条 L1，确定性解析器才产生草案；不调用模型。
3. 主动交流设置的固定 UTC 偏移用于解释当地日期。1–12 点没有上午/下午等时段时视为歧义；过去、90 天外和模糊时间不猜测。
4. V36 候选记录 `explicit_conversation_request` 和直接用户 L0 ID，并继续冻结 L1 ID 与内容指纹。相同 L0 最多形成一条候选。
5. 若主动交流总开关已开启，用户原话中的“到时候问我”视为该事项的一次授权：候选和绑定的一次性主动账本在同一事务创建，不要求用户访问网页。此时不访问设备。
6. 若总开关关闭，只保存未启用候选并明确说明原因；日后仍可在设置中心核对启用。账本创建失败会回滚候选，但不回滚此前已经提交的 L0/L1。
7. 到点仍进入第 36 节的 P4 完整护栏；一次授权不等于保证播报，也不会让模型推断的普通计划自动联系。
8. “取消刚才的跟进”等固定表达只匹配最近 30 分钟内唯一一条仍未执行的自然跟进；成功时原子取消候选和未来账本。零条、多条或已开始处理时只给固定说明，不猜目标。

具体边界见 [ADR-0103](../adr/0103-explicit-conversation-follow-up-suggestions.md)与 [ADR-0104](../adr/0104-conversation-authorized-one-shot-follow-up.md)。

## 38. 当前实现：明确临时状态的有效期

1. 网页或圆屏输入仍先保存 L0；规则提取或日常模型提取形成 L1 候选后，共用确定性时间后处理器。
2. 第一版只处理以“我今天”或“我这两天”开头、含受支持状态词且不含持久含义的自述；其他表达维持普通 L1，不猜期限。
3. 系统按 UTC+8 写入左闭右开的 `valid_from/valid_to`。“今天”到下一个自然日开始时失效，“这两天”覆盖前一日和当日。
4. 每次关键词或本地 BGE 召回都在统一查询时刻先筛选有效 L1；到期记录仍可在管理页和 L0 来源中审计，但不注入回答。
5. 重复判断只复用查询时刻仍有效的相同 L1，所以后续自然日再次陈述同一状态会生成新的 L1。
6. 有限期 L1 暂不进入自动 L1→L2 整理，也不能支持有效期外的一次性跟进，避免短期状态被长期化。
7. 管理页面按读取时刻显示“当前、未生效、已到期、已退役”；这只是投影，不改数据库生命周期状态。
8. 六条固定完整表达可进一步映射为当天的“只倾听、建议前先询问、直接建议”之一；附加文字和近义猜测不触发。
9. 每轮回答前，Runtime 从仍有效的 L1/L0 来源中选择最新一次明确互动设置。最新项到期后恢复长期默认，不回退到更早的临时项。
10. 模型收到的是代码内固定行为文本，不是用户原话；当前问题明确索要建议时允许响应该即时请求。
11. 该 L1 作为实际使用证据加入回答轨迹；暂停使用记忆时不加载临时互动方式。
12. 用户可用两条固定完整表达追加当天的“恢复默认”选择；读取器遇到最新恢复记录就不再注入临时指令，也不让旧模式重新生效。
13. 当前不支持自由表达和“仅下一轮”，也不把实现测试当作圆屏模型已稳定遵循。

具体边界见 [ADR-0105](../adr/0105-explicit-temporary-state-validity.md)、[ADR-0106](../adr/0106-temporary-interaction-mode.md)与 [ADR-0107](../adr/0107-explicit-temporary-interaction-restore.md)。
