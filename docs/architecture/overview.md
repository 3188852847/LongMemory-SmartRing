# 系统架构总览

P2 声音设置有两条边界：React → 本机认证/CSRF API → 当前 TTS，用于网页朗读、停止和浏览器本地说话打断；启动面板 → 独立 VoxCPM2 Python 3.11 常驻环回服务 → Xiaozhi `CustomTTS` → WAV 转 Opus → 圆屏。VoxCPM2 动态读取本机声音方案，受控参考 WAV 决定音色，表达指令/CFG/推理步数分别承担风格、遵循强度和质量成本。音频不入库；后端切换仍采用私有配置摘要、备份和明确重启，不改 Memory Core。见 ADR-0024、ADR-0025、ADR-0083。

更新：2026-09-08。本文描述模块、边界和数据归属；具体执行步骤见[运行流程](workflows.md)，先后顺序见[路线图](../../ROADMAP.md)。采用文字与表格，不维护图形副本。

## 1. 定位与现状

当前优先建设单用户、可定制的日常陪伴助手；独立记忆核心和研究接口保留。SmartRing-Plus 是 ESP32-S3 智能圆屏，不是戒指。已跑通的合成演示不等于长期陪伴质量验收。

已有：本机网页文字聊天、设备音量控制、记忆查看与受限 L1 删除、隔离实验中心、小智语音记忆桥，以及网页/圆屏共用且已通过真实双向验收的常驻 Memory Runtime。

新增最小 Windows 启动面板，统一拉起现有服务并核对控制台实例，见 ADR-0016。网页会话列表与持久恢复已实现，见 ADR-0019。人工错误纠正、显式事实变化及圆屏高精度自然记忆操作已实现；运行期可分别暂停 L1 生成或记忆注入。L3 对用户呈现一份读取时生成的统一画像，底层仍是可追溯原子断言，见 ADR-0044。真实产品入口是圆屏语音；网页控制台属于开发者/所有者的观察、补录、纠错和回滚平面，不能成为普通记忆积累的必经入口。确定性 L3 风险门控、自动生效执行器和默认关闭的低频整理周期已实现。主动交流已具备默认关闭的规则、账本、手动与固定时刻投递，以及第一种可版本化回滚的保守习惯策略；自动播放完成回执和通用陪伴策略学习仍未实现。

## 2. 部件与进程归属

网页助手角色通过 `RoleSettings` 存入独立 `.role.sqlite3` 旁库，保存采用版本冲突检查，回答开始时固定角色快照。基础提示约束不变；不修改 CLI、研究回答器或 L0/L1。独立 `DeviceRole` 接口在明确确认后经小智 Python 仅同步私有配置 prompt；不自动重启。见 ADR-0022、ADR-0023。

React 控制台在 `web/react-chat/` 渐进扩展，开发时构建，日常由现有 Python 进程提供 `/chat-react` 与 `/memories`；不增加常驻前端服务。记忆页按路径动态加载，旧页面暂留 `/memories-legacy`。后端只公开构建清单中的 JS/CSS，HTML 使用每响应随机样式 nonce，认证与 API 边界不变。见 ADR-0032。

React Router、TanStack Query、统一 AppShell 与组件测试已经建立，聊天、记忆、设备、设置和实验页已完成渐进迁移。LongMemory API 继续使用 aiohttp；Pydantic 已从聊天消息入口渐进覆盖到所有者明确补录入口并保持旧错误语义，后续仍按风险逐条覆盖。FastAPI 当前只是条件触发候选，不是已实施迁移。完整技术雷达见[技术策略](technology-strategy.md)。

P2 聊天外观使用独立 appearance 模块和局部 CSS；浏览器仅保存枚举主题、字号和动画偏好，设置即时生效，不写服务端或记忆库。React 网页角色使用版本化旁库，圆屏仍使用小智配置，角色可显式同步；声音窗口支持 Edge 音色编辑，并只读显示 VoxCPM2 配置与服务状态。见 ADR-0021 至 ADR-0025。

模型连接配置由启动进程从显式选择的学校或官方 env 档案读取。设置中心显示当前进程，允许只写式覆盖新 Key 并选择下次启动档案；读取 API 永不返回 Key，修改不热加载，也不把网页配置误报为圆屏 Xiaozhi 已同步。见 ADR-0085 与 ADR-0089。

防火墙面板是启动器的显式管理入口：只读查询无需主动提权；添加/撤销经用户确认，通过 UAC 单独运行原项目规则脚本。普通启动与 IP 同步不改变系统规则，后台等待不阻塞服务状态轮询。

启动面板的网络辅助层通过 .NET 枚举本机地址；显式同步调用小智现有 Python 环境，仅更新私有 YAML 的三个网络字段并备份。非敏感启动首选项保存在忽略提交的 `data/control/launcher.json`，密钥、对话和删除权限不保存。不涉及模型服务请求；不自动调整系统防火墙或固件设置。见 ADR-0017 与 ADR-0040。

| 部件 | 当前职责 | 不负责什么 |
|---|---|---|
| 网页控制台 `web/` | React 聊天、L0/L1 管理、L2 场景与 L3 用户画像复核 | 不保存模型密钥，不直接连接圆屏控制令牌，不执行记忆算法 |
| Windows 启动面板 | 默认文字、可选语音；管理自有 Windows Job 进程树并打开网页 | 不接管已有终端进程、不探测校园模型、不迁移数据库 |
| LongMemory 本机 API | 提供本地静态页面与 API，编排网页聊天/管理/实验，并托管仅供同机小智调用的令牌化 Runtime 接口 | 不是小智语音进程，不自动启动小智 |
| 常驻 `MemoryRuntime` | 只依赖中立 `MemoryMethod` 和注入的应用能力；串行执行网页/圆屏写入、召回及受限自然记忆操作，维护本次运行的开关，并单一拥有可选低频整理调度生命周期 | 不选择具体方法，不生成回答，不合并两端短期会话，不持久化开关，不是多用户服务；当前真实整理周期默认关闭 |
| LongMemory 记忆核心 | 默认规则提取＋关键词召回；可选模型辅助 L1 提取及关键词＋本地 BGE 排名融合；来源绑定、SQLite 存储和上下文构建 | 不负责录音、语音合成、设备播放或主动调度 |
| 方法层 `methods/` | 日常 v1 包装；隔离实验的原文分块、模型提取方法 | 不强迫未来方法使用同一种数据库或 L1 表示 |
| 小智服务（仓库外独立环境） | 语音识别、对话生成、语音合成、设备连接 | 不把专用协议侵入独立记忆核心 |
| 小智记忆桥 | 统一启动时按白名单选择 LongMemory、小智本地摘要或无长期记忆；LongMemory 调用回环 Runtime | 不负责生成小智最终回答；失败不自动重试/切换，不迁移不同后端数据 |
| 小智设备控制桥 | 对活动设备连接进行受限音量读写；P4.1 可把短测试文本放入既有 TTS 队列，圆屏实机发声已通过 | 当前没有自动播放完成回执；用户观察单独记录，也不是定时主动交流系统 |
| 主动交流账本与策略 | V14 保存当前投影与只追加事件；V15–V19 接入许可、定时、L2 话题和开发验证；V34–V36 增加 L1 长期事项候选、显式一次性启用和明确对话来源 | 跟进候选绑定 L1/L0 但不属于 L0–L3；自然形成不等于启用，到点仍经过 P4 且不补发 |
| 陪伴互动与反馈事件 | V20 记录正式问候后首条用户 L0 的时间关系；V21 记录用户明确拒绝并原子停用对应话题 | 不复制结果正文，不纳入 L3；排除手动/开发问候，沉默和时间先后不代表因果或满意度 |
| 网页回答记忆复核 | 当前标记与追加式修订保存在聊天旁库，通过 `chat_id + request_id` 关联已有回答轨迹 | 四类标记不是用户事实，不进入 L0–L3；每日汇总不复制问题、回答或记忆正文 |
| 智能圆屏 | 采集、传输、显示、播放 | 不存放项目长期记忆库、不运行本项目评估 |
| 圆屏状态模拟器 | 在浏览器用当前板级资料对应的 360×360 画布验证交互、情绪、系统覆盖和圆形安全区 | 不连接真实设备，不证明 B V2 固件能力，不拥有角色素材 |
| 模型接口 | 按所选配置生成回答；隔离实验可做提取 | 不自动知道本地库内容，只有收到的上下文可供使用 |

LongMemory 与小智仍使用独立 Python 环境。统一启动时，小智通过 `127.0.0.1` 的受令牌保护接口调用控制台内的常驻 Runtime；它不是额外对局域网开放的服务。共享 Runtime 仍不等于共享临时会话。

### 2.1 产品交互平面与内部控制平面

| 平面 | 面向对象 | 允许的职责 | 不应承担的职责 |
|---|---|---|---|
| 产品交互平面 | 使用 SmartRing-Plus 圆屏终端的最终用户 | 语音聊天、自然陈述、明确跳过本轮 L1、自然纠正、接收受控主动交流 | 打开网页逐条审核候选、理解数据库层级或处理内部错误 |
| 内部控制平面 | 当前所有者、开发与研究人员 | 查看来源和版本、纠正/停用/回滚、调整策略、诊断和实验 | 代替产品正常交互，或把人工点击伪装成系统已具备自主能力 |

现有 L2/L3 复核页面继续保留，但其定位是内部安全工具。面向产品的自动化必须通过独立风险策略决定，不能用“网页默认点击接受”代替。

### 2.2 P3 目标边界（P3.1 已实现）

P3 目标采用三个并列平面，不把知识库误称为个人记忆的 L4：

| 平面 | 目标职责 | 主要契约 |
|---|---|---|
| 个人记忆 | L0 原始证据、L1 原子记忆、L2 场景、L3 用户画像与行为模式 | `MemoryMethod` / Memory Core |
| 外部知识 | 文档、切片、向量、可选实体关系及引用 | 拟议 `KnowledgeProvider` |
| 上下文编排 | 判断调用哪一平面、合并证据、控制预算并记录注入 | 应用服务，不拥有事实 |

L0 是不可原地改写的证据层；L1/L2/L3 是可重建、可失效、可取代的派生层。上层必须能追溯到下层证据。助手角色 `assistant_persona` 与 L3 用户画像 `user_profile` 分开。外部文档主张不得自动写成用户事实，模型推断不得伪装成用户陈述。见 ADR-0026。

### 2.3 两条演化回路（均有受控第一版）

| 回路 | 演化对象 | 候选来源 | 激活门控 |
|---|---|---|---|
| 个人记忆演化 | L1 事实、L2 场景、L3 用户画像 | L0 证据及当前有效派生记忆 | 来源角色、证据门槛、敏感性、冲突和风险；低风险才可自动激活 |
| 陪伴策略演化 | 助手回应和主动交流策略 | 最小化结果事件、跨次经验模式、固定合成离线门控和 V25 不可变策略草案 | 真实质量门槛、当前版本激活与回滚 |

两条回路只能通过显式上下文编排协作，不能共享一个可任意改写的提示词或表。模型只提出严格候选，不直接修改生产状态；当前不训练模型权重。见 ADR-0047。

控制台默认本机访问，操作指南示例端口 8767（程序默认 8765）；小智音量桥为本机 8766；设备侧 HTTP/WS 使用小智配置的 8003/8000。端口可受实际配置影响，不把说明中的 IP 当永久地址。

## 3. 代码职责

| 目录 | 用途 |
|---|---|
| `src/longmemory/core/` | 领域模型、存储契约、提取/召回职责，不绑定网页或圆屏 |
| `src/longmemory/application/` | 聊天、记忆处理与管理用例 |
| `src/longmemory/methods/` | 可替换方法契约、白名单工厂和具体方法封装 |
| `src/longmemory/adapters/` | SQLite、模型与设备桥等外部技术实现 |
| `src/longmemory/infrastructure/` | 配置、数据库连接、当前 schema、逐版本 migration 与日志 |
| `src/longmemory/entrypoints/` | CLI、本机 API 和小智管道入口；API 目前仍承载部分网页编排 |
| `src/longmemory/evaluation/` | 隔离实验、评分与报告，不是日常回答路径 |
| `web/` | React/TypeScript/antd 日常聊天页及保留的原生管理页面；生产构建由 Python 静态托管 |
| `scripts/development/xiaozhi/` | 既有小智准备、启动与受限设备辅助工具 |
| `datasets/` | 可版本化的合成或公开评估输入 |
| `experiments/` | 实验配置、独立运行状态和结果 |

依赖原则：入口/`bootstrap` 选择并装配具体方法，用例与常驻 Runtime 只调用核心或中立方法契约，适配器实现技术细节。L1 的规范模型和 Store 契约位于 `core/memory/l1_atomic/`，旧路径只作兼容转发。SQLite 当前完整定义位于 `database/definition.py`，历史变化按 `migrations/vN_to_vN+1.py` 独立保存，`schema.py` 只负责连续调度。当前不是一次性完成的理想分层，后续随功能增量整理，不为目录美观重写全部模块。见 ADR-0036。

## 4. 数据与配置归属

| 内容 | 当前归属与限制 |
|---|---|
| L0 原始消息 | 电脑 SQLite；文字路径保存双方角色，小智桥目前仅归档用户 ASR 正文 |
| L1 长期事实 | SQLite，带来源；支持人工及高精度自然纠错/事实变化，所有者确认的漏记补录另存不含正文的质量事件；任意语义冲突自动发现尚未实现 |
| L2 生活场景 | 候选、来源、有效期和生命周期；V12 区分人工/策略复核，已有一次性自动执行器但未挂后台；可受控参与回答 |
| L3 用户画像 | 已实现统一画像投影、候选式取代、策略审计及受控回答；跨时间 L2→L3 整理器已接可选低频调度，但个人库默认关闭 |
| 网页会话/轨迹 | 独立旁库持久化；不等于 L0/L1，也不与圆屏短期上下文合并 |
| 记忆质量反馈与复核 | 网页当前反馈留在会话旁库；圆屏明确反馈、问答回执和 V33 只追加复核事件位于日常 SQLite。复核事件不复制正文，也不进入 L1–L3 |
| 小智短期上下文 | 小智连接侧独立管理，不与网页自动合并 |
| 圆屏记忆后端选择 | 非敏感下次启动指针；LongMemory SQLite、小智 `.memory.yaml` 与 `nomem` 相互隔离 |
| 助手角色 | 已有提示文本与启动配置；不是用户画像 |
| LongMemory 模型配置 | 本地 `.env`/环境和启动参数；不把密钥交给浏览器 |
| 小智配置 | 独立环境的私有 YAML；与网页未自动同步 |
| 实验数据 | 独立实验目录与状态；日常库不自动进入实验 |
| 网页角色 / 外观 / 未来习惯 | 角色在 `.role.sqlite3` 旁库；外观枚举在浏览器；V20–V24 分别保存互动结果、明确拒绝、问候后候选、用户主动出现证据及其时段候选 |

统一启动模式下，网页和圆屏使用同一常驻 Runtime 与日常库；手动小智模式仍可显式使用旧子进程回退。召回失败仍可能导致“不记得”，不能只凭一次答错判断数据未共享。日志不是全量可恢复的会话档案。

## 5. 已有实验能力与日常能力的区别

隔离实验已验证过模型提取及本地 BGE 冻结语料检索。日常路径已可分别选择模型辅助提取和关键词＋本地 BGE 混合召回，但默认仍为规则＋关键词，真实质量待验收。提取模型失败返回 `source_only`；BGE 失败返回 `dense_retrieval_failed` 并显式使用关键词结果。两者不改变隔离实验档案或旧数据库。

日常管理页仍围绕现有 L1，不宣称对任意外部论文方法都能直接管理。人工错误纠正会追加 `user_corrected` 新事实；情况变化会分别写入旧事实 `valid_to` 与新事实 `valid_from`。两者都 SUPERSEDE 旧事实并保留审计历史。撤销、自动冲突和跨层传播仍未实现。

记忆模式是 Runtime 级状态，不是数据库字段：暂停“生成新 L1”后，用户与助手原始对话仍按 L0 归档；暂停“使用已有记忆”后，本轮不检索、不注入，但独立的 L1 写入仍可继续。两个入口共享状态，重启服务恢复全部开启。见 ADR-0031。

## 6. 拟议扩展（未实现）

- P1：运行管理负责启动、状态、停止；会话恢复单独处理持久化。统一配置需明确权威来源，不盲目覆盖小智 YAML。
- P2：设置用例负责保存/预览/回退；外观、助手角色与语音参数分开。具体前端框架后定。
- P3：有预算、幂等和失败可见的低频 L1→L2→L3 整理已接入但个人库默认关闭；门控、自动生效执行器、圆屏自然操作和所有者明确补录保持独立职责。
- P3.9 已落地 `memory_consolidation_runs`：只存调度元数据、成功游标、模型调用计数和 V13 风险复核器版本，不复制记忆正文。两阶段执行、独立风险复核、只读状态、中断收束原语及 Runtime 单一后台周期已有；真实整理需显式开启且默认关闭。
- P3 目标分层：先统一常驻 Memory Runtime 和可靠 L0/L1，再做 L2 场景、L3 用户画像；轻量知识库经中立接口并列接入，知识图谱按真实需求后置。
- P4：主动触发、策略、投递和结果独立于记忆检索。P4.2 已增加 V14 当前投影和只追加事件账本；P4.3 的默认关闭确定性策略只使用显式配置与可信运行状态。设备投递通过适配层，离线、过期或仅服务端排队都不冒充设备确认或播放。见 ADR-0059、ADR-0060。
- P5：V20–V24 分别建立结果、明确拒绝、两类时间证据与候选；它们不混写、不进入 L3，也不直接修改 P4。`routine-absence-trigger-v1` 与 16 条固定合成回放检查草案不能绕过 P4 门控；V25 保存不可变策略版本，V26 以单一指针和只追加事件治理切换，V27 把每次习惯问候结构化绑定到当时版本、选择 revision 和评估日期。当前版本已复用 P4 后台和投递链，真实长期质量仍需日常结果验证。

## 7. 安全和变更约束

控制台保持本机访问、同源/CSRF 校验、受限资源和动态纯文本渲染。真实数据、音频、密钥与本地配置不提交 Git。当前学校 HTTP 接口存在明文风险，不因产品化自动适合发送敏感信息。

删除 L1 不会删除全部 L0；暂停写入不等于暂停聊天归档。批量删除、数据库迁移、索引重建或固件烧录需说明影响并确认。主动问候、开机自启和新增外部传输默认不启用。
