# LongMemory 控制台视觉系统

更新：2026-09-09。用户选定“克制的未来科技仪表盘”为控制台与 Tk 启动面板的共同视觉方向。第一切片新增可回退的未来主题，并统一深海军蓝、青色主操作、琥珀警告和红色故障语义；业务行为与圆屏视觉仍保持独立。

## 1. 目标

视觉统一首先服务于日常可用性：用户应快速判断自己在哪里、系统是否可用、下一步能做什么，以及某项操作是否危险。它不改变记忆算法、设备协议或服务边界，也不把“看起来可用”冒充后端或圆屏已经执行成功。

## 2. 参考如何分工

- [Linear](https://linear.app/now/how-we-redesigned-the-linear-ui)：整体外壳、紧凑信息密度、导航分组、中性表面与单一强调色；不复制其品牌和具体布局。
- [Supabase Table Editor](https://supabase.com/docs/guides/database/tables)：记忆列表、筛选、详情抽屉和来源关系。
- [Vercel 状态与日志](https://vercel.com/docs/deployments/troubleshoot-a-build)：服务状态、阶段进度、失败摘要与日志下钻。
- Stripe Dashboard：删除、覆盖和恢复等危险操作的视觉权重与确认语义。

Ant Design 继续作为控件实现层；参考产品负责提供设计判断，不引入第二套组件库。

## 3. 未来控制台令牌

| 类别 | 约束 |
|---|---|
| 画布与表面 | 画布、普通表面、柔和表面、提升表面四级；主要通过边框区分，不堆叠重阴影 |
| 品牌色 | 单一低亮青色，用于当前导航、主要操作和焦点；不把所有标题染色，不使用全屏霓虹光效 |
| 状态色 | 成功、提醒、危险、信息各自固定语义；不能只依赖颜色表达 |
| 文字 | 标题、正文、次要说明、元数据四级；ID、路径和时间使用等宽字体 |
| 形状 | 未来主题使用小圆角、细边框和少量切角；切角只用于品牌、当前导航与关键消息，不装饰所有控件 |
| 密度 | 默认控件高 36px、桌面侧栏 264px；内容最大宽度 1320px |

平静浅色、经典深色与未来主题共用相同状态语义，不能由页面自行维护另一套颜色。未来主题作为可选项而非不可逆覆盖；字号和减少动画继续服从现有外观偏好。中文正文继续使用无衬线字体，等宽字体只用于 ID、时间、模型名、路径和状态码。

## 4. 共享外壳

- 品牌区只说明产品身份和当前空间，不挤占页面业务标题。
- 导航按日常使用、长期记忆、控制与观察分组；活动项同时使用文字、背景、边框和图标变化。
- 主内容使用统一宽度、页首层级和间距；页面业务组件不得自行创建第二个全局侧栏。

## 5. 聊天页专项（已完成）

- 全局导航优先于会话工具，避免“新聊天”被误认为整个控制台的主操作。
- 会话新建、搜索、选择、重命名和置顶集中在侧栏的独立会话区。
- 消息区占用剩余空间；输入区作为一个稳定表面，发送说明、快捷键和主操作保持同一层级。
- 运行状态使用状态点加文字，不仅依赖颜色；原有记忆过程查看、会话操作和错误恢复行为保持不变。

## 6. 记忆页专项（已完成）

- 页首下方先显示当前层级、记录数和召回状态，不要求用户从开关和列表反推运行状态。
- L1/L2/L3 的运行开关使用“操作名＋影响”的两层文案，并明确标记为服务重启后恢复默认的临时设置。
- L0/L1 在同一个列表表面中切换；每行按层级、内容、状态、时间和稳定 ID 的顺序呈现。
- 纠正错误、记录变化和删除继续位于详情抽屉；视觉整理不改变 SUPERSEDE、时间有效性或 L0 保留语义。

## 7. 设备与状态页专项（已完成）

- 总体状态优先显示，再分别呈现小智控制服务、圆屏连接、设备工具与 AEC 上报；底部保留活动连接数、刷新时间和轮询边界。
- 扬声器和屏幕控制卡显式标记可控状态；值的选择仍不会自动发送，只有点击操作按钮才触发设备写入。
- 最近操作作为独立审计卡，不与当前设备状态混同；历史快照在设备离线后仍明确标注为历史读数。
- 页面不新增设备能力，不从源码猜测固件支持，不改变五秒状态轮询或写操作不自动重试的安全语义。

## 8. 设置中心专项（已完成）

- 页面先显示设置服务、当前助手、当前模型和模型通道摘要，再进入具体编辑。
- 模型、记忆后端、助手角色、声音、外观和主动交流仍是六个独立设置域，不因视觉统一而共享错误的保存或生效边界。
- 每个设置域保留“当前浏览器 / 当前进程 / 下次启动 / 持久许可”等作用范围标识。
- API Key 继续不被页面读取或回显；角色同步、TTS 试听、记忆后端切换和主动交流授权的原有安全边界保持不变。
- 760px 以下导航变为可横向滚动的紧凑入口，必须保留全部页面且不得产生整页横向溢出。
- 键盘用户可以跳过侧栏直接进入主要内容。

## 9. 主动交流专项（已完成）

- 页面先显示总许可、后台定时、今日对话和上次问候四项摘要，避免用户从多个开关和账本反推当前状态。
- 联系许可、时间边界、手动验证、习惯策略与运行记录继续分区呈现；配置和审计证据不混在同一张卡片中。
- 视觉整理不放宽勿扰、频率、待回应、设备忙碌或默认关闭等既有门控，也不把服务端 `queued` 显示为圆屏已播放。

## 10. 实验中心专项（已完成）

- 页面先显示可读档案、当前筛选、当前选择和逐题复核能力，再进入运行参数或结果详情。
- “启动一次回答对照”与“阅读冻结档案”保持两个独立区域；只读服务不会因为浏览档案而加载模型或启动任务。
- 档案列表在桌面端保持可见，详情区承担组间结果、逐题回答、实际注入、召回来源和人工复核；空数据与不可运行原因使用明确文本。
- 本轮不改变数据集、答案模型、字符预算、联网确认或评估口径，词面初筛仍不能冒充语义质量结论。

## 11. Tk 启动面板专项（实现完成，待可见体验）

- 保留系统自带 Tkinter 和既有两页分层，不为一次启动入口新增 Electron、Tauri、前端构建或常驻服务。
- 页首明确“本机启动器”和“不接管外部进程”；颜色、标题、页签、卡片、状态点和按钮复用控制台的中性表面、单一强调色与语义状态原则。
- 启动、重新打开网页、停止和指南固定在页签外的底部操作栏；窗口变矮或高级设置较长时不需要先滚到底部。
- 日常页与高级页继续支持纵向滚动；配置摘要、运行状态和完整文字仍是事实来源，颜色不能代替错误说明。
- 本轮不改变启动命令、端口、配置同步、确认规则、进程所有权、模型、个人数据库或圆屏固件。

## 12. 后续载体

圆屏继续遵守圆形安全区与状态优先原则，按真实板级分辨率和设备状态机单独设计，不照搬桌面控制台或浏览器模拟器。

## 13. 验收

- 业务行为、API 请求和安全确认保持不变。
- 浅色、深色、桌面与 390px 窄窗口均可操作。
- 页面无第三方字体、图标或 CDN 请求，离线控制台仍可使用。
- 关键动作具有文本标签；状态不能只由颜色传达。
- 组件测试、TypeScript、生产构建和隔离 Playwright 路径通过。
