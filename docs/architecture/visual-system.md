# LongMemory 控制台视觉系统

更新：2026-09-08。第一阶段已实现共享设计变量、React 外壳和响应式主导航；聊天页专项整理也已完成。其他功能页的信息重排、Tk 启动面板和圆屏视觉仍按后续阶段推进。

## 1. 目标

视觉统一首先服务于日常可用性：用户应快速判断自己在哪里、系统是否可用、下一步能做什么，以及某项操作是否危险。它不改变记忆算法、设备协议或服务边界，也不把“看起来可用”冒充后端或圆屏已经执行成功。

## 2. 参考如何分工

- [Linear](https://linear.app/now/how-we-redesigned-the-linear-ui)：整体外壳、紧凑信息密度、导航分组、中性表面与单一强调色；不复制其品牌和具体布局。
- [Supabase Table Editor](https://supabase.com/docs/guides/database/tables)：记忆列表、筛选、详情抽屉和来源关系。
- [Vercel 状态与日志](https://vercel.com/docs/deployments/troubleshoot-a-build)：服务状态、阶段进度、失败摘要与日志下钻。
- Stripe Dashboard：删除、覆盖和恢复等危险操作的视觉权重与确认语义。

Ant Design 继续作为控件实现层；参考产品负责提供设计判断，不引入第二套组件库。

## 3. 第一阶段令牌

| 类别 | 约束 |
|---|---|
| 画布与表面 | 画布、普通表面、柔和表面、提升表面四级；主要通过边框区分，不堆叠重阴影 |
| 品牌色 | 单一克制玫红，用于当前导航、主要操作和焦点；不把所有标题染色 |
| 状态色 | 成功、提醒、危险、信息各自固定语义；不能只依赖颜色表达 |
| 文字 | 标题、正文、次要说明、元数据四级；ID、路径和时间使用等宽字体 |
| 形状 | 7/10/14px 三档圆角；卡片和弹窗不使用过度胶囊化造型 |
| 密度 | 默认控件高 36px、桌面侧栏 264px；内容最大宽度 1320px |

明暗主题共用相同语义，不能由页面自行维护另一套颜色。字号和减少动画继续服从现有外观偏好。

## 4. 共享外壳

- 品牌区只说明产品身份和当前空间，不挤占页面业务标题。
- 导航按日常使用、长期记忆、控制与观察分组；活动项同时使用文字、背景、边框和图标变化。
- 主内容使用统一宽度、页首层级和间距；页面业务组件不得自行创建第二个全局侧栏。

## 5. 聊天页专项（已完成）

- 全局导航优先于会话工具，避免“新聊天”被误认为整个控制台的主操作。
- 会话新建、搜索、选择、重命名和置顶集中在侧栏的独立会话区。
- 消息区占用剩余空间；输入区作为一个稳定表面，发送说明、快捷键和主操作保持同一层级。
- 运行状态使用状态点加文字，不仅依赖颜色；原有记忆过程查看、会话操作和错误恢复行为保持不变。
- 760px 以下导航变为可横向滚动的紧凑入口，必须保留全部页面且不得产生整页横向溢出。
- 键盘用户可以跳过侧栏直接进入主要内容。

## 5. 后续页面顺序

1. 聊天：会话导航、模型故障、消息层级、输入区和记忆过程。
2. 记忆：L0/L1 列表、过滤、详情抽屉、纠正与删除。
3. 设备与服务：连接状态、能力、单次快照、操作结果与日志。
4. 设置：角色、模型、声音、主动交流和外观分组。
5. L2/L3 与主动交流：候选、来源、状态和复核动作。
6. 实验中心：预检、预算、任务状态、结果比较和逐题复核。
7. Tk 启动面板：复用同一文字与状态语义，但不伪装成 Web 页面。
8. 圆屏：继续遵守圆形安全区与状态优先原则，单独设计，不照搬桌面控制台。

## 6. 验收

- 业务行为、API 请求和安全确认保持不变。
- 浅色、深色、桌面与 390px 窄窗口均可操作。
- 页面无第三方字体、图标或 CDN 请求，离线控制台仍可使用。
- 关键动作具有文本标签；状态不能只由颜色传达。
- 组件测试、TypeScript、生产构建和隔离 Playwright 路径通过。
