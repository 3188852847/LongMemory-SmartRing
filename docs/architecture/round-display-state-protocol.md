# SmartRing-Plus 圆屏状态协议

更新：2026-09-08。浏览器模拟协议已建立；B V2 已完成原样基线、LVGL 资源策略修复，并接入第一个真实 `thinking` 显示切片。该切片已构建和烧录，真实 STT/TTS 视觉序列待验收，其余中立状态尚未完整接入。

## 1. 目的与边界

圆屏首先要让用户一眼判断设备是在等待、聆听、处理、回应，还是发生了故障。状态协议把业务事实与角色素材分开：以后更换表情、颜色或角色包，不应改写语音、记忆和设备控制逻辑。

当前 `/display-preview` 按厂家 B V2 板级源码记录的 360×360 分辨率模拟。它不连接圆屏、不发送设备指令、不修改个人数据库，也不能证明预编译 B V2 固件已经实现这些画面。

## 2. 三个正交维度

| 维度 | 含义 | 第一版值 |
|---|---|---|
| `interaction_state` | 当前交互阶段，决定主体动画 | `booting`、`idle`、`wake_acknowledged`、`listening`、`thinking`、`speaking`、`interrupted`、`no_speech`、`error` |
| `emotion_state` | 表达风格，不改变业务状态 | `neutral`、`warm`、`happy`、`concerned` |
| `system_state` | 设备或服务状况，必要时覆盖主体 | `normal`、`charging`、`low_battery`、`network_offline`、`model_unavailable`、`server_unavailable`、`provisioning`、`updating` |

情绪不是用户情绪识别结果，也不能由一次回答或沉默自动推断。它只描述助手当前的表现方式。

## 3. 展示优先级

从高到低：

1. 更新与配网：用户必须知道设备暂时不能正常对话。
2. 网络、模型或电脑服务不可用：覆盖普通交互，且三者文案必须不同。
3. 普通交互阶段：待机、聆听、处理、回应等。
4. 充电与低电量：作为边缘提示，不遮住当前对话焦点；只有硬件策略判定必须停止工作时才升级为阻塞状态。
5. 情绪：只改变颜色、眼神与动作幅度。

任何错误都必须同时使用文字或图形语义，不能只靠颜色区分。

## 4. 基本流转

正常对话：

```text
booting → idle → wake_acknowledged → listening → thinking → speaking → idle
```

用户打断：

```text
speaking → interrupted → listening
```

识别不到有效语音：

```text
listening → no_speech → listening 或 idle
```

系统覆盖层可以从任一状态进入；故障恢复后，应根据真实会话状态重新解析画面，不能一律假定回到 `speaking`。

## 5. 事件来源要求

| 状态 | 允许的真实证据 | 不允许的推断 |
|---|---|---|
| `listening` | 固件/语音会话已经开始采集 | 仅因为设备在线 |
| `thinking` | 一轮有效输入已结束，回答尚未开始输出 | 仅因为网络请求存在 |
| `speaking` | TTS 播放已经在设备侧开始，或以后获得等价回执 | 服务端只返回 `queued` |
| `interrupted` | 播放停止并重新进入采集得到确认 | 只检测到麦克风能量 |
| `model_unavailable` | 模型适配层返回分类后的不可用结果 | 把所有网络错误都称为 Key 错误 |
| `charging` / `low_battery` | 固件实时硬件读数 | 根据 USB 是否插入猜测 |

当前小智主动播报只有服务端 `queued`，不能据此驱动“已播放”事实。B V2 v2.2.3 已完成原样实机基线，但仍须逐项定位真实设备事件并通过实机验证，不能从板级入口或“正常显示”直接推断完整状态回执。

## 6. 圆形布局纪律

- 360px 直径圆内的轴对齐内接正方形约为 255×255px；关键文字和控件优先放入此区域。
- 表情、背景和光晕可以延伸至圆周；不能把矩形页面四角当作可用空间。
- 单屏只保留一个主焦点；完整设置、长日志和记忆详情留在网页控制台。
- 顶部只放短状态，底部最多一行短提示；长回答字幕分段显示。
- 支持减少动画偏好。当前厂家资料将屏幕记录为 1.85 英寸 IPS、ST77916；除非 B V2 最新资料另有证据，不按 AMOLED 的烧屏约束作事实设计。

## 7. 接入顺序

1. 用浏览器模拟器评审状态辨识、圆形裁切和文案。
2. 已固定 B V2 的 ESP-IDF v5.5.4 构建与实机基线；实现前先解决应用分区余量、资源分区警告和第三方源码跟踪方式。当前审计结果见[固件审计记录](../research/round-display-firmware-audit-2026-09-08.md)。
3. **进行中**：建立服务事件到中立状态协议的适配器；第一切片用有效 STT 作为 `thinking` 证据，尚未补齐 `interrupted`、`no_speech` 和分类服务故障。
4. 用占位几何图形完成设备端最小状态 UI，并实机验收正常对话、打断与故障恢复。
5. 最后加入可替换角色资源包；角色素材不进入 Memory Core。
