# 0002：识别完成后显示思考状态

状态：补丁已应用、构建并完成应用分区烧录；真实 STT/TTS 视觉序列待验收。

## 目的

B V2 已有待机、聆听、说话、配网、升级和错误画面，但收到有效 STT（语音识别文本）后仍保持“聆听中”，直到第一段 TTS 开始。这个间隔正是用户感知模型延迟的阶段。

本补丁在有效 STT 正文进入 UI 线程后，仅为 SmartRing-Plus 圆屏显示“思考中...”和已有 `thinking` 表情。它不新增或伪造 `DeviceState`，不改变音频采集、WebSocket、模型、TTS、记忆或服务端协议；后续 `tts.start` 仍由原状态机切换到 `speaking`。

## 证据边界

- 允许证据：设备收到非空、类型正确的 STT 文本。
- 不把“设备在线”“请求已排队”或麦克风有能量当作思考。
- 当前不能区分模型推理、记忆检索和 TTS 首包等待，只将它们合并为用户可见的“处理中”阶段。
- 回答失败时由既有 alert、断线或通道关闭流程覆盖；本补丁不自行猜测失败类型。

## 应用前条件

目标 `main/application.cc` SHA-256 必须为：

```text
936b079179e5ec8b845e5efae167e93147f30d7e68fc074640de86848dc68f2c
```

该哈希对应已应用 0001、但 `application.cc` 未被修改的实验副本。哈希不一致时停止。

## 验收标准

1. 0001 与 0002 可按顺序干净应用，ESP-IDF v5.5.4 全新构建成功。
2. 新应用仍落入原 `xiaozhi` 分区并记录余量，资源分区继续挂载。
3. 实机说一句可识别的话后，屏幕从“聆听中”进入“思考中...”，第一段语音开始时进入“说话中...”。
4. 无有效 STT 时不能显示“思考中...”；用户打断后仍由既有状态机回到聆听。
5. 本轮不宣称已经实现 `no_speech`、细分模型故障、可替换角色皮肤或动画状态机。
