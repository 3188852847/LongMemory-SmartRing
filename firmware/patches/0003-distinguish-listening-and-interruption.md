# 0003：区分普通聆听与真实播放打断

状态：补丁已通过前置哈希、干净应用检查和 ESP-IDF v5.5.4 增量构建；尚未烧录，实机验收待完成。

## 目的

厂家 B V2 已能在说话状态检测唤醒词、向服务端发送 `abort`，随后回到聆听，但屏幕只显示普通“聆听中”，用户无法判断刚才的回答是否真的被打断。同时普通聆听仍显示中性表情，不够直观。

本补丁只在 SmartRing-Plus 当前使用的应用状态流中增加一次性显示证据：

- 普通进入聆听时显示现有 `microphone` 字体图标；
- 只有从 `speaking` 状态检测唤醒词、执行 `AbortSpeaking()` 并进入 `listening` 时，显示“已打断，请继续...”一次；
- 下一次普通聆听恢复原有本地化文案；
- `speaking` 继续保留服务端下发的情绪，不用状态图标覆盖角色表达。

## 修改范围

- `main/application.h`：增加一个不持久化的一次性 UI 标记。
- `main/application.cc`：在真实播放打断路径设置标记，并在下一次聆听状态消费；普通聆听使用已有麦克风图标。
- 不新增 `DeviceState`，不改变音频采集、VAD、ASR、WebSocket、TTS、记忆、唤醒词或服务端协议。
- 不把麦克风能量、普通重新聆听或服务端排队当作播放已中断。

## 应用前条件

补丁基于已应用 0001 和 0002 的副本。目标文件 SHA-256 必须为：

```text
main/application.cc  77fe145ef06971962a7dd9dd28d1d78afe2ae2ae2d639d69c32eaa2f5d2be127
main/application.h   2ba86323a14203de062ccdfd20a12b23ab55b42d1b422e0f0d5936ae8c0d3516
```

任一哈希不一致时停止，不强行应用。

## 验收标准

1. 0001、0002、0003 顺序明确，0003 能在当前实验副本干净应用。
2. ESP-IDF v5.5.4 构建成功，应用仍落入原 `xiaozhi` 分区并记录余量。
3. 正常唤醒后显示“聆听中”与麦克风图标。
4. 回答播放期间再次唤醒，声音实际停止后显示“已打断，请继续...”，并继续接收下一句话。
5. 在普通聆听状态再次唤醒不冒充“已打断”。
6. 后续收到有效 STT 仍进入 0002 的“思考中...”，TTS 开始仍进入“说话中...”。

## 未包含

- 没有可靠设备事件时不显示 `no_speech`。
- 不把所有连接错误合并成“模型不可用”；模型、电脑服务和网络故障分类需服务端协议提供证据。
- 不包含角色皮肤、动画或新图片资源。
