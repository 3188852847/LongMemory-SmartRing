# 0010：服务端 AEC 与 WebSocket v2 自然打断实验

状态：补丁前置检查、反向回退检查、ESP-IDF v5.5.4 离线构建、仅应用分区烧录和独立读回均已通过；自然说话打断的运行时验收尚未完成。

## 目的

控制台“停止当前回答”已经由用户确认能立即停止圆屏播放，但它是显式按钮操作。自然说话打断还要求设备在播放期间持续上传麦克风音频，并让服务端借助播放参考音频抑制扬声器回声。

当前 B V2 的服务端 AEC 使用音频包时间戳关联麦克风帧与播放参考帧。原实验固件既未启用 `CONFIG_USE_SERVER_AEC`，又默认使用无时间戳的 WebSocket v1，因此只修改其中一项都不能形成完整链路。

## 修改范围

- 为 `viewe-smartring-plus` 构建配置增加 `CONFIG_USE_SERVER_AEC=y`。
- 仅在该配置启用时，把直连 WebSocket 固定为 protocol v2，避免历史 NVS 中的 `version=1` 静默覆盖实验条件。
- v2 使用固件已有的 16 字节大端时间戳音频头；服务端对应兼容层已经实现严格解析、输出参考缓存和畸形包拒绝。
- 不启用设备端 AEC，不修改动态壁纸、分区表、基础 assets、NVS、记忆数据库、模型或 TTS 配置。

`CONFIG_USE_SERVER_AEC` 在厂家 Kconfig 中明确标为 `Unstable`。本补丁用于受控实验，不是默认发布能力。

补丁中的协议改动采用零上下文小切片，应用和回退检查均须带 `git apply --unidiff-zero`；应用前仍必须先核对本记录中的两个源码哈希，不能对未知版本强行套用。

## 真机验收

烧录与独立读回通过后，先在设备页确认四层门槛全部成立：设备声明 AEC、直连 v2 时间戳传输已安装、服务端 AEC 活动、监听模式为 `realtime`。随后分别观察：

1. 安静环境正常回答是否完整播放；
2. 只有扬声器回声时是否不会自我打断；
3. 近距离自然插话是否能停止当前回答；
4. 较远距离插话是否能停止；
5. 停止后是否继续识别用户新话语并正常回答。

任何一次成功都不能代替“仅回声不误触”的负例。出现频繁自断、音频异常、重连循环或无法继续对话时，立即回滚 v1 镜像。
